# SVG Asset Builder — 장면 소품용 손그림 일러스트 SVG

> 생성 이미지(래스터)는 "씬 전체"(image form)와 인물·생물 스프라이트 전용이고,
> **씬의 부분 요소로 들어가는 그림 소품은 SVG 직필**이다.
> 목표는 기하학적 아이콘이 아니라 **다시 써도 아깝지 않은 완성도의 일러스트**다.

## 2026-09-29 개정 — 무엇이 바뀌었나

교사중심-AI지원체계 덱에서 `plated-dish` · `receipt-printer` · `rubber-stamp`를
새 방식으로 그렸고, 사용자가 "품질이 매우 뛰어나며 재사용이 되어도 아깝지 않은
수준, 이전의 SVG와 차별된다"고 평가했다. 그래서 세 가지를 바꿨다.

1. **표준 스타일이 `clean-hand-illustration`으로 바뀌었다.** 흔들리는 잉크 선
   (`ink-sketch`)은 더 이상 기본값이 아니다.
2. **재사용은 2세대(이 개정 이후 생성분)만 한다.** 그 이전 SVG는 manifest에
   `reusable: false`로 표시했다. 이미 쓰고 있는 덱은 그대로 두되, 새 덱에서는
   가져다 쓰지 않는다.
3. **등록할 때 쓰인 맥락(`contexts`)을 함께 적는다.** 다음 사람이 재사용 여부를
   판단할 재료다.

## 발동 조건 — 넷 모두 만족하면 그린다

1. **소품이 장면을 살린다** — 이 그림이 있으면 메타포가 한눈에 읽힌다
   (영수증이 프린터에서 나온다, 도장이 달력에 찍힌다). CSS 도형으로 흉내 낼 수
   있더라도, 그림 소품이 장면의 완성도를 분명히 올린다면 그린다.
   *(2026-09-29 완화 — 이전의 "대안 부족" 조건은 없앴다)*
2. **인물·생물이 아니다** — 비례·해부학이 있는 형태는 `image-asset-builder`로
   생성 이미지를 크롭한다(졸라맨 금지, scene-grammar §17). 사물·기계·도구·음식·
   건물·풍경 소품은 여기서 그린다.
3. **재사용 후보가 없거나 맞지 않는다** — 아래 「재사용」 절의 판단을 먼저 한다.
4. **면과 선으로 분해할 수 있다** — 윗면·앞면·그림자처럼 면 몇 개와 윤곽선,
   결 스트로크로 나눠 적을 수 있다.

예산: 덱당 5개가 소프트 캡이다. 넘기려면 사용자에게 확인한다.

## 저작 규칙 — `clean-hand-illustration`

### 1. 그리기 전에 면 계획을 적는다

형태를 면 단위로 먼저 나눈다: `윗면(밝은 명도) → 앞면(어두운 명도) → 배출구 →
받침 → 반사 두 줄 → 통풍 결`. 입체감은 **명도가 다른 평평한 면**으로 내고
그라데이션은 쓰지 않는다.

### 2. 선과 면

- **윤곽선 굵기는 거의 일정하게**: 주 윤곽 2.2~2.4, 내부 이음선 1.6~2.0,
  결·질감 1.2~1.4 (viewBox 기준). 흔들리는 선, 겹쳐 그은 흐린 보조 획,
  들쭉날쭉한 굵기는 쓰지 않는다 (2026-09-29 사용자 결정).
- `stroke-linecap="round"` · `stroke-linejoin="round"`.
- **면은 평평한 채색**, 윤곽선 안쪽을 반드시 채운다(열린 선으로 두지 않는다).
- **손맛은 절제해서**: 짧은 결 스트로크(나뭇결·밥알·통풍구), 흰색 반사 한두 줄
  (opacity .2~.35), 옅은 그림자 면(잉크 opacity .06~.08) 정도.
- 곡선은 정돈된 베지어로. 완벽한 기하 도형을 일부러 피할 필요는 없다.

### 3. 색 — 팔레트를 파일 머리에 선언한다

- 잉크(윤곽) 1색 + 채색 3~6색. 밝은 덱이면 짙은 잉크(`#16201b` 등), 어두운
  덱이면 밝은 잉크를 쓰고 면 명도를 뒤집는다.
- **파일 머리 주석에 팔레트를 적는다.** 재사용할 때 색을 기계적으로 바꿀 수 있게
  하기 위해서다.

```xml
<!-- 의도: … (무엇을 왜)
     팔레트: ink #16201b · body #27322d · top #3b4842 · paper #dfe6e1 · accent #6fc3a2
     앵커: 배출구 viewBox y≈172, x 50~490 -->
```

- **앵커**(덱이 좌표를 맞춰야 하는 지점: 배출구, 찍히는 면, 손잡이 끝)가 있으면
  같은 주석에 적는다.
- 텍스트 요소는 넣지 않는다(글자는 덱이 얹는다).

### 4. 렌더 검수 (BLOCKING)

덱 배경색 위에 `<img>`로 띄워 Playwright 스크린샷 → Read로 확인한다.

| 볼 것 | 기준 |
|---|---|
| 인식성 | 무엇인지 1초 안에 읽히나 |
| 완성도 | 다른 덱에서 다시 써도 아깝지 않은가 |
| 구성 | 비어 보이거나 납작하지 않은가(음식 구성이 빈약함, 기계가 판처럼 보임 같은 문제) |
| 배경 대비 | 덱 배경에서 윤곽이 살아 있나 |

미달이면 면 계획부터 고쳐 다시 그린다. 이번 세 점은 1~2회 만에 통과했다
(접시는 음식 구성 보강, 프린터는 윗면·절단 날 추가).

### 5. 저장 + manifest 등록

- 파일: `assets/svg/<영문-slug>.svg`
- `assets/manifest.json`에 항목을 추가한다.

```json
{
  "file": "assets/svg/receipt-printer.svg",
  "type": "svg",
  "origin": "generated",
  "style": "clean-hand-illustration",
  "reusable": true,
  "created": "2026-09-29",
  "license": "자체 제작 (Claude 직필)",
  "palette": { "ink": "#16201b", "body": "#27322d", "top": "#3b4842" },
  "anchors": "배출구 viewBox y≈172, x 50~490",
  "tags": ["한+영 5~10개"],
  "alt": "무엇이 어떻게 생겼는지 한 줄",
  "usedIn": ["teacher-centered-ai"],
  "contexts": [
    {
      "deck": "teacher-centered-ai",
      "slide": 2,
      "role": "소품 — 영수증이 이 프린터에서 한 줄씩 출력된다",
      "metaphor": "사업비 하나에 부수 과제가 줄줄이 딸려 나오는 영수증",
      "placement": "왼쪽 40% 구역, 폭 540px, 배출구 아래로 HTML 영수증 종이가 자란다",
      "adaptation": "원본 그대로. 인쇄 중 LED는 덱이 덮어 그렸다",
      "background": "밝은 종이 #f3f5f2"
    }
  ]
}
```

`contexts`는 쓰일 때마다 하나씩 덧붙인다(재사용한 덱도 자기 항목을 추가한다).
`usedIn`도 함께 갱신한다.

### 6. 덱에서 사용

```tsx
<img src="assets/svg/receipt-printer.svg" alt="영수증 프린터" style={{ width: 540 }} />
```

서빙 URL로 참조한다(번들 import 금지). 움직임은 이미지 한 장을 t의 순수 함수로
옮기거나(도장이 달력 위를 오가며 누름) 이미지 위에 HTML 요소를 겹쳐서 낸다
(프린터 배출구에서 자라는 영수증 종이, 인쇄 중 LED).

## 재사용 — 2세대만, 그리고 반드시 판단을 거쳐서

### 대상

manifest에서 `type: "svg"` 이면서 **`reusable: true`**인 항목만 재사용 후보다.
`reusable: false`(2026-09-29 이전의 `ink-sketch`·`template` 등)는 후보로 올리지
않는다. 이미 그 SVG를 쓰는 덱을 고칠 때는 그대로 둔다.

### 판단 절차

재사용은 **복사해 붙이는 일이 아니라 이 슬라이드에 맞게 옮겨 오는 일**이다.
판단 없이 그대로 쓰면 덱의 통일성이 깨진다.

1. **그림 자체를 본다** — 파일을 렌더해 Read로 확인한다. `contexts`가 없거나
   지금 쓰려는 맥락과 달라도 괜찮다. **그림만 보고도 재사용을 결정할 수 있다.**
   맥락은 판단을 돕는 재료일 뿐 조건이 아니다.
2. **맥락을 참고한다** — 전에 어떤 역할·메타포로 쓰였는지, 어떤 배경과 크기에서
   검증됐는지 본다. 같은 메타포를 다른 덱에서 되풀이하면 청중이 알아챌 수 있으니,
   같은 청중이 볼 덱끼리는 피한다.
3. **이 덱에 맞는지 따진다**
   - 배경: 밝은 덱에서 검증된 그림을 어두운 덱에 그대로 올리지 않는다.
   - 팔레트: 덱의 강조색·보조색과 부딪히는가.
   - 선 굵기: 표시 크기에서 주변 요소(도표 선, 카드 테두리)와 굵기가 어울리는가.
   - 시점·밀도: 옆에 놓일 다른 소품과 시점(정면·비스듬히·위에서)과 디테일
     밀도가 맞는가.
4. **맞추는 방법을 고른다**
   - 그대로: 위 넷이 모두 맞을 때만.
   - 색 변형: 파일 머리의 팔레트를 덱 색으로 바꾼 **변형 파일**을 만든다
     (`<slug>--<덱id>.svg`, manifest에 `variantOf: "<원본 slug>"`). 원본은
     고치지 않는다.
   - 크기·잘라 쓰기: 표시 크기를 바꾸면 선 굵기가 같이 변하므로, 크게 줄이거나
     키울 때는 굵기를 조정한 변형을 만든다.
   - 쓰지 않기: 맞추는 데 드는 손이 새로 그리는 것보다 크면 새로 그린다.
5. **기록한다** — 재사용한 덱의 `contexts` 항목을 추가하고, `adaptation`에
   무엇을 바꿨는지 적는다. plan.md의 `- svg:` 라인에는 `재사용: <slug>(변형 여부)`로
   적는다.
