# Lesson Script Planner — 대사 우선 기획

> **이 스킬은 범용 pd 파이프라인(`pd-script` → `pd-chunk` → `pd-scene`)의 수업 대사
> 응용이다.** 범용 규칙(대본 7원칙·비트 연출 메타 3a~3f·씬당 metaphor·pattern 분포·
> dedup·sketch 4조건)은 pd-* 스킬이 갖고, 여기에는 **수업에만 있는 규칙**만 남긴다 —
> 교사 발화 260자/분 시간 검산, `[행동]` 소요 시간, 구간 예산 ±20%.
>
> newVideoGen 원문은 나레이션을 먼저 만들고 자막 경계 위에서 씬을 잘랐다. 이 스킬은
> **교사 발화**를 먼저 만들고 그 경계 위에서 슬라이드를 자른다.
>
> 연출 디테일(비트 역할·merge_hint·focal/subline·이웃 관계·pattern_ref)이 필요하면
> script.md를 `pd-chunk`의 입력으로 넘겨라 — 이 스킬의 ③④⑤는 그 축약판이다.
>
> **`lesson-deck-planner`와의 관계**: 둘 다 `plan.md`를 만드는 경로다. 하나만 쓴다.
>
> | | lesson-deck-planner | lesson-script-planner (이 스킬) |
> |---|---|---|
> | 시작점 | 학습 목표 → 아크 → 슬라이드 | **교사 발화 전문** → 비트 → 슬라이드 |
> | 발표자 노트 | 슬라이드를 정한 뒤 사후 작성 | **먼저 쓴 발화가 그대로 노트** |
> | 시간 검산 | 불가 (슬라이드 수만 셈) | **가능 (발화 분량 = 수업 시간)** |
> | 유리한 상황 | 시각 메타포가 수업의 뼈대일 때 | 시간 배분이 빡빡하고 설명이 뼈대일 때 |

## 왜 순서를 뒤집는가

슬라이드를 먼저 만들면 두 가지가 반복해서 무너진다.

1. **시간이 안 맞는다.** 14장이 50분인지 80분인지 아무도 모른다. 슬라이드 수는
   수업 시간과 상관이 없다. 말한 분량만이 시간이다.
2. **화면을 읽어주는 수업이 된다.** 슬라이드에 문장을 적어 두면 교사는 그걸 읽고,
   학생은 이미 읽은 것을 다시 듣는다. 둘 다 손해다.

발화를 먼저 쓰면 두 문제가 같이 풀린다. 분량이 곧 시간이고, 화면은 **말하지 않는
것만** 담으면 된다.

## ① 발화 쓰기 (script.md)

**슬라이드를 생각하지 말고**, 교사가 실제로 입으로 낼 말을 처음부터 끝까지 쓴다.

### 작성 원칙

1. **구어체.** "~입니다"보다 "~이에요", "~거든요", "~잖아요". 교실에서 실제로 나오는 말투.
2. **한 문장 15~35자.** 한 호흡에 말할 수 있는 길이. 길면 잘라 쓴다.
3. **한 줄 = 한 문장.** 줄바꿈이 호흡 단위다. 이 원자성이 뒤에서 시간 계산과
   슬라이드 경계의 기준이 된다.
4. **청자 참여.** "한번 생각해 보세요", "여러분은 어떨 것 같아요?"를 실제로 넣는다.
5. **전환어.** "그런데 말이죠", "자 그러면", "여기서 중요한 건" — 비트 경계는 대개
   전환어에서 생긴다.
6. **구체적 사례 우선.** 추상적 설명보다 학교에서 실제로 있었던 일.

### 발화가 아닌 것은 대괄호로

말이 아닌 진행은 `[행동]`으로 적는다. 이것도 시간을 먹으므로 따로 센다.

```
[공공데이터포털을 띄운다]
[학생 두 명에게 물어본다]
[15분 타이머 시작]
```

### script.md 형식

```markdown
# 데이터 탐색과 문제 발견 · 교사 발화

> 대상: 고등학교 · 차시: 1차시 50분 · 구간: 도입5 / 이론15 / 실습25 / 정리5

## [도입] 5분

오늘은 좀 다르게 시작해 볼게요.
[완성 예시 사이트를 띄운다]
이거, 작년에 여기 앉아 있던 학생이 만든 거예요.
...
```

구간 제목은 수업 명세의 시간 배분을 그대로 쓴다. 구간이 시간 예산의 단위다.

---

## ② 시간 검산 (BLOCKING)

발화를 다 쓰면 **바로 세어 본다.** 안 맞으면 슬라이드를 만들기 전에 발화를 고친다.

```bash
node .claude/skills/lesson-script-planner/scripts/script-budget.mjs <script.md 경로>
```

계산 기준 (교실 실측 근사):

| 항목 | 값 | 근거 |
|---|---|---|
| 교사 발화 | **분당 260자** | 낭독(분당 350자)보다 느리다. 판서·시선·호흡이 섞인다 |
| 문장 사이 | 문장당 **+0.4초** | 마침표마다 숨을 쉰다 |
| `[행동]` 한 줄 | **기본 20초** | `[…30초]`처럼 초를 적으면 그 값을 쓴다 |
| 학생 활동 | 발화에 넣지 않는다 | 실습·타이머는 구간 예산에서 따로 뺀다 |

**판정**: 구간별 예상 시간이 명세 배분의 **±20%** 안에 들어야 한다. 벗어나면
문장을 덜어내거나 채운다. 슬라이드를 줄여서 해결하려 하지 마라 — 시간을 먹는 것은
슬라이드가 아니라 말이다.

## ③ 비트 묶기

발화 문장을 **인접한 2~6개씩** 의미 단위로 묶는다. 이 묶음이 비트이고,
**비트 경계가 화면이 바뀌는 자리**다.

> **원자성 (HARD)**: 비트는 문장을 **묶기만** 한다. 합치거나 지우지 않는다.
> script.md의 문장 총수 = 모든 비트의 문장 수 합. 이 등식이 깨지면 발표자 노트에서
> 말이 사라진다.
>
> newVideoGen이 이 규칙을 얻은 경위: 자막 260개를 비트 96개로 **합쳤더니** 자막
> 하나가 122자가 되어 화면에서 3줄로 감겼고, 원본 180개를 잃었다. 묶는 것은 화면
> 전환을 설계하는 일이지 말을 줄이는 일이 아니다.

각 비트에 연출 메타를 붙인다.

| 필드 | 값 | 쓰임 |
|---|---|---|
| `intent` | define · explain · compare · example · emphasize · list | 서사 곡선 |
| `shape` | contrast · flow · cluster · metric · hierarchy · transformation · evidence · summary | 화면 관계 |
| `energy` | calm · neutral · sharp | 리듬 |
| `focal` | 이 비트에서 화면에 남길 **단 하나** | 화면 설계의 씨앗 |

### intent progression (BLOCKING)

비트의 intent 배열이 학생의 인지 흐름이다. 다음을 어기면 비트를 재배열한다.

- **emphasize 2연속 금지** — 에너지 피로. 사이에 explain이나 example을 넣는다.
- **define/explain 3연속 금지** — 교과서 나열. 사이에 example이나 compare를 넣는다.
- **compare 다음에는 emphasize 또는 example** — 비교만 하고 끝내면 결론이 안 남는다.
- **첫 비트는 define 또는 emphasize** — 주제 선언으로 연다.
- **마지막 두 비트는 emphasize 또는 list** — 정리로 닫는다.

좋은 진행: `example → explain → define → compare → emphasize`
나쁜 진행: `define → define → define`, `emphasize → emphasize`

## ④ 슬라이드 자르기

**슬라이드 1장 = 비트 1~3개.** 비트마다 한 장씩 만들지 마라 — 짧은 연결 비트는
같은 장 안에서 `<Build>` 단계로 처리한다.

경계 판단:
- 비트 사이에 **화제가 바뀌면** 새 슬라이드
- 화제는 같은데 **단계가 쌓이면** 같은 슬라이드의 다음 Build
- `[행동]`이 30초 이상이면 그 자리는 **띄워 둘 장**이다 (실습 안내 등)

---

## ⑤ 화면 설계 — dedup이 핵심 (BLOCKING)

각 슬라이드의 화면 텍스트를 그 슬라이드가 덮는 **발화에서 도출**하되,
**발화와 겹치면 안 된다.**

> **원칙**: 교사가 입으로 말하는 문장을 화면에도 적으면, 학생은 같은 것을 두 번
> 처리하느라 아무것도 안 남는다. 화면은 **말하지 않는 것**을 담는다.

### 치환 규칙

화면 후보 텍스트가 발화 문장과 **60% 이상 겹치면** 셋 중 하나로 바꾼다.

| 방법 | 발화 | 화면 (겹침) | 화면 (치환) |
|---|---|---|---|
| **요약** | "행이 서른 개는 넘어야 비교를 하든 추천을 하든 할 수 있거든요" | "행이 30개 넘어야 비교·추천 가능" | `행 ≥ 30` |
| **은유** | "조건 안 맞는 데이터는 아까워도 빼야 해요" | "조건 안 맞으면 뺀다" | 체에 걸린 알 그림 |
| **수치 추상화** | "작년에 여섯 팀 중 두 팀이 데이터를 못 구해서 멈췄어요" | "6팀 중 2팀 중단" | `⅓이 멈췄다` |

### 자가 점검

```bash
node .claude/skills/lesson-script-planner/scripts/script-budget.mjs <script.md> --dedup <plan.md>
```

각 슬라이드의 화면 텍스트와 그 슬라이드가 덮는 발화의 최대 유사도를 출력한다.
**0.6 초과가 하나라도 있으면 통과가 아니다.**

## ⑥ plan.md 쓰기

형식은 `lesson-deck-planner`의 `references/plan-format.md`를 **그대로** 따른다.
렌더러가 변환 없이 소비해야 하기 때문이다. 이 스킬은 두 가지만 더한다.

1. 헤더에 `대사` 행 — `script.md` 경로와 시간 검산 결과
2. 슬라이드 블록에 `- beats:` 행 — 이 장이 덮는 비트 번호
3. **발표자 노트는 새로 쓰지 않는다** — script.md의 해당 문장들을 그대로 옮긴다

「ELI5 적용 원칙」 절은 다른 계획과 똑같이 **필수**다(`eli5` 스킬). 이 스킬은
노트를 새로 쓰지 않으므로, **① 발화 쓰기 단계에서 이미 그 원칙대로 말을
써야 한다** — 용어가 나오면 그 자리에서 한 문장 풀이, 장마다 생활에서 온 비유
하나, 구간 끝에 "그래서 여러분에게는" 한 문장, 단순화한 곳에 "실제로는 …".
뒤에서 고치면 시간 검산이 흔들린다.

```markdown
## Slide 6 — 체를 세 번 친다
- form: scene
- beats: B07, B08
- scene: metaphor: 굵기가 다른 체 세 개 | emotion: 후련함 | intent: …

**핵심 메시지:** 셋 중 하나라도 통과하지 못하면 후보에서 뺀다.

**화면 텍스트:** `행 ≥ 30` · `열 ≥ 3` · `내가 연다`
(발화 최대 유사도 0.31 — 조건 문장을 기호로 추상화)

**형태 설계:** …

**발표자 노트 (script.md B07~B08 그대로):**
자, 그러면 아무 데이터나 다 되느냐. 그건 아니에요.
체를 세 번 친다고 생각하시면 돼요.
…
```

## 검증 게이트 (BLOCKING — 통과 전 렌더러 호출 금지)

1. **시간**: 구간별 예상 시간이 명세 배분 ±20% 안
2. **원자성**: script.md 문장 수 = 비트 문장 수 합 (손실 0)
3. **intent progression**: emphasize 2연속·define 3연속 없음, compare 뒤 결론 있음
4. **dedup**: 모든 슬라이드에서 화면 텍스트 ↔ 발화 유사도 ≤ 0.6
5. **노트 일치**: plan.md의 발표자 노트가 script.md 문장과 글자 단위로 같음
6. **form 다양성**: 3연속 동일 form 없음, scene 메타포 중복 없음 (lesson-deck-planner와 동일)
7. **ELI5 점검**: 「ELI5 적용 원칙」 절이 있고 다섯 가지를 확인했다 — 풀이 없는
   용어 없음(장당 새 용어 ≤3) · 장마다 비유 하나(중복 없음) · 구간 끝의 so what ·
   한 문장에 생각 하나와 "여러분" 주어 · 목적 → 원리 순서 (`eli5` 스킬 4단계)

---

## 렌더러 디스패치

`lesson-deck-planner`의 ⑥ 표와 동일하다. plan.md의 form 분포로 결정한다.
사용자에게 **시간 검산 결과와 dedup 최댓값**을 요약해 보인 뒤 렌더러를 호출한다.

## 원본

newVideoGen(`E:` 드라이브의 로컬 프로젝트)의 `/vg-script` · `/vg-chunk` · `/vg-scene`.
세 파일을 **바이트 그대로**
`references/`에 옮겨 두었다 — 이 문서가 무엇을 바꾸고 무엇을 버렸는지 대조하려면
원문이 있어야 하기 때문이다. 대조표와 버린 목록은 `references/README.md`.

- `references/vg-script.md` — 주제에서 대본을 만든다
- `references/vg-chunk.md` — 자막을 의미 그룹(beat)으로 묶고 연출 메타를 붙인다
- `references/vg-scene.md` — beat를 씬으로 묶고 시각 구성안을 확정한다

가져온 것은 코드가 아니라 **순서와 게이트**다 — 대사 우선, 원자성 보존,
자막↔화면 dedup, intent progression. 매체가 영상에서 수업으로 바뀌면서
자막은 발표자 노트가 되고, 씬 경계는 슬라이드 경계가 되고, 오디오 길이는
수업 시간이 되었다.

## 마무리 — 프롬프트 기록 (모든 덱·활동지 작업 공통)

작업을 끝내기 직전, 사용자가 이 자료를 위해 입력한 프롬프트를 자료 폴더의 `prompts.md`에
**전문 그대로** 덧붙인다. 형식과 제외 규칙은 `.claude/rules/prompt-log.md`. 최초 요청이면
머리글에 이 스킬 이름을 적는다 (`· /<스킬명>`). 첨부 이미지는 세션 id와 순번만.
