# [선택] 덱 전체를 한 편의 영상으로

발표자 영상까지 만든 덱을, 가상 발표자가 처음부터 끝까지 설명하는 **mp4 한 편**으로 내보낸다.
연수 영상·다시 보기·공유용. 1920×1080 · 30fps · H.264 + AAC.

## 왜 이렇게 만드나 (판단 근거)

- **덱은 실시간으로 녹화한다.** 이 덱의 움직임은 두 종류다 — 빌드 등장은 CSS 전환, 씬은
  requestAnimationFrame 시간. 가상 시간으로 한 프레임씩 찍으면 CSS 쪽이 맞지 않는다. 실시간 CDP
  스크린캐스트(`Page.startScreencast`)는 둘 다 그대로 담는다. 프레임마다 에포크 초 시각이 붙어
  키 누른 시각(`Date.now()/1000`)과 같은 시간축이라 정확히 자를 수 있다(약 60fps, 정지 화면에서는 드문드문)
- **발표자는 녹화하지 않고 따로 얹는다.** 브라우저 안에서 발표자 영상까지 같이 녹화하면 재생 시작 지연 때문에
  입 모양과 소리의 시차를 보장할 수 없다. 녹화 때는 발표자 영상 요청을 막아(`page.route` abort) Presenter를
  숨기고, 합성 때 투명 WebM을 덱과 같은 자리·크기·그림자로 얹는다. 소리는 그 단계 mp4의 TTS 원음
- **단계마다 그 단계 발표자 영상 길이만큼 머문다** → 빌드가 말과 같은 순간에 뜬다.
  그래서 **캐스트(목소리)를 바꾸면 단계 길이가 달라져 녹화부터 다시** 한다(20분 덱이면 20분)

## 절차

dev 서버(5199)가 떠 있어야 한다. 발표자 영상이 모두 완성·검수된 뒤에 한다.

```bash
S=.claude/skills/deck-narration-builder/scripts
P="data/<그룹>/<과목>/<수업>/presenter"
R=C:/AI/narration/rec-<media>[-<cast>]                     # 녹화 작업 폴더 — 중간 작업물, 저장소 밖

node $S/record.mjs "$P" $R [--cast <id>] [--from N --to M]              # 실시간 — 덱 길이만큼 걸린다
$PY $S/compose.py "$P" [--cast <id>] $R presenter-media/video/<media>[-<cast>].mp4 --fade-in --drop-frames
```

- `--fade-in`: 첫 장은 등장 애니메이션을 녹화하지 못하므로(페이지를 연 뒤에 녹화가 시작된다) 0.8초 페이드인으로 연다.
  `--from N`(N>첫 장)이면 직전 장 마지막 단계에서 넘기며 시작하므로 등장까지 담긴다
- `--drop-frames`: 녹화 프레임(20분에 약 7만 장 · 9GB)을 고정 프레임률 `base.mp4`(약 140MB)로 편 뒤 지운다.
  base.mp4가 있으면 합성만 다시 할 수 있다(자리 조정 등 — 약 10분). 합성은 단계 길이를 **지금의 발표자 영상**에서 읽으므로,
  녹화 뒤에 발표자 영상을 **줄였으면**(끝 자르기) 녹화 그대로 합성만 다시 한다. **늘었으면** 다음 단계 화면이 섞이므로 compose가 멈추고 다시 녹화하라고 한다
- 20분 덱 기준: 녹화 21분 + 합성 약 8분 → 약 100~120MB. 30MB가 넘으면 SendUserFile로 못 보내니
  앞 1~2장만 `-c copy`로 잘라 미리보기로 보낸다

## 검수

1. 영상·소리 길이가 같은가 (ffprobe `stream=duration`)
2. 발표자 자리를 옮긴 장과 첫·끝 장에서 단계 60% 지점 프레임을 뽑아 한 장에 붙여 본다 — 자리·그림자·겹침
3. 새 캐스트는 윤곽이 달라 본문과 닿을 수 있다 — 닿는 장은 `narration.json` overlay에서 옮긴다
   (덱과 영상이 같은 값을 쓰므로 한 곳만 고치면 된다) 그리고 합성만 다시
4. 첫 장면 페이드인, 마지막 단계 끝의 미소까지 담겼는가

## 한 장만 빨리 보여 줄 때

움직임이 없는 장(표지 등)은 녹화 없이 정지 화면 위에 얹어도 최종본과 같다:
`base.mp4`나 스크린샷 한 장을 `-loop 1`로 깔고 compose.py와 같은 필터로 WebM을 얹는다.
