# Software Walkthrough Builder — 절차를 화면으로 시연하는 씬

컴퓨터과학 수업의 "○○ 설치하기", "○○ 사이트에서 △△ 하기", "명령어로 □□
하기"는 텍스트 목록으로 쓰면 죽고, **실제 화면을 단순화한 목업 위에서
포인터가 클릭하고 타이핑이 흐르는 시연**으로 만들면 산다. 이 스킬은 그
시연(walkthrough) 씬의 저작 절차다.

- **매체**: 네이티브 React 덱 전용 (`react-deck-builder` 파이프라인 안에서
  form: walkthrough 슬라이드를 맡는다). 레거시 HTML 덱은 미지원.
- **역학과 표현의 분리**: 포인터·클릭 파동·타이핑·창 크롬은
  `src/walkthrough` 모듈(역학)을 쓰고, **목업 UI 내용(사이트 구조·다이얼로그
  내용)은 씬마다 자유 JSX로 저작**한다 — scene-grammar의 "표현 층 해방"이
  여기서도 원칙이다. 목업용 공용 템플릿을 만들지 마라.
- **결정론**: 모든 모션은 `useSceneTime()` t의 순수 함수. 슬라이드 진입 시
  t가 리셋되어 발표 중 매번 처음부터 재생된다. 썸네일(freezeAt 기본값)은
  절차 완료 상태로 정지.

## 러닝타임 — `src/walkthrough` (import 경로: `../../../src/walkthrough`)

| export | 역할 |
|---|---|
| `<Pointer path={CursorKey[]}>` | 웨이포인트 따라 움직이는 마우스. `{t,x,y,click?,hide?}` — 씬 컨테이너 % 좌표. click=도착 후 파동, hide=퇴장 |
| `clickFlash(t, at, dur?)` | 클릭 순간 목업 버튼을 빛나게 할 0~1 강도 (boxShadow 링에 곱해 쓴다) |
| `typed(t, text, delay, cps?)` | delay부터 초당 cps자로 드러나는 부분 문자열 — CLI/폼 타이핑 |
| `typedDoneAt(text, delay, cps?)` | 타이핑 완료 시각 — 다음 국면 계산용 |
| `<Caret />` | 깜빡이는 블록 캐럿 (t 기반 결정론) |
| `<AppWindow kind title url badge>` | 창 크롬 셸 — kind: browser/installer/terminal/app. badge="①" 절차 순번. 본문은 자유 저작 |
| `popIn(t, at)` | 창 스프링 등장 — style에 spread |
| `dimAfter(t, at)` | 지나간 창을 밝기 필터로 뒤로 물리기 — popIn 뒤에 spread (불투명 유지가 핵심) |

`Scene`/`interpolate`/`easeInOut`/`riseIn`은 기존 `src/scene`에서 그대로.

## 절차 (씬당)

0. **실사 확인 (BLOCKING — 기억으로 목업을 그리지 않는다)**:
   - **웹 절차**: 실제 페이지를 브라우저(Playwright)로 열어 **페이지 이동까지
     그대로 따라가며** 확인한다 — 스크린샷 + 버튼/드롭다운 라벨 DOM 덤프로
     랜드마크·기본값(버전 번호 등)·클릭 대상의 정확한 문구를 채집한다.
     정적 fetch는 JS 렌더 UI를 못 본다 — 반드시 실 브라우저.
   - **웹이 아닌 프로그램**(설치 마법사·데스크톱 앱): 공식 문서·공식 다운로드
     페이지·공식 스크린샷을 검색해 확인한다. **공식 소스 우선** — 블로그
     캡처는 버전이 다를 수 있다.
   - 채집한 실물과 목업의 라벨·순서·기본값이 다르면 목업이 틀린 것이다.
1. **절차 대본**: 실제 절차를 "창 × 행동 × 확인" 3열로 분해한다.
   `① nodejs.org | LTS 클릭 | 다운로드 칩` → `② 마법사 | [다음]×2·[설치] |
   진행바→완료` → `③ PowerShell | node --version 타이핑 | v22 출력`.
   창이 4개를 넘으면 절차를 슬라이드 두 장으로 쪼갠다.
2. **무대 배치**: 창들을 절차 순서대로 캐스케이드(예: 좌상→우하). 헤더
   텍스트 밴드와 창 무대의 zone을 좌표로 분리. 절차 연결선(SVG)이 배지
   ①→②→③을 잇고 화면 중앙을 통과하게 (edge-cling 금지).
3. **목업 저작**: 실물의 **랜드마크 3~5개만** 재현 (로고 워드마크·핵심 버튼·
   주소창 텍스트). 브랜드 색은 힌트로 한 색만 (Node 초록, Claude 코랄).
   나머지는 tokens 변수. 텍스트는 실물보다 크게 — 교실 뒤에서도 읽히게.
4. **시각표**: 국면 시각을 상수로 선언하고 포인터·창·타이핑이 공유한다.
   클릭 간격 1.1s±, 타이핑 cps 11~14, 총 8~15s. 첫 창은 t≤0.3s에 등장
   (hero ≤1.5s 게이트).
5. **포인터 경로**: 클릭 대상마다 `data-pt="이름"`을 달고, 좌표는 **눈으로
   환산하지 말고 실측한다**(아래 6-a). 클릭마다 대상 버튼에 `clickFlash`
   피드백 필수. 타이핑 국면 진입 시 hide.
6. **검증 (BLOCKING)** — 둘 다 돌린다. 코드 통과 ≠ 픽셀 통과.
   - **6-a 포인터 검산**: 화살촉이 클릭 시각에 대상 안에 있는지 자동 판정.
   - **6-b 픽셀 검수**: 국면별 스크린샷을 찍어 멀티모달로 확인 — 겹침·잘림·
     near-empty·창 가림이 없는지.

```bash
# 6-a 포인터 검산 — t목록에는 "클릭이 일어나는 시각"(시각표 상수)을 넣는다
node .claude/skills/software-walkthrough-builder/scripts/measure_pointer.mjs <deckId> <슬라이드번호> <t목록: 1.6,3.2,4.7>

# 6-b 픽셀 검수 캡처
node .claude/skills/software-walkthrough-builder/scripts/capture_walkthrough.mjs <deckId> <슬라이드번호> <t목록: 1.5,6,13> [출력폴더]
```

### 6-a 포인터 검산을 반드시 하는 이유

창 좌표에 본문 오프셋을 더해 손으로 % 를 계산하면 **어긋난다.** `AppWindow`의
제목줄(약 36px)과 본문의 flex·padding이 추정과 다르기 때문이다. 2026-09-15에
`ai-how-to-learn` 18쪽의 「모델 업로드」가 **225px** 어긋나 있었고, 17쪽의
연필 아이콘은 45px 벗어나 클릭이 허공에서 일어났다. 스크린샷만 보고는
"거의 맞는 것 같다"로 넘어가기 쉽다 — 숫자로 판정해야 잡힌다.

절차는 셋뿐이다.

1. 클릭 대상 요소에 `data-pt`를 단다. 목업 안의 **실제 클릭 대상**에 달아야
   한다(버튼을 감싼 바깥 div가 아니라 버튼 자신).
   ```tsx
   <span data-pt="upload" style={{ ...ring(T.UPLOAD) }}>☁ 모델 업로드</span>
   ```
2. 클릭 시각 목록으로 `measure_pointer.mjs`를 돌린다. 출력은 이렇게 읽는다.
   ```
   t=8.8  포인터 화살촉 (53.38, 39.21)
     ✓ upload      대상 중심 { x: 53.38, y: 39.21 }  거리 0%p
   ```
   `✗`가 나오면 마지막 줄이 넣을 좌표를 알려 준다. 그 값을 `TG` 상수에 박고
   다시 돌려 전부 `✓`가 될 때까지 반복한다.
3. 좌표는 **상수로 박는다.** 런타임 DOM 측정(useLayoutEffect + ResizeObserver)도
   가능하지만, 창 배치가 고정된 walkthrough에서는 상수가 더 단순하고
   결정론적이다. 값 옆에 실측 날짜를 주석으로 남기고, 창 배치를 바꾸면
   다시 잰다.

**재는 시각을 틀리면 검산도 틀린다.** 대상의 화면 위치는 시간에 따라 변한다.

- `popIn`이 끝나기 전(`at + dur` 이전)에는 창이 작다.
- `dimAfter`·`shrinkAfter`로 물러난 창은 줄어들어 있다.
- 타이핑으로 라벨 길이가 바뀌면 옆 요소가 밀린다. 실제로 클래스 이름이
  `Class 1` → `치와와`로 줄면서 연필 아이콘이 45px 왼쪽으로 옮겨 갔다.

그래서 **각 대상은 그 대상을 클릭하는 시각에 재고**, 그 시각에 창이 정착
상태인지 확인한다. 검산 출력에 `포인터 화살촉 숨김/없음`이 찍히면 그 시각에
포인터가 화면에 없다는 뜻이다 — 클릭 연출이 보이지 않으므로 경로를 고친다.

## 수칙 (walkthrough 고유)

- **CLI에 `$`·`>` 프롬프트를 표시하지 않는다** — 초심자는 프롬프트 기호까지
  입력해야 하는 줄 오해한다. 명령은 굵기·타이핑 모션으로 구분한다.
  (공용 `Terminal` 컴포넌트도 기본 무프롬프트 — 필요 시 `prompt` prop)
- 지나간 창은 `dimAfter`로 물러나고 현재 창만 밝다 — 시선 유도.
  창이 셋 이상이면 `shrinkAfter`를 함께 써 크기까지 줄인다(어두운 큰 판이
  계속 자리를 차지하면 현재 창이 작아 보인다).
- **`hide`는 다음 웨이포인트까지만 숨긴다.** 타이핑 국면마다 포인터를
  내렸다가 다음 클릭 때 돌려보낼 수 있다. hide 뒤에 키가 없으면 그대로
  퇴장한다(마지막 hide = 씬 종료 연출). 타이핑이 두 번 이상이면 hide도 두 번
  쓰고, 6-a 검산으로 각 클릭 시각에 포인터가 보이는지 확인한다.
- 창 배지 ①②③ + 창 제목(title/url)이 절차 순번과 장소를 말한다.
- 시연으로 끝내지 않는다: 학생이 실제 접속할 URL은 헤더/리드에
  **클릭 가능한 링크**로 병기 (저장소 클릭 링크 규칙).
- 마지막 국면은 "성공 판정 화면"(✓ 라인·완료 다이얼로그)으로 끝낸다 —
  freezeAt 썸네일이 곧 요약 컷이 된다.
- 창 겹침 시 z-order는 절차 순서(뒤 창이 위). 겹치는 창은 불투명 배경
  유지(AppWindow가 처리) — 반투명이면 연결선·뒤 창이 비쳐 보인다.

  수업 중 반복 재생 가능.
