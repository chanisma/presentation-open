# 씬 철학 — newVideoGen에서 이식한 설계 원칙

이 문서는 E:\newVideoGen 프로젝트(에이전트 영상 씬 생성)가 수만 토큰의 시행착오 끝에
도달한 결론을 슬라이드덱 맥락으로 옮긴 것이다. 씬 저작 전 반드시 읽는다.

## 0. 왜 이 철학인가 — DSL 실패의 교훈

원 프로젝트는 처음에 74종의 정형 블록(DSL)으로 씬을 조립했고, 품질이 오르지 않자
검증 규칙을 33종까지 늘렸다. 결과: 35%가 빈 화면, 쌍둥이 구도 반복. 깨달음은 정반대였다:

> **"품질이 안 오를 때 규칙을 더 추가하지 마라. 표현 층 자체를 해방시켜라.
> 그리고 결과물의 구조만 검증하라."**

| | 표현 층 (과정) | 측정 층 (결과) |
|---|---|---|
| 원칙 | **자유 극대화** | **엄격 고정** |
| 실패한 방식 | 템플릿/블록 조합 (제약된 자유) | 느슨한 다수 규칙 |
| 성공한 방식 | 씬별 자유 코드 (완전 자유) | 소수의 구조 게이트 + 픽셀 검수 |

제약(템플릿·프리셋·공용 컴포넌트)을 늘릴수록 모든 씬이 "규칙을 만족하는 몇 안 되는 조합"으로
수렴해 오히려 더 generic해진다. 슬라이드도 똑같다 — **bullet list 지옥은 표현 제약의 산물이다.**

## 1. 적은 '무난함'이다

AI가 만드는 화면은 기본적으로 단조롭다. 통계적 평균으로 수렴하기 때문이다.
목표는 "AI가 만든 것 같지 않은 덱". **매 요소는 존재 이유를 증명해야 한다.**

## 2. 절대 원칙

1. **사각형 나열 금지** — 네모 카드 줄세우기는 파워포인트지 씬이 아니다.
2. **비대칭이 기본** — 좌우대칭·균등분할은 디자인 포기 신호다.
3. **깊이감** — 전경/중경/배경 층위를 의식한다 (그림자·크기 대비·겹침).
4. **필러 금지** — 빈 공간을 장식 아이콘·뻔한 수치·이모지로 메우면 패배.
   빈 공간은 레이아웃으로 푼다 (의도적 여백은 무기다).
5. **같은 구도 반복 금지** — 같은 구조가 3씬 이상이면 시청자(학생)가 패턴을
   인식하고 지루해진다. validator가 구조 시그니처로 차단한다.
6. **요소 증명 책임** — "왜 이 요소가 여기 있는가?" 대답 못 하면 삭제.

## 3. 씬 작성 전 게이트 질문 (매 씬 반복)

```
이 씬을 직전 씬들과 어떻게 *시각적으로* 다르게 만들 것인가?
→ 답이 "텍스트만 다르고 구도 같음"이면: 멈추고 메타포 재발명.
```

씬 워크플로우: ① 전달할 내용 읽기 → ② 감정 추출 (놀람? 아하? 긴장?) →
③ 시각 메타포 결정 (저울/거품/영수증/계량기/도장/지도…) → ④ 레이아웃 자유 설계 →
⑤ 코드 작성 (매 씬 처음부터) → ⑥ 픽셀 확인.

## 4. Lazy Defaults — AI가 자동으로 손 뻗는 기본값을 의식적으로 거부

- 균등 3열 카드 그리드 → 비대칭 분할로
- 전체 중앙 정렬 → 앵커를 한쪽에 몰고 여백을 반대쪽에
- 이모지·스톡 아이콘 → 씬의 자기 시각 언어로
- 뻔한 수치(99.9%, 50%) 장식 → 실제 의미 있는 숫자만
- 순수 검정 #000 / 순수 흰 #fff 배경 → 톤이 있는 잉크/종이 색으로
- 기본 폰트만 나열 → 크기·굵기·자간의 극단적 대비를 활용

## 5. 결정론적 모션 (frame-purity의 웹 이식)

모션은 **활성화 후 경과 시간 t의 순수 함수**다. `Math.random()`·`Date.now()` 금지.
같은 씬을 두 번 열면 정확히 같은 모션이 재생되어야 한다 — 그래야 검수가 가능하고,
픽셀 리뷰(t≈1.6s 캡처)가 의미를 가진다.

- 히어로 프레임(모든 요소가 가장 잘 보이는 정적 순간)에 **t ≤ 1.5초** 안에 도달할 것.
- 모션은 이해를 돕는 도구다. 장식 모션(무한 반복 흔들림 등)은 필러의 일종.
- 레이아웃 먼저, 모션은 그다음 (Layout Before Animation) — 정적으로 읽히지 않는 씬은
  움직여도 읽히지 않는다.

## 6. 하드 게이트 vs 소프트 원칙

**validator가 기계적으로 차단 (하드)**: 의도 주석 누락, metaphor 중복, 구조 시그니처
클러스터 > 2, 씬 간 텍스트 유사도 > 0.65, 이모지, 균등 그리드, 비결정 코드,
스코프 밖 스타일. **pixel_review가 차단**: 밀도 12% 미만(near-empty).

**사람(에이전트)이 지키는 것 (소프트)**: 비대칭, 깊이감, 필러 금지, 감정-메타포 정합,
모션의 교육적 의미. — 하드 게이트를 통과했다고 좋은 씬이 아니다.
**스키마 통과 ≠ 픽셀 통과.** 최종 판단은 렌더된 PNG를 눈으로 보고 한다.

## 7. 이 철학이 금지하는 유혹들

- "씬 헤더/푸터를 공용 컴포넌트로 빼면 코드가 절약된다" → 그 절약이 바로 generic 회귀의 씨앗.
  공유해도 되는 것은 **인프라**(네비게이션, Scene Motion Runtime, 색 토큰)뿐이다.
- "구도 카탈로그를 만들어두고 고르게 하자" → 새 DSL의 재발명. 금지.
- "스크립트로 씬 N개를 일괄 생성하자" → 일괄 생성물은 전부 닮는다. 씬은 한 장씩 손으로.
