# Collage Grammar — 종이 콜라주 + 카메라 여행 문법 상세 (슬라이드덱판)

newVideoGen `/vg-vox` v1.3의 문법을 이 저장소 매체로 옮긴 것.
레퍼런스 구현: `data/dev/테스트 수업 자료/데이터-콜라주-샘플/deck.tsx` (`?deck=vox-demo`).

## 0. 매체 변환 — 영상 문법을 슬라이드로 옮길 때 바뀌는 것

| 영상(vg-vox) | 슬라이드덱(이 스킬) |
|---|---|
| 씬 = 4~8초 컷, 59씬 | 슬라이드 = 8~14초, 4~8장 |
| SFX(팝·슬라이드·딩) + BGM | **이식 안 함** — 등장 스냅 + `EntryBurst` 파편이 강조를 맡는다 |
| SRT 자막 | 자막 없음 — `Tag`·`AnchorBox`·고정 헤드라인이 텍스트 전부 |
| 비디오 클립·아이콘 매체 믹스(정량 기준) | 이식 안 함 — 덱은 조각 + 타이포 + 모션그래픽으로 충분 |
| 카메라 총 이동 ≥600px | 그대로 (슬라이드당) |
| — | `<Build>` 축: 정리·권리 목록은 클릭으로 |

## 1. 월드 설계가 먼저다

**프레임(1920×1080)에 가두지 마라.** 콜라주는 프레임 밖까지 이어진 큰 종이 위에 펼쳐
놓고, 카메라가 그 위를 여행한다.

```
world { w: 3200, h: 1080 }   // 가로 여행
world { w: 2600, h: 1200 }   // 대각 여행(세로 여유)
world { w: 1920, h: 1080 }   // 정지 프레임(마지막 장 등)
```

- 클램프 공식: 카메라 중심은 `[w/2 − mx, w/2 + mx]`, `mx = w/2 − 960/s`. 즉 **줌아웃할수록
  팬 여유가 줄고**, `s = 1920/w`까지 내리면 월드 전체가 한 화면에 들어온다(줌아웃 리빌).
- 콘텐츠가 실제로 있는 범위까지만 팬하라 — 월드만 크게 잡고 가장자리가 비면 그 빈 종이가
  그대로 나온다.

## 2. 카메라 안무 — 슬라이드마다 다르게

| 안무 | 키프레임 감각 |
|---|---|
| 롱 팬 | `x` 1500px+ 이동, `s` 1.2 → 1.0 (넓어지며 도착) |
| 줌아웃 리빌 | `s` 1.9 → 1.0, `x` 고정 — 가까이서 시작해 전체를 드러낸다 |
| 대각 여행 | `x`·`y` 동시 이동, `s` 미세 변화 |
| 정지 프레임 | 이동 0, `s` 1.0 → 1.08 미세 푸시인 (마지막 장) |

- **첫 2초는 멈춰 있어라** — 학생이 화면을 읽을 시간. 그 다음 여행이 시작된다.
  (키프레임 3개 패턴: `[t0 정지] → [t≈2 같은 위치] → [t끝 목적지]`)
- 한 키프레임 구간이 5초를 넘지 않게 나눈다.
- **모션 블러 금지** — 종이의 물성이 사라진다.

## 3. 스테이션 배치 — 경로 위에 내용을 깔아라

카메라가 지나가는 길에 **덩어리(스테이션)** 를 놓아 화면이 늘 채워져 있게 한다.
2026-08-18 검수에서 두 번 걸린 항목이 이것이다(중간이 빈 채로 카메라만 이동).

- 가로 3200 월드라면 스테이션 간격 **300~450px**, 슬라이드당 조각 5~7개.
- 조각은 나열이 아니라 관계로: 수렴 / 대비 / 흐름 / 순환 / 누적 중 하나.
- 마지막 프레임에 **이야기의 두 축**(주장과 반증, 출발과 도착)이 함께 남게 배치하면
  교사가 정리하기 쉽다.

## 4. 조각(Cutout) 운용

```tsx
<Cutout src={P.phone} x={620} y={640} w={200} at={0.2} entry="pop"
        drift={{ x: 18, rot: -2, to: 8 }} depth={1} />
```

- **entry**: `pop`(기본·칩/작은 조각) · `slide`(옆에서) · `tear`(위에서 기울며 — 종이답다) ·
  `drop`(낙하 + 착지 squash). 0.3초 스냅이며 느린 페이드 등장은 금지.
- **drift는 필수**. dominant `|x|+|y| ≥ 60px` 또는 `rot ≥ 5°`, 보조 ≥ 30px.
  `from`/`to`로 구간을 잡으면 **씬 중반의 사건**(가로지르기·합류·낙하)을 만들 수 있다 —
  슬라이드당 최소 1개.
- **depth**: 0.75~0.9 배경(카메라보다 덜 움직임) · 1.0 주인공 · 1.05~1.2 전경.
  패럴랙스가 있어야 종이가 여러 겹으로 읽힌다.
- **크기**: dominant 480~760 월드px 세로 · 조연 240~420 · 배경 90~200(`dim` 0.8~0.9).
  크롭 원본보다 크게 늘리지 마라.

## 5. 모션그래픽 — 관계를 그리는 어휘

슬라이드당 **3~5개**, 서로 다른 색(`VOX_HUES` 순환). 전부 등장 후에도 계속 도는 루프라
후반이 정지 포스터가 되지 않는다.

| 어휘 | 쓰임 |
|---|---|
| `ArrowFlow` | 방향·전이 — 쐐기가 경로를 흘러간다 |
| `DashTrail` | 여정·추적 — 점선 + 선두 점 왕복 |
| `CircleScan` | 대상 지목 — 회전 조준원 |
| `PulseDot` | 주목 신호 — 맥동 링 |
| `RadialBurst` | 확산·강조 |
| `Strike` | 부정·폐기 — 취소선 + 미세 진동 |
| `InkCircle` | 단발 주석 — 손으로 두른 타원 |
| `AnchorBox` | 대상 라벨 — 모서리 브래킷 + 칩 |

⚠ 이건 **주석 어휘**지 레이아웃 구조가 아니다. 여기서 Kicker/Hero/Footer 같은 구조를
만들면 모든 슬라이드가 같은 구도로 수렴한다.

## 6. 텍스트 규약 (겹침 사고에서 도출)

1. **고정 헤드라인은 여행 시작 시 물러난다** — 켠 채로 카메라를 밀면 조각이 글자를 덮는다.
   그 역할은 `AnchorBox` 라벨과 `Tag`가 이어받는다.
2. **여행 중 설명은 카메라 안**(`Tag`)에 두어 대상과 함께 움직이게 한다.
3. **라벨은 대상 bbox 바깥**. 조각 위에 얹으면 종이 질감에 글자가 묻힌다.
4. **z 순서**: 조각 5~9 · 모션그래픽 12~14 · 라벨/칩 15~16 · 고정 헤드라인 40.
   칩 배경(불투명)이 취소선을 덮은 사고가 있었다 — 칩 위를 지나는 `Strike`는 `z={18}`.
5. 하단 0~7%는 덱 크롬. 월드 좌표로 환산해 라벨을 그 위로 올린다.

## 7. 자산 — 시트 배경은 회색으로

조각의 정체성은 **흰 종이 테두리**다. 시트 배경을 오프화이트로 요청하면 크롭 키잉이
테두리를 배경으로 오인해 먹어 버린다. **중간 회색 `#8f9296`** 배경으로 생성하고
`crop_sheet.py --tol 55`(그림자까지 제거)로 자른다.

## 함정 (검수에서 실제로 터진 것들)

1. **`margin: %`는 세로도 컨테이너 *너비* 기준** — 월드 div를 %margin으로 중앙 정렬하면
   화면이 위로 밀린다. 킷은 `translate(-50%,-50%)`로 고정했다(자기 크기 기준).
2. **카메라가 클램프에 걸려 요청 좌표에 못 간다** — `mx` 공식을 확인하고, 안 되면 월드를
   넓히거나 `s`를 올린다. 캡처로 확인 없이 좌표를 믿지 마라.
3. **조각 사이가 비면 여행이 지루하다** — 스테이션 간격을 좁히거나 의미 있는 조각을 넣는다.
   빈 카드로 메우는 것은 금지.
4. **라벨 y를 `w` 비례로 추정하면 어긋난다** — 조각의 실제 높이는 `w / ar`. 라벨은
   `y + (w/ar)/2 + 여백`에 두거나 캡처로 확정한다.

## 자가 점검 (슬라이드마다)

1. 카메라 총 이동 ≥ 600px인가? (아니면 정지 프레임으로 설계했나)
2. 경로 위에 1초 이상 빈 종이가 없나?
3. 모든 조각에 drift가 있고, 슬라이드에 사건이 1개 있나?
4. 모션그래픽 3~5개가 서로 다른 색인가?
5. 마지막 프레임에 이야기의 두 축이 남아 있나?
6. 라벨이 조각·칩에 가려지지 않았나? (초·중·말 3시점 캡처로 확인)
