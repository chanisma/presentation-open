# 3D Model Builder — 원리를 만질 수 있는 모형

> **한 줄 정의**: 슬라이드가 "보여 주는" 자료라면, 모형은 학생이 **손잡이를 돌려 보는
> 교구**다. 상태 변수 하나를 긁으면 3D 무대와 2D 차트와 수식의 숫자가 한꺼번에
> 움직이고, 그 숫자는 전부 진짜로 계산된 값이다.

- **매체**: 자기완결 HTML 한 장(`data/<그룹>/<과목>/<수업>/index.html`). 허브가 `type: doc`으로
  원본을 그대로 연다. bolt 크롬을 입히지 않는다.
- **기술 스택 고정**: three.js r169(`assets/vendor/three/`, `<script type="module">`), 아트보드
  1672×941 스케일, 자가 점검 API, Playwright 헤드리스 검수. 이것이 이 스킬의 알맹이다.
- **UI 컨셉 자유**: 색·카드 배치·라이트/다크·글꼴은 소재에 맞게 새로 정한다. 두 레퍼런스
  모형(확산·어텐션)의 라이트 스튜디오 룩을 베낄 이유가 없다. 스캐폴드는 골격만 준다.

## 언제 이 스킬인가

| 상황 | 스킬 |
|---|---|
| 학생이 **변수를 바꿔 가며 원리를 체감**해야 한다 (확산 단계, 어텐션 가중치, 엔진 크랭크각) | **3d-model-builder** |
| 개념을 순서대로 **설명**한다 (슬라이드) | `lesson-deck-planner` → 렌더러 스킬 |
| 설명 덱 안에 체감 교구가 **한 장** 필요하다 | `lesson-deck-planner`가 `form: model`로 계획 → 이 스킬이 먼저 만들고 덱이 부른다 |
| 한 슬라이드 안의 작은 위젯(2D) | `react-deck-builder`의 인터랙티브 컴포넌트 |
| 소프트웨어 절차 시연 | `software-walkthrough-builder` |

판별 한 줄: **"학생이 돌릴 손잡이가 있고, 돌리면 숫자와 그림이 함께 바뀌는가?"** 그렇다면 모형이다.

## 기술 스택 — 고정하는 것과 자유로운 것

| 고정 (스킬의 알맹이) | 자유 (소재마다 새로) |
|---|---|
| three.js r169 벤더 `assets/vendor/three/three.module.min.js` (`../../../../` 상대 경로) | 무대 메타포 (격자·기둥·궤도·지형·공장 라인…) |
| 아트보드 1672×941 + `--scale` + `camera.fov` 역산 (창 크기와 무관하게 같은 구도) | 색 토큰·카드 배치·라이트/다크·글꼴 |
| `project()`로 3D 점 → 아트보드 좌표 (콜아웃·HTML 라벨 정합) | 어떤 손잡이를 둘 것인가 (슬라이더·토글·프리셋·예문) |
| 상태 객체 하나 + `state.t` 재생 루프 + URL 파라미터 초기화 (`?t=`·`?paused=1`·`?mode=demo`·**`?embed=1`**) | 2D 차트 종류 (SVG 직접 그린다) |
| `window.<app>` 자가 점검 API: `snapshot / setState / advance / capture` | 카메라 프리셋 개수와 각도 |
| 스튜디오 PMREM 환경맵 + 방향광 섀도맵 + 셰이더 접지 그림자 (원하면 교체 가능) | 자동 시연 시나리오 |
| `file://`에서는 동작하지 않으므로 8초 뒤 안내문 (모듈 import 때문) | |

## 설계 문법 — 다섯 원칙 (BLOCKING)

1. **상태 변수는 하나가 주인이다.** V8 엔진의 크랭크각, 확산 모형의 단계 t, 어텐션 모형의 계산
   진행도 t처럼, 무대·차트·수식이 전부 그 값의 **순수 함수**여야 한다. 요소마다 제 타이머를
   두면 동기가 깨지고 되감기가 안 된다. `Math.random()`은 시드 난수(mulberry32)로 대체한다.
2. **화면의 모든 숫자는 진짜 계산이다.** 예시값을 적어 넣지 않는다. 데이터가 장난감이면
   장난감이라고 화면에 쓴다("손으로 설계한 임베딩", "학습이 완벽하다고 가정"). 근사한 부분은
   무엇을 근사했는지 안내문에 명시한다. 이것이 `adversarial-review`를 통과하는 유일한 길이다.
3. **3D 무대와 2D 차트는 같은 함수를 공유한다.** 차트 곡선은 무대가 쓰는 `schedule()`·`cycle()`을
   그대로 샘플링해 그린다. 두 벌의 데이터가 있으면 반드시 어긋난다.
4. **메타포는 소재에서 발명한다.** 격자 큐브(확산)·기둥과 빔(어텐션)을 다른 소재에 재사용하지
   않는다. `.claude/rules/scene-grammar.md`의 Lazy Defaults 목록을 시작 전에 읽는다.
5. **자가 점검 API가 없는 모형은 미완성이다.** `snapshot()`이 수식 검산에 필요한 수치(합·평균·
   오차·argmax·드로우콜·프레임 시간)를 돌려주고, `setState()`가 어떤 상태든 강제할 수 있어야
   헤드리스 검수가 한 번에 끝난다.

## 파이프라인

### Phase 0 — 개념 분석 (코드 작성 금지 단계)

`lesson-deck-planner`에서 넘어왔다면 plan.md의 `form: model` 블록(체감 한 문장·주인 상태
변수·진짜 계산·장난감인 부분·손잡이·embed)이 이미 이 단계의 답이다. 그대로 이어받아
Phase 1로 간다. 소재만 들고 직접 호출된 경우에는 아래를 새로 적는다.

작업 폴더의 `plan.md`가 아니라 **답변 본문**에 다음을 먼저 적고 사용자에게 보인다. 갈림길이
있으면 `AskUserQuestion`으로 묻되, 형식·위치처럼 이미 정해진 것은 다시 묻지 않는다.

```
- 학생이 체감할 한 문장:  "AI는 지우개질을 배운 것이다"
- 주인 상태 변수:        t ∈ [0,1] (단계 0~50)
- 진짜 계산:             x_t = √ᾱ·x₀ + √(1−ᾱ)·ε  (코사인 스케줄)
- 근사·장난감인 부분:     목표 이미지 4종은 수식으로 그림 / 역과정은 정과정 되짚기
- 손잡이:                방향(생성·학습)·프롬프트·시드·배율·카메라
- 검산 기준:             t=1에서 평균 0·표준편차 1, t=0에서 원본 오차 0
```

기존 자료와의 관계를 반드시 확인한다. 같은 수업의 덱이 이미 다룬 것(예문·용어·색 언어)을
이어받고, 덱이 "다루지 않는다"고 명시한 부분을 모형이 맡는 식으로 **자매편**을 만든다.

### Phase 1 — 무대 설계 (UI 컨셉은 여기서 새로 정한다)

- **구역**: 3D 무대가 차지할 자유 영역(대개 아트보드 x 350~1290, y 110~790)과 2D 카드 열을
  먼저 좌표로 나눈다. 카드가 무대를 가리면 카메라 반경·타깃으로 무대를 옮긴다.
- **메타포 1개 + 3단 이내의 국면**: 상태 변수가 흐르며 무대가 어떻게 변하는지 국면별로 적는다
  (확산: 노이즈→형체 / 어텐션: 빔→튜브→꾸러미).
- **2D 카드**: 수식 카드(살아 있는 숫자 대입) 1개는 필수. 나머지는 소재가 요구하는 차트만.
- **손잡이**: 재생·되감기·단계 슬라이더는 기본. 그 위에 소재 고유 손잡이 2~4개.
- **정직성 안내문**: 어디에 어떤 문장으로 넣을지 정한다.
- **콜아웃**: 3D 점을 가리키는 라벨은 3개 이내. 이름·설명 두 줄, 종이색 받침.

1. `references/scaffold.html`을 새 폴더의 `index.html`로 복사한다. `▼▼ 모형 고유 ▼▼ … ▲▲`
   사이만 채우고 그 밖(렌더러·카메라·아트보드·API·루프)은 그대로 둔다. API 이름(`modelApp`)은
   소재에 맞게 바꾼다(`diffusionApp`, `attentionApp`).
2. 기법은 `references/model-grammar.md`의 카탈로그에서 고른다: InstancedMesh(수천 개 동일
   요소), TubeGeometry + drawRange(선이 자라남), HTML 라벨(한글 텍스트), 셰이더 접지 그림자,
   PMREM 스튜디오, 마스크 박스, 궤적 스프라이트…
3. 한국어 문장: 안내문·노트는 완결된 문장으로(CLAUDE.md fluent-korean 보완 조항). 카드 제목과
   버튼 라벨은 짧은 카피여도 된다.
4. `data/…/prompts.md`에 사용자 프롬프트 전문을 남긴다(`.claude/rules/prompt-log.md`).

### Phase 3 — 검수 (BLOCKING · "tsc 통과"는 근거가 아니다)

```bash
npm run dev -- --port 5199          # 이미 떠 있으면 생략
node .claude/skills/3d-model-builder/scripts/model-check.mjs \
  --page "data/dev/테스트 수업 자료/<폴더>/index.html" --api diffusionApp \
  --states .claude/skills/3d-model-builder/references/states.example.json \
  --out tmp/model-shots
```

- `states` 파일은 `[{ "name": "01-hero", "set": { … setState 인자 … } }, …]`. 상태마다 스크린샷과
  `snapshot()`을 `summary.json`에 남긴다. 콘솔 오류가 있으면 종료 코드 1.
- 스크린샷은 **반드시 Read(멀티모달)로 직접 본다**: 메타포가 읽히나, 카드가 무대를 가리나,
  큰 글자가 꺾이나, 콜아웃 선이 무대를 가로지르나, 라벨이 카드에 겹치나.
- 수치 검산은 `summary.json`의 snapshot으로 한다(합=1, 평균·표준편차, 오차 0, argmax).
- 조작 점검(클릭·드래그·스크럽·키보드·자동 시연)은 같은 스크립트를 `--interact` 없이 별도의
  짧은 Playwright 스크립트로 한다(`references/model-grammar.md` 끝의 예시).

### Phase 5 — 덱에 얹기 (embed 모드가 기본 · 2026-09-09 사용자 결정)

모형은 **별도 페이지로 만들고, 덱 슬라이드에는 부가 설명을 뺀 모형과 컨트롤러만 iframe으로
넣는다.** 슬라이드에서 동작을 보여 주고, 자세히 보려면 전체 페이지 링크(+QR)로 넘어간다.
plan.md에 `embed:`가 적혀 있으면 그대로 따르고, 없으면 `iframe`이 기본이다.

| embed | 방법 |
|---|---|
| `iframe` (기본) | 슬라이드 안에 `<iframe src="/data/…/index.html?embed=1&paused=1">` + 같은 슬라이드에 전체 페이지 링크·QR. 썸네일(`isStatic`)에서는 WebGL을 띄우지 않고 자리표시자 |
| `link` | 덱 슬라이드에 클릭 가능한 링크만. 교사가 새 탭으로 띄워 시연한다 (iframe이 무거운 모형·화면이 작아 무대가 안 읽히는 모형) |
| `standalone` | 덱에 넣지 않는다. 수업 중 아무 때나 띄우는 교구로만 둔다 |

**embed 모드 계약** (스캐폴드에 훅이 있다 — `.embed` 클래스 + `#embed-bar`):

- `?embed=1`이면 `body.embed`가 붙고 제목·차트·계산·과제·안내 카드가 모두 숨는다. 남는 것은
  무대 + `#embed-bar`(좌상단: 모형 이름 + **소재 고유 손잡이만**, 예: 어텐션 종류·기준 조각·자동 시연)
  + 하단 재생 바. 카메라·표시 토글은 전체 페이지에만 둔다.
- 시작 코드에서 소재 고유 컨트롤 DOM을 `#embed-bar`로 `append`해 옮긴다(복제하지 않는다 —
  같은 버튼이 두 벌이면 `syncControls`가 어긋난다).
- iframe 크기(덱에서 대개 1180×700)로 `?embed=1&paused=1`을 캡처해 무대가 잘리지 않는지 본다.
  잘리면 embed일 때 카메라 반경을 조금 키운다.
- 덱 쪽 패턴은 `data/2026-2/인공지능기초/트랜스포머는-어떻게-영상을-만들까/deck.tsx`의 `ModelSlide`
  (iframe 1180×700 왼쪽 + 오른쪽 좁은 열에 링크·QR·과제).

어느 쪽이든 모형 자체는 원본 그대로 둔다. URL 파라미터(`?t=`·`?paused=1`·소재 고유)로 특정
장면을 고정해 부를 수 있게 설계해 두면 덱에서 쓰기 쉽다.

## 절대 금지

1. **예시값 하드코딩** — 가중치·확률·수치를 손으로 적어 넣고 "계산"처럼 보이게 하는 것
2. **요소별 자체 타이머** — `setInterval`·개별 `Date.now()`. 모든 모션은 `state.t`의 함수
3. **CDN import** — three.js는 반드시 `assets/vendor/three/`. 학교망은 CDN이 막힌다
4. **라이브러리 인라인** — 680KB를 자료마다 복사하지 않는다. 벤더는 한 곳에서 공유
5. **`.slide` 마크업** — 모형은 덱이 아니다. classify가 doc으로 판정하도록 슬라이드 클래스를 쓰지 않는다
6. **레퍼런스 룩 복제** — 라이트 스튜디오·종이 카드·앰버 액센트는 두 레퍼런스의 선택이지 규칙이 아니다
7. **검수 없는 완료 보고** — 스크린샷을 눈으로 보지 않고 "tsc·스모크 통과"로 끝내는 것
8. **한글을 3D 텍스트 지오메트리로** — 폰트 로딩·깨짐 문제. 한글 라벨은 HTML 오버레이 + `project()`
