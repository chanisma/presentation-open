# Adversarial Review — 만든 사람이 못 보는 것을 찾는다

> **왜 필요한가.** 자료를 만든 주체가 그대로 검수하면 자기가 세운 전제를 그대로
> 믿는다. 실제로 이 저장소에서 한 번의 적대 검증이 **학생에게 보여줄 사실 오류
> 5건**과 **덱↔활동지 절차 모순 2건**을 잡아냈다. 수치·연도가 들어간 자료,
> 여러 번 고쳐 편집 잔재가 쌓인 자료, 배포 직전 자료에는 반드시 돌린다.

## 언제 돌리나

- 덱·활동지를 **완성한 직후**, 그리고 **클래스룸 게시·배포 직전**
- 수정을 5회 이상 반복해 앞뒤 문구가 어긋났을 가능성이 있을 때
- 외부에서 조사한 수치·사례를 그대로 옮겨 실은 자료 (특히 최근 사건)

## 0. 준비 — codex 헤드리스

```bash
export CODEX_HOME="C:/Users/you/.codex-headless"
codex exec --help >/dev/null || echo "codex 없음"
```

인증이 만료되면 orca 홈의 `auth.json`을 복사한다
(`%APPDATA%\orca\codex-accounts\<id>\home\auth.json` → `.codex-headless\auth.json`).
상세는 메모리 `codex-cli-헤드리스-환경`.

## 0.5. 보고서가 갈 곳 — **수업 폴더** (BLOCKING)

검증 보고서는 그 수업의 산출물이다. `tmp/`에 두면 다음 학기에 남아 있지 않다
(실제로 2026-08-23 검증에서 씬 보고서는 `tmp/`에 뒀다가 사라졌고, 저장소 루트에
`r1.md`처럼 흘린 텍스트 보고서 세 개만 살아남았다). **처음부터 수업 폴더에 쓴다.**

```bash
LESSON="data/<그룹>/<과목>/<수업>"        # 예: data/2026-2/정보과제연구/데이터의-가치와-활용
REVIEW="$LESSON/review"; mkdir -p "$REVIEW"
```

| 무엇 | 어디 | 왜 |
|---|---|---|
| **보고서 원문** (`-o` 산출물) | `$REVIEW/<YYYY-MM-DD>-<갈래>.md` | 자료와 함께 남아야 다음 수정 때 다시 읽는다 |
| **검증 프롬프트** (갈래별 `p*.txt`) | `$REVIEW/<YYYY-MM-DD>-<갈래>-프롬프트.txt` | 프롬프트가 없으면 보고서를 어떤 기준으로 받았는지 재현·비교할 수 없다. `tmp/`에만 두면 다음 검증이 같은 이름을 덮어쓴다 (실제로 2026-08-26 검증이 8/24 프롬프트를 덮어써 codex 로그의 `user` 블록에서 복구했다) |
| 반영·미반영 요약 | `$LESSON/plan.md` 헤더 한 줄 표 | 결론은 계획서에서 바로 보인다 |
| 꾸러미·캡처 (`bundle.md`·`*.jpg`) | `tmp/review`·`tmp/scene-shots` | 재생성 가능한 중간물 — 버려도 된다 |

프롬프트는 작성 직후(codex 실행을 기다리지 말고) 바로 복사해 둔다:

```bash
cp tmp/review/p1.txt "$REVIEW/$(date +%F)-사실검증-프롬프트.txt"   # 갈래마다 반복
```

갈래 파일명은 `사실검증` · `교육설계` · `일관성` · `용어` · `눈높이` · `씬연출` · `씬접근성`. 같은 날 두 번
돌렸으면 `-2`를 붙인다. 보고서 맨 위에 검증 일자·갈래·검증자·대상·반영 기록 위치를
표로 적고, **본문은 codex가 낸 그대로 둔다** — 요약하면 근거 링크가 사라진다.

`data/`는 `build-static.mjs`가 통째로 dist에 복사하므로 이 파일들도 배포에 포함된다.
`plan.md`·`prompts.md`와 같은 취급이고, 허브는 pages.json만 읽으므로 화면에는 안 나온다.

## 1. 재료 추출 — 소스가 아니라 **학생이 보는 것**을 검증한다

deck.tsx를 그대로 넘기면 스타일 코드가 대부분이라 검증이 흐려진다. dev 서버를
띄우고 **실제로 렌더된 텍스트**를 뽑는다.

```bash
npx vite --port 5199 --strictPort &
node .claude/skills/adversarial-review/scripts/extract-deck-text.mjs <deckId> <장수> tmp/review
```

산출물 `tmp/review/deck-text.md` — 슬라이드마다 화면 텍스트(빌드 클릭 후 상태 포함)
와 발표자 노트. 여기에 활동지 화면 텍스트와 quiz.json을 이어 붙여 하나의 꾸러미로
만든다.

## 2. 텍스트 검증 — 다섯 갈래로 나눠 돌린다

한 프롬프트에 다 넣으면 초점이 흐려진다. **관점을 쪼개는 것이 이 절차의 핵심**이다.

| 갈래 | 무엇을 시키나 | 웹 검색 |
|---|---|---|
| ① 사실 | 모든 수치·연도·기업·사건을 하나씩 판정 (확인됨/부분적으로 맞음/틀림/과장/검증 불가) | **필수** |
| ② 교육 설계 | 시간 배분·개념 분류의 결함·학생이 막힐 지점·실패 시나리오를 **공격** | 불필요 |
| ③ 일관성 | 덱↔활동지↔문항 모순, 편집 잔재, 끊긴 참조, 한국어 오류 | 불필요 |
| ④ 용어·비유 | 비유어가 정식 용어의 자리(화면 라벨·정의 문장·활동지 칸 이름·문항 선지)를 차지했는지, 한국어 관용 의미와 충돌하는 표현은 없는지 판정(유지/병기 필요/교체 필요) + 정식 용어 대조표 | 불필요 |
| ⑤ 눈높이(ELI5) | **대상 학생이 이 설명으로 이해할 수 있는가**를 학생 입장에서 공격 — 풀이 없이 지나간 용어, 한 장에 셋을 넘는 새 용어, 비유가 없거나 앞 장과 겹치는 장, so what이 없는 노트, 한 문장에 생각이 둘 이상인 문장, 단순화했는데 "실제로는 …"이 없는 곳을 **장 번호와 함께** 지적 | 불필요 |

```bash
cat tmp/review/bundle.md | codex exec \
  -c tools.web_search=true --skip-git-repo-check -s read-only \
  -C "$(pwd)/tmp/review" \
  -o "$(pwd)/$REVIEW/$(date +%F)-사실검증.md" "$(cat tmp/review/p1.txt)" < /dev/null
```

`-o`는 `-C`가 아니라 프로세스 cwd 기준이므로 **절대경로**로 준다(함정 3).
갈래마다 파일명만 바꿔 다섯 번 돌린다.

프롬프트 뼈대는 `references/prompts.md`. 다섯 가지 규칙을 지킨다.

1. **검증할 항목을 번호로 나열해 준다** — "모든 사실을 확인하라"만 시키면 훑고 만다.
2. **판정 어휘를 고정한다** — 표 형식과 다섯 가지 판정으로 강제해야 비교가 된다.
3. **③에는 삭제한 기능의 목록을 알려 준다** — "무작위 카드 뽑기·갤러리 워크·팀 이름은
   이미 삭제되었다"처럼. 그래야 잔재를 찾는다.
4. **④에는 자료의 비유어를 미리 뽑아 번호로 준다** — 비유는 이 저장소 덱의 전통이라
   전부 결함이 아니다. "정식 용어의 자리를 차지했는가 / 한국어 관용과 충돌하는가"
   두 기준으로만 판정시키고, 수업 후 학생이 알아야 할 정식 용어 목록과 대조시킨다
   (2026-08-26 사용자 지적: 통용되지 않는 비유·정확한 용어 자리의 비유가 학생을
   헷갈리게 한다).
5. **⑤에는 대상 학년과 선수 학습을 알려 준다** — 검증자를 "그 학년 학생"의 자리에
   세워야 한다. 전문가 자리에 두면 "더 정확히 쓰라"는 반대 방향 지적이 돌아온다.
   ELI5 원칙 일곱 가지를 번호로 주고 **장 번호와 함께** 지적하게 한다
   (2026-09-16 사용자 결정: ELI5가 이 저장소의 공식 설명 방식).

## 3. 시각 검증 — 씬은 **그림으로** 심사한다

텍스트 검증은 씬의 연출을 전혀 보지 못한다. 프레임을 캡처해 이미지로 첨부한다.

```bash
node .claude/skills/adversarial-review/scripts/capture-scenes.mjs <deckId> "2:0,1,2,3 5:0,1,2 9:0,0,1" tmp/scene-shots
python .claude/skills/adversarial-review/scripts/shrink-images.py tmp/scene-shots tmp/scene-small
export CODEX_HOME="C:/Users/you/.codex-headless"
IMGS=""; for f in tmp/scene-small/*.jpg; do IMGS="$IMGS -i $(pwd)/$f"; done
codex exec $IMGS --skip-git-repo-check -s read-only \
  -o "$(pwd)/$REVIEW/$(date +%F)-씬연출.md" \
  "$(cat tmp/review/ps1.txt)" < /dev/null
```

두 갈래로 본다.

- **연출 심사** — `.claude/rules/scene-grammar.md`를 채점 기준으로 준다(Lazy Defaults,
  씬당 고유 메타포, 레이아웃 계약, 모션의 필연성). 씬마다 10점 만점 점수를 매기게 한다.
- **학생·접근성** — 오해할 지점, 뒷자리 가독성, 색 의존, 정보량, 지루함.

프롬프트에 **파일명이 곧 순서**임과 각 씬이 무엇을 말하려는 장면인지 한 줄씩 적어 준다.
그러지 않으면 그림만 보고 엉뚱하게 해석한다.

## 4. 분류 — 무엇을 내가 고치고 무엇을 사용자에게 넘기나

지적을 그대로 다 반영하면 안 된다. 세 칸으로 나눈다.

| 칸 | 기준 | 처리 |
|---|---|---|
| **즉시 고친다** | 사실 오류(출처로 확인된 것), 내부 모순, 편집 잔재, 맞춤법, 레이아웃 계약 위반 | 바로 반영하고 보고 |
| **교사 확인** | 학교 내부 정보, 접속 가능 여부, 원출처를 못 찾은 주장 | plan.md 헤더에 목록으로 남긴다 |
| **사용자 판단** | 수업 구조 변경(시간 배분·활동 재설계·개념 틀 수정), 씬 전면 재설계 | 선택지 2~3개로 제시하고 권고안을 밝힌다 |

## 5. 검증자도 검증하라 (BLOCKING)

**codex의 지적을 그대로 믿지 마라.** 실제로 겪은 두 가지:

- 웹 검색 없이 답한 항목이 **환각**이었다(있지도 않은 규제 기관 조사를 원인으로 지목).
- **스트리밍 중간본을 최종본으로 오독**했다. `-o` 파일은 완료 시점에 다시 쓰이므로,
  **exit 코드를 확인한 뒤에 읽는다.** 크기가 바뀌었으면 다시 읽는다.

핵심 수치는 반드시 **직접 웹 검색으로 교차 확인**한다. 판정이 "틀림"인데 근거 링크가
없으면 반영하지 않는다.

## 함정 (실제로 밟은 것들)

1. **병렬 실행이 stdin에서 멈춘다** — 배경 실행 시 codex가 stdin을 읽으려 대기한다.
   반드시 `< /dev/null`을 붙이고, 이미지가 많으면 **순차 실행**한다.
2. **이미지 16장이면 웹소켓이 끊긴다** — 1100px·JPEG로 줄이면 18MB → 1.3MB.
   `shrink-images.py`가 그 일을 한다.
3. **`-o` 경로는 `-C`가 아니라 프로세스 cwd 기준** — 절대경로로 준다.
4. **애니메이션 중간 프레임을 오류로 오해한다** — 카운터가 올라가는 중간값(예: 359,772)을
   "이전 판의 잔재"라고 지적한다. 캡처 시점을 프롬프트에 알려 주거나 무시한다.
5. **0-based 인덱스를 모른다** — quiz.json의 `slide`가 0-based인 것을 "한 장씩 어긋났다"고
   지적한다. 저장소 규약은 사람이 지켜야 한다.
6. **파일을 고치지 말라고 명시** — 프롬프트 끝에 "파일을 절대 수정하지 마라"를 넣고
   `-s read-only`로 돌린다.

## 마무리

- 반영한 것과 남긴 것을 `plan.md` 헤더에 한 줄 표로 기록한다(검증 일자 포함).
- **보고서 원문과 갈래별 검증 프롬프트가 `$REVIEW/`에 있는지 확인한다** — `tmp/`나
  저장소 루트에 남아 있으면 수업 폴더에 옮긴 뒤 커밋한다(`tmp/`는 gitignore라 `git mv`가
  아니라 `cp`). 이 확인 없이 작업을 끝내지 않는다.
- 사용자 요청으로 돌린 검증이라면 `prompts.md`에도 그 요청을 남긴다.
