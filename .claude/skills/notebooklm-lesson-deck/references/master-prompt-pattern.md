# Master Plan 작성 패턴

Master Plan(수업계획.md)의 슬라이드 블록 문법과, 흐름 설계 시 참고할 수 있는
검증된 아크 예시를 정리한 참조 문서.

## 흐름 설계 원칙 (우선순위 순 — 아래 어떤 예시보다 이 원칙이 먼저다)

1. **사용자가 언급한 맥락이 최우선.** 사용자가 밝힌 수업 의도·순서·강조점·대상·
   차시 구성이 페이지의 흐름과 구성을 결정한다. 사용자의 맥락과 이 문서의 어떤
   패턴이 충돌하면 언제나 사용자의 맥락을 따른다.
2. **공백은 교육학적 근거로 채운다.** 사용자 언급에 빈 부분이 있으면 고정 틀로
   자동 회귀하지 말고, 그 수업·그 학생에게 맞는 구조를 교육학적 근거(예: 선행
   지식 활성화, 구체→추상 순서, 예제 후 연습, 인지부하 분산, 오개념 교정,
   형성평가 배치)로 직접 판단해 설계한다. 판단의 이유를 plan에 한 줄로 남긴다.
3. **아래 아크들은 검증된 예시일 뿐, 기본값도 체크리스트도 아니다.** 좋은 출발점이
   될 때만 빌려 쓰고, 수업에 맞게 자르고 재배열한다.

## 참고 아크 예시 — 개념 수업 7단계 (조건문·반복문에서 검증)

| 단계 | 슬라이드 비중 (13페이지 기준) | 목적 |
|------|------------------------------|------|
| 1. 도입부 (개념 이해 + 흥미 유발) | 2장 | 일상 비유로 단원 친숙화, 마법의 키워드 미리보기 |
| 2. 기본 문법 | 2장 | 가장 단순한 형태와 규칙 |
| 3. 심화/확장 | 2~3장 | 선택지 늘리기, 다중 조건, 변형 |
| 4. 도구 활용 | 1~2장 | 연산자·옵션·키워드 결합 |
| 5. 실전 연습 | 2장 | 빈칸 채우기·직접 작성 코드 |
| 6. 피드백 | 1장 | 초보자가 자주 하는 실수 4가지 + 디버깅 |
| 7. 마무리 | 1~2장 | 실생활 적용 사례 + 한눈에 정리 마인드맵 |

문법 요소를 처음 배우는 개념 수업에서 잘 작동한 배열이다. 프로젝트·토론·복습·
평가 등 다른 성격의 수업이라면 이 표를 무시하고 원칙 1·2로 설계한다.
분량 감각: 13페이지 안팎이 정보 교과 한 차시(45~50분), 15~21페이지가 2차시.

## 슬라이드 4-블록 구조

모든 슬라이드(표지 제외)는 아래 4개를 반드시 작성한다:

```markdown
## Slide N — <짧고 매력적인 제목>

**핵심 메시지 (Heading):** <한 문장으로 슬라이드 주제를 관통>

**핵심 내용 (Key Points):**
- <학생이 이해해야 할 요점 3~4가지>
- ...

**비주얼 가이드 (Visual Concept):**
<화이트보드/종이에 손으로 그릴 도식·아이콘·말풍선·색상 상세 묘사>

**발표자 노트 (Presenter Note):**
"<교사가 학생에게 실제로 건넬 친근한 멘트, 보통 2~4 문장>"
```

## 비주얼 가이드 작성 팁 (NotebookLM이 정확히 따라가게 하기)

NotebookLM은 텍스트 묘사를 매우 충실히 시각화한다. 다음을 명시할수록 의도한 결과가 나온다:

- **마커 색상**: "파란 마커로 X 그림", "빨간 마커로 ✗", "초록 마커로 ✓"
- **위치**: "왼쪽에 코드 박스", "오른쪽에 흐름도", "중앙에 큰 ♾️"
- **도식 종류**: "결정 마름모", "사다리형 분기", "벤다이어그램", "원형 루프", "4사분면"
- **손그림 디테일**: "지친 사람 손그림", "줄지어 선 오리", "웃는 컴퓨터 모니터"
- **말풍선**: 누가 무엇을 말하는지 정확히 — "사람 말풍선 '100번 박수…?'", "컴퓨터 말풍선 '1초면 쉽지!'"
- **강조 표시**: "노란 형광펜", "빨간 동그라미", "별 ★ 표시"

**나쁜 예:** "조건문을 시각화하라"
**좋은 예:** "왼쪽에 코드 박스 (검정 손글씨) `if 점수 >= 60: print('통과')`, 오른쪽에 파란 마름모 안에 `점수 >= 60?` 손글씨. 마름모에서 두 갈래 화살표 — TRUE는 초록 마커로 ↘ '통과 출력', FALSE는 빨간 마커로 ↙ 검정 X. 하단에 빨간 마커 강조: '⚠️ 콜론(:) 잊지 마세요!'"

## NotebookLM Instruction 템플릿

슬라이드덱 생성 명령에 전달할 instruction은 다음 패턴이 잘 작동한다:

```
수업계획.md에 명시된 N페이지 구조를 정확히 따라주세요. 각 슬라이드는 master plan의
핵심 메시지·핵심 내용·비주얼 가이드를 그대로 반영하고, 디자인_프롬프트.txt와
스타일_참조.png에 묘사된 <스타일 핵심 묘사>로 모든 슬라이드를 디자인해 주세요.
<단원별 핵심 비유나 특별 지시>. 고등학생 대상으로 친근하면서 학습 효과 높은 톤
유지. 모든 텍스트 한국어. 슬라이드 순서: ①<제목1> ②<제목2> ... ⑬<제목13>
```

**Whitetone(기본) 스타일 핵심 묘사:**
> 화이트톤 미니멀 벡터 인포그래픽 스타일(오프화이트 배경, 얇은 균일 선, 틸·코랄·머스터드·슬레이트네이비 4색만 절제 사용, 넓은 여백, 캐릭터 없음)

**Whiteboard 스타일 핵심 묘사:**
> 화이트보드 손글씨 마커 스타일(검정/파랑/빨강/초록 마커, 손그림 결정 마름모, 화살표, 경고 표지판, 사람·동물·컴퓨터 손그림)

**Etching 스타일 핵심 묘사:**
> 크림색 종이에 검정 잉크 펜으로 그린 미니멀 잡지 일러스트 스타일(가벼운 회색 워시 한 톤만, 검정 채움 없음, 자신감 있는 손그림 선)

번호 매기기(①②③...)는 NotebookLM이 순서를 정확히 지키는 데 매우 효과적이다.

## 단원별 핵심 비유 (검증된 도입 슬라이드 아이디어)

| 단원 | 도입 비유 | 비주얼 |
|------|----------|--------|
| 조건문 | 인생은 선택의 연속 / 비 오면 우산 | 갈림길 + 사람, 우산 vs 태양 |
| 반복문 | 박수 100번 / 줄지어 선 오리 / 컨베이어 벨트 | 지친 사람 + 무한 오리들 + 웃는 컴퓨터 |
| 함수 | 자판기 / 요리 레시피 | 입력→박스→출력, 요리 단계 |
| 변수 | 이름표·라벨 / 편지봉투 | 봉투 안에 값, 라벨 붙은 박스 |
| 입력 | 컴퓨터의 귀 / 마이크 | 입에서 컴퓨터 귀로 화살표 |
| 자료형 | 작업대·저울·도구상자 | 다양한 데이터 모양 |
| 리스트 | 줄 선 학생들 / 사물함 | 번호 매겨진 칸 |
| 알고리즘 | 라면 끓이기 / 하노이 탑 | 단계별 순서도 |

도입에 **일상 비유 + 시각화**를 쓰기로 판단했다면 위 표가 좋은 출발점이다 (배치 여부·위치는 흐름 설계 원칙을 따른다).

## 빠뜨리기 쉬운 요소 점검 (권장 질문 — 필수 아님)

기존 ODP/PPTX를 분석해보면 다음이 자주 누락된다. Plan 개선 단계에서 **질문으로**
점검하되, 답이 "이 수업엔 불필요" 또는 "사용자 맥락과 충돌"이면 넣지 않는다:

1. **흥미 유발 도입** — 단순 "오늘의 목표"만 있고 일상 비유가 없지 않은가?
2. **자주 하는 실수** — 학생이 빠질 함정을 다루는 장이 필요하지 않은가?
3. **실생활 적용 사례** — 어디에 쓰이는지 보여줄 자리가 있는가?
4. **한눈에 정리** — 마무리가 단순 "감사합니다"로 끝나지 않는가?
5. **단원 고유 경고** (예: while의 무한 루프) — 이 단원만의 위험 지점이 있는가?
