# Diorama Grammar — 무대 연출 문법 상세 (슬라이드덱판)

newVideoGen `/vg-diorama` v2.2의 연출 문법 S1~S14를 이 저장소 매체(bolt 슬라이드덱:
클릭 빌드 + t 타임라인 + 브라우저 렌더)로 옮긴 것. SKILL.md의 절차를 실제 코드로
쓸 때 옆에 두고 읽는다. 레퍼런스 구현:
`data/dev/테스트 수업 자료/디오라마-샘플/deck.tsx` (`?deck=diorama-demo`).

## 0. 매체 변환 — 영상 문법을 슬라이드로 옮길 때 바뀌는 것

| 영상(vg-diorama) | 슬라이드덱(이 스킬) |
|---|---|
| 숏 = scenes-v2 씬 = 4~8초, 자막 1~3개 | **숏 = 슬라이드 1장 = 6~14초**, 나레이션은 교사 |
| 무대 지속 10~20초 = 숏 1~4개 | 무대 지속 = **슬라이드 1~3장** (4장 이상 금지) |
| SRT 자막 바 | 자막 없음 — 라벨·말풍선·헤드라인이 텍스트 전부 |
| 페이싱 게이트(숏 중앙값 ≤8s) | 히어로 프레임 ≤1.5s + 슬라이드 총 길이 6~14s |
| S14 코믹 SFX | **이식 안 함** (오디오 트랙 없음) — S13 임팩트가 대신한다 |
| 컷 전환(transition=0) | 슬라이드 넘김이 곧 컷 |
| — | **`<Build>` 신규 축**: 교사가 말하는 동안 멈출 정보는 클릭으로 |

시간 축이 두 개(자동 t · 교사 클릭)인 것이 이 매체의 고유 자산이다. **연기는 t,
정보 공개는 Build.** 둘을 섞되 서로를 참조하지 않는다 (t 안에서 clicks를 읽지 말 것).

## S1. 무대 지속 + 프레이밍 컷

무대(배경 자산)와 숏(슬라이드)은 다른 단위다. 같은 `stage-NN.png`를 쓰는 연속
슬라이드는 **프레이밍으로 차별화**한다 — 같은 자산인데 카메라가 움직인 것처럼 보인다:

```tsx
// 4쪽 — 와이드
<Stage src={S3} />
// 5쪽 — 같은 무대, 펀치인 + 우측으로
<Stage src={S3} framing={{ scale: 1.45, x: -12, y: 4 }} />
// 6쪽 — 같은 무대, 반전 + 살짝 흐림(전경 배우를 띄운다)
<Stage src={S3} framing={{ flip: true, scale: 1.2, blur: 2 }} dim={0.25} />
```

**배우 좌표 환산 (펀치인의 핵심)** — 배경만 `scale s`로 확대하면 배우는 따라
확대되지 않는다. 같은 자리에 "카메라가 다가간 것처럼" 세우려면 배우 좌표를 직접 환산한다:

```
ground' = 50 + (ground - 50) × s      // 바닥선도 중심 기준으로 밀린다
h'      = h × s
x'      = 50 + (x - 50) × s  (+ framing.x 보정)
```

- `scale` 1.25~1.6이 펀치인의 실용 범위. 1.8을 넘으면 원본 해상도가 드러난다.
- 확대한 만큼 스프라이트도 커지므로, 펀치인·클로즈업에 쓸 포즈는 **1×2 시트로 크게**
  따로 뽑아 둔다(`packet-idle-l` 식 별도 슬러그). 작은 크롭을 늘리면 뭉갠다.
- `x`/`y`는 확대 후 이동(%)이다 — 오른쪽을 보려면 x를 **음수**로.
- 요소 누적은 슬라이드를 넘어 이어진다: 4쪽에서 세운 팻말은 5쪽 펀치인에도 있어야
  연속성이 산다 (같은 좌표에 다시 그린다).

## S2. 입장 — 고스트 페이드 + stagger

```tsx
<Actor … enter={{ at: 0.2, style: 'ghost' }} />                  // 기본
<Actor … enter={{ at: 0.35, style: 'slide-left' }} />            // 가장자리에서
<Actor … enter={{ at: 0.5, style: 'pop', dur: 0.6 }} />          // 소품·강조
<Actor … enter={{ at: 0.8, style: 'drop' }} />                   // + DustPuff 짝
```

- 고스트 페이드는 opacity 0 → 0.45 → 1 (약 0.5초). 만화적 "스윽" 등장의 정체다.
- 그룹은 개체당 **0.12~0.2초 stagger**. 동시에 등장하면 무리가 아니라 벽이 된다.
- 첫 배우는 t ≤ 0.6s — 슬라이드에 들어왔는데 빈 무대가 1초 이상 보이면 죽는다.
- `drop`은 착지 프레임에 `DustPuff` + (큰 사건이면) `Stage shake`를 같은 `at`으로.

## S3. 포즈 스왑 연기 (플립북)

같은 캐릭터의 포즈 PNG를 비트 경계에서 **하드 스왑**한다. 크로스페이드 금지 —
섞으면 유령처럼 보인다. 연속 2~4포즈가 하나의 연기 비트다.

```tsx
<Actor poses={PACKET}
       acting={[{ at: 1.6, pose: 'worry' }, { at: 3.2, pose: 'idle' }]}
       flipbook={{ poses: ['walk-a', 'walk-b'], fps: 5, from: 0, to: 2.4 }} />
```

- 포즈 유지 0.5~2초. 0.3초 미만으로 갈아끼우면 깜빡임으로 읽힌다.
- 걷기·떨림은 포즈 2장 × 4~6fps 교차 + x 이동 + `bob`이면 충분하다.
- 캐릭터당 4~8포즈면 덱 하나를 덮는다. 포즈를 늘리기 전에 **크기·각도·모션으로
  못 만드는 다른 동작인지** 자문한다.

## S4. 이동 — 코드가 움직인다

```tsx
<Actor x={[{ t: 0, x: 10 }, { t: 2.4, x: 40 }, { t: 5, x: 40 }]} … />
<RouteDraw points={ROUTE} at={0.6} dur={2.2} ghost />
<Traveler points={ROUTE} at={0.6} dur={2.2} size={4}>
  <img src={`${SPR}/packet-idle.png`} style={{ width: '100%' }} />
</Traveler>
```

PNG는 정지 한 장이면 충분하다. 등장·이동·강조는 전부
`translate / scale / opacity / 포즈 스왑`이 만든다.

## S5. 클로즈업 — 배경 교체로 컷

감정·강조 비트는 와이드 무대를 확대하지 말고 **다음 슬라이드에서 클로즈업 무대로
컷**한다. 배경은 생성하지 말고 코드로:

```tsx
<Stage bg="radial-gradient(ellipse at 40% 45%, #24406b 0%, #0f1830 70%)">   // 보케·긴장
<Stage bg="linear-gradient(160deg, #f4ecdd 0%, #e7d9bd 100%)">              // 코믹·회상
```

⚠ 확대 금지선: 크롭 원본보다 크게 늘리지 마라. 클로즈업에 쓸 캐릭터는 크롭 긴 변
≥1200px로 뽑아 둔다 (image-asset-builder).

## S6. 정보 지목 — 씬 내 줌·팬 금지

지도의 한 지점을 보여주려면 카메라를 움직이지 말고 **다음 슬라이드에서 그 지점이
크게 잡힌 프레이밍으로 컷**하고, 전경에 라벨·하이라이트를 얹는다. 무대가 슬금슬금
움직이면 교실 화면에서는 멀미가 나고, 오버레이 정합도 흔들린다.
(newVideoGen §18 "화면은 정지, 강조는 오버레이"의 직계 규칙)

## S7. 감정 오버레이

- **말풍선** `<Bubble>` — 교사 나레이션(존댓말·정보)과 분리된 **짧은 반말 한마디**.
  덱당 2~4회, 연속 슬라이드 금지. 꼬리(`tail`)는 말하는 배우 쪽으로.
- **손글씨** `<HandNote>` — 여백에 갈겨쓴 한마디. 왼→오른 와이프로 등장.
  Nanum Pen Script를 첫 사용 시 지연 로드하므로 index.html 수정이 필요 없다.
- **타이핑** `typed(t, text, delay, cps)` + `<Caret />` — 챕터 카드 제목·검색어·
  명령처럼 "글자가 입력되는" 표현은 **순차 등장**(초당 11~14자)으로. fade-in
  일괄 등장으로 대체 금지.

## S8. 정보 오버레이

- **라벨 칩** `<LabelChip flag>` — 지명·용어. `flag`면 지목 지점까지 깃대가 내려간다.
- **스탬프 팻말** `<Stamp>` — 고유명사·설정 각인. `shakeStyle`을 같은 `at`으로 짝지어
  무대를 흔들면 "쿵" 소리가 안 들려도 들린다.
- **항로 드로잉** `<RouteDraw ghost>` — 계획(점선 ghost) 위에 실제 경로가 그려지는
  대비가 오프닝 훅의 기본형이다.
- **밑줄은 물결** `<WavyUnderline>` — 직선 `<line>` 금지. 사람이 자를 안 대고 그은 선.
- 오버레이 z는 6~9, 배우는 1~3. **텍스트는 언제나 그림 위**.

## S9. 척추 보드 (spine)

지도·연표·관계도 중 **1종만** 정해 반복 등장시킨다. 돌아올 때마다 진행이 누적된다
(항로 한 구간 추가 · 연표 한 칸 채움 · 칩 하나 점등). 학생의 "지금 어디쯤인가"
감각과 진행률 게이지를 동시에 해결한다. 덱 8~14장 기준 2~4회 복귀.

## S10. 챕터 카드

다크 무대(#순검정 금지 — 틴트) + 모서리 장식 + **타자기 타이핑 제목**.
2~3초짜리 숨 고르기 장이므로 정보를 넣지 않는다.

## S11. 오프닝 훅 — 약속과 배신

첫 장에서 그림 한 장의 **대비**로 긴장을 건다: 계획된 직선(ghost 점선) ↔ 실제로
벌어진 구불구불한 경로. 전체 조망(척추 보드)에서 시작해 "왜?"를 던진 뒤 본편으로.

## S12. 클로징 — 척추 회귀 + 의미

마지막은 척추 보드로 돌아와 전체 여정을 한 화면에 보여주고, 주인공 재등장 +
주제 한 문장으로 닫는다. 정리 슬라이드를 따로 만들지 말고 이 장이 정리가 되게 한다.

## S13. 임팩트 모션

| 임팩트 | 언제 | API |
|---|---|---|
| 방사 스피드라인 | 팝인·스탬프·놀람 | `<SpeedLines x y at size />` |
| 먼지 puff | 착지·급정지 | `<DustPuff x y at />` (발밑 좌표) |
| 무대 shake | 슬램·쿵 | `<Stage shake={{ at, amp: 6 }}>` |
| squash 착지 | 낙하 종점 | `squash(t, at)` — Actor style에 spread |
| 펄스 강조 | 칩 갱신·도달 | `pulse(t, at)` — scale에 곱한다 (1회만) |
| 집중선 vignette | 긴장·대치 | `<FocusVignette at />` |

**밀도 규율: 슬라이드당 1~3개.** 모든 등장에 스피드라인을 붙이면 소음이 된다 —
사건의 크기에 비례시킨다. 전부 t 결정론(`Math.random` 금지, 지터는 `Math.sin(i*7.3)`).

## 좌표·크기 치트시트

```
ground(발이 닿는 바닥선)  : 무대 이미지의 지평선/바닥선 y% — 보통 82~90
h(세로 높이 %)            : dominant 34~52 · 조연 18~28 · 군중 8~14 · 클로즈업 60~85
Bubble/LabelChip y        : 배우 머리 위 = (100 - ground) + h 를 넘지 않게 계산
텍스트 밴드               : 상단 0~22% (헤드라인) — 배우 bbox와 겹치지 않게
하단 안전 영역            : 0~6%는 덱 크롬(진행바·미니바)이 지나간다 — 중요 요소 금지
```

## 함정 (검수에서 실제로 터진 것들)

1. **transform 걸린 래퍼로 오버레이를 감싸지 마라.** `<div style={{transform:'scale(…)'}}>`
   안에 `position:absolute` 오버레이를 넣으면 그 div가 새 containing block이 되어
   좌표가 무대가 아니라 래퍼 기준이 된다 — 팻말이 화면 구석으로 튄다.
   배율은 컴포넌트의 `scale` prop으로 넘긴다(`<Stamp scale={pulse(t, at)}>`).
2. **직접 SVG를 그릴 때 dash 드로잉 금지.** 무대 좌표계는 `preserveAspectRatio="none"`
   (가로·세로 배율이 다르다) — `strokeDasharray` 기반 드로잉은 방향마다 길이가 달라져
   선이 토막난다. 런타임의 `RouteDraw`/`WavyUnderline`은 **기하 자르기·clip-path 와이프**로
   구현돼 있으니 그대로 쓰고, 직접 그릴 때도 같은 방식을 택한다.
3. **발광하는 밝은 영역 위에 텍스트 금지.** 무대 그림에 램프·모니터·창처럼 밝은 면이 있으면
   그 위 글자는 사라진다. 텍스트 밴드는 무대의 **어두운 zone**으로 옮긴다(무대마다 다르다 —
   캡처를 보고 정한다).
4. **하단 0~7%는 덱 크롬**(진행바·미니바·페이지 표시)이 지나간다. 하단 텍스트 밴드는
   `bottom: 9%` 이상에 둔다.
5. **`LabelChip`은 기준점 위로 뜬다**(translate -100%). y를 너무 작게 주면 화면 위로 잘린다 —
   y ≥ 12 를 권장.
6. **무대 그림에 이미 있는 것을 코드로 다시 그리지 마라** — 해저 케이블·도로처럼 배경에
   그려진 선 위에 같은 선을 또 그으면 미세하게 어긋나 지저분해진다. 그 위를 `Traveler`로
   지나가게만 한다.

## 자가 점검 (슬라이드마다 · 캡처 검수 전에)

1. 배우가 바닥에 서 있나? (`ground`·그림자 확인 — 공중부양은 sub-agent 공통 실수)
2. 이 슬라이드는 직전 슬라이드와 **다른 그림**인가? (무대가 같다면 프레이밍이 다른가)
3. 텍스트가 배우·장식에 먹히지 않나? (z-order·zone 분리)
4. 임팩트가 사건 없이 붙어 있지 않나?
5. 히어로 배치가 t ≤ 1.5s에 완성되나? `freezeAt`이 그 시각인가?
6. 말풍선이 직전 슬라이드에도 있었나? (연속이면 하나를 뺀다)
