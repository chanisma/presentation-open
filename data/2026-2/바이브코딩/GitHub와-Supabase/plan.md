## 환경 전제 — 관리자 권한 없이 Git을 들이는 길

지난 수업은 "Git은 필요해지는 수업에서 다룬다"고 미뤘다(「에이전트에게 첫 명령」 S7). 오늘이 그 수업이다. 원칙은 같다 — **관리자 암호 창이 뜨는 길은 기본 경로가 아니다.**

| 상황 | 이 덱이 택한 방법 | 저작 시 확인 |
|---|---|---|
| Git 설치 | Codex에게 «Git for Windows를 관리자 권한 없이 내 사용자 폴더에 설치해 줘. 설치 뒤 `git --version`으로 확인해 줘»를 시킨다. Codex가 고를 길: `winget install --id Git.Git -e --scope user` 또는 Git for Windows 설치기를 사용자 모드로 실행 | **G1** — 학교 노트북과 같은 비관리자 계정에서 실제로 관리자 창 없이 설치되는지, winget이 Intune에서 막혀 있지 않은지 확인. 둘 다 막히면 **예비 수단**: 교사가 PortableGit(압축 해제형)을 학급 드라이브에 미리 두고, Codex에게 «이 파일을 `%LOCALAPPDATA%\Programs\Git`에 풀고 사용자 PATH에 넣어 줘» |
| 첫 푸시의 로그인 | Git for Windows에 함께 오는 Git Credential Manager가 브라우저 로그인 창을 띄운다 → GitHub에 로그인해 허용 | **G2** — 첫 `git push`에서 브라우저 창이 실제로 뜨는지, 창 문구 채집(S10 목업용). PortableGit 경로에서도 같은지 |
| 커밋 이름표 | Codex에게 «git 사용자 이름은 내 GitHub 사용자 이름, 이메일은 GitHub의 noreply 주소로 설정해 줘» — 개인 이메일이 공개 저장소 기록에 남지 않게 | **G3** — noreply 주소 형식(`<숫자>+<사용자이름>@users.noreply.github.com`)과 GitHub 설정의 위치(Settings → Emails) 확인 |
| 설치 직후 `git`을 못 찾을 때 | 이미 켜져 있던 터미널·Codex 세션은 설치 전의 PATH를 들고 있어서 «git을 찾을 수 없음»이 날 수 있다. **설치가 끝나면 터미널을 닫고 새로 열어 `codex`를 다시 켠다** (카드 1 문장에 포함, S8·S15에 명시) | **G4** — 비관리자 설치 직후 같은 세션에서 `git --version`이 되는지, 새 터미널에서는 되는지 확인 |
| 관리자 암호 창이 떴을 때 | 멈추고 손을 든다 — 지난 수업과 같은 규칙. 교사가 관리자 계정으로 처리하거나 예비 수단으로 | — |
| GitHub 동시 가입 | 학교 공인 IP 하나에서 수십 명이 동시에 가입하면 스팸 방지 퍼즐이 어려워지거나 잠시 막힐 수 있고, 학교 망에서 개인 웹메일이 안 열릴 수도 있다. **우회 경로**: 퍼즐이 계속 실패하거나 인증 메일이 안 열리면 스마트폰(모바일 데이터)으로 가입한 뒤 노트북에서 로그인한다. 가능하면 **수업 전날 가입을 과제로 안내**해 실습 시간의 병목을 줄인다 (S7 노트 · S15 1단계) | **G5** — 교실 망에서 GitHub 가입 퍼즐과 웹메일 접속이 되는지 미리 한 번 확인 |

## ELI5 적용 원칙 (이 수업 기준)

외부 ELI5 스킬(https://github.com/DreambigOu/ELI5)의 원칙을 고등학생 청중에 맞게 적용한다.

1. **구조**: 슬라이드마다 핵심 내용과 발표자 노트를 같은 순서로 짠다. ① 무엇인가 ② 이미 아는 것에 잇는 비유(게임 세이브·우체통·진열창·칠판·구글 시트·학번·방문증·사물함·콘센트·조립 키트 — 전부 학교와 생활에서 온다) ③ 실제로 어떻게 되어 있는가(spacekijun 커밋 수, 다마고찌 표, 이 수업 퀴즈 표, Supabase 플러그인 파일) ④ 그래서 내 바이브코딩에 무슨 의미인가.
2. **어휘**: 정식 용어를 소개하되 나오는 즉시 한 문장으로 풀이한다. 화면에서는 용어 옆에 작은 풀이 칩을 둔다(예: `커밋` 옆 «지금 상태를 이름 붙여 저장한 한 장»). 영어 원어는 괄호로 한 번만 보인다. git 명령어(`git add` 등)는 화면에 외우라고 띄우지 않는다 — Codex가 실행하는 것을 보여 줄 때만 터미널 목업 안에 나온다.
3. **비유**: 비유는 장마다 하나씩, 정식 용어를 대체하지 않는다. 화면 라벨·quiz 선지·프롬프트 카드 문장은 정식 용어로 쓴다.
4. **문장**: 한 문장에 생각 하나. 노트는 "여러분"을 주어로 학생에게 직접 말한다. 카피(헤드라인·라벨)는 짧게 끊되 설명 문장은 완결 문장으로 쓴다.
5. **어조**: 약간 편하게, 어린애 취급하지 않는다. 도구마다 **"이게 없으면 바이브코딩에서 무엇이 곤란한가"를 먼저** 말하고 원리는 그 뒤에 말한다(S3 → S4, S16 → S17, S23 → S24).
6. **정확성**: 단순화한 자리는 노트에 "실제로는 …"으로 한 줄 밝힌다(예: 커밋 전에 올릴 파일을 고르는 단계(스테이징)가 있다, GitHub Pages 말고 다른 호스팅도 있다, 공개 키도 RLS 정책이 허술하면 위험하다, MCP 서버는 로컬 프로그램일 수도 있다).
7. **분량**: 한 장에 새 용어는 셋 이하. S6(로컬·원격·푸시)·S17(표·행·열)·S24(MCP·MCP 서버·도구)는 정확히 셋이므로 다른 용어를 더하지 않는다.

## Slide 4 — Git과 GitHub는 다르다
- form: build

**핵심 메시지:** Git은 내 컴퓨터에서 변경 기록을 찍는 도구이고, GitHub는 그 기록을 올려 두고 공유하는 인터넷 저장소다.

**핵심 내용:**
- **Git**: 파일이 어떻게 바뀌어 왔는지 기록하는 프로그램 — 내 컴퓨터에서 돈다, 인터넷 없어도 된다
- **GitHub**: Git 기록을 올려 두는 웹사이트 — 백업, 다른 기기·친구와 공유, 웹사이트로 서비스(GitHub Pages)
- 오늘 할 일: Git은 Codex에게 설치·실행을 맡기고, GitHub에는 내가 가입한다

**형태 설계:** 좌우 비대칭 — 왼쪽 40%에 노트북 윤곽(순수 도형) 안에 카메라 셔터 아이콘(동심 원과 날개 6장, 순수 도형) «Git — 내 노트북 안»; 오른쪽 60%에 구름 윤곽 안에 사진 썸네일 격자 «GitHub — 인터넷». Build 1: 왼쪽만 켜짐, 풀이 칩 «변경 기록을 찍는 프로그램». Build 2: 노트북에서 구름으로 위로 휘는 보라 화살표(라벨 없음 — 이름은 S6에서), 오른쪽 켜짐 + 풀이 칩 «기록을 올려 두는 웹사이트». Build 3: 구름 아래로 쓰임새 세 줄(백업 · 공유 · 웹사이트로 서비스 — 마지막 줄만 보라 굵게, S12 예고). 하단 띠: «Git = Codex가 설치·실행 / GitHub = 내가 가입».

**발표자 노트:** (왼쪽 노트북 안에 카메라가, 오른쪽 구름 안에 사진 앨범이 있습니다.) "이름이 비슷해서 헷갈리는데, 둘은 다른 거예요." (클릭 1) "Git은 내 노트북 안에서 도는 프로그램입니다. 파일이 바뀔 때마다 그 순간을 찍어 두는 카메라라고 생각하면 돼요. 인터넷이 없어도 찍을 수 있어요." (클릭 2) "GitHub는 그렇게 찍은 기록을 올려 두는 웹사이트예요. 폰 사진을 클라우드 앨범에 올려 두는 것과 비슷하죠." (클릭 3) "올려 두면 좋은 게 세 가지예요. 노트북이 고장 나도 남아 있고, 다른 컴퓨터나 친구와 나눌 수 있고, 그리고 오늘 할 것, 웹사이트로 바로 서비스할 수 있어요." "실제로는 GitHub 말고도 GitLab 같은 비슷한 곳이 있지만, 가장 많이 쓰는 곳이 GitHub입니다." "그래서 여러분이 할 일은 GitHub에 가입하는 것 하나예요. Git을 설치하고 명령을 치는 일은 Codex에게 맡깁니다."

## Slide 5 — 저장소와 커밋: 세이브 슬롯
- form: scene
- scene: metaphor: 게임 세이브 슬롯 — 가로 진행 막대 위에 세이브 점이 하나씩 찍히고(각 점에 세이브 이름), 맨 끝에서 보스(버그)에 지면 이전 세이브 점으로 캐릭터가 되돌아간다 | emotion: 안도 — "아, 그럼 막 시도해도 되겠네" | intent: 커밋이 "이름 붙인 저장 지점"이고 언제든 그 시점으로 돌아갈 수 있다는 것을 체감시킨다

**핵심 메시지:** 커밋은 프로젝트의 지금 상태를 이름 붙여 저장한 지점이고, 저장소는 그 커밋들이 쌓이는 곳이다.

**핵심 내용:**
- **저장소(repository)**: 프로젝트 폴더 + 그 폴더의 모든 변경 기록
- **커밋(commit)**: 지금 상태를 한 장으로 저장한 지점 — 언제든 그 시점으로 돌아갈 수 있다
- **커밋 메시지**: 그 저장 지점에 붙이는 이름 — «첫 페이지 완성», «버튼 색 변경»
- 잘 될 때마다 커밋 → 망치면 마지막 커밋으로

**형태 설계:** 화면 가운데를 가로지르는 진행 막대(가로축 중앙을 통과 — edge-cling 금지). t=0.4~2.4: 막대 위에 세이브 점 네 개가 왼쪽부터 찍힌다(보라 원, 위에 손글씨풍 커밋 메시지: «첫 페이지» · «제목 추가» · «사진 넣기» · «버튼 색 변경»). 점 옆에 작은 해시 칩(`a1f3c` 같은 7자 — 장식이 아니라 "커밋마다 고유 번호가 붙는다"는 사실, 숫자는 예시로 명시). t=2.8: 막대 오른쪽 끝에 경고색 번개(버그) 아이콘, 캐릭터 점(잉크색 작은 원)이 거기서 깜빡. t=3.4~4.2: 캐릭터가 세 번째 세이브 점으로 휘는 궤적을 따라 되돌아간다(spring). 아래쪽 30%에 정의 띠 두 줄: «저장소 = 폴더 + 모든 기록» «커밋 = 이름 붙인 저장 지점». 오른쪽 위 작은 슬롯 UI(세이브 1/2/3 칸)가 막대와 같은 이름으로 채워진다 — secondaries.

**발표자 노트:** (가운데 막대 위에 세이브 점이 하나씩 찍힙니다.) "게임 하다가 보스 앞에서 세이브하죠? 커밋이 바로 그거예요." "커밋은 지금 프로젝트 상태를 한 장으로 저장해 두는 일입니다. 저장할 때 이름을 붙이는데, 그걸 커밋 메시지라고 해요. '첫 페이지 완성', '버튼 색 변경'처럼요." (번개가 칩니다) "그러다 버튼 색을 바꾸다 망쳤다면?" (캐릭터가 세 번째 점으로 돌아갑니다) "마지막으로 잘 됐던 세이브로 돌아가면 됩니다. 아까 모래성은 사진이 없었지만, 이제는 있어요." "이 세이브들이 모여 있는 폴더를 저장소라고 불러요. 영어로 repository, 줄여서 '레포'라고 많이 합니다." "실제로는 커밋 전에 어떤 파일을 담을지 고르는 단계가 하나 더 있는데, 그건 Codex가 알아서 해 줍니다." "그러니까 여러분은 에이전트에게 마음껏 시도를 시켜도 돼요. 잘 될 때마다 세이브만 해 두면요."

## Slide 6 — 로컬과 원격, 그리고 푸시
- form: build
- live: choice · "인터넷이 끊긴 교실에서도 할 수 있는 것은?" · 선지: ① 커밋 ② 푸시 ③ 둘 다 ④ 둘 다 못 한다 · 정답 ① (방금 설명한 로컬·원격 구분 확인)

**핵심 메시지:** 커밋은 내 노트북(로컬)에 쌓이고, 푸시해야 GitHub(원격)에 올라간다.

**핵심 내용:**
- **로컬 저장소**: 내 노트북의 `vibe` 폴더 — 커밋이 먼저 여기에 쌓인다
- **원격 저장소**: GitHub에 있는 같은 저장소
- **푸시(push)**: 로컬에 쌓인 커밋을 원격으로 올리는 일 — 인터넷이 필요하다
- 커밋만 하고 푸시를 안 하면 GitHub에는 아무것도 없다

**형태 설계:** 위아래 두 층 — 아래 45%에 책상 단면(나무색 띠)과 열린 서랍, 서랍 안에 커밋 카드 세 장이 쌓여 있다 «로컬 — 내 노트북». 위 35%에 GitHub 구름(S4와 같은 모양, 크기만 작게) «원격 — GitHub». 둘 사이 오른쪽에 우체통(빨간 우체통 대신 보라 우체통 — 순수 도형: 둥근 머리 + 투입구 + 다리). Build 1: 서랍 안 카드 세 장만 «커밋은 여기 쌓인다». Build 2: 구름이 켜지는데 비어 있음 «아직 비어 있다». Build 3: 카드 세 장이 우체통 투입구로 들어가고 구름 안에 같은 카드 세 장이 나타난다 — 화살표 라벨 «푸시». Build 4: 하단 경고색 띠 «커밋만 하고 푸시 안 하면 GitHub에는 없다». 서랍·우체통·구름이 대각선으로 놓여 가로 중앙을 지나간다.

**발표자 노트:** (아래에 책상 서랍, 위에 구름, 오른쪽에 우체통이 있습니다.) "커밋을 하면 그 세이브는 어디에 생길까요?" (클릭 1) "먼저 내 노트북 안에 생깁니다. 내 책상 서랍에 쌓이는 셈이에요. 이걸 로컬 저장소라고 해요. 로컬은 '내 컴퓨터 쪽'이라는 뜻입니다." (클릭 2) "GitHub에 있는 저장소는 원격 저장소라고 불러요. 처음엔 비어 있습니다." (클릭 3) "서랍에 쌓인 커밋을 GitHub로 올리는 일을 푸시라고 해요. 편지를 우체통에 넣는 거죠. 이건 인터넷이 있어야 합니다." (클릭 4) "제일 많이 하는 실수가 여기예요. 커밋만 하고 푸시를 안 하면, 내 노트북에는 있는데 GitHub에는 없어요. 다른 컴퓨터에서 열면 텅 비어 있죠." (라이브 문항을 엽니다) "그럼 하나 물어볼게요. 인터넷이 끊긴 교실에서도 할 수 있는 건 뭘까요?" (결과 확인 후) "커밋이에요. 서랍에 넣는 건 인터넷이 없어도 되니까요. 나중에 인터넷이 될 때 푸시하면 됩니다." "실제로는 GitHub에서 노트북으로 내려받는 반대 방향도 있는데, 그건 다른 컴퓨터에서 이어서 작업할 때 배웁니다."

## Slide 7 — GitHub 가입하기
- form: walkthrough
- scene: metaphor: 브라우저 창 하나에서 가입 양식이 한 칸씩 채워지고, 사용자 이름 칸 아래에 그 이름이 들어간 미래의 웹 주소가 미리 보인다 | emotion: "어렵지 않네" | intent: 가입 절차를 보여 주면서, 사용자 이름이 내 사이트 주소가 된다는 점을 가입하는 순간에 알게 한다

## Slide 12 — GitHub Pages: 창고 문을 진열창으로
- form: scene
- scene: metaphor: 창고(저장소)의 셔터 문이 올라가며 유리 진열창으로 바뀌고, 진열창 위에 간판 주소가 켜지며 길 가던 사람(폰 세 대)이 들여다본다 | emotion: "내 것이 세상에 걸렸다" | intent: GitHub Pages가 저장소의 파일을 그대로 웹 주소로 서비스해 주는 호스팅이라는 것, 주소의 규칙, 첫 화면이 `index.html`이라는 것을 남긴다

**핵심 메시지:** GitHub Pages는 저장소에 있는 웹 파일을 그대로 `https://<사용자이름>.github.io/<저장소>/` 주소로 서비스해 주는 GitHub의 무료 호스팅이다.

**핵심 내용:**
- **GitHub Pages**: 저장소의 HTML·CSS·JS 파일을 웹 주소로 열어 주는 기능 (지난 시간의 **호스팅**)
- 주소 규칙: `https://mintcode07.github.io/vibe-site/` — 사용자 이름 + 저장소 이름
- 첫 화면은 `index.html`
- 푸시할 때마다 1~2분 뒤 사이트에 반영된다

## Slide 14 — 안 열릴 때 보는 표
- form: static

**핵심 메시지:** Pages가 안 열릴 때는 대부분 파일 이름, 푸시 여부, 기다림, 공개 여부 넷 중 하나다.

**핵심 내용:**

| 증상 | 원인 | 해결 |
|---|---|---|
| 주소를 열면 404 | 첫 화면 파일이 `index.html`이 아니거나 폴더 안쪽에 있다 | Codex에게 «첫 페이지 이름을 index.html로 바꾸고 저장소 맨 위에 두고 푸시해 줘» |
| 고쳤는데 사이트가 그대로 | 커밋만 하고 푸시를 안 했다 / 아직 1~2분이 안 지났다 / 브라우저가 옛 화면을 기억한다 | 푸시 확인 → 기다림 → 강력 새로고침(Ctrl+F5) |
| Pages 메뉴에 브랜치를 못 고른다 | 저장소가 비공개(Private) | Settings 맨 아래에서 Public으로 바꾸기 (무료 계정 조건, F12) |
| 그림이 깨진다 | 그림 파일을 안 올렸다 / 파일 이름이 한글·띄어쓰기 | «그림 파일도 커밋했는지 확인하고, 파일 이름을 영문으로 바꿔 줘» |

**형태 설계:** 4행 표가 화면의 dominant(왼쪽 70%) — 행마다 왼쪽에 증상 아이콘 대신 **실제 화면 조각**(404 페이지의 큰 숫자, 그대로인 페이지 위 시계, 회색으로 잠긴 드롭다운, 깨진 그림 상자 — 전부 순수 도형으로 작게). "해결" 열의 Codex 부탁은 보라 모노. 오른쪽 30%에 세로 띠 하나 «먼저 물어볼 것: 푸시했나?» 큰 글씨(가장 흔한 원인이라 따로 뺀다). 빌드 없음 — 실습 중 띄워 두는 참조 장.

**발표자 노트:** (표에 증상 네 가지가 있습니다. 실습하다 막히면 이 장을 다시 띄울게요.) "실습하다 보면 꼭 안 열리는 사람이 나와요. 거의 이 넷 중 하나예요." "404가 뜨면, 첫 화면 파일이 index.html이 아니거나 폴더 안쪽 깊이 들어가 있는 거예요." "고쳤는데 그대로면, 오른쪽에 크게 적어 둔 걸 먼저 물어보세요. 푸시했나? 커밋만 하고 푸시를 안 한 경우가 제일 많아요. 푸시했다면 1~2분 기다리고 Ctrl+F5로 새로고침." "브랜치를 못 고르면 저장소가 비공개인 거예요. 무료 계정은 공개로 바꿔야 해요." "그림이 깨지면 그림 파일을 안 올렸거나 파일 이름이 한글이에요." ## Slide 17 — 데이터베이스는 표로 담는다
- form: build

**핵심 메시지:** 데이터베이스는 데이터를 표로 담는데, 열은 담을 항목이고 행은 하나하나의 기록이다.

**핵심 내용:**
- **표(테이블)**: 한 종류의 기록을 모아 두는 곳 — 방명록이면 `guestbook` 표 하나
- **열**: 기록마다 담을 항목 — 번호 · 이름 · 글 · 쓴 시각
- **행**: 기록 하나 — 친구 한 명이 남긴 글 한 줄
- 열마다 담을 수 있는 종류가 정해져 있다 (글자 / 숫자 / 시각)

**형태 설계:** 구글 시트 모양의 표가 화면 가운데에서 약간 왼쪽(65%, dominant) — 위쪽에 시트 탭 하나 «guestbook», 열 머리 `id` · `name` · `message` · `created_at`. Build 1: 빈 표와 탭만 + 풀이 칩 «표 — 한 종류의 기록». Build 2: 열 머리가 청록으로 켜지고 세로 강조 띠 + 풀이 칩 «열 — 담을 항목». 열 머리 아래 작은 회색 종류 칩 «숫자 · 글자 · 글자 · 시각». Build 3: S16 칠판의 세 줄이 칠판 모양 그대로 날아와 표의 행으로 착지(장 사이 회수 — 같은 글, 같은 이름) + 가로 강조 띠 + 풀이 칩 «행 — 기록 하나». Build 4: 오른쪽 35%에 작은 비교 메모 «구글 시트와 닮았다 / 다른 점: 열의 종류를 미리 정한다 · 수많은 사람이 동시에 써도 안전하다».

**발표자 노트:** (가운데에 구글 시트처럼 생긴 빈 표가 있습니다.) "데이터베이스는 데이터를 표로 담아요. 여러분이 활동지 낼 때 결과가 쌓이던 구글 시트 기억나죠? 그거랑 많이 닮았어요." (클릭 1) "방명록이면 방명록 표 하나를 만듭니다. 표는 한 종류의 기록을 모아 두는 곳이에요." (클릭 2) "위쪽의 칸 이름들이 열이에요. 기록마다 무엇을 담을지 정한 항목이죠. 번호, 이름, 글, 쓴 시각." "열마다 담을 수 있는 종류가 정해져 있어요. 번호 칸엔 숫자, 시각 칸엔 시각만 들어갑니다." (클릭 3, 칠판 글이 날아와 행이 됩니다) "아까 칠판에서 지워졌던 그 글들이요. 이제 표에 한 줄씩 들어갔어요. 이 한 줄 한 줄이 행입니다. 기록 하나예요." (클릭 4) "구글 시트와 다른 점은 둘이에요. 열의 종류를 미리 정해 두고, 수많은 사람이 동시에 써도 엉키지 않게 해 줍니다." "그래서 여러분이 설계도에 '무엇을 저장할까'를 적었다면, 그건 사실 '어떤 표에 어떤 열을 만들까'를 정한 거예요."

## Slide 18 — 기본 키: 행마다 학번이 있다
- form: static

**핵심 메시지:** 기본 키는 표의 각 행을 하나로 딱 집어 주는 열이고, 실제 서비스의 표도 이렇게 생겼다.

**핵심 내용:**
- **기본 키(primary key)**: 행마다 다르고 절대 겹치지 않는 값 — 이름은 같을 수 있어도 기본 키는 다르다
- 실제 표: 다마고찌의 `tama_pet` (F9)

| 열 | 담는 것 | 규칙 |
|---|---|---|
| `id` | 펫마다 다른 번호 | **기본 키** |
| `owner` | 주인 학생의 계정 | 계정이 있어야 한다 |
| `name` | 펫 이름 | 1~8자 |
| `state` | 배고픔·행복·단계 묶음 | 정해진 모양이어야 한다 |
| `version` · `updated_at` | 몇 번째 저장인지 · 언제 저장했는지 | — |

**형태 설계:** 왼쪽 40%에 학생증 카드 두 장이 겹쳐 있다(순수 도형 — 이름은 둘 다 «한시우», 학번만 «10203» «20115»로 다르고 학번 칸만 청록 테두리) + 아래 한 줄 «이름은 겹쳐도, 학번은 안 겹친다». 오른쪽 60%에 위 표(dominant) — `id` 행만 청록 바탕, `owner`·`name`·`state`의 «규칙» 칸은 회색. 표 오른쪽 위 귀퉁이에 다마고찌 `baby-idle.png` 하나(정수배 확대, pixelated)와 칩 «spacekijun 다마고찌의 실제 표». 빌드 없음.

**발표자 노트:** (왼쪽에 이름이 같은 학생증 두 장이, 오른쪽에 실제 표가 있습니다.) "우리 학교에 한시우이 두 명 있으면 어떻게 구분하죠? 학번으로요." "표에서도 똑같아요. 행마다 절대 겹치지 않는 값을 하나 두는데, 그걸 기본 키라고 합니다." "오른쪽이 선생님이 만든 다마고찌의 진짜 표예요. 펫마다 id가 있고, 그게 기본 키입니다. 이름이 같은 펫이 있어도 id는 달라요." "다른 열도 볼까요. owner는 주인 학생, name은 펫 이름인데 1~8자만 된다는 규칙이 걸려 있어요. state에는 배고픔이나 행복 같은 상태를 묶어서 담고요." ## Slide 19 — Supabase가 주는 열쇠 두 개
- form: scene
- scene: metaphor: 학교 행정실 창구에서 출입증 두 장이 나온다 — 목에 거는 **방문증**(학생 화면에 보여도 되는 것, 정해진 곳만 열림)과 금고에 넣는 **마스터키**(모든 문이 열림). 방문증은 진열창 쪽으로, 마스터키는 금고로 들어가 잠긴다 | emotion: 긴장 — "이건 진짜 조심해야겠다" | intent: 공개 키는 브라우저(=공개 저장소)에 실려도 되도록 만든 키이고, 비밀 키는 절대 공개되면 안 된다는 구분을 남긴다

**핵심 메시지:** 공개 키는 브라우저에 실려도 되는 키이고, 비밀 키는 모든 데이터를 마음대로 할 수 있어서 절대 저장소나 화면에 올리면 안 된다.

**핵심 내용:**
- 사이트가 데이터베이스에 접속하려면 **프로젝트 주소 + 키**가 필요하다
- **공개 키**(publishable, `sb_publishable_…`): 내 사이트 코드에 넣는다 — 누구나 볼 수 있다는 전제로 만든 키
- **비밀 키**(secret, `sb_secret_…`): 모든 표를 마음대로 — **절대** GitHub·채팅·화면에 올리지 않는다
- 공개 키가 안전한 조건은 다음 장에 (F8)

**형태 설계:** 화면 가운데 위쪽에 창구(가로로 긴 카운터 + 유리 칸막이, 순수 도형). t=0.5: 창구에서 카드 두 장이 미끄러져 나온다 — 왼쪽은 청록 목걸이형 방문증 «공개 키 sb_publishable_…», 오른쪽은 경고색 금속 열쇠 «비밀 키 sb_secret_…». t=1.4~2.4: 방문증은 왼쪽 아래로 이동해 S12 진열창 축소판(내 사이트) 유리 위에 붙는다 — 칩 «코드에 넣어도 된다». 마스터키는 오른쪽 아래 금고(두꺼운 사각 + 다이얼)로 들어가고 문이 닫힌다 — 칩 «절대 공개 금지». t=2.8: 금고 위에 경고색으로 취소된 아이콘 셋 «GitHub · 채팅 · 화면 공유». 두 경로가 X자로 갈라지며 가로 중앙을 통과. 헤드라인 «열쇠 두 개, 운명은 반대».

**발표자 노트:** (가운데 창구에서 카드 두 장이 나옵니다.) "여러분 사이트가 데이터베이스에 글을 쓰려면, 어느 데이터베이스인지 알려 주는 주소와 열쇠가 필요해요. Supabase는 열쇠를 두 개 줍니다." ## Slide 20 — RLS: 내 열쇠로 내 칸만
- form: build
- live: choice · "공개 저장소의 사이트 코드에 넣어도 되는 것은?" · 선지: ① 공개 키 — RLS가 켜져 있을 때 ② 비밀 키 — RLS가 켜져 있을 때 ③ 둘 다 괜찮다 ④ 둘 다 안 된다 · 정답 ① (방금 설명한 키·RLS 확인)

**핵심 메시지:** RLS는 표의 행마다 누가 읽고 쓸 수 있는지 정하는 규칙이고, RLS가 꺼진 표는 공개 키만으로 누구나 다 읽고 고칠 수 있다.

**핵심 내용:**
- **RLS(Row Level Security, 행 수준 보안)**: 표의 각 행에 "누가 읽고, 쓰고, 지울 수 있나"를 거는 잠금
- **정책(policy)**: 그 잠금의 규칙 한 줄
- 실제 정책: `tama_pet_owner_read` — «로그인한 사람의 id가 owner와 같은 행만 읽을 수 있다» (F9)
- 방명록이라면: 읽기 = 누구나 / 쓰기 = 누구나 / 고치기·지우기 = 아무도
- RLS 꺼짐 + 공개 키 = 누구나 모든 행을 읽고 지우는 표

**형태 설계:** 화면 왼쪽 55%에 세 칸 사물함(`school-lockers.svg`, dominant) — 칸마다 이름표 «서연의 펫» «하윤의 펫» «민지의 펫». 오른쪽 45%에 정책 카드. Build 1: 사물함 문이 전부 닫혀 있고 풀이 칩 «RLS — 행마다 거는 잠금» + 사물함 칸 = 표의 행이라는 연결선(S17 표의 행 세 줄이 사물함 칸과 점선으로 이어짐). Build 2: 오른쪽 정책 카드에 실제 정책 이름(모노)과 우리말 풀이 «로그인한 사람 = 주인인 행만 읽기» + 풀이 칩 «정책 — 잠금의 규칙 한 줄». Build 3: 서연의 방문증이 다가가자 «서연의 펫» 칸만 열린다(문 그룹 회전), 다른 칸은 잠긴 채 흔들림. Build 4: 아래 30%에 방명록 정책 세 줄 표(읽기 누구나 ✓ / 쓰기 누구나 ✓ / 고치기·지우기 ✕). Build 5: 하단 경고색 띠 «RLS 꺼짐 + 공개 키 = 누구나 다 읽고 지운다» — 이때 사물함 문이 전부 덜컥 열리는 1초 연출로 위험을 체감.

**발표자 노트:** (왼쪽에 학교 사물함 세 칸이 있습니다. 칸마다 다마고찌 펫 주인 이름이 붙어 있습니다.) "방문증만 있으면 아무 데나 들어갈 수 있으면 곤란하죠. 그래서 표의 행마다 잠금을 겁니다. 이걸 RLS, 우리말로 행 수준 보안이라고 해요." (클릭 1) "사물함 한 칸이 표의 한 행이라고 생각하세요." (클릭 2) "잠금의 규칙 한 줄을 정책이라고 해요. 이건 다마고찌 표에 실제로 걸려 있는 정책이에요. 로그인한 사람이 그 행의 주인일 때만 읽을 수 있다." (클릭 3) "그래서 서연이는 자기 펫만 볼 수 있고, 하윤이 펫은 못 봅니다. 자기 열쇠로 자기 칸만 여는 사물함이죠." (클릭 4) "방명록이라면 정책이 달라요. 읽기는 누구나, 쓰기도 누구나, 그런데 남의 글을 고치거나 지우는 건 아무도 못 하게." (클릭 5, 사물함이 전부 열립니다) "만약 RLS를 깜빡하고 안 켜면? 공개 키만 있으면 누구나 모든 칸을 열어요. 방명록 글을 전부 지울 수도 있습니다." (라이브 문항을 엽니다) "그럼 확인해 볼게요. 공개 저장소의 코드에 넣어도 되는 건 뭘까요?" (결과 확인 후) "1번, RLS가 켜진 상태의 공개 키예요. 비밀 키는 RLS를 무시하고 모든 문을 여는 마스터키라서 어떤 경우에도 안 됩니다." "실제로는 RLS를 켜도 정책을 허술하게 쓰면 위험해요. 그래서 이따 에이전트에게 '보안 점검해 줘'를 꼭 시키라고 할 거예요."

**핵심 내용:**
- 부탁 예시 (화면에 그대로):

RLS를 켜고, 읽기와 쓰기는 누구나, 고치기와 지우기는 아무도 못 하게 정책을 걸어 줘. index.html에 방명록을 붙이되 공개 키(publishable key, 예전 이름 anon key)만 쓰고 비밀 키(secret key, 예전 이름 service_role key)는 절대 쓰지 마. npm 설치 없이 이 HTML 파일 하나로 GitHub Pages에서 바로 돌아가도록 supabase-js는 CDN 스크립트로 불러와 줘. 다 되면 보안 점검을 하고, 커밋하고 푸시해 줘.
- 키 이름을 괄호로 병기하는 이유: Supabase가 키 이름을 바꾸는 중이라(F7) 에이전트가 옛 이름(anon)을 찾다 헤매지 않게 한다
- CDN 조건을 넣는 이유: 학생 폴더는 번들러가 없는 HTML 한 파일이라, `npm install`로 붙이면 GitHub Pages에서 모듈 경로를 못 찾는다 (F18)
- Codex가 하는 일: MCP 도구로 표·정책 만들기 → 공개 키 가져오기 → `index.html` 고치기 → 보안 점검 → 커밋·푸시
- 1~2분 뒤 Pages 주소의 방명록에 친구가 글 → Supabase 표에 행이 생긴다

**절차 대본 (창 × 행동 × 확인):**

4. 터미널 창 · 파일 변경 요약 «index.html 수정 — 방명록 칸 · 목록» · Codex «보안 점검: guestbook 표 RLS 켜짐, 정책 2개 확인» · 커밋 «방명록 추가 (Supabase)» · 푸시

## Slide 28 — 에이전트에게 데이터베이스를 맡길 때의 수칙
- form: static

**핵심 메시지:** 에이전트는 MCP로 데이터베이스를 지울 수도 있으므로, 연습용 프로젝트에만 연결하고, 승인을 읽고, 비밀은 건네지 않는다.

**핵심 내용:**
1. **연습용 프로젝트에만 연결한다** — 진짜 사람들의 데이터가 든 프로젝트는 연결하지 않는다. 꼭 필요하면 그 프로젝트 하나로 묶고 읽기 전용으로 (F5: `project_ref` · `read_only`)
2. **승인 창을 읽고 허락한다** — 특히 «지우기 · 표 삭제 · 정책 변경». `--yolo`로 켠 Codex는 묻지 않으니 데이터베이스 작업에는 쓰지 않는다 (F17)
3. **비밀은 건네지 않는다** — 비밀 키·DB 비밀번호를 채팅에 붙이지 않는다. MCP가 연결해 주니 필요 없다
4. **끝나면 보안 점검을 시킨다** — «모든 표에 RLS가 켜져 있고 정책이 맞는지 점검해 줘»
5. **표를 바꿨으면 커밋한다** — 코드와 함께 기록이 남는다

**형태 설계:** 다섯 수칙을 **비행기 이륙 전 점검표** 모양으로 — 클립 없는 세로 점검 카드(조종석 체크리스트처럼 왼쪽에 항목, 오른쪽 끝에 «확인» 칸) 한 장이 화면 왼쪽 64%를 차지하고, 항목마다 큰 번호와 수칙 굵은 줄, 아래 작은 회색 근거. 1번 줄만 높이가 1.5배이고 경고색 왼쪽 띠(가장 중요, dominant). 2번 줄의 `--yolo`는 경고색 모노. 오른쪽 36%에 이륙 전 활주로 끝을 단순 도형으로(가는 선 두 줄 + 끝 표시) — "점검을 마쳐야 출발한다"는 한 장면. 오른쪽 위 작은 출처 칩 «Supabase MCP 공식 문서의 권고». 빌드 없음.

**발표자 노트:** (화면에 이륙 전 점검표처럼 수칙 다섯 줄이 있습니다. 첫 줄이 가장 큽니다.) "비행기는 이륙 전에 조종사가 점검표를 한 줄씩 확인해요. 에이전트에게 데이터베이스를 맡기기 전에도 그런 점검표가 필요합니다." "에이전트가 데이터베이스를 직접 만질 수 있다는 건 편하지만, 반대로 지울 수도 있다는 뜻이에요. 그래서 수칙 다섯 개를 꼭 지킵니다." "첫째가 제일 중요해요. 연습용 프로젝트에만 연결하세요. 친구들 데이터가 실제로 쌓여 있는 프로젝트를 에이전트에게 열어 주면, 실수 한 번에 다 사라질 수 있어요. Supabase 공식 문서도 같은 말을 해요. 꼭 필요하면 그 프로젝트 하나로 묶고 읽기만 되게 하라고요." "둘째, 승인 창을 읽으세요. 지운다, 표를 삭제한다, 정책을 바꾼다는 말이 보이면 멈추고 생각하세요. 그래서 데이터베이스 작업할 때는 --yolo로 켜지 마세요. 그건 묻지 않고 다 해 버리는 모드예요." "셋째, 비밀 키와 DB 비밀번호는 채팅에 붙이지 않아요. MCP가 연결해 주니까 필요가 없습니다." "넷째, 끝나면 보안 점검을 시키세요. 다섯째, 표를 바꿨으면 커밋하세요." "이 다섯 개만 지키면, 에이전트에게 데이터베이스를 맡겨도 됩니다."
