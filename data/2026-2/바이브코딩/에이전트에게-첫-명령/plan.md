## 환경 전제 — Intune 노트북에서 관리자 권한 없이 가는 길

학생 계정에 로컬 관리자 권한이 없으면 "관리자 권한으로 실행"은 관리자 암호 입력창에서 멈춘다. 교사가 관리자 계정을 갖고 있으므로 그 창에서 교사가 암호를 넣어 줄 수는 있지만, 노트북 수만큼 반복해야 한다. 그래서 이 덱은 **관리자 권한이 필요한 단계를 처음부터 넣지 않고**, 관리자 계정은 막혔을 때의 예비 수단으로만 쓴다.

| 상황 | 관리자 권한이 필요한 흔한 방법 | 이 덱이 택한 방법 |
|---|---|---|
| Codex 설치 | Node.js .msi → `npm install -g @openai/codex` | 공식 PowerShell 설치기 한 줄 — 사용자 폴더에 `codex.exe`를 놓고 사용자 PATH에 등록. Node 불필요. `.ps1` 심(shim)이 없으므로 실행 정책 문제도 피한다 |
| 실행 정책이 Intune으로 강제된 경우 | `Set-ExecutionPolicy` (정책이 덮어써 실패) | 설치 명령은 스크립트 파일이 아니라 `irm \| iex` 문자열 실행이라 실행 정책의 적용 대상이 아니다. npm으로 설치한 경우에만 `codex.cmd`로 실행하거나 cmd 창을 쓴다 |
| PATH 미등록 | 시스템 환경 변수 편집 | 새 터미널을 연다. 그래도 안 되면 사용자 환경 변수 창(`rundll32 sysdm.cpl,EditEnvironmentVariables`)은 관리자 없이 열린다 |
| 관리자 암호를 묻는 창이 떴을 때 | — | 오늘 경로에서는 뜨지 않는다. 떴다면 관리자용 설치기를 눌렀다는 뜻 — 멈추고 손을 든다. 교사가 관리자 계정으로 진행하거나 사용자 경로로 되돌린다 |
| Node.js · Git | .msi(관리자 암호) · Git "모든 사용자" | **이 수업에서는 설치하지 않는다** (흐름 근거 (d)). 필요해지는 수업에서 다룬다 — 그때는 에이전트에게 사용자 폴더 설치를 시키거나, 교사가 관리자 계정으로 .msi를 설치한다 |
| 네트워크가 releases.openai.com을 막는 경우 (최후 수단) | — | 교사가 GitHub Releases의 `codex-x86_64-pc-windows-msvc.exe`를 미리 받아 학급 드라이브로 배포, 작업 폴더에 두고 `.\codex.exe`로 실행. 저작 시 실제 자산명 확인 |

## Slide 18 — 색 견본: 예시를 주면 정확해진다
- form: scene
- scene: metaphor: 색 견본 맞추기 | emotion: 납득 | intent: 같은 요청이라도 예시가 0개·1개·여러 개일 때 결과가 의도에 점점 가까워지는 것을 색으로 보여, few-shot을 어려운 용어가 아니라 "견본을 건네는 일"로 이해시킨다

**핵심 메시지:** 원하는 것의 예시를 한두 개 붙이면 결과가 의도에 가까워진다. 예시가 없으면 zero-shot, 하나면 one-shot, 여럿이면 few-shot이라 부른다.

**핵심 내용:**
- zero-shot: "파란 느낌으로" → 결과가 제각각(하늘색·남색·청록)
- one-shot: 견본 색 한 장을 같이 줌 → 근접
- few-shot: 견본 세 장(배경·제목·버튼) → 의도와 일치
- 프로그램에도 똑같다: "이런 카드 모양으로"라며 좋아하는 사이트의 설명 한 줄, 원하는 문장 예시, 표의 예시 행을 붙인다
- 목적과 예시가 함께 있으면 에이전트는 "왜"와 "어떻게"를 둘 다 안다

**형태 설계:** 세 줄의 실험대가 위에서 아래로. 각 줄 왼쪽에 요청 카드(같은 문장 "파란 느낌으로"에 견본 스와치가 0·1·3장 붙어 있음), 오른쪽에 결과 스와치 3장. t=0.5: 첫 줄 결과가 제각각 색으로 흩어져 등장. t=1.7: 둘째 줄, 견본 1장이 카드에 붙고 결과 3장이 견본 쪽으로 색이 수렴(HSL 보간). t=3.0: 셋째 줄, 견본 3장 → 결과가 견본과 거의 일치, 각 결과 위에 작은 ✓. t=3.8: 오른쪽 세로 라벨에 zero-shot / one-shot / few-shot 정식 용어가 줄마다 붙는다. 하단 밴드에 "프로그램에서의 견본" 예 3개 칩. 헤드라인 "견본을 건네라"는 왼쪽 상단. 스와치는 JSX 사각형(추상 도형 — SVG 자산 불필요). 색 값은 `color-mix`로 테마 안에서.

**발표자 노트:** (세 줄. 첫 줄은 '파란 느낌으로'만 있고 결과가 제각각입니다.) "'파란 느낌'이라고만 하면 하늘색이 올 수도, 남색이 올 수도 있어요." (둘째 줄에 견본 한 장이 붙고 결과가 모입니다) "견본 하나를 붙이면 확 가까워지죠." (셋째 줄) "세 장이면 거의 일치. 이걸 어려운 말로 zero-shot, one-shot, few-shot이라고 합니다. 예시가 몇 개냐는 뜻이에요." (하단 칩) "프로그램에서는 색 대신 '이 사이트의 카드처럼', 원하는 문장 하나, 표의 예시 한 줄을 붙이면 됩니다. 목적을 적고 예시까지 붙이면 에이전트는 '왜'와 '어떻게'를 둘 다 아는 거예요."

## Slide 19 — 실습: 나의 첫 웹 페이지
- form: static

**핵심 메시지:** 주문서를 채운 프롬프트 하나로 첫 웹 페이지를 만든다. 주제는 자유, 조건은 셋이다.

**핵심 내용:**
- 도구: `codex --yolo` (vibe 폴더) · 모델: Sol · 실습 시간은 교사가 현장에서 정한다
- 조건 셋: ① 파일 하나 `index.html` ② 열면 제목·소개 문장·버튼 하나가 보인다 ③ 버튼을 누르면 화면의 무언가가 바뀐다
- 주제 예시: 자기소개 한 장 / 지난 시간에 남긴 내 문제 후보를 소개하는 한 장 / 내가 좋아하는 것 소개
- 예시 프롬프트 (Slide 17 주문서와 동일 문장, 복사용):
  ```
  목적: 나를 처음 보는 친구가 30초 안에 내가 어떤 사람인지 알게 하는 한 장짜리 소개 페이지
  대상: 우리 반 친구들
  기능: 1) 이름과 한 줄 소개 2) 좋아하는 것 세 가지 목록 3) "더 보기" 버튼을 누르면 숨겨진 한 문장이 나타난다
  화면: 한 화면, 어두운 남색 배경에 밝은 글자, 제목은 위 가운데
  제약: index.html 파일 하나만, 외부 라이브러리 없이, 한국어, 휴대폰에서도 보이게
  완료 기준: 브라우저에서 열면 이름과 목록이 보이고, 버튼을 누르면 문장이 나타난다
  ```
- 막히면: 오류 메시지를 **그대로 복사해** 에이전트에게 붙여넣는다 ("이 오류가 나. 고쳐 줘")

**형태 설계:** 왼쪽 55%에 복사용 프롬프트 코드 블록(줄마다 칸 이름이 민트로 강조 — Slide 17의 주문서 칸과 같은 순서·색). 오른쪽 45% 위에 조건 3개 체크박스(큰 글씨), 아래에 주제 예시 칩 3개와 "막히면" 카드. 상단 띠에 "codex --yolo · Sol · 조건 셋". 교사가 이 화면을 띄운 채 실습을 진행한다. 활동지·제출 폼은 계획하지 않는다(사용자 요청에 없음) — 완성 화면 공유는 다음 장 뒤 발표자 노트의 선택지로만 둔다.

**발표자 노트:** (왼쪽 프롬프트, 오른쪽 조건 셋.) "왼쪽 프롬프트를 그대로 써도 되고, 칸을 자기 걸로 바꿔도 됩니다. 주제는 자유, 조건은 오른쪽 셋." "모델은 Sol인지 `/status`로 한 번 확인하고 시작하세요." "오류가 나면 읽지 말고 그대로 복사해서 에이전트에게 주세요 — '이 오류가 나, 고쳐 줘'. 그게 정답입니다." (막힌 학생은 Slide 9·21 카드로 안내) (이 장은 실습 내내 띄워 둔다)

## Slide 20 — 만든 페이지 열기와 고치기
- form: walkthrough
- scene: metaphor: 브라우저와 터미널의 핑퐁 | emotion: 성취 | intent: 에이전트가 만든 파일을 브라우저로 여는 두 가지 방법과, 고쳐 달라고 한 뒤 새로고침으로 바뀐 것을 확인하는 왕복 리듬을 화면으로 보여 준다

**핵심 메시지:** 만든 파일은 탐색기에서 더블클릭하거나 터미널에서 `start index.html`로 연다. 고치면 F5로 확인한다.

**절차 대본 (창 × 행동 × 확인):**
1. ① 파일 탐색기(vibe 폴더) | `index.html` 더블클릭 | 기본 브라우저가 열리며 내 페이지가 보인다 ✓
2. ② 터미널(codex 실행 중) | 두 번째 방법: 에이전트에게 `index.html을 브라우저로 열어 줘` 또는 직접 `start index.html` | 같은 페이지가 열린다
3. ② 터미널 | 수정 요청 타이핑: `버튼 색을 민트색으로 바꾸고 제목을 더 크게 해 줘` | 에이전트가 파일 수정 보고
4. ③ 브라우저 | **F5**(새로고침) | 버튼 색과 제목 크기가 바뀐다 ✓ — 이 왕복이 앞으로의 작업 리듬

**형태 설계:** Slide 8(릴레이)·10(단계 카드+왕복)·15(터미널 dominant+계기판)와 다른 구도 — **브라우저 창과 터미널 창을 좌우에 거의 같은 크기로 나란히** 두고 포인터가 둘 사이를 오간다(핑퐁). 위에 작은 탐색기 창이 첫 국면에만 잠깐 앞으로 나왔다가 `shrinkAfter`. F5 키 칩이 브라우저 위에서 눌리는 순간 `clickFlash`. 브라우저 안 페이지는 Slide 19 예시 프롬프트의 결과와 일치하는 목업(이름·목록·버튼). 마지막 국면은 바뀐 페이지 + 하단 리듬 라벨 "요청 → 수정 → F5 → 확인". 프롬프트 기호 없음.

**발표자 노트:** (왼쪽 브라우저, 오른쪽 터미널, 위에 잠깐 탐색기.) "완성했으면 vibe 폴더에서 index.html을 더블클릭. 브라우저가 열리면 여러분의 첫 웹 페이지예요." (터미널에 start index.html) "터미널에서 `start index.html`을 쳐도 되고, 에이전트한테 열어 달라고 해도 됩니다." (수정 요청 → F5 → 바뀜) "고치고 싶으면 에이전트에게 말하고, 브라우저에서 F5. 요청, 수정, 새로고침, 확인 — 이 리듬이 앞으로 우리 수업의 리듬입니다." (선택: 완성 화면을 캡처해 지난 시간 collab 노트에 댓글로 남기게 해도 된다 — 계획에는 넣지 않았다)

## Slide 21 — 자주 하는 실수 다섯

**핵심 메시지:** 방금 겪었을 실수는 대부분 이 다섯 가지이고, 각각 한 줄 처방이 있다.

## Slide 22 — 명령 히스토리 되감기

**문항 명세:**
- kind: exit · id `exit-ticket` · slide "last" · prompt "오늘 수업을 마무리하며 — 이해도(1~5)와 한마디"

**발표자 노트:** (터미널 화면에 오늘 친 명령들이 아래에서 위로 올라옵니다.) "오늘 여러분이 친 명령이에요. 설치 한 줄, 버전 확인, yolo, 파일 만들기, 모델 바꾸기, 첫 페이지, 열기. 일곱 줄로 오늘이 끝났습니다." (맨 아래 커서가 깜빡입니다) "다음 줄은 다음 시간이에요. 같은 폴더에서, 지난 시간에 남긴 문제 후보로 기획 문서를 씁니다. vibe 폴더 지우지 마세요." "설치는 한 번, 명령은 매일. 나가기 전에 출구티켓 한 줄만."
