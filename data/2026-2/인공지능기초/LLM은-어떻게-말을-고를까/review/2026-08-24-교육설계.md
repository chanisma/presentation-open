# 수업 실패 가능성 심사

## 1. 시간 배분

### 1-1. 2부 시간표의 합계가 수업 시간과 맞지 않는다

(원문 인용) → 슬라이드 15: “3분 / 12분 / 17분 / 5분”

(무엇이 문제인가) → 합계는 37분이다. 45분 수업이면 8분, 50분 수업이면 13분이 남지만, 이 시간에 슬라이드 15~19 설명, 활동지 접속, 학번·이름·암호 입력, 주제 선택, 서버 대기, 제출, 오류 대응을 모두 처리해야 한다. 슬라이드 15~19 설명만 장당 1분으로 잡아도 5분이어서 실제 여유는 3~8분에 불과하다.

(구체적 수정안) → 시간표에 `도입·접속 5분 / A 5분 / B 15분 / C 8분 / D 10분 / E·제출 7분`처럼 모든 절차를 명시하고, 45분 수업에서는 복원을 1회로 줄이거나 E를 다음 차시 시작 활동으로 옮겨라.

### 1-2. A 구역 3분은 서버 호출까지 포함하면 성립하기 어렵다

(원문 인용) → “3분 — AI 켜기 A — 주제를 고르고 글을 한 편 받는다. 여기까지만 쓰고 곧바로 닫는다.”

(무엇이 문제인가) → 학생은 활동지 열기, 개인정보 입력, 여섯 주제 읽기, 선택, 생성 요청, 응답 대기를 3분 안에 해야 한다. 30명이 동시에 Supabase Edge Function을 호출하면 지연·재시도가 생길 수 있고, 한 명만 1~2분 늦어져도 B의 12분이 잠식된다.

(구체적 수정안) → 수업 전에 로그인·학번 입력을 끝내고, A를 최소 5분으로 늘려라. 동시에 호출하지 않도록 주제별 호출 시차를 두거나, 미리 생성한 예비 글 6편을 활동지 안에 넣어 실패 즉시 배부하라.

### 1-3. B 구역 12분에는 요구량이 과도하다

(원문 인용) → “질문은 넷뿐이다. 대신 세어 보고 확인한 것만 적는다.”

(무엇이 문제인가) → 실제 요구는 주장, 근거, 대상 독자, 필수 재료, 숫자 신뢰성, 문단 수, 문단별 역할, 문장 종결, 문장·글 길이, 마지막 문장, 제목·목록 여부, 학생 자작 질문과 답까지 최소 12개 관찰이다. 글 읽기까지 포함한 12분이면 항목당 약 1분도 되지 않는다.

(구체적 수정안) → B를 15~18분으로 늘리고, 필수 관찰을 `내용 규칙 2개 + 구조 규칙 2개 + 자작 질문 1개`로 제한하라. 문장 길이 세기처럼 시간이 많이 드는 작업은 자동 통계를 그대로 옮기는 대신 표본 문장 하나만 분석하게 하라.

### 1-4. C·D 17분에는 최소 네 번의 AI 호출과 두 번의 채점이 들어간다

(원문 인용) → “17분 — AI 켜기 C·D — 찾아낸 규칙만으로 프롬프트를 쓰고, 두 번 복원해 본다.”

(무엇이 문제인가) → 학생은 1차 프롬프트 작성→글 생성→채점→항목별 근거 읽기→수정점 작성→2차 프롬프트 작성→글 생성→재채점을 해야 한다. A까지 합치면 학생당 서버 호출은 최소 5회다. 각 호출이 20초만 걸려도 순수 대기 100초이며, 보통 학생이 채점 근거를 읽고 수정하는 시간까지 합치면 17분을 넘는다.

(구체적 수정안) → 45분 수업에서는 1차 복원까지만 공통 수행하고, 2차 복원은 빠른 학생용 또는 다음 시간 과제로 돌려라. 두 번을 반드시 유지하려면 C 10분, D 12분 이상을 따로 확보하라.

### 1-5. E 5분 뒤 제출 시간이 배정되어 있지 않다

(원문 인용) → “5분 — AI 끄기 E — 다시 닫고, 내가 못 보고 지나친 것을 자기 말로 적는다.”

(무엇이 문제인가) → E 작성 뒤에는 암호 확인, 필수 19개 항목 검증, TXT 다운로드, 시트 전송, 제출 확인이 남는다. 첫 제출에서 누락 경고가 뜨면 이전 구역으로 돌아가야 한다. 그런데 제출 시간은 37분 계산 어디에도 없다.

(구체적 수정안) → E를 3분, 제출·확인을 4분으로 분리하고 종료 7분 전에 새 AI 호출을 막아라. 미제출자는 TXT만 저장해 사후 제출할 수 있다는 공식 절차도 제시하라.

### 1-6. 라이브 문항 3개와 위젯 조작 시간이 1부에 반영되지 않았다

(원문 인용) → “각자 기기로 라이브 참여”, “①②③을 눌러 보세요”, “온도 손잡이”, “🎲 뽑기”

(무엇이 문제인가) → 라이브 접속 2~4분, 문항별 공개·입력·제출·분포 확인·학생 발언에 각 2~3분이면 6~9분, 세 위젯 시범에 각 2~3분이면 6~9분이 든다. 이것만 14~22분이다. 여기에 뉴스 사례와 14장 설명을 넣으면 45분 안에 슬라이드당 평균 1.6~2.2분밖에 남지 않는다.

(구체적 수정안) → 1부 실행표를 분 단위로 공개하고, 라이브 발언은 문항당 1명으로 제한하라. 토큰 비교기·어텐션·온도 중 학생 개별 조작은 하나만 남기고 나머지는 교사 시범 또는 후속 탐구 링크로 돌려라.

### 1-7. 1부 14장은 사실상 50분에도 과밀하다

(원문 인용) → “1부(슬라이드 1~14)”와 슬라이드 4~6의 국가사업·평가·모델 분류, 슬라이드 7~14의 트랜스포머 설명

(무엇이 문제인가) → 1부는 확률분포, 정책 뉴스, 벤치마크 평가, 공개 모델 분류, 토큰, 벡터, 어텐션, 온도, 반복, 환각을 한 차시에 모두 다룬다. 라이브와 조작을 제외해도 개념 전환이 너무 잦아 질문이나 오개념 점검 시간이 사라진다.

(구체적 수정안) → 슬라이드 4~6의 정책 사례를 2부 평가 도입으로 옮기거나 1장으로 압축하라. 1차시는 `빈칸→확률분포→네 단계→반복`만 완주하고, “좋은 AI” 판단은 별도 사례 활동으로 확보하라.

## 2. 개념 설명의 결함

### 2-1. 네 단계가 실제 트랜스포머의 전체 처리 과정처럼 제시된다

(원문 인용) → “껍데기를 벗기면 심장은 하나 — ① 자르기 ② 좌표로 ③ 서로 쳐다보기 ④ 고르기”

(무엇이 문제인가) → 이 틀은 교육적 축약을 넘어 임베딩 뒤에 어텐션을 한 번 하고 곧바로 확률을 출력한다는 인상을 준다. 실제 모델의 반복되는 여러 층, 피드포워드 연산, 잔차 연결, 정규화, 출력 투영이 모두 사라져 “어텐션이 곧 트랜스포머 전체”라는 오개념이 생긴다.

(구체적 수정안) → ③을 “여러 층에서 서로 참고하고 표현을 고쳐 쓰기”로 바꾸고, `어텐션뿐 아니라 각 토큰을 따로 가공하는 과정도 여러 번 반복되지만 오늘은 생략`이라는 경계 문장을 넣어라.

### 2-2. Q·K·V를 뺀 결과 ‘쳐다보기’의 기준이 사라진다

(원문 인용) → “낱말마다 ‘나는 어느 말을 봐야 하는가’를 정하고, 본 만큼 뜻이 섞여 들어간다.”

(무엇이 문제인가) → 학생은 단어가 의지를 가지고 중요한 단어를 알아서 선택하거나, 단순한 의미 유사도 때문에 보는 것으로 이해할 수 있다. 같은 토큰도 현재 찾는 정보에 따라 서로 다른 관계를 보고, 여러 헤드가 다른 관계를 병렬로 본다는 핵심이 빠졌다.

(구체적 수정안) → Q·K·V 기호는 빼더라도 “지금 필요한 정보와 각 단어가 줄 수 있는 정보를 비교해 가중치를 정한다”는 한 문장을 넣고, 같은 문장에서 주어 찾기와 의미 찾기의 형광펜이 다를 수 있음을 보여라.

### 2-3. 정적 좌표와 문맥적 의미의 관계가 충돌한다

(원문 인용) → 슬라이드 9: “그래서 뜻이 가까운 말은 서로 가까운 자리에 앉는다.” / 슬라이드 11: “본 만큼 뜻이 정해진다.”

(무엇이 문제인가) → 앞에서는 낱말마다 의미 좌표가 이미 정해져 있다고 말하고, 뒤에서는 어텐션이 의미를 정한다고 말한다. 초기 토큰 임베딩과 문맥을 반영한 층별 표현을 구별하지 않기 때문에 학생은 “배의 자리는 하나인가, 문장마다 바뀌는가”에 답할 수 없다.

(구체적 수정안) → 슬라이드 9를 “처음 들어갈 때의 출발 좌표”라고 명시하고, 슬라이드 11에서 “주변을 참고할 때마다 좌표가 문맥에 맞게 바뀐다”고 연결하라.

### 2-4. “어텐션으로 뜻이 정해진다”는 인과가 지나치게 강하다

(원문 인용) → “어디를 보는지 정하고, 본 만큼 뜻이 정해진다.”

(무엇이 문제인가) → 어텐션 가중치 하나가 인간이 해석하는 단어 뜻을 직접 결정한다고 오해하게 한다. 어텐션 값은 모델 내부 정보 혼합의 한 요소이고, 특정 가중치를 곧바로 설명이나 의미의 증거로 해석할 수도 없다.

(구체적 수정안) → “다른 토큰의 정보를 비율대로 섞어 현재 표현을 바꾼다”로 표현을 낮추고, “가중치가 크다고 그것만이 인간이 말하는 결정적 이유라는 뜻은 아니다”라고 적어라.

### 2-5. ‘낱말마다 한 바퀴’는 토큰 설명과도 모순된다

(원문 인용) → 슬라이드 7: “낱말 하나마다 한 바퀴” / 슬라이드 13: “한 조각 쓰고, 다시 읽는다.”

(무엇이 문제인가) → 앞 장에서 토큰은 단어가 아닐 수 있다고 가르친 뒤 다시 낱말 단위 생성으로 말한다. 학생은 한국어 한 어절이 여러 토큰이면 생성 바퀴가 몇 번 도는지 혼동한다.

(구체적 수정안) → 모든 장에서 “토큰 한 조각마다 한 번 생성”으로 통일하고, 화면에 보이는 한 단어가 여러 바퀴에 걸쳐 완성될 수 있음을 한 사례로 보여라.

### 2-6. “다시 읽는다”는 계산 방식도 부정확하게 받아들여질 수 있다

(원문 인용) → “한 조각 쓰고, 다시 읽는다.”

(무엇이 문제인가) → 학생은 매번 전체 문장을 인간처럼 처음부터 새로 읽고 동일한 계산을 반복한다고 이해한다. 실제 추론에서는 이전 계산을 캐시하는 경우가 일반적이며, 새 토큰은 인과적 제약 아래 앞 토큰만 참고한다.

(구체적 수정안) → “개념적으로는 늘어난 문맥을 다시 입력으로 삼는다. 실제 구현은 앞 계산을 저장해 재사용하기도 한다”로 구분하라.

### 2-7. 한국어가 불리하다는 결론을 단일 예시로 일반화한다

(원문 인용) → “같은 뜻인데 한국어가 1.4배”, “여러분이 한글로 질문하면 영어로 물을 때보다 돈이 더 듭니다. 진짜예요.”

(무엇이 문제인가) → 특정 문장과 `o200k_base`의 결과를 모든 문장·모든 모델·모든 요금제에 일반화한다. API가 입력 토큰당 과금되지 않거나 한국어 중심 토크나이저를 쓰는 모델에는 같은 결론이 성립하지 않는다. “한국어라서 품질이 낮다”는 결정론도 생긴다.

(구체적 수정안) → 여러 장르의 문장과 두 개 이상의 토크나이저를 비교하고, “이 토크나이저와 이 예문에서는”이라고 한정하라. 한국어 불리함은 토큰 수, 학습 데이터 비중, 모델별 차이라는 서로 다른 근거로 분리하라.

### 2-8. 온도 설명이 실제 서비스의 모든 변동 원인처럼 제시된다

(원문 인용) → “같은 질문에 다른 답이 나오는 것은 고장이 아니라 설계다.” / 발표자 노트: “이 손잡이 때문입니다.”

(무엇이 문제인가) → 출력 차이는 온도뿐 아니라 샘플링 방식, top-p/top-k, 시스템 지시, 모델 업데이트, 서버 설정 등에도 좌우된다. 또한 낮은 온도가 “늘 같은 답”을 보장하지 않는다.

(구체적 수정안) → “온도는 여러 조절 장치 중 하나이며, 낮추면 대체로 분포가 더 뾰족해진다”로 고쳐라. `늘 같은 답`은 `같은 답이 나올 가능성이 커짐`으로 바꿔라.

## 3. 실시간 문항의 타당성

### 3-1. attention-boat의 ‘타고’는 유일한 정답이 아니다

(원문 인용) → “①번 ‘배’가 ‘타는 배’라는 것을 정해 준 결정적인 말은?” / 정답: “타고”

(무엇이 문제인가) → 조사 “를”, 동사구 “타고 가다가”, 문장 전체의 사건 구조가 함께 선박 해석을 만든다. “배를 타다”라는 결합에서는 ‘를’과 ‘타다’의 관계가 중요하고, 어텐션도 단일 토큰만 보는 것이 아니다. 유일 정답 지정은 오히려 바로 뒤의 “여러 단어를 조금씩 함께 본다”와 충돌한다.

(구체적 수정안) → 정답을 복수 선택으로 바꾸어 `타고`를 가장 강한 단서, `배를`의 조사와 `가다가`를 보조 단서로 토론하게 하라. 또는 “가장 직접적인 단어”라고 질문 범위를 좁혀라.

### 3-2. 문항과 형광펜 수치가 실제 증거처럼 결합된다

(원문 인용) → “'타고'를 고른 사람이 많죠? 기계도 똑같이 합니다.” / “타고 0.52”

(무엇이 문제인가) → 학생 응답 다수와 임의로 만든 어텐션 수치를 연결해 인간 판단과 모델 내부 계산이 같다고 주장한다. 자료 스스로 “실제 모델의 계산 결과가 아니라 예시”라고 밝히므로 “똑같이”라는 결론을 지지하지 못한다.

(구체적 수정안) → “사람의 단서 선택과 비슷한 직관을 줄 수 있지만 모델의 실제 가중치와 동일하다는 뜻은 아니다”라고 말하고, 가능하면 실제 소형 모델의 예를 별도 자료로 비교하라.

### 3-3. 첫 워드클라우드는 한 단어 지시 때문에 오히려 답이 갈릴 수 있다

(원문 인용) → “「가는 말이 고와야 ___」 — 빈칸에 올 말을 한 단어로 적어 주세요”

(무엇이 문제인가) → 관용구의 완성은 “오는 말이 곱다”인데 한 단어만 요구하면 `오는`, `오는 말`, `곱다`, `오는말이곱다`가 나뉠 수 있다. 표기 변형도 별도 워드로 집계되면 의도한 뾰족한 분포가 깨진다.

(구체적 수정안) → 빈칸을 “가는 말이 고와야 오는 ___”로 바꾸어 정답을 `말`로 한정하거나, 제출 전에 띄어쓰기·어미를 정규화하라.

### 3-4. 두 번째 워드클라우드도 반드시 납작해지지 않는다

(원문 인용) → “오늘 아침에 눈을 뜨니 창밖에 ___”

(무엇이 문제인가) → 실제 교실의 날씨, 직전 발언, 계절에 의해 `비가`나 `눈이`에 답이 몰릴 수 있다. `눈`, `눈이`, `눈이 왔다`처럼 조사와 구문 길이 때문에 의미상 같은 답도 갈라진다. 반대로 첫 문항보다 단순히 표기 종류만 많아질 수 있어 확률분포와 언어 형식의 혼란을 구별하지 못한다.

(구체적 수정안) → 사전 시험으로 응답 분산을 확인하고, “상자 안에는 ___이 있었다”처럼 현재 날씨의 영향을 덜 받는 문장을 사용하라. 의미 범주별 정규화 결과와 원문 워드클라우드를 함께 보여라.

### 3-5. 워드클라우드가 실패하면 슬라이드 3의 실증성이 무너진다

(원문 인용) → “방금 여러분이 만든 두 개의 분포”, 화면 수치 “10 / 3 / 2 / 1”

(무엇이 문제인가) → 실제 응답이 예상과 다르더라도 슬라이드에는 이미 뾰족한 분포와 납작한 분포가 고정되어 있다. 학생 결과가 화면 서사와 반대라면 “방금 여러분이 만든”이라는 말이 거짓이 되고, 이후 확률분포 설명이 조작된 결론처럼 보인다.

(구체적 수정안) → 실제 라이브 응답으로 그래프를 그리거나, 슬라이드 3을 `예상 A/예상 B`가 아니라 두 결과에 모두 대응하는 분기 슬라이드로 만들어라. 실패 시 “왜 예상과 달랐는가”를 분석하는 대체 질문도 준비하라.

## 4. 학생이 막힐 지점

### 4-1. B1 한 칸에 서로 다른 판단을 너무 많이 요구한다

(원문 인용) → “주장을 내 말로 한 문장, 그것을 받치는 근거, 그리고 이 글에 빠짐없이 들어간 재료를 함께 적는다. 나온 숫자를 믿어도 되는지도 한 줄 덧붙인다.”

(무엇이 문제인가) → 주장 요약, 근거 추출, 필수 요소 일반화, 사실 검증 가능성 판단이 한 입력칸에 섞여 있다. 학생은 무엇을 ‘규칙’으로 옮겨야 하는지 모르고 글 내용을 길게 요약하는 쪽으로 흐른다.

(구체적 수정안) → `주장 / 근거 유형 / 반드시 포함할 요소 / 검증이 필요한 수치` 네 줄 템플릿으로 분리하라.

### 4-2. “내가 만든 질문”은 자유도가 너무 크고 성공 기준이 없다

(원문 인용) → “이 글을 더 알아내려면 무엇을 더 물어야 할까.”

(무엇이 문제인가) → 내용 질문, 사실 확인 질문, 글의 형식 질문, 필자의 의도 질문 중 무엇을 요구하는지 불명확하다. 학생은 “이 글은 재미있는가?”나 앞 질문을 바꿔 쓴 질문을 제출해도 왜 부적절한지 판단할 기준이 없다.

(구체적 수정안) → “앞의 세 질문에서 다루지 않은, 재현 프롬프트에 넣을 수 있는 규칙을 묻는다”라고 제한하고, 적합·부적합 예시를 각각 2개 제공하라.

### 4-3. 자작 질문의 답이 C 프롬프트에 어떻게 연결되는지 끊겨 있다

(원문 인용) → “B의 2번과 3번에 적은 답을 옆에 두고, 그 규칙들을 지시문으로 옮긴다.”

(무엇이 문제인가) → 활동에서는 자작 질문이 “가장 중요한 칸”이라고 하지만, C 안내는 B2와 B3만 사용하라고 한다. B1과 B4에서 찾은 내용 규칙을 프롬프트에 넣어야 하는지 학생이 알 수 없다.

(구체적 수정안) → C 지시를 “B1~B4에서 찾은 규칙 중 재현에 필요한 것을 모두 옮긴다”로 바꾸고, 각 B 답 옆에 `프롬프트에 넣기` 체크칸을 두어라.

### 4-4. ‘같은 글’과 ‘닮은 글’의 목표가 다르다

(원문 인용) → 슬라이드 16: “같은 글이 다시 나오면” / 활동지 C: “A의 글과 닮은 글을 써 낼 수 있어야 한다.”

(무엇이 문제인가) → 학생은 원문 내용과 문장을 최대한 복제해야 하는지, 구조와 문체만 재현해야 하는지 알 수 없다. 복제를 목표로 잡으면 원문 붙여넣기가 가장 합리적인 전략이 된다.

(구체적 수정안) → 목표를 “주제 내용은 유지하되 문장을 복사하지 않고, 구조·길이·말투·마무리 규칙을 재현한다”로 한 문장에 고정하라.

### 4-5. D에서는 채점 근거를 프롬프트 지시로 번역하는 발판이 없다

(원문 인용) → “1차 채점에서 무엇이 깎였고, 무엇을 고칠 것인가”

(무엇이 문제인가) → `문단 구성 12점` 같은 피드백을 읽는 것과 실행 가능한 지시문으로 바꾸는 것은 별도 능력이다. 낮은 독해력 학생은 점수만 베끼거나 “더 자세히 써 줘”처럼 포괄적 수정만 한다.

(구체적 수정안) → `채점 근거의 말 → 빠진 규칙 → 새 지시문` 3열 틀을 제공하고, 한 항목을 교사가 전원과 함께 변환한 뒤 독립 작업으로 넘겨라.

### 4-6. E는 도구를 닫으라는 지시와 근거를 보라는 지시가 충돌한다

(원문 인용) → “도구를 모두 닫고” / “두 번의 채점 근거를 근거로 삼아 쓴다.”

(무엇이 문제인가) → 채점 근거는 활동지 화면 안에 있다. 활동지를 닫으면 근거를 볼 수 없고, 열어 두면 “도구를 모두 닫고”를 지키지 않은 셈이다.

(구체적 수정안) → “외부 생성형 AI 창만 닫고 활동지의 채점 근거는 보아도 된다” 또는 “근거를 종이에 한 줄 옮긴 뒤 화면을 닫는다” 중 하나로 명확히 정하라.

### 5-1. ‘AI를 닫는다’의 대상이 불명확하다

(원문 인용) → “여기까지만 쓰고 곧바로 닫는다.”

(무엇이 문제인가) → 활동지 자체가 Solar Pro 3를 호출하므로 학생은 브라우저 탭을 닫으라는 말인지, 생성 버튼만 누르지 말라는 말인지, 별도 챗봇을 닫으라는 말인지 다르게 해석할 수 있다.

(구체적 수정안) → “활동지는 열어 둔다. B가 끝날 때까지 활동지의 생성·채점 버튼과 다른 AI 서비스를 사용하지 않는다”로 바꿔라.

### 5-2. ‘무엇이 반드시 들어 있는가’의 기준이 모호하다

(원문 인용) → “무엇을 말하는 글이고, 무엇이 반드시 들어 있는가”

(구체적 수정안) → “이 원문에 반복되거나 모든 문단에서 확인되는 요소”처럼 관찰 기준을 정하거나, `실제로 든 요소`와 `재현할 때 반드시 넣을 요소`를 분리하라.

### 5-3. ‘문장의 끝’이 문법 형식인지 내용 기능인지 불명확하다

(원문 인용) → “문장과 글의 마지막은 어떤 모양인가”

(무엇이 문제인가) → 학생은 종결어미 `-다`, 마지막 문장의 주장·제안 기능, 문장부호, 결론 문단의 구조 중 어느 것을 적어야 하는지 모른다.

(구체적 수정안) → `문장 종결어미`, `마지막 문장의 기능`, `마지막 문장부호`를 각각 구분해 제시하라.

### 5-4. “숫자를 믿어도 되는가”는 자료만으로 답할 수 없다

(원문 인용) → “여기 나온 숫자를 믿어도 되는가”

(무엇이 문제인가) → AI 사용과 검색을 금지한 상태에서 출처 없는 숫자의 진위를 학생이 확인할 방법이 없다. “출처가 없으니 보류한다”와 실제 사실 검증을 혼동한다.

(구체적 수정안) → 질문을 “숫자의 출처가 글 안에 제시되어 있는가, 현재 자료만으로 검증 가능한가”로 바꿔라.

(원문 인용) → 코드 주석: “진짜 방어선은 서버의 detectCopy(어절 6개 연속 일치)” / “넘더라도 막지 않고 경고만 띄운다.”

(구체적 수정안) → 복사 탐지는 부정행위 방지의 주 수단으로 삼지 말고 프롬프트의 구조 조건을 별도 채점하라. 원문 고유 문구가 아니라 추상화된 규칙을 구두로 설명하게 하거나, 재현 단계에서 주제를 바꾸어 규칙의 전이 가능성을 시험하라.

### 6-3. 학생이 점수만 올리는 반복 게임으로 바꾼다

(원문 인용) → “점수를 올리는 것이 목적이 아니라” / 화면에는 “0점”, 총점 막대, 항목별 “/20”이 두 차례 표시됨

(구체적 수정안) → 학생 화면에서는 총점을 숨기고 항목별 서술 피드백만 보여라. 2차 완료 뒤에만 1·2차 차이를 공개하고, 평가는 수정 근거의 구체성과 B 관찰의 증거로 하라.

## 7. 학생 눈높이에서 어려운 개념·어휘

### 7-1. 정책·산업 어휘가 설명 없이 연속 등장한다

(원문 인용) → “파운데이션 모델”, “GPU”, “B200”, “오픈소스”, “소버린 AI”, “가중치 비공개”, “단계평가”

(무엇이 문제인가) → 고등학생은 GPU와 B200의 관계, 오픈소스와 가중치 공개의 차이, 소버린 AI의 의미를 모를 수 있다. 이 어휘를 모르면 슬라이드 4~6의 논점을 모델 성능이 아니라 이름 암기로 받아들인다.

(구체적 수정안) → 수업 목표에 직접 필요한 `벤치마크·사용자 평가·공개 여부`만 남기고, 나머지는 각 10자 안팎의 풀이말이나 용어 카드로 제공하라.

### 7-2. 기술 어휘가 비유와 전문어 사이에서 갑자기 전환된다

(원문 인용) → “토큰”, “벡터”, “어텐션”, “확률분포”, “softmax(점수 ÷ 온도)”

(무엇이 문제인가) → 앞에서는 조각·자리·형광펜·점수 뭉치라는 비유를 쓰다가 슬라이드 12~13에서 전문어가 한꺼번에 등장한다. 특히 softmax 표기는 실제로는 단순히 ‘점수 ÷ 온도’가 아니어서 용어 이해와 정확성을 동시에 해친다.

(구체적 수정안) → 각 비유 옆에 전문어를 처음부터 일대일로 붙이고, softmax는 “점수를 확률로 바꾸는 계산”까지만 제시하라. 수식을 가르치지 않을 것이라면 괄호의 부정확한 축약은 삭제하라.

### 7-3. 평가 관련 어휘도 선행 이해를 요구한다

(원문 인용) → “벤치마크”, “아티피셜 애널리시스 종합지표”, “평가 영역별 1위”

(무엇이 문제인가) → 벤치마크를 단순 시험 점수로 볼지, 여러 과제를 묶은 비교 지표로 볼지 설명이 없다. 학생은 47점이 무엇의 47점인지도 모른 채 “1등이 탈락했다”는 반전만 소비한다.

(구체적 수정안) → 벤치마크를 “정해진 문제 세트로 모델을 비교하는 시험”으로 정의하고, 47점의 척도와 한계를 최소 한 문장으로 밝혀라.

## 8. 평가의 공정성과 변별력

### 8-1. “점수는 채점 대상이 아니다”라는 말과 화면 설계가 충돌한다

(원문 인용) → “점수는 채점 대상이 아니다.” / “1차 결과물 0점”, “2차 결과물 0점”, 항목별 “○/20”

(무엇이 문제인가) → 총점·색상·막대·항목 점수를 두 번 크게 보여 주면 학생에게 실제 보상 신호는 점수다. 교사의 말보다 인터페이스가 강하므로 학생은 높은 점수를 성취 기준으로 해석한다.

(구체적 수정안) → 총점과 막대를 제거하고 `잘 재현됨 / 일부 재현됨 / 빠짐` 같은 진단 표시만 제공하라. 수치가 꼭 필요하면 교사용 화면에만 표시하라.

### 8-2. 같은 프롬프트도 생성 변동 때문에 점수가 달라질 수 있다

(원문 인용) → “제가 똑같은 프롬프트를 두 번 넣어서 몇 점이 나오는지 보여 드릴게요. 그게 오늘의 만점선입니다.”

(무엇이 문제인가) → 이 시연은 오히려 점수가 학생 능력뿐 아니라 생성 운에 좌우됨을 인정한다. 학생마다 원문도 다르고 생성 결과도 달라 동일한 프롬프트 품질을 공정하게 비교할 수 없다.

(구체적 수정안) → 생성 결과의 점수가 아니라 학생이 명시한 규칙과 수정 논리를 평가하라. 비교가 필요하면 모든 학생에게 동일 원문과 고정된 후보 결과물을 제공하라.

### 8-3. 네 칸은 수행 여부만 보이고 수준 차이를 구분하지 못한다

(원문 인용) → “B의 분석 → 내가 만든 질문 → 1차 프롬프트 → 고친 근거와 2차 ✓”

(무엇이 문제인가) → 이 네 칸은 루브릭이라기보다 제출 체크리스트다. 피상적 분석과 근거 있는 분석, 중복 질문과 새로운 질문, 막연한 수정과 정밀한 수정 사이의 성취 수준 기술이 없다. 빈칸을 채운 학생은 모두 같은 수준으로 처리될 수 있다.

(구체적 수정안) → 각 칸에 최소 3수준 기술어를 두어라. 예를 들어 B는 `인상만 씀 / 관찰은 있으나 근거 부족 / 수치·문구 근거로 규칙을 일반화함`으로 변별하라.

### 8-4. AI 채점의 기준과 일관성을 학생·교사가 검증할 수 없다

(원문 인용) → “글 만들기와 채점은 활동지 안에서 Solar Pro 3가 맡는다.”

(무엇이 문제인가) → 채점 시스템 프롬프트, 항목 정의, 점수 경계, 재채점 일관성이 자료에 드러나지 않는다. 같은 결과가 다른 점수를 받을 수 있고, 학생은 이의를 제기할 근거가 없다.

(구체적 수정안) → AI 점수는 형성 피드백으로만 사용하고 성적에는 반영하지 말라. 교사용 명시 루브릭과 표본 이중채점으로 일관성을 점검하고, 최종 평가는 학생 산출물에 교사가 적용하라.

## 9. 기술 의존과 대비책

### 9-1. Supabase Edge Function 실패 시 2부 핵심 활동 전체가 멈춘다

(원문 인용) → “글 만들기와 채점은 활동지 안에서 Solar Pro 3가 맡는다.”

(무엇이 문제인가) → Edge Function이 실패하면 A 원문 생성, C·D 결과 생성, 두 차례 채점이 모두 불가능하다. 자료에는 오류 토스트만 있고 오프라인 원문, 고정 후보 결과, 수동 채점표가 없다.

(구체적 수정안) → 주제별 예비 원문, 1·2차 후보 결과물, 종이 루브릭을 PDF로 준비하라. 장애 시 전원이 동일 예비 글을 분석하고 후보 두 편을 비교 채점하도록 전환하라.

### 9-2. 라이브 세션 실패 시 슬라이드 2~3과 10~11의 연결이 끊어진다

(원문 인용) → “방금 여러분이 만든 두 개의 분포”, “방금 여러분이 고른 답과 비교해 보자.”

(무엇이 문제인가) → 접속 또는 제출이 실패하면 ‘방금 만든 분포’와 ‘고른 답’이 존재하지 않는다. 발표자 노트에는 손들기, 포스트잇, 교사 사전 데이터 같은 대체 절차가 없다.

(구체적 수정안) → 라이브 장애 시 손들기 표결표와 칠판 집계 절차를 슬라이드 노트에 넣어라. 워드클라우드용 예비 응답 카드도 준비하라.

### 9-3. 위젯 실패 시 핵심 개념이 정적인 주장으로 남는다

(원문 인용) → “내 문장은 몇 조각일까”, “①②③을 눌러 보세요”, “온도 손잡이”

(무엇이 문제인가) → 토큰 비교기, 어텐션 형광펜, 온도 슬라이더가 하나라도 작동하지 않으면 학생이 조작으로 확인한다는 설계가 무너진다. 자료에 조작 전후 캡처나 수기 계산표가 없다.

(구체적 수정안) → 각 위젯마다 3단계 정적 캡처를 덱에 숨은 백업 슬라이드로 넣고, 온도는 세 설정의 고정 분포표, 어텐션은 세 배의 인쇄 형광펜 활동으로 대체하라.

### 9-4. 제출 성공을 실제 서버 저장 성공으로 오인할 수 있다

(원문 인용) → 코드: `fetch(... mode: 'no-cors')` 뒤에 “제출했어요.”

(무엇이 문제인가) → `no-cors` 요청은 서버가 실제로 저장했는지 응답 내용을 확인할 수 없다. 네트워크 계층에서 요청이 전송되기만 하면 성공 처리될 수 있어, 학생은 저장되지 않은 제출을 성공으로 믿을 수 있다.

(구체적 수정안) → 제출 뒤 서버 조회로 해당 학번의 저장 시각을 자동 확인한 경우에만 ‘제출 완료’를 표시하라. 확인 실패 시 TXT 보관과 재제출 절차를 명시하라.

### 9-5. 자료 안에 실질적인 장애 전환안이 없다

(원문 인용) → 오류 문구: “글을 받지 못했어요”, “글을 만들지 못했어요”, “채점하지 못했어요”

(무엇이 문제인가) → 오류를 알려 주기만 하고 학생이 다음에 무엇을 해야 하는지 제시하지 않는다. 한 기능의 장애가 개인별 진도 차를 만들고, 교사는 동시에 여러 기기의 오류를 처리하느라 수업 운영을 놓친다.

(구체적 수정안) → 모든 오류 문구에 `한 번 재시도→예비 자료 번호 선택→교사에게 번호만 알림`의 3단계 대응을 넣고, 교사용 장애 전환 기준을 “3명 이상 실패하면 전원 오프라인 모드”처럼 정하라.

# 치명적 3가지

## 1순위 — 2부의 시간표가 실제 작업량을 수용하지 못함

37분이라는 표면 합계는 45~50분에 들어가 보이지만, 수업 안내·접속·다섯 번의 서버 호출·채점 근거 읽기·필수항목 검증·제출을 제외한 숫자다. 가장 먼저 희생될 부분은 핵심인 B의 독립 읽기 12분이다. 학생이 B를 급히 채우면 C와 D는 원문 복원 활동이 아니라 점수를 보고 프롬프트를 덧붙이는 시행착오 게임이 된다. 그러면 목표 ④는 직접 실패한다.

## 2순위 — 핵심 활동이 단일 AI 서버와 자동채점에 종속됨

Supabase Edge Function 하나가 원문 생성, 두 차례 재현, 두 차례 채점을 모두 담당한다. 장애가 나면 일부 기능이 아니라 2부의 전체 인과 사슬이 끊긴다. 자료에 예비 원문·후보 결과·수동 루브릭이 없으므로 교사가 현장에서 즉시 대체할 수도 없다. 네트워크나 호출 제한이라는 흔한 장애 하나가 한 차시 전체를 무수업 상태로 만들 수 있다는 점에서 치명적이다.

## 3순위 — 독립 독해를 평가한다면서 AI 사용을 강제할 수 없고 점수 최적화를 유도함

“AI를 끈다”는 규칙은 새 탭·휴대전화·브라우저 내장 AI를 막지 못하며, 원문 복사 방지도 연속 6어절 탐지와 경고에 그친다. 동시에 화면은 총점·색상·막대·항목별 점수를 두 번 제시한다. 따라서 성실한 학생은 혼자 읽느라 시간을 쓰고, 우회한 학생은 AI 분석과 점수 최적화로 더 높은 외형적 결과를 얻을 수 있다. 이는 목표 ④의 타당성과 평가 공정성을 동시에 무너뜨린다.
