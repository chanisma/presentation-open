## 1. 오해

### s03 — 답 분포

(s03-0-c0.jpg, s03-1-c0.jpg, s03-2-c0.jpg)  
→ 세 프레임의 구슬 수와 위치가 사실상 같아, 시간이 흐르며 응답이 “쌓인다”는 장면으로 보이지 않는다. 학생은 정지 화면이나 중복 프레임으로 받아들일 수 있다.  
→ 프레임마다 구슬이 실제로 추가되게 하고, 상단에 `응답 도착: 1명 → 8명 → 20명`처럼 시간 또는 누적 응답 수를 표시한다.

(s03-*.jpg)  
→ 왼쪽의 `10`, 오른쪽의 `3·2·2·2·1`이 학생 수인지, 점수인지, 확률인지 단위가 없다. 실제 모델이 계산한 확률로 오해할 수도 있다.  
→ `응답한 학생 수(명)`라는 축·범례를 붙이고, 수업용 가상 예시라면 `예시 응답 20명`이라고 명시한다.

(s03-*.jpg)  
→ 막대처럼 보이는 도형과 아래의 빛나는 점이 각각 무엇인지 불분명하다. 지형의 높이를 나타내는 막대인지, 답이 쌓인 구슬인지 구별하기 어렵다.  
→ 모든 응답을 같은 형태의 원으로 쌓거나, 막대를 쓸 경우 `답별 응답 수`라는 축과 답 라벨을 붙인다. 구슬과 막대 표현을 섞지 않는다.

(s03-*.jpg)  
→ 오른쪽의 다섯 웅덩이에 실제로 어떤 답들이 들어갔는지 보이지 않는다. “답이 여러 개다”가 아니라 “숫자가 작다” 정도로만 이해될 수 있다.  
→ 각 웅덩이에 `비가`, `새가`, `눈이` 같은 실제 학생 답 예시를 직접 적는다.

(s03-*.jpg)  
→ 골짜기가 원인이고 응답 집중이 결과인지, 응답이 집중돼 골짜기 모양이 된 것인지 인과관계가 모호하다.  
→ `문맥이 답을 강하게 제한함 → 한 답에 집중`과 `문맥의 제약이 약함 → 여러 답으로 분산`처럼 원인과 결과를 화살표 문장으로 분리한다.

### s07 — 네 단계와 반복

(s07-0-c0.jpg)  
→ 원의 일부만 밝고 나머지는 거의 보이지 않아, 아직 작동하지 않는 단계·실패한 단계 또는 끊어진 과정처럼 보인다.  
→ 진행 중인 단계는 굵은 테두리와 `현재 단계` 라벨로 표시하고, 나머지 단계도 읽을 수 있는 밝기로 유지한다.

(s07-1-c0.jpg)  
→ 원형 선에 방향 표지가 한 곳뿐이고 작다. ①→②→③→④인지 반대 방향인지 뒷자리에서는 판단하기 어렵다.  
→ 각 구간에 큰 화살촉을 넣거나 중앙에 `①→②→③→④→①`을 문자로 병기한다.

(s07-*.jpg)  
→ `자르기·좌표로·서로 쳐다보기·고르기`가 실제 모델의 정확한 내부 단계명처럼 보인다. 모델마다 구조가 다르다는 제목과도 긴장이 생긴다.  
→ `수업용 단순화`를 명시하고, 가능하면 `토큰화·벡터화·문맥 반영·다음 토큰 선택`을 작은 정식 용어로 함께 적는다.

(s07-1-c0.jpg)  
→ 중앙의 `한 낱말 하나마다 한 바퀴`는 한 단어를 만들 때 네 단계가 정확히 한 번씩만 실행된다는 뜻으로 읽힌다. 실제로는 여러 층의 계산과 토큰 단위 처리가 섞여 있다.  
→ `설명을 위한 개념적 한 바퀴`라고 제한하고, `실제 모델 내부에서는 이 계산이 여러 층에서 반복됨`을 덧붙인다.

### s09 — 좌표와 다의어

(s09-0-c0.jpg)  
→ 세 범주 안의 단어가 단순한 표 형태로 배치돼 있어 “가까운 뜻은 좌표상 가까이 놓인다”는 핵심이 충분히 드러나지 않는다.  
→ 공통 좌표 공간에 점으로 배치하고, 가까운 단어끼리 거리선이나 묶음 윤곽을 보여준다.

(s09-1-c0.jpg, s09-2-c0.jpg)  
→ 세 범주의 점선이 모두 `배`로 모여, “어디에도 정할 수 없다”가 아니라 “배는 세 범주에 동시에 속한다”로 이해하기 쉽다.  
→ 세 화살표 끝에 각각 `배(boat)`, `배(pear)`, `배(belly)`를 표시하고, 중앙에는 `문맥이 없으면 어느 뜻인지 결정할 수 없음`이라고 쓴다.

(s09-1-c0.jpg, s09-2-c0.jpg)  
→ `배`가 세 칸에 못 앉는 이유가 좌표 표현의 실패인지, 동음이의어 때문인지 즉시 드러나지 않는다.  
→ `단어 모양만 같고 뜻은 셋`이라는 중간 설명을 먼저 제시한 뒤 문맥 문장을 추가해 위치가 하나로 좁혀지는 후속 장면으로 연결한다.

(s09-*.jpg)  
→ `뜻이 가까운 말은 서로 가까운 자리에 앉는다`가 모든 모델에서 고정된 하나의 2차원 좌표를 갖는다는 뜻으로 받아들여질 수 있다.  
→ `실제로는 많은 차원의 수치이며, 이 그림은 이해를 위한 2차원 비유`라고 명시한다.

### s13 — 반복 생성

(s13-0-c0.jpg)  
→ 문장 전체가 네 단계를 통과한다고 그려져 있어, 모델이 매번 전체 문장을 처음부터 같은 방식으로 “다시 읽기만” 한다고 이해할 수 있다.  
→ `지금까지의 토큰들을 입력으로 사용해 다음 토큰 하나의 확률을 계산`한다고 표현을 고친다.

(s13-0-c0.jpg)  
→ 오른쪽의 `눈이 62 / 비가 21 / 바람이 9`는 단위와 출처가 없어 실제 모델 실행 결과처럼 보인다. 합도 100이 아니어서 나머지 후보의 존재가 설명되지 않는다.  
→ `%`, `수업용 가상 수치`를 표시하고 `기타 8%`를 넣거나, 숫자를 제거하고 상대적 막대만 사용한다.

(s13-0-c0.jpg)  
→ `고르기`에서 가장 높은 후보가 언제나 선택된다고 보인다. 그러면 같은 입력에 늘 같은 출력만 나온다고 오해한다.  
→ `가장 높은 것을 택하기도 하고, 설정에 따라 확률적으로 뽑기도 함`이라는 짧은 주석을 넣는다.

(s13-1-c1.jpg)  
→ 출력에서 입력으로 돌아가는 초록 선이 화면 오른쪽을 크게 돌아 왼쪽을 향한다. 뒷자리에서는 화살촉이 작아 흐름을 역방향으로 읽을 수 있다.  
→ `출력 토큰 → 문장 끝에 붙이기 → 늘어난 입력`의 세 칸을 만들고, 굵고 짧은 화살표로 연결한다.

(s13-1-c1.jpg)  
→ 새로 나온 `눈이`와 원래 문장 끝의 `창밖에`가 같은 줄에 붙지만, 어디까지가 이전 입력이고 어디부터가 새 출력인지 색 외에는 구별하기 어렵다.  
→ 새 토큰에 `[새 출력] 눈이` 라벨, 괄호 또는 다른 테두리 모양을 함께 사용한다.

(s13-2-c2.jpg)  
→ `바퀴 428`이 특정 답변을 만드는 데 실제로 428회의 모델 계산이 필요했다는 실측값처럼 보인다. “바퀴”가 토큰 수인지 글자 수인지도 알 수 없다.  
→ `예시: 428번째 토큰 생성` 또는 `설명용 가상 횟수`로 바꾸고 단위를 명확히 한다.

(s13-2-c2.jpg)  
→ 428회 반복이 보이지만 언제 멈추는지 설명이 없다. 모델이 무한히 계속 쓰거나 정해진 횟수만큼만 쓴다고 오해할 수 있다.  
→ `종료 표시를 고르거나 최대 길이에 도달하면 멈춤` 단계를 추가한다.

(s13-2-c2.jpg)  
→ `창밖에` 주변의 분홍색 손그림 표시는 무엇이 잘못됐다는 교사 첨삭처럼 보이지만 의미가 설명되지 않는다.  
→ 의도된 강조라면 정돈된 괄호와 `이전 입력` 라벨로 바꾸고, 의미 없는 장식이라면 제거한다.

### s18 — 완성된 글의 도면

(s18-0-c0.jpg, s18-1-c0.jpg, s18-2-c0.jpg)  
→ `문단 구성·문장의 끝·길이와 분량·들어간 요소·마무리 모양`을 실제로 측정 가능한 다섯 숫자처럼 제시하지만 값과 단위가 없다. 학생은 모델이 이런 다섯 항목만 정확히 계산한다고 오해할 수 있다.  
→ 각 항목에 구체적인 예시값을 넣거나, 측정값이 아니라면 `글을 살펴보는 다섯 관점`으로 이름을 바꾼다.

(s18-1-c0.jpg, s18-2-c0.jpg)  
→ 가운데 표만 있으면 오른쪽에 “같은 글”이 재현되는 것처럼 보인다. 다섯 특징만으로 원문의 내용과 문장을 복원할 수 있다는 잘못된 인과관계를 만든다.  
→ `같은 글`이 아니라 `비슷한 구조의 새 글`이라고 표현하고, 주제·핵심 내용·독자 같은 추가 입력도 함께 표시한다.

(s18-*.jpg)  
→ 왼쪽 글에서 표로 향하는 점선은 있지만, 무엇을 어떻게 추출했는지 알 수 없다. 자동 분석인지 학생의 관찰 활동인지도 모호하다.  
→ `학생이 표시한다` 또는 `모델이 특징을 추정한다`처럼 행위 주체를 명시한다.

(s18-1-c0.jpg, s18-2-c0.jpg)  
→ 가운데에서 오른쪽으로 가는 초록 화살표 하나 때문에 다섯 항목 중 라임색 항목인 `문장의 끝`만 새 글에 사용되는 것처럼 보일 수 있다.  
→ 다섯 항목을 묶는 괄호에서 화살표를 시작하거나 `다섯 항목 모두 사용`이라고 라벨을 붙인다.

## 2. 가독성

(s03-*.jpg)  
→ 그래프 아래 설명, 답 분포의 숫자, 하단 말풍선이 너무 작다. 교실 뒤에서는 제목과 막대 수치 외에는 읽기 어렵다.  
→ 설명문을 1문장씩 크게 만들고, 하단 말풍선은 별도 클릭 장면으로 분리한다.

(s07-0-c0.jpg)  
→ 비활성 단계의 이름과 원형 경로가 배경에 묻힌다. 저시력 학생에게는 ① 외의 과정이 거의 사라진다.  
→ 비활성 요소도 최소 4.5:1 대비를 확보하고, 강조는 밝기 저하 대신 굵기·채움·크기로 표현한다.

(s07-1-c0.jpg)  
→ 중앙의 부연문과 화살촉이 작다. 큰 제목이 화면 대부분을 차지해 핵심 도식에 충분한 면적이 배정되지 않았다.  
→ 제목을 한 줄 줄이고 도식을 25~35% 확대한다.

(s09-*.jpg)  
→ 왼쪽 본문과 단계 탭, 오른쪽 범주명 및 `어느 칸?`이 작다. 뒷자리에서는 큰 제목과 단어 카드만 남는다.  
→ 본문을 핵심 두 문장으로 축약하고, 범주명과 결론 문구를 카드 단어와 같은 크기로 키운다.

(s13-*.jpg)  
→ 네 단계 카드 안의 보조 라벨 `토큰·벡터·어텐션·확률`, 확률 숫자, 상단 설명이 모두 작다.  
→ 보조 라벨을 삭제하거나 각 단계를 개별 장면으로 확대한다. 확률 숫자는 최소 본문 크기로 올린다.

(s13-2-c2.jpg)  
→ 입력 토큰이 한 줄에 과밀하게 늘어서고, 새 토큰과 흐린 예정 토큰이 겹쳐 보인다.  
→ 이전 입력은 한 덩어리로 축약하고 최근 2~3개 토큰만 크게 보여준다.

(s18-*.jpg)  
→ 세 열의 제목, 다섯 측정 항목, 하단 설명이 작고 대비도 낮다. 화면의 넓은 빈 공간에 비해 핵심 도식은 지나치게 작다.  
→ 도식을 화면 중앙에서 크게 확대하고, 하단 설명은 별도 장면으로 옮긴다.

## 3. 색 의존

(s03-*.jpg)  
→ 좁은 답과 넓은 답의 구분이 주로 앰버와 라임에 의존한다. 두 색을 구분하지 못하면 두 분포가 같은 종류로 보인다.  
→ 왼쪽은 원형 구슬, 오른쪽은 사각 구슬처럼 모양을 달리하고 `집중형 / 분산형` 라벨을 직접 붙인다.

(s03-*.jpg)  
→ 제목의 핵심 대비인 `뾰족한 답 / 납작한 답`도 흰색·앰버·라임 색 변화에 의존한다.  
→ 핵심어 아래에 서로 다른 밑줄 모양이나 아이콘(▼ 좁음, ↔ 넓음)을 병기한다.

(s07-*.jpg)  
→ 현재 진행 구간은 밝은 앰버, 나머지는 어두운 선으로만 구분된다. 저시력 학생에게 비활성 경로가 사라진다.  
→ 현재 구간을 굵은 실선, 지난 구간을 이중선, 다음 구간을 점선처럼 선 형태로도 구분한다.

(s09-1-c0.jpg, s09-2-c0.jpg)  
→ `타는 것·먹는 것·몸의 부위`와 `배`를 잇는 세 점선이 색으로만 대응한다.  
→ 각 선에 🚗·🍐·몸 아이콘 또는 `①·②·③`을 넣고, 카드에도 같은 기호를 반복한다.

(s13-*.jpg)  
→ 토큰·벡터·어텐션·확률의 대응이 앰버·파랑·보라·라임 색에 크게 의존한다.

## 학생에게 가장 위험한 오해 3가지

1. **`배`가 세 의미를 동시에 가진 하나의 좌표에 놓인다는 오해**  
   s09의 세 색 점선이 한 `배`로 합쳐진다. 실제 핵심은 문맥 없이는 같은 표기의 여러 의미 중 하나를 결정할 수 없다는 것이다.

2. **LLM이 정확히 네 단계를 한 번씩 돌고 가장 높은 확률의 단어를 고른다는 오해**  
   s07과 s13을 함께 보면 실제 모델 구조도 단순한 네 단계 고정 루프이며 출력도 항상 결정적이라고 받아들이기 쉽다. 반드시 `수업용 단순화`와 확률적 선택 가능성을 밝혀야 한다.

3. **화면의 숫자가 실제 모델에서 측정된 값이라는 오해**  
   s03의 `10·3·2…`, s13의 `62·21·9`와 `428`은 단위·출처가 없다. `학생 수`, `%`, `토큰 생성 횟수`, `가상 예시`를 각각 명시하지 않으면 서로 다른 종류의 숫자가 모두 실제 계산 결과처럼 보인다.
