## 1. 개념 순서와 설명의 결함

### 1) 과부하의 핵심은 개념 수보다, 연결을 확인하지 않고 넘어가는 구조다

**원문 인용** → “돌려주는 값(반환값)” → “내가 만드는 함수: def” → “빈칸이 있는 함수: 매개변수”
**무엇이 문제인가** → 호출·반환값·정의·매개변수를 첫 수업에 함께 소개하는 것 자체가 잘못은 아니다. 그러나 여기서는 `print`로 화면에 보여 주기, `len`으로 값을 얻기, `def`로 동작 묶기, 인자를 매개변수에 묶기가 연속해서 등장하고, 학생이 각각을 구별했는지 확인하는 다리가 없다. 특히 직접 만드는 함수는 모두 출력만 하므로, 반환값은 고립된 `len` 사례로 끝난다.
**구체적 수정안** → `print` 호출 → `len` 결과를 변수에 대입하고 다시 사용 → 출력과 반환 비교 → 인자 없는 함수 정의·호출 → 매개변수 한 개 순으로 연결하라. `return`까지 추가하기보다, 이번 수업에서는 “반환값을 받아 쓰기”까지 다룬다고 범위를 명시하라.

### 2) 반환값 설명이 화면과 발표자 노트에서 충돌한다

**원문 인용** → 화면: “화면에 보여 주고 끝. 묶을 값이 나오지 않는다” / 노트: “실제로는 print도 None이라는 ‘아무것도 없음’ 값을 돌려줍니다.”
**무엇이 문제인가** → 화면에서 배운 명제를 교사가 말로 뒤집는다. 학생이 `result = print("안녕")`을 실행하면 이름에 값이 실제로 묶이므로, “묶을 값이 없다”는 설명으로는 관찰 결과를 설명할 수 없다. 출력과 반환을 구분하려다 부정확한 이분법을 만든다.
**구체적 수정안** → 화면을 “`print`는 화면에 출력하고, 반환값은 `None`이다. `len`은 센 결과를 반환한다”로 고쳐라. 다음 코드를 실행해 화면에 나온 글자와 변수에 묶인 값을 따로 묻게 하라.

```python
shown = print("인공지능")
count = len("인공지능")
print(shown)
print(count)
```

### 3) “위에서 아래로” 설명을 함수 실행에서 갱신하지 않는다

**원문 인용** → “실행 / 컴퓨터가 코드를 위에서 아래로 읽고 그대로 하는 것”
**무엇이 문제인가** → 직선 코드의 입문 설명으로는 쓸 수 있다. 그러나 이를 그대로 유지하면 학생은 `def` 아래의 출력문이 정의할 때 실행된다고 읽는다. 14장의 “만들기만 하고 부르지 않으면” 설명은 있지만, 호출 위치에서 함수 안으로 들어갔다가 돌아오는 실행 순서가 명시되지 않는다.
**구체적 수정안** → 14장에서 “정의할 때는 안의 일을 실행하지 않는다. 호출하면 안으로 들어가 실행하고, 호출한 다음 줄로 돌아온다”를 실행 화살표로 보여라. 출력 줄 수뿐 아니라 **실제로 실행되는 순서**를 학생이 표시하게 하라.

### 4) 함수 밖의 `name` 설명은 실행 환경에 따라 틀린다

**원문 인용** → “함수가 끝나면 이 이름표는 사라져서, 함수 밖에서 name을 부르면 찾지 못합니다.”
**무엇이 문제인가** → 함수 밖에 이미 `name`이 있으면 찾는다. 앞선 예제들이 반복해서 `name = "민지"`를 사용하므로, 실행기가 상태를 공유한다면 특히 혼란스럽다. 실행기별 상태 격리 여부는 제공 자료만으로 확인할 수 없다.
**구체적 수정안** → “매개변수로 받은 `name`은 함수 안의 이름이다. 함수 밖에 따로 만든 `name`과는 별개다”로 고쳐라. 실행기 상태도 명시하고, 지역 변수 예제에서는 기존 예제와 겹치지 않는 이름을 써라.

## 2. 실시간 문항의 타당성

### 5) 객관식 네 문항의 정답에는 큰 반론이 없지만, 목표를 충분히 측정하지 않는다

**원문 인용** → “이 코드를 실행하면 무엇이 출력될까요?” / “변수 이름으로 쓸 수 있는 것은 무엇일까요?” / “print(\"name\")” / “화면의 4번 코드가 실행되지 않는 까닭”
**무엇이 문제인가** → 제시된 코드와 선택지에서는 네 정답 모두 타당하다. `score + 5`, `"name"`처럼 초보자의 오개념을 겨냥한 오답도 그럴듯하다. 다만 반환값, 정의와 호출의 차이, 인자와 매개변수의 연결을 묻는 문항은 없다. 출구 티켓의 정의 암기만으로 그 공백을 메울 수 없다.
**구체적 수정안** → 기존 문항 일부를 바꾸거나 활동지에 짧은 확인을 넣어라. 예를 들어 `n = len("민지")`만 실행했을 때 **화면 출력과 n의 값**을 따로 묻고, 함수의 인자만 바꿨을 때 출력이 어떻게 달라지는지 예측하게 하라.

### 6) 오류 문항은 오류 메시지를 읽는 능력을 검증하지 않는다

**원문 인용** → “화면의 4번 코드가 실행되지 않는 까닭은 무엇일까요?”
**무엇이 문제인가** → 네 선택지는 각각 따옴표·들여쓰기·이름·괄호라는 대표 오류에 대응한다. 도입 확인용으로는 적절하지만, 학생은 줄 앞의 빈칸만 보고 맞힐 수 있다. 수업 목표인 “오류를 스스로 읽고 고친다”의 달성 근거로 쓰기에는 약하다.
**구체적 수정안** → 처음 보는 오류 코드와 실제 오류 원문을 주고 “어느 부분을 근거로, 어느 줄을 어떻게 고칠 것인가”를 답하게 하라. 원인 선택과 수정 수행을 구분해서 확인하라.

## 3. 활동지 난이도 곡선과 자동 점검의 허점

다음 자동 점검 평가는 제공된 F절을 기준으로 한다. `r.info`의 수집 구현과 변수 수집 범위는 없으므로, 정적 분석인지 실행 횟수 집계인지에 따라 달라지는 우회는 단정하지 않는다.

### 7) 2번에서 만든 것을 3번에서 활용하지 않고, 갑자기 복합 디버깅으로 전환한다

**원문 인용** → “나를 소개하는 변수 5개” → “아래 자기소개 코드에는 오류가 네 개 숨어 있습니다.”
**무엇이 문제인가** → 변수 만들기 다음에 이름 규칙, 대소문자, 따옴표, 괄호를 한꺼번에 고치게 한다. 특히 구문 오류 때문에 실행조차 시작되지 않는 상태에서, 학생은 앞에서 배운 “오른쪽부터 계산”이나 변수 상자를 활용할 수 없다. 반면 5번은 출력 형식이 거의 완성돼 있어, 과제 번호가 올라간다고 사고 부담이 점진적으로 커지는 구조도 아니다.
**구체적 수정안** → 오류 하나가 있는 짧은 코드를 먼저 고치게 한 뒤 복합 오류 코드로 넘어가라. 5번은 완성 틀 채우기와 빈 편집기에서 작성하기를 선택하게 하고, 6번 앞에는 매개변수 하나인 함수를 수정하는 연결 과제를 두어라.

### 8) 2번은 변수 다섯 개를 만들고, 하나도 사용하지 않아도 통과한다

**원문 인용** → “자기소개에 필요한 값 다섯 개를 골라 변수를 만들고, print()로 확인하세요.” / `return (r.info.prints || 0) >= 1;`
**무엇이 문제인가** → 다음 코드는 다섯 변수, 문자열, 숫자, `print`, 오류 없음 조건을 충족한다. 그러나 출력이 변수와 아무 관계가 없고, 이름도 자기소개 의미를 나타내지 않는다.

```python
a = "민지"
b = 17
c = 1
d = 2
e = 3
print("완료")
```

**구체적 수정안** → 지시를 “만든 변수 다섯 개의 값을 모두 출력해 확인하세요”로 분명히 하라. 자동 점검은 변수 개수·자료형만 확인한다고 표시하고, 변수 사용과 이름의 의미는 별도 확인 대상으로 남겨라. `print` 존재만으로 “확인 완료”를 판정하지 마라.

### 9) 3번은 오류를 고치지 않고 출력을 통째로 바꿔도 통과한다

**원문 인용** → “한 곳씩 고쳐서 끝까지 실행되게 만드세요.” / `(r.out || '').replace(/\s+$/, '') === T3_EXPECT`
**무엇이 문제인가** → 다음 코드는 원래 오류 네 종류를 해결했다는 증거 없이 두 점검을 모두 통과한다. 수정 설명란이 있어도 자동 점검 결과 자체는 이를 구별하지 못한다.

```python
print("이름: 민지\n취미: 그림 그리기\n나이: 17\n반가워!")
```

**구체적 수정안** → “원래 변수 대입과 출력문의 구조를 유지하고 잘못된 부분만 고치세요”를 추가하라. 점검 명칭은 “예상 출력 일치”로 한정하고, 오류 해결 여부는 원본 대비 수정 내용과 학생의 설명으로 확인하라.

### 10) 3번은 출력 공백 기준을 공지하지 않고 정확히 일치할 것을 요구한다

**원문 인용** → “값(민지, 그림 그리기, 17)은 바꾸지 마세요.” / `T3_EXPECT = '이름: 민지\n취미: 그림 그리기\n나이: 17\n반가워!';`
**무엇이 문제인가** → 다음 코드는 문법적으로 맞고, 지정된 값도 유지하며, 자기소개 네 줄을 출력한다. 그러나 콜론 뒤 공백이 없어 점검에서 떨어진다. “원래 구조를 유지하라”나 “출력 공백까지 동일하게 하라”는 지시가 없어 정답 판정에 반론이 가능하다.

```python
name = "민지"
hobby = "그림 그리기"
age = 17
print(f"이름:{name}")
print(f"취미:{hobby}")
print(f"나이:{age}")
print("반가워!")
```

**구체적 수정안** → 정확한 출력 형식이 목표라면 예상 결과를 공백까지 제시하라. 디버깅이 목표라면 줄별 내용과 값의 보존을 중심으로 판단하고, 공백 차이를 오류 해결 실패와 구분하라.

### 11) 5번은 세 출력 방법 중 하나를 검사하지 않는다

**원문 인용** → “변수 그대로 · 쉼표로 나열 · f-문자열, 세 방법을 모두 써 봤나요?”
**무엇이 문제인가** → F절에는 `print(변수)` 형태와 출력에 사용된 변수의 연결을 검사하는 조건이 없다. 다음 코드는 문자열 변수 세 개, 출력 세 번, 쉼표 출력, f-문자열 출력을 갖추지만 버킷리스트 변수를 전혀 출력하지 않는다.

```python
bucket1 = "세계 여행"
bucket2 = "악기 배우기"
bucket3 = "책 쓰기"

print("첫째")
print("둘째", "항목")
print(f"셋째")
```

**구체적 수정안** → 기본 출력 `print(bucket1)`도 확인 대상으로 넣고, f-문자열에 실제 변수 삽입이 있는지 구분하라. 단, 형식 검사만으로 학습을 보증하지 말고 “변수 값을 바꿨을 때 출력도 바뀌는가”를 학생이 확인하게 하라.

### 12) 6번은 함수 이름·매개변수 사용·출력·서로 다른 인자를 검사하지 않는다

**원문 인용** → “def card(name, hobby):로 소개 카드를 출력하는 함수를 만들고, 서로 다른 두 사람으로 두 번 불러 보세요.”
**무엇이 문제인가** → 다음 코드는 F절의 네 조건을 충족한다. 하지만 소개 카드를 출력하지 않고, 매개변수를 사용하지 않으며, 서로 다른 사람도 아니다.

```python
def card(name, hobby):
    pass

card("민지", "그림")
card("민지", "그림")
```

**구체적 수정안** → 최소한 두 호출의 결과가 실제로 출력되고, 이름과 취미가 각각 반영되는지 확인하라. “정의 하나”, “매개변수 두 개”, “호출 두 번”이 **같은 함수**에 대한 조건인지도 연결해서 검사하라.

### 13) 맞는 함수 코드가 떨어질 가능성은 있지만, F절만으로 확정할 수는 없다

**원문 인용** → `((r.info.calls || {})[d.name] || 0) >= 2`
**무엇이 문제인가** → 다음 코드는 `card`를 서로 다른 두 사람으로 두 번 실행한다. `calls`가 소스에 나타난 직접 호출만 센다면 `card` 호출은 하나로 기록돼 탈락한다. 실제 실행 횟수를 센다면 통과한다. 수집 구현이 없으므로 어느 쪽이라고 단정하면 안 된다.

```python
def card(name, hobby):
    print(name, hobby)

def run_card(name, hobby):
    card(name, hobby)

run_card("민지", "그림")
run_card("서연", "독서")
```

**구체적 수정안** → 점검이 “코드에 적힌 호출 수”와 “실제로 실행된 호출 수” 중 무엇을 세는지 명시하고 검증하라. 전자라면 점검 문구를 “함수 이름으로 직접 호출한 문장 두 개”로 제한하거나, 실행 결과 중심으로 고쳐라.

## 4. 학생이 실제로 손을 멈출 지점과 모호한 지시

### 14) “오류 네 개”와 “하나씩 나타남”은 실제 경험과 어긋난다

**원문 인용** → “오류가 네 개 숨어 있습니다.” / “파이썬은 한 번에 오류 하나만 알려 줍니다. 하나를 고치면 다음 오류가 나타납니다.”
**무엇이 문제인가** → `2nd_hobby`는 대입문과 출력문 두 곳에 등장한다. 네 **종류**로 묶을 수는 있어도 수정 위치는 다섯 곳이다. 또한 첫 줄의 `name = 민지`보다 뒤쪽 구문 오류가 먼저 보고될 수 있다. 구문 분석이 끝나야 첫 줄의 `NameError`가 발생하므로, 학생은 위에서부터 하나씩 고칠 수 있다고 기대하면 막힌다.
**구체적 수정안** → “오류 네 종류가 여러 곳에 있습니다. 먼저 문법 오류가 보고되고, 이를 고친 뒤 실행 중 오류가 나타날 수 있습니다. 이름을 바꾸면 사용하는 곳도 함께 고치세요”로 바꿔라.

### 15) 한글 입력·따옴표·들여쓰기를 위한 복구 안내가 부족하다

**원문 인용** → “따옴표 안의 ○○를 여러분 이름으로 바꾸고 실행하세요.” / “Tab을 누르면 빈칸 네 칸이 들어갑니다”
**무엇이 문제인가** → 한글 조합 중 실행 단축키를 누르거나, 따옴표까지 선택해 지우거나, `“ ”` 같은 문장용 따옴표를 붙여 넣으면 첫 실행부터 막힌다. 함수에서는 자동 들여쓰기와 Tab을 중복 적용하거나 호출문까지 들여쓸 수 있다. 편집기의 조합 처리·자동 들여쓰기·내어쓰기 동작은 자료에 없다.
**구체적 수정안** → 실제 학생 기기에서 한글 조합 상태의 실행, 붙여넣기, Tab 동작을 확인하라. 학생 안내에는 “이름 입력을 마친 뒤 실행 버튼 누르기”, 사용 가능한 `'`·`"`, 호출문을 맨 왼쪽으로 되돌리는 방법, 시작 코드 복원 방법을 넣어라.

### 16) 한국어 오류 풀이를 읽어도 다음 행동이 정해지지 않는다

**원문 인용** → “빨간 상자의 맨 앞 단어와 줄 번호부터 보세요.”
**무엇이 문제인가** → `SyntaxError`라는 분류와 줄 번호만 알아서는 무엇을 고칠지 알 수 없다. 특히 3번의 잘못된 식별자는 16장 오류 카드에 없는 유형이다. “없는 이름” 풀이도 따옴표 누락인지, 대소문자 오타인지, 대입 누락인지 구분해 주지 않는다.
**구체적 수정안** → 오류 읽기를 “마지막 오류 문장 확인 → 표시된 줄과 앞줄 확인 → 의심 부분 하나 수정 → 재실행”으로 구체화하라. `invalid decimal literal`처럼 3번에서 실제 만날 메시지를 포함하고, `NameError`에는 “글자 값인가, 이미 만든 변수인가?”라는 분기 질문을 붙여라.

### 17) 규칙과 관례, 숫자와 문자열의 경계가 모호하다

**원문 인용** → “영문자 · 숫자 · 밑줄( _ )로 짓는다” / “한글 이름도 동작하지만” / “글자는 따옴표, 숫자는 그대로”
**무엇이 문제인가** → 앞 문장은 한글 변수명을 문법 위반처럼 읽게 하고, 뒤 문장은 허용한다. “숫자”도 값의 자료형인지 겉모양인지 모호하다. 학번 `"10307"`처럼 숫자로 보이는 문자열을 쓰는 학생에게 어떤 설명을 적용할지 불분명하다.
**구체적 수정안** → “파이썬은 한글 이름도 허용한다. 이번 활동에서는 영어 소문자와 밑줄을 권장한다”로 구별하라. 숫자는 “계산할 숫자는 `17`, 글자로 다룰 값은 `"17"`”처럼 의도를 기준으로 설명하라.

### 18) 과제 2·5·6의 문장은 서로 다른 완성물을 허용한다

**원문 인용** → “print()로 확인하세요.” / “세 가지 출력 방법으로 한 줄씩 출력하세요.” / “서로 다른 두 사람으로 두 번 불러 보세요.”
**무엇이 문제인가** → 2번은 다섯 변수를 모두 출력해야 하는지, 하나만 출력해도 되는지 불명확하다. 5번은 항목마다 다른 방법 하나씩인지, 각 항목을 세 방법 모두로 출력하는지 잠시 갈릴 수 있다. 6번은 이름만 다르면 되는지 취미도 달라야 하는지, 소개 카드가 몇 줄이어야 하는지 알 수 없다.
**구체적 수정안** → “다섯 변수의 값을 모두 출력”, “첫 항목은 변수 그대로, 둘째는 쉼표, 셋째는 f-문자열로 총 세 줄”, “서로 다른 이름 두 개로 호출하고 각 호출에서 이름과 취미가 모두 보이게 출력”이라고 써라.

## 5. 교사가 개입하지 않을 때의 실패 시나리오 3개

### 19) 실패 시나리오 ①: 오류 수정이 무작위 삭제로 변한다

**원문 인용** → “하나를 고치면 다음 오류가 나타납니다.”
**무엇이 문제인가** → 학생은 첫 줄부터 실행될 것으로 기대하지만 뒤쪽 구문 오류를 먼저 만난다. `2nd_hobby`를 한 곳만 고친 뒤 또 오류가 나면 “고쳤는데 안 된다”고 판단한다. 결국 문제 줄을 지우거나 정답 출력문으로 대체하고, 자동 점검 통과를 디버깅 성공으로 받아들인다.
**구체적 수정안** → 오류 한 개짜리 연습을 먼저 제공하고, 복합 과제에는 “오류 원문 / 고친 위치 / 다시 실행한 결과” 기록을 붙여라. 출력 일치와 원인 설명을 별도로 확인하라.

### 20) 실패 시나리오 ②: 초록 체크는 가득하지만 변수와 매개변수는 장식이다

**원문 인용** → “자동 점검은 정답을 알려 주는 것이 아니라 빠진 것이 있는지만 알려 줍니다.”
**무엇이 문제인가** → 학생은 체크 문구를 완료 기준으로 삼는다. 변수 다섯 개를 만들고 고정 문자열을 출력하며, `card`는 인자를 무시한 채 같은 문장만 출력한다. 모든 체크가 켜져도 값에 이름을 붙여 재사용하거나 인자로 동작을 바꾸는 경험은 없다.
**구체적 수정안** → 제출 전 “변수 값 하나만 바꾸어 출력 바꾸기”, “호출 인자만 바꾸어 소개 대상 바꾸기”를 수행하게 하라. 초록 체크 옆에 검사 범위를 구체적으로 표시하라.

### 21) 실패 시나리오 ③: 함수 목표가 선택 과제와 말로 하는 정의에만 남는다

**원문 인용** → “이 과제는 비워도 제출할 수 있습니다.” / “변수와 함수를 각각 여러분의 말로 한 문장씩 설명해 주세요.”
**무엇이 문제인가** → 6번을 건너뛴 학생은 함수 정의와 매개변수를 직접 다루지 않고도 제출할 수 있다. 출구 티켓에는 “함수는 일에 붙인 이름”을 옮겨 적는다. 결과물에는 함수 이해를 판단할 실행 증거가 거의 남지 않는다.
**구체적 수정안** → 함수 작성 전체는 도전으로 남겨도 된다. 대신 모든 학생에게 짧은 함수의 호출 위치 찾기, 인자와 매개변수 연결하기, 호출 인자를 바꿔 실행하기는 요구하라.

## 6. 18장 AI 코드 읽기의 적합성

### 22) 실제 코드의 `=`를 설명하는 문장이 틀리다

**원문 인용** → “= 왼쪽은 전부 변수” / “등호 왼쪽을 보세요. model, prediction, confidence_score. 전부 이름표입니다.”
**무엇이 문제인가** → 골라 든 세 예시는 맞지만 화면 전체에 대한 일반화는 틀리다. `compile=False`, `shape=...`, `dtype=...`, `end=""`는 호출에 건네는 키워드 인자이며 변수 대입이 아니다. `data[0] = ...`의 왼쪽도 단순한 변수 이름이 아니다. 첫 수업에서 막 배운 판별 규칙을 실제 코드가 곧바로 깨뜨린다.
**구체적 수정안** → “이 세 줄의 `model`, `prediction`, `confidence_score`는 결과에 붙인 이름이다”로 범위를 좁혀라. 코드 전체의 모든 `=`를 분류시키지 말고, 해당 세 줄만 강조하라.

### 23) “큰 흐름을 읽는다”는 성취 주장이 실제 과제보다 크다

**원문 인용** → “오늘 배운 두 가지만으로 AI 코드의 큰 흐름을 읽을 수 있습니다.” / “점( . )과 대괄호( [ ] )는 앞으로 배웁니다”
**무엇이 문제인가** → 실제 코드에는 가져오기, 속성·메서드 접근, 키워드 인자, 배열, 인덱싱, 슬라이싱이 겹쳐 있다. 학생이 `이름(`과 `=`를 찾는 것만으로 이미지 전처리와 예측 결과 선택의 흐름까지 읽었다고 할 수는 없다. 특히 반환값 사용을 활동지에서 확인하지 않은 상태라, 교사의 설명을 따라 끄덕이는 장면으로 끝나기 쉽다.
**구체적 수정안** → 18장은 **관련성 소개용으로는 적합하지만 이해 평가용으로는 부적합하다.** 전체 코드는 배경으로 두고 `model = load_model(...)`, `prediction = model.predict(data)`, `print(...)` 세 줄에 한정해 “부르는 부분 / 결과에 붙인 이름 / 화면 출력”을 찾게 하라. `...`는 생략 표시임을 밝히고 실행용 코드와 구분하라.

### 24) 슬라이드 실행기에서 AI 코드를 실행할 수 있다고 오해할 여지가 있다

**원문 인용** → “오늘 배우는 모든 것은 이 창에서 바로 확인할 수 있습니다.” / “18장: Teachable Machine 내보내기 Keras 예제 코드”
**무엇이 문제인가** → 같은 실행기 흐름에서 이 코드를 제시하지만 필요한 패키지·모델 파일·라벨 파일·이미지 경로가 준비됐다는 정보는 없다. 학생이 실행했을 때 환경 오류가 나면, 오늘 배운 따옴표·괄호·들여쓰기 문제로 잘못 진단할 수 있다. 실제 실행 성공 여부는 제공 자료만으로 확정할 수 없다.
**구체적 수정안** → 18장에 “읽기 전용 예시: 실행에는 별도 환경과 파일이 필요함”을 표시하라. 실행 가능한 시연으로 운영하려면 필요한 환경과 파일을 따로 준비하고, 이 수업의 오류 수정 과제와 분리하라.

## 치명적 3가지

1. **자동 점검 통과와 학습 목표 달성이 분리돼 있다.** 변수 미사용, 정답 출력으로 대체, 매개변수를 무시한 함수가 통과한다. 학생과 교사 모두 잘못된 완료 신호를 받는다.
2. **함수 이해를 연결하고 확인하는 필수 과제가 없다.** 반환값은 고립되고, 정의·매개변수 실습은 선택이다. 목표를 가르쳤다는 기록은 있어도 학생이 이해했다는 증거가 부족하다.
3. **복합 디버깅 과제의 안내가 실제 오류 발생 방식과 어긋난다.** 오류 네 종류와 수정 위치를 혼동하고, 구문 분석과 실행 중 오류를 구분하지 않아 첫 디버깅 경험을 무작위 수정으로 만들 위험이 크다.
