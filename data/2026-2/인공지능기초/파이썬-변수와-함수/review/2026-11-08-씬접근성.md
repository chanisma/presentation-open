첨부된 최종 화면을 기준으로 검토했다. 실행 전 출력·변수 상자가 비어 있는 것은 결함으로 보지 않았다. 다만 실행 전 안내 문구가 실제 출력처럼 보이는지, 시연 전에 학생이 무엇을 예측할 수 있는지는 검토했다. 1·5·13장의 움직임 자체는 정지 화면으로 확인할 수 없으므로, 마지막 화면에 남는 의미를 기준으로 판단했다.

## 1. 오해

- **(s01-0-c0.jpg)** → 제목은 “이름으로 기억하고, 이름으로 부른다”인데 화면에는 변수 이름만 있어, 처음 보는 학생은 변수와 함수가 같은 방식으로 쓰인다고 생각할 수 있다. → 제목 아래에 **“값을 찾을 때는 변수 이름 / 일을 시킬 때는 함수 이름()”**을 구분해 둔다. 표지에서 설명하지 않을 계획이라면 이 구분은 19장에서 반드시 회수한다.

- **(s02-0-c3.jpg)** → “블록 한 줄이 코드 한 줄이 된다”와 `print("앞으로")`의 조합은 **이 코드가 캐릭터를 앞으로 움직인다**는 오해를 만든다. 화면 아래의 “설명을 위해 단순하게 바꾼 줄”은 작고, 무엇을 단순화했는지도 불분명하다. → 제목을 **“블록으로 내리던 명령을 이제 글자로 쓴다”**로 바꾸고, 코드 바로 옆에 **“여기서는 이동 대신 명령 이름을 화면에 출력한다”**를 명시한다.

- **(s03-0-c0.jpg)** → 오른쪽의 `[▶ 실행]을 누르면…`이 코드 출력과 비슷한 고정폭 글자로 표시되어, 실행 전에도 이미 출력이 있다고 생각할 수 있다. → 빈 출력 영역에는 작은 안내 아이콘과 일반 본문 글씨로 **“아직 실행하지 않았습니다”**를 표시하고, 실행 결과와 시각적으로 구분한다.

- **(s04-0-c3.jpg)** → 오른쪽의 `print(…name…야.)` 같은 축약 표현은 실제 파이썬 문법처럼 보인다. 텍스트 코딩 입문자는 그대로 따라 쓸 가능성이 높다. → 실행 가능한 `print(f"안녕, 나는 {name}야.")`를 사용하고 바뀌는 부분만 테두리로 표시한다. 문법을 아직 소개하지 않으려면 코드 상자 밖의 문장 도식으로 표현한다.

- **(s05-0-c0.jpg, s06-0-c2.jpg)** → 이름표가 값에 묶이고 옮겨 다니는 비유는 대입 설명에 유용하지만, **값 자체가 변하거나 이름표 하나만 붙을 수 있다**고 받아들일 여지가 있다. → “이름이 가리키는 값이 바뀐다”로 표현을 통일한다. `score = score + 5`에서는 기존 `10`을 `15`로 고쳐 쓰기보다, 새 값 `15`로 연결이 바뀌는 모습을 보여 준다. 여러 이름이 같은 값을 가리키는 내용은 지금 추가하지 않아도 된다.

- **(s06-0-c2.jpg)** → “=는 같다가 아니다”만 기억하면 모든 프로그래밍 상황에서 등호가 비교와 무관하다고 일반화할 수 있다. → **“이 코드에서 `=`는 대입: 오른쪽 결과를 왼쪽 이름에 연결한다”**로 범위를 분명히 한다. `==` 설명까지 한꺼번에 추가할 필요는 없다.

- **(s08-0-c0.jpg)** → “글자는 따옴표, 숫자는 그대로”는 **`"17"`도 문자열이고, 따옴표 없는 `name`은 이름**이라는 핵심을 놓친다. 한글 이름도 실제로 쓸 수 있어 “민지는 따옴표가 없어서 무조건 잘못”이라고 외우는 것도 부정확하다. → `"17"` → 문자열, `17` → 숫자, `name` → 이름으로 연결된 값의 세 사례를 나란히 보여 준다.

- **(s10-0-c3.jpg)** → 주문서의 `(샷 추가)`는 선택 사항처럼 보이므로, 코드의 괄호도 필요할 때만 붙이는 장식으로 오해할 수 있다. → **“괄호는 호출 표시, 괄호 안은 건네는 값”**을 분리해 표시하고 `print()`처럼 인자가 없어도 괄호가 남는 예를 덧붙인다.

- **(s11-0-c0.jpg)** → 예측해야 할 2·3번 줄은 가려져 있지만 오른쪽 카드에 같은 코드가 보인다. 학생은 “가린 줄 보기”가 무엇을 공개하는지, 답을 어디에 예측해야 하는지 혼란스러울 수 있다. → 오른쪽 두 코드를 예측 문제로 명확하게 제시하고, 버튼은 **“코드 확인”**, 실행은 **“예측 확인”** 역할로 구분한다. 두 곳의 중복 코드 중 하나는 없애도 된다.

- **(s13-0-c0.jpg)** → `n = len("인공지능")`이 있지만 마지막 장면은 기계의 `4`와 값 카드 `4`만 강조한다. **반환값이 자동으로 화면에 출력된다**고 생각하기 쉽고, `n`에 연결되는 과정은 남지 않는다. → 마지막 상태에 `n` 이름표를 `4` 카드에 연결하고 **“반환: 계산한 값을 코드로 돌려준다 / 출력: 화면에 보여 준다”**를 구분한다.

- **(s14-0-c0.jpg)** → 정의와 두 번의 호출이 한꺼번에 있어, 위에서 아래로 읽는 초보자는 **정의할 때도 본문이 실행되고 호출할 때 또 실행된다**고 예측할 수 있다. → `def` 부분만 먼저 실행해 출력이 없음을 확인한 뒤, 첫 `cheer()`에서 본문으로 이동하는 순서를 보여 준다.

- **(s15-0-c0.jpg)** → 위쪽 화살표가 `greet("민지") → def greet(name)`으로 향해 **호출하면 함수를 정의한다**는 의미로 읽힐 수 있다. → 화살표를 `"민지"`에서 `name`으로만 연결하고 **“호출할 때 이 값이 이 이름에 연결된다”**고 쓴다. 다음 호출에서는 `"서연"`으로 바뀌는 것을 확인한다.

- **(s18-0-c3.jpg)** → “괄호가 붙으면 함수 호출”은 `shape=(1, 224, 224, 3)` 같은 괄호까지 함수로 분류하게 만든다. 밑줄 친 `convert`, `fit`, `predict` 등은 앞서 배운 단순한 `이름()`보다 형태도 복잡하다. → **“오늘 배운 호출 모양 찾기: `print(...)`”**부터 시작한다. 점 뒤의 호출은 “이런 모양으로도 부른다” 정도로만 표시하고, 모든 괄호를 호출로 판정하게 하지 않는다.

## 2. 가독성

실제 투사 크기와 조명에 따라 달라지지만, 첨부 화면에서 이미 작은 글씨는 교실 뒤에서 읽기 어렵다.

- **(s01-0-c0.jpg, s02-0-c3.jpg, s05-0-c0.jpg, s09-0-c3.jpg, s10-0-c3.jpg, s19-0-c0.jpg)** → 핵심 제목은 크지만 하단 정의·주의·보충 문구는 훨씬 작다. 학생에게 필요한 조건이 작은 글씨에 숨어 있다. → 수업 중 읽어야 하는 문장은 본문 크기로 올리고, 읽지 않아도 되는 보충 설명은 발표자 노트로 옮긴다.

- **(s04-0-c3.jpg)** → 오른쪽 코드의 출력문이 흐려서, 변수를 쓰는 코드가 어떻게 생겼는지 비교할 수 없다. → `name`만 강조하더라도 나머지 문법은 충분히 읽히게 유지한다. 두 코드의 글자 크기도 맞춘다.

- **(s06-0-c2.jpg)** → 강조 줄의 어두운 배경은 주변과 차이가 작고, 왼쪽 공책의 작은 설명은 멀리서 읽기 어렵다. → 실행 중인 줄에는 **왼쪽 화살표와 “지금 계산” 라벨**을 붙인다. 공책의 작은 설명은 큰 한 문장으로 바꾼다.

- **(s07-0-c0.jpg, s08-0-c0.jpg, s11-0-c0.jpg, s15-0-c0.jpg)** → 코드 아래 빈 공간은 넓은데 코드와 실행 버튼 글씨는 작다. 프로젝터에서는 들여쓰기, 따옴표, 괄호처럼 중요한 작은 기호부터 놓친다. → 편집기 글자와 줄 간격을 키우고, 시연용 버튼도 확대한다. 코드 공간을 채우기 위해 줄을 늘릴 필요는 없다.

- **(s09-0-c3.jpg)** → 오른쪽 규칙 목록과 키워드 예시, 아래 관례 설명까지 크기가 작다. 왼쪽 판정과 오른쪽 규칙을 오가며 읽기도 어렵다. → 후보 옆에 해당 규칙을 직접 붙이고, 오른쪽에는 결론 두세 줄만 남긴다.

- **(s11-0-c0.jpg, s12-0-c0.jpg)** → 예측 카드와 출력 비교 영역이 흐리게 처리되어 있다. 아직 공개하지 않는 정보와 단순히 대비가 낮은 정보의 경계가 불분명하다. → 공개 전에는 **“실행 후 공개”**라는 선명한 덮개를 사용한다. 읽게 할 텍스트는 흐리게 두지 않는다.

- **(s16-0-c4.jpg)** → 네 코드와 긴 영문 오류, 한국어 풀이를 한 화면에서 읽어야 한다. 특히 연한 붉은 배경의 붉은 오류 글씨는 작은 크기와 겹쳐 읽기 어렵다. → 오류 종류와 문제 위치를 크게 보여 주고, 영문 원문은 선택적으로 펼친다. 원문을 유지한다면 짙은 글자색을 쓴다.

- **(s17-0-c0.jpg)** → 활동지 화면 안의 설명은 투사 화면에서 읽기 어렵다. QR을 읽지 못하는 학생에게 밑줄 친 “활동지 열기”는 주소가 보이지 않아 접근 경로가 되지 않는다. → 실제 짧은 주소를 큰 글씨로 제공하고, 활동지 화면은 입력할 위치만 확대한다.

- **(s18-0-c3.jpg)** → 19줄의 긴 코드, 작은 글자, 많은 강조가 겹쳐 가장 읽기 어렵다. 밑줄과 배경 강조가 따옴표·밑줄 문자와도 경쟁한다. → 수업에서 찾을 3~5줄을 크게 발췌하고, 전체 코드는 활동지로 제공한다.

## 3. 색 의존

- **(s01-0-c0.jpg, s05-0-c0.jpg)** → 이름표와 값은 모양·텍스트로도 구분되고, HP에는 숫자가 있어 주요 의미가 색에만 의존하지 않는다. **이 부분은 뚜렷한 색 의존 문제가 없다.** 다만 HP 막대가 움직일 때도 숫자가 함께 바뀌어야 한다.

- **(s03-0-c0.jpg, s07-0-c0.jpg, s08-0-c0.jpg, s11-0-c0.jpg, s12-0-c0.jpg, s14-0-c0.jpg, s15-0-c0.jpg)** → 코드 색칠 자체보다 **색칠이 따옴표·이름·함수를 알아보는 유일한 단서가 되는 것**이 문제다. 저시력 학생은 작은 기호를 놓치고 색 덩어리로만 기억할 수 있다. → 첫 등장에 `"민지"`에는 “문자열”, `name`에는 “변수 이름”, `print(...)`에는 “함수 호출”이라는 바깥 라벨을 붙인다. 이후에는 문법 기호로 판단하게 한다.

- **(s06-0-c2.jpg, s07-0-c0.jpg, s15-0-c0.jpg)** → 현재 실행 줄을 배경색 변화만으로 표시하면 색각 차이와 투사 환경에서 놓칠 수 있다. → 줄 번호 옆의 `▶`와 **“실행한 줄”** 표시를 함께 사용한다.

- **(s09-0-c3.jpg)** → 후보 판정에는 “통과/불가”와 이유가 있어 색 이외의 단서가 충분하다. **판정 자체의 색 의존 문제는 크지 않다.** 다만 아래 `a`와 `math_score` 비교는 회색·초록 테두리로 좋고 나쁨을 암시한다. → 각각 **“뜻을 알기 어려움 / 점수라는 뜻이 보임”**을 붙인다.

- **(s14-0-c0.jpg)** → 블록 그림의 자홍·파랑 테두리와 설명의 작은 색 사각형을 대응해야 한다. 색 차이를 못 보면 어느 영역의 설명인지 찾기 어렵다. → 그림 영역에 **A: 함수 안의 명령 / B: 함수 호출**을 직접 표시하고 설명에서도 같은 문자를 쓴다.

- **(s18-0-c3.jpg)** → 변수의 자홍 배경, 호출의 파란 밑줄, 신뢰도의 노란 테두리는 서로 다른 강조 방식을 쓰지만, 한 코드에 겹쳐 있어 범주를 추적하기 어렵다. → 한 번에 한 범주만 표시하고 **“변수 찾기 ①”**, **“호출 찾기 ②”**처럼 과제를 붙인다. `confidence_score`는 별도 범주보다 변수의 한 예로 다룬다.

## 4. 정보량 — 잘라야 할 것

- **(s02-0-c3.jpg)** → 지난 시간 회상, 블록과 코드 대응, `print`, 파이썬·코드·실행의 정의, 변수·함수 정의까지 한 장에서 시작한다. → 이 장에는 **“이제 글자로 명령을 쓴다”와 오늘의 두 단어**만 남긴다. “실행”은 3장의 실제 행동으로 설명한다.

- **(s09-0-c3.jpg)** → 네 후보, 네 규칙, 키워드 설명, 대소문자, 한글 이름, 좋은 이름 관례가 한꺼번에 나온다. → 먼저 네 후보를 판정하고, **대소문자와 좋은 이름 관례는 별도 짧은 확인 문제**로 넘긴다.

## 학생에게 가장 위험한 오해 3가지

1. **`print("앞으로")`가 실제 이동 명령이라는 오해 — s02**  
   블록과 코드의 대응을 처음 배우는 지점이라 이후의 “출력” 개념까지 흔들린다. 이동과 출력이 다르다는 문구를 코드 바로 옆에 둬야 한다.

2. **함수는 정의할 때 실행되고, 반환값은 자동으로 화면에 나온다는 오해 — s13·s14**  
   **정의, 호출, 반환, 출력**의 역할이 섞이는 문제다. 정의만 실행했을 때 출력이 없는 장면과, 반환값을 변수에 연결한 뒤 `print`로 출력하는 장면을 구분해야 한다.

3. **따옴표가 없으면 숫자이고, 글자는 반드시 따옴표를 붙여야 한다는 오해 — s08·s11**  
   `name`을 문자열 `"name"`으로 바꿔 쓰게 만드는 직접적인 원인이다. **`"17"`은 문자열 / `17`은 숫자 / `name`은 값을 찾는 이름**이라는 세 갈래를 명시해야 한다.
