정지 화면에서 확인되는 전달력과 구도를 기준으로 평가했다. 실행 전의 빈 출력 영역과 11장의 가림 처리는 의도된 수업 상태로 보며, 결함으로 감점하지 않았다. 시간으로 움직이는 1·5·13장은 마지막 화면의 완결성만 평가했다. 하단 재생 도구는 덱 외부 UI로 보고 제외했다.

### 1장 — 제목과 상태창은 읽히지만, ‘이름은 그대로’라는 핵심은 작은 주석에 맡겼다 (8/10)
- 읽히는가: ‘변수·함수 입문’과 게임 상태창은 즉시 읽힌다. 값이 바뀌어도 이름이 유지된다는 관계는 정지 화면만으로 확정하기 어렵다.
- 문제점: `s01-0-c0.jpg` → 제목의 자홍색 ‘부른다’가 강해서 변수보다 함수 호출이 먼저 강조된다 → 상태창에서 고정된 이름표와 변하는 값의 대비를 더 키우고, ‘이름은 그대로, 값만 바뀐다’를 상태창 바로 아래에서 읽을 수 있는 크기로 올린다.

### 2장 — 블록에서 코드로 넘어가는 방향은 명확하나, 대응 관계는 약하다 (8/10)
- 읽히는가: 왼쪽 블록 → 오른쪽 코드의 변환은 3초 안에 읽힌다.
- 문제점: `s02-0-c3.jpg` → 블록에는 ①②③ 표시가 있지만 코드에는 대응 표시가 없어 어느 블록이 어느 줄인지 다시 찾아야 한다 → 코드 세 줄에도 같은 번호를 붙인다.
- 문제점: `s02-0-c3.jpg` → 용어 칩 세 개와 하단 ‘오늘의 두 단어’가 별도 층을 만들어 시선이 네 구역으로 나뉜다 → 용어 칩을 변환 그림의 짧은 캡션으로 붙이고, 하단은 변수·함수 두 단어만 남긴다.

### 3장 — 행동 순서는 선명하고, 상단 설명만 시선을 분산시킨다 (9/10)
- 읽히는가: ① 입력 → ② 실행 → ③ 출력의 동선이 바로 보인다. 실행기 자체가 주인공이다.
- 문제점: `s03-0-c0.jpg` → 상단 오른쪽의 긴 설명이 제목과 경쟁하며, 첫 실습에 앞서 읽어야 할 문장처럼 보인다 → `print()` 설명을 한 문장으로 줄여 입력 영역 가까이에 두고, ‘10장에서’ 같은 진행 안내는 발표자 노트로 옮긴다.
- 문제점: 그 외 뚜렷한 잘림이나 겹침은 없다.

### 4장 — ‘세 군데 대 한 군데’는 강하지만, 오른쪽 코드가 비교 증거로 약하다 (8/10)
- 읽히는가: 수정 횟수 3 대 1은 즉시 읽힌다.
- 문제점: `s04-0-c3.jpg` → 변수 사용 코드가 흐리고 일부만 드러나, 왼쪽의 완전한 코드와 대등하게 비교하기 어렵다 → 오른쪽도 문법적으로 완전한 코드를 선명하게 제시하고 `name`만 자홍색으로 표시한다.
- 문제점: `s04-0-c3.jpg` → 두 코드 상자의 높이와 하단 설명 위치가 달라 비교 기준선이 흔들린다 → 첫 줄과 하단 요약 카드의 기준선을 맞춘다. 비교 장에서는 정렬이 의미를 강화한다.

### 5장 — 이름표 메타포는 전달되지만, 서로 다른 끈 길이가 불필요한 의미를 만든다 (8/10)
- 읽히는가: 이름표가 값에 연결된다는 관계는 설명 없이 읽힌다.
- 문제점: `s05-0-c0.jpg` → `name`은 값 가까이에, `age`는 멀리 떨어져 긴 곡선으로 연결돼 두 관계가 다른 종류처럼 보인다 → 마지막 상태에서는 두 이름표를 각 값 카드 왼쪽의 비슷한 거리에 정착시킨다. 이동의 차이는 애니메이션 과정에 남긴다.
- 문제점: `s05-0-c0.jpg` → 위 코드와 아래 연결 그림 사이에 넓은 단절이 있다 → 코드 두 개를 각 이름표·값 관계 가까이 배치해 코드와 비유를 직접 대응시킨다.

### 6장 — 대입의 처리 순서가 가장 명확하게 조직된 장이다 (9/10)
- 읽히는가: 수학적 의문 → 코드 → 오른쪽 계산 → 이름 갱신의 순서가 읽힌다.
- 문제점: `s06-0-c2.jpg` → 오른쪽 아래의 `score → 15`는 앞서 설명한 ‘값에 이름표를 붙인다’보다 이름에서 값으로 이동한다는 인상을 준다 → `score` 이름표가 15 카드에 붙은 작은 그림으로 바꿔 앞 장의 메타포를 유지한다.
- 문제점: 그 외 주인공과 보조 정보의 위계에는 큰 문제가 없다.

### 7장 — 상태창 연계는 유효하지만, 실행기 장의 반복을 끊을 정도는 아니다 (8/10)
- 읽히는가: `hp`가 실행에 따라 변한다는 실습 목적은 보인다.
- 문제점: `s07-0-c0.jpg` → 상태창이 작고 좌상단에 떨어져 있어 실행기와 별개의 삽화처럼 보인다 → 상태창을 오른쪽 변수 상자 위에 붙이거나, 변수 상자의 대표 표시로 통합한다.
- 문제점: `s07-0-c0.jpg` → 하단 코드 전환 버튼과 사용 설명이 좁은 띠에 몰린다 → 코드 전환 버튼은 실행기 도구줄로 옮기고, 하단에는 ‘다음 줄마다 값이 바뀐다’는 안내만 둔다.

### 8장 — 따옴표 비교보다 실행기 면적이 먼저 보인다 (7/10)
- 읽히는가: 문자열과 숫자의 구분은 읽힌다. 제목의 핵심인 ‘따옴표가 뜻을 바꾼다’는 직접 비교가 부족하다.
- 문제점: `s08-0-c0.jpg` → `"민지"`와 `17`은 내용까지 달라 따옴표 효과만 분리해 보여주지 못한다 → 오른쪽 비교를 `"17"`과 `17`로 바꾸고, 따옴표 없는 `name`은 별도 짧은 예로 구분한다.
- 문제점: `s08-0-c0.jpg` → 11장과 같은 ‘왼쪽 실행기·오른쪽 설명 카드’ 구도로 수렴한다 → 이 장은 따옴표 비교를 상단의 큰 시각 요소로, 실행기를 하단의 검증 도구로 배치한다.

### 9장 — 판정은 빠르지만, 네 줄 나열과 규칙 목록이 중복된다 (8/10)
- 읽히는가: 후보별 통과·불가와 이유가 바로 보인다.
- 문제점: `s09-0-c3.jpg` → 왼쪽 네 후보와 오른쪽 규칙 목록이 같은 내용을 반복해 훑을 양이 많다 → 후보 옆 이유를 중심으로 두고, 오른쪽에는 후보에서 드러나지 않는 대소문자 규칙과 권장 관례만 남긴다.
- 문제점: `s09-0-c3.jpg` → 이름표 위의 긴 갈색 선은 연결이나 지지 기능이 보이지 않는다 → 제거한다. 이름표 자체의 끈으로 메타포는 충분하다.

### 10장 — 호출 구문은 잘 해부했지만, 카페 비유가 정확히 맞물리지 않는다 (7/10)
- 읽히는가: 함수 이름·괄호·인자의 구분은 즉시 읽힌다.
- 문제점: `s10-0-c3.jpg` → ‘아이스 아메리카노’와 ‘샷 추가’가 `print`와 `"안녕"`에 연결되지만, 함수가 하는 일과 전달하는 값의 관계를 명확히 대응시키지 못한다 → 주문 예를 ‘말하기(“안녕”)’처럼 동작·전달값이 맞는 비유로 바꾸거나, 카페 비유를 빼고 코드 해부를 주인공으로 삼는다.
- 문제점: `s10-0-c3.jpg` → 점선이 코드 상자 위에서 끝나 정확한 토큰까지 연결되지 않는다 → 각 점선을 해당 토큰의 위쪽 가장자리까지 연결하고, 아래 구문 라벨과 수평 위치를 맞춘다.

### 11장 — 예측 장치는 적절하지만, 공개 전 화면을 지나치게 흐리게 만들었다 (8/10)
- 읽히는가: 두 표현의 결과를 예측하는 장이라는 것은 읽힌다.
- 문제점: `s11-0-c0.jpg` → 오른쪽 비교 카드의 질문까지 옅어서 학생이 무엇을 예측해야 하는지 힘이 빠진다 → `print(name)`과 `print("name")`, 물음표는 선명하게 유지하고 실제 정답만 숨긴다.
- 문제점: `s11-0-c0.jpg` → 8장과 거의 같은 실루엣이다 → 두 예측 카드를 실행기 위에 나란히 크게 두고, 아래 실행기로 확인하는 순서로 바꾼다.

### 12장 — 두 출력 방식의 차이를 보여줘야 하는데, 최종 화면의 하단이 비어 보인다 (7/10)
- 읽히는가: 쉼표와 f-문자열을 함께 배운다는 것은 보인다. 두 방식의 출력 차이는 실행 전에는 읽히지 않는다.
- 문제점: `s12-0-c0.jpg` → 하단 ‘출력을 크게 보면’ 영역이 넓은 빈 카드처럼 남아 화면의 무게를 떨어뜨린다 → 실행 전에는 해당 영역을 접고, 실행 후 결과가 생길 때 펼친다.
- 문제점: `s12-0-c0.jpg` → 두 코드 줄이 같은 강조를 받아 공백 차이와 `{food}`의 역할이 묻힌다 → 쉼표 방식의 자동 공백과 f-문자열의 삽입 위치에 각각 작은 표시를 붙인다.

### 13장 — 기계가 숫자를 만든다는 인상은 있으나, 입력과 대입이 화면에서 빠졌다 (6/10)
- 읽히는가: `len`이 4를 돌려준다는 것은 읽힌다. `"인공지능"`이 들어가서 나온 값이라는 인과는 약하다.
- 문제점: `s13-0-c0.jpg` → 마지막 상태에서 입력 문자열이 투입구에 없고, 기계와 결과 카드 사이도 크게 비어 있다 → 투입구 위에 작은 `"인공지능"` 잔상을 남기고, 출력구 바로 옆에 4 카드를 정착시킨다.
- 문제점: `s13-0-c0.jpg` → 코드에는 `n =`이 있지만 결과 카드에는 `n` 이름표가 없어 앞서 만든 변수 메타포가 끊긴다 → 반환된 4 카드에 `n` 이름표가 붙는 상태까지 마무리한다.

### 14장 — 블록 묶음과 함수 정의의 대응이 설명문에 의존한다 (7/10)
- 읽히는가: 블록 코딩 경험을 `def`와 연결하려는 의도는 보인다. 어떤 부분끼리 대응하는지는 읽어야 안다.
- 문제점: `s14-0-c0.jpg` → 왼쪽 F1 묶음의 자홍 테두리가 오른쪽 함수 본문으로 이어지지 않는다 → 들여쓴 두 줄에도 같은 자홍 괄호를 붙여 ‘묶인 일’을 대응시킨다.
- 문제점: `s14-0-c0.jpg` → 프로그램 안 F1과 `cheer()` 호출의 연결도 범례에만 있다 → 두 `cheer()` 호출에 파란 표시를 붙여 왼쪽 F1 호출과 직접 대응시킨다. 설명 카드의 글은 줄인다.

### 15장 — 매개변수의 정의는 있으나, ‘값을 받는 순간’이 작다 (7/10)
- 읽히는가: 인자와 매개변수의 구분은 상단 도식에서 읽힌다.
- 문제점: `s15-0-c0.jpg` → 핵심인 `"민지" → name` 전달이 작은 상단 띠에 갇혀 있고, 화면 대부분은 앞 장들과 같은 실행기다 → 전달 도식을 제목 아래 크게 확장하고, `"민지"`와 `"서연"`이 같은 `name` 자리에 들어가는 두 상태를 보여준다.
- 문제점: `s15-0-c0.jpg` → 위 도식의 `def greet(name)`에는 코드 본문의 콜론이 없다 → `def greet(name):`로 통일한다. 초보자용 문법 장에서는 도식과 코드 표기를 맞춘다.

### 16장 — 진단표로는 명료하지만, 오류 네 개가 같은 무게로 늘어서 있다 (8/10)
- 읽히는가: 잘못된 코드 → 오류 메시지 → 뜻의 가로 읽기는 명확하다.

- 문제점: `s16-0-c4.jpg` → 네 행이 반복되고 하단 설명까지 있어 한 번에 제시하면 과밀하다 → 수업 중에는 행별 공개로 진행하고, 이 전체 화면은 마지막 참고표로 사용한다. 비교표 자체를 억지로 비대칭화할 필요는 없다.

### 17장 — 활동 접속과 과제 목록이 경쟁한다 (7/10)

### 18장 — 실제 AI 코드로 연결되지만, 강조가 많아 찾기의 초점이 흐려진다 (7/10)

### 19장 — 한 줄 요약은 강하지만, 상태창 회수는 장식 수준에 머문다 (8/10)
- 읽히는가: `n = len(name)`에서 변수와 함수를 함께 정리한다는 것은 즉시 읽힌다.
- 문제점: `s19-0-c0.jpg` → 작은 상태창의 `nickname`과 중앙 코드의 `name`이 달라 도입 장면과 한 줄 코드가 직접 연결되지 않는다 → 상태창 이름을 `name`으로 통일하고, 그 값 `"민지"`가 `len(name)`의 입력임을 짧게 연결한다.
- 문제점: `s19-0-c0.jpg` → 변수 설명은 `n`만 가리켜 인자로 쓰인 `name`도 변수라는 사실을 놓친다 → `n`과 `name`을 같은 자홍 계열로 표시하고, `len`만 함수 색으로 분리한다.
