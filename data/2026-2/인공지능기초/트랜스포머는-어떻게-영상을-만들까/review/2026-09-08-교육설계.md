현재 자료로는 **100분 안에 전원 4컷 제출을 달성한다는 근거가 부족하며, 개념을 정확히 이해한 학생이 S8에서 오답 처리될 수 있습니다.** 시간 합계 자체는 맞습니다. 문제는 빠진 작업과 잘못 묶은 개념입니다.

아래는 제공된 문구에 대한 심사입니다. 모형의 실제 클릭 동작·가중치 전체·활동지 저장 기능은 실행 검증하지 않았으므로, 문구상 결함과 구현 확인이 필요한 사항을 구분했습니다. 파일은 수정하지 않았습니다.

**시간 배분과 실습 성립 조건**

1. **100분 합계는 맞지만, 구간 표시와 여유 시간이 맞지 않는다.**  
   **원문 인용 →** S3: “1부 원리 · 50분”, “2부 실습 · 45분”; 계획: “S11 한 기계 3분”.  
   **문제 →** 실제 합계는 S1~S11 **51분**, 휴식 5분, S12~S17 **44분**으로 총 100분이다. 산술 초과는 없다. 다만 전환·접속·질문 시간이 별도로 없고, 설명이 3분만 늘어도 실습이나 출구 평가를 깎아야 한다.  
   **구체적 수정안 →** 표시를 51·5·44분으로 맞추고, 원리 설명에서 3분을 줄여 복구 시간으로 명시한다. S14의 로그인 2분이 설명 시간에 포함되는지, 학생이 실제 로그인하는 시간인지도 확정한다.

2. **이미지 4장의 출처와 준비 시간이 통째로 빠져 있다.**  
   **원문 인용 →** S13: “① 같은 스타일의 이미지 4장”; 활동지: “4장의 이미지를 만들 때 매번 똑같이 쓸 묘사”; S15: “설계 4분 / 생성 … 14분”.  
   **문제 →** 앞 수업에서 이미지를 배웠다는 사실은 학생에게 연결 가능한 이미지 4장이 있다는 뜻이 아니다. 직접 생성한다면 이미지 프롬프트 작성·생성·선별·저장부터 해야 한다. 검색하거나 이전 작품을 쓴다는 해석도 가능하다. **영상 생성 버튼을 누르기 전에 일정이 무너진다.**  
   **구체적 수정안 →** 26분을 유지하려면 교사가 동일 인물·화풍·화면비의 이미지 4장 세트를 미리 배포한다. 직접 이미지 제작까지 목표라면 별도 사전 활동으로 배정하고, 수업 시작 전 파일 확보를 확인한다.

3. **‘4장 준비’와 ‘끝 프레임으로 다음 컷 만들기’는 서로 다른 제작 경로다.**  
   **원문 인용 →** S13: “① 같은 스타일의 이미지 4장”, “② 끝 장면 → 다음 첫 이미지”, “앞 클립의 마지막 프레임을 캡처해 다음 컷의 이미지로”.  
   **문제 →** 번호 때문에 둘 다 필수로 읽힌다. 그러나 후자를 따르면 미리 준비한 2~4번 이미지를 대체하게 된다. 더 치명적인 것은 **생성 1 → 캡처 → 생성 2 → 캡처 → 생성 3 → 캡처 → 생성 4**라는 순차 의존성이다. 다음 프롬프트를 써도 다음 생성은 시작할 수 없다.  
   **구체적 수정안 →** 기본 경로는 “제공 이미지 4장을 각각 영상화”로 고정하고, 마지막 프레임 연결은 시간 여유가 있는 심화 활동으로 분리한다. 두 경로를 동시에 필수로 제시하지 않는다.

4. **영상 생성 14분은 대기 시간의 조건을 제시하지 않은 목표치다.**  
   **원문 인용 →** S14: “14분 · 대기 중 다음 프롬프트”; S15: “생성 … 14분”.  
   **문제 →** 순차 생성이라면 업로드·설정·대기·확인·캡처까지 **회당 평균 3.5분 이하**여야 한다. 대기만 회당 3분이라는 가정에서도 12분이 소모돼 나머지 작업 전체에 2분만 남는다. 이는 설명용 가정이며 실제 대기 시간 측정치는 아니다. 공식 안내의 “몇 분”도 학급 동시 요청의 완료 시간을 보장하지 않는다. [미리캔버스 공식 안내](https://www.miricanvas.com/ko/features/video-generator)  
   **구체적 수정안 →** 실제 학생 계정·학교망으로 생성 4회를 예행하고, 동시 요청 가능 여부와 느린 사례까지 기록한다. S15 시작 18분 후에는 생성 대기를 종료하고 예비 클립으로 편집하도록 정한다. 예비 클립을 쓰면 ‘직접 4회 생성’ 목표를 달성한 것은 아니라는 점도 평가에 구분한다.

5. **편집 4분과 제출 4분에 숨겨진 작업이 너무 많다.**  
   **원문 인용 →** S14: “클립 4개를 순서대로 배치해 한 편으로”; S15: “공유·제출 4분”; 활동지: “장면 설명”, “입력한 프롬프트” 각각 4개.  
   **문제 →** 클립을 에디터로 가져오는 경로, 파일 구별, 화면비·길이 확인, 전체 재생이 빠져 있다. 제출에는 게시 설정, 링크 복사, 비로그인 열람 검사, 필수 입력 확인, 저장 성공 확인까지 있다. 설계 4분에 기획 3항목과 컷별 8항목까지 모두 완성한다고 보기도 어렵다.  
   **구체적 수정안 →** 4페이지 편집 템플릿과 파일명 규칙 `01~04`를 제공한다. S12~S13의 8분에 활동지 A·B 초안을 실제로 작성하게 하고, S15에는 실제 입력한 프롬프트만 갱신한다. 자막·음악·전환은 제출 후 선택 활동으로 둔다.

6. **무료 크레딧 지급과 4회 생성 가능은 다른 주장이다.**  
   **원문 인용 →** S14: “크레딧은 매일 무료 지급분 안에서 · 부족하면 짝과 나눠 생성”.  
   **문제 →** 공식 안내는 무료 크레딧 지급과 조건별 소모 차이를 설명하지만 학생 계정마다 4회 생성이 가능하다는 수치는 제시하지 않는다. 이미지 생성까지 하면 같은 예산을 더 쓸 수 있다. 짝도 부족하면 대안이 되지 않으며, 개인 과제가 갑자기 공동 과제로 바뀐다. [미리캔버스 공식 안내](https://www.miricanvas.com/ko/features/video-generator)  
   **구체적 수정안 →** 사용할 모델·길이·해상도를 고정하고 학생 계정의 잔여량으로 4회 가능 여부를 사전 확인한다. 짝 활동이면 처음부터 담당 컷, 파일 전달법, 공동 링크와 개인 제출 기준을 명시한다. 부족한 계정에는 예비 클립 경로를 제공한다.

7. **공유 지시는 실제 메뉴와 다르고, 짝의 기기도 검사 조건이 불명확하다.**  
   **원문 인용 →** S14: “공유 → 접근 권한 ‘링크가 있는 누구나’”; S15: “짝의 기기에서 링크가 열리는지”; 활동지: “짝의 기기(로그인하지 않은 상태)”.  
   **문제 →** 공식 도움말은 ‘공유’와 ‘게시’를 구분하며, 외부 링크 열람은 **게시 → 디자인 문서 공개**로 안내한다. 원칙 도해라는 단서는 정직하지만, 학생의 클릭 절차로는 불충분하다. 로그인한 짝이 열었다고 비로그인 공개가 검증되는 것도 아니다. [미리캔버스 공유 도움말](https://help.miricanvas.com/hc/ko/articles/360030161192)  
   **구체적 수정안 →** 수업 계정에서 확인한 메뉴명으로 S14와 활동지를 함께 고친다. “짝의 비공개 창에서 링크를 열어 로그인 요구 없이 4컷 전체가 재생되는지 확인”으로 통일하고, 최종 편집물의 링크인지도 검사한다.

8. **활동지 인증보다 제출 성공 판정이 더 불명확하다.**  
   **원문 인용 →** “학번은 학년(1) + 반(2) + 번호(2) 다섯 자리”, “제출 암호”, “TXT + 시트 저장”, `scriptUrl`의 `https://script.google.com/macros/s/.../exec`.  
   **문제 →** 학번 예시 `20317`은 올바르다. 다만 괄호 숫자가 자리 수라는 뜻은 설명해야 한다. 암호는 배부받는지 직접 정하는지 본문에서 즉시 드러나지 않는다. `scriptUrl`을 학생이 입력해야 하는지, TXT 저장만 되어도 제출인지, 시트 저장 실패를 어떻게 아는지도 문구로 확인되지 않는다. 구현 고장이라고 단정할 근거는 없다.  
   **구체적 수정안 →** “학년 1자리+반 2자리+번호 2자리”, “이번 활동용 암호를 직접 4자 이상 정하세요”로 쓴다. 서버 주소는 교사 설정으로 처리하고, “서버 접수 완료·학번·시간”을 제출 완료 기준으로 명시한다. TXT는 백업인지 대체 제출인지 별도로 정한다.

**개념 분류의 논리적 결함**

9. **자기·공간·시간·교차는 같은 수준의 네 종류가 아니다.**  
   **원문 인용 →** S8: “계산은 하나, 보는 범위가 네 갈래”, “자기 어텐션 / 공간 어텐션 / 시간 어텐션 / 교차 어텐션”.  
   **문제 →** 자기/교차는 주로 **Q와 K·V가 같은 입력 집합에서 오는가**의 구분이고, 공간/시간은 **참조 범위를 어떻게 제한하는가**의 구분이다. 영상의 공간·시간·전체 어텐션도 자기 어텐션일 수 있다. 지금 분류는 학생에게 ‘자기 어텐션은 글자 전용’이라는 오개념을 준다. [Transformer 원논문](https://arxiv.org/abs/1706.03762), [TimeSformer 논문](https://arxiv.org/abs/2102.05095)  
   **구체적 수정안 →** 먼저 “영상 조각끼리: 자기 어텐션 / 영상 조각이 텍스트 표현 참조: 교차 어텐션”으로 나눈다. 자기 어텐션 안에 이 모형의 공간·시간·전체 범위를 배치한다.

10. **‘글자는 앞만 본다’는 텍스트 일반의 성질이 아니다.**  
    **원문 인용 →** S7: “글자는 앞의 글자만 보지만”; S8: “자기 어텐션 — 글자 ↔ 글자”; 문항 해설: “글자용 가림막”.  
    **문제 →** 앞말만 참조하도록 제한하는 것은 인과적 마스크를 쓰는 생성 방식의 성질이다. BERT 같은 인코더는 좌우 문맥을 함께 참조한다. 일반적인 인과적 자기 어텐션에서도 현재 입력 위치 자신은 포함한다. [BERT 원논문](https://arxiv.org/abs/1810.04805)  
    **구체적 수정안 →** “지난 시간의 다음 말 생성 모델은 현재 위치까지의 토큰을 참고하고 뒤쪽 토큰은 가린다. 글을 이해하는 다른 모델은 앞뒤를 함께 볼 수 있다”로 고친다. ‘글자’ 대신 ‘텍스트 토큰’을 쓴다.

11. **전체 어텐션은 공간 어텐션과 시간 어텐션을 단순히 더한 것이 아니다.**  
    **원문 인용 →** 모형 FULL: “64조각 전부를 볼 수 있습니다(공간 + 시간을 한 번에).”  
    **문제 →** 이 모형에서 한 Q의 공간 범위는 16개, 시간 범위는 4개이며 자신이 겹치므로 합집합은 **19개**다. 전체의 64개에는 ‘다른 프레임의 다른 자리’가 추가된다. 공간·시간 계산을 차례로 수행하면 정보가 간접 전달될 수 있지만, 전체 64개에 한 번 소프트맥스를 적용한 것과 같은 계산은 아니다. [TimeSformer 공식 설명](https://ai.meta.com/blog/timesformer-a-new-architecture-for-video-understanding/)  
    **구체적 수정안 →** “공간: 같은 프레임 / 시간: 같은 자리의 여러 프레임 / 전체: 모든 프레임의 모든 자리”로 비교한다. 공간+시간은 ‘별도 계산을 조합하는 방식’, 전체는 ‘한 번에 함께 참조하는 방식’으로 구별한다.

12. **같은 자리의 시간 어텐션은 가능한 설계지만, 움직임 추적의 일반 정의가 아니다.**  
    **원문 인용 →** S8: “시간 어텐션 — 조각 ↔ 앞뒤 프레임의 같은 자리”; 모형: “움직임이 이어지는지 잇는 어텐션”.  
    **문제 →** 동일 좌표를 따라가는 시간 어텐션은 실제 설계에 존재하므로 그 자체가 오류는 아니다. 그러나 오른쪽으로 이동한 공은 다른 열에 있다. 이 범위만으로는 그 공 조각을 직접 볼 수 없다. 공간 계산과의 조합 또는 전체 범위 등으로 정보를 연결하는 설명이 빠졌다. [TimeSformer 논문](https://arxiv.org/abs/2102.05095)  
    **구체적 수정안 →** “이 모형의 시간 모드는 같은 자리를 비교하는 한 가지 설계다”라고 한정한다. 공이 옆 칸으로 이동한 사례에서 시간 모드로 직접 볼 수 없는 공을 찾고, 전체 모드와 비교하게 한다.

13. **시공간 패치 설명과 모형의 조각 단위가 이어지지 않는다.**  
    **원문 인용 →** S6: “가로 1 × 세로 1 × 시간 4”, “같은 자리의 프레임 4장을 한 덩어리”; 모형: “4프레임 × 4×4 조각”, 전체 “64조각”.  
    **문제 →** 같은 4×4 격자에서 시간 4장을 하나로 묶으면 조각은 16개가 된다. 모형은 프레임별 64개 조각을 사용하므로 시간 두께가 다른 예시다. 설명 없이 전환하면 학생은 ‘토큰 하나가 네 프레임인지, 한 프레임인지’부터 혼동한다. Sora의 설명도 원본 픽셀 블록을 그대로 자르는 것이 아니라 압축된 잠재 표현을 패치화하는 방식이다. [Sora 기술 보고서](https://openai.com/index/video-generation-models-as-world-simulators/)  
    **구체적 수정안 →** S6에 “실제 모델은 압축 표현을 자르기도 한다”, S7에 “범위 비교를 쉽게 하려고 여기서는 시간 두께 1인 조각을 사용한다”를 넣는다. “이미 알고 있습니다”는 “시간에 따른 변화 정보가 담길 수 있습니다”로 바꾼다.

14. **‘①만 바뀐다’는 자료 자체의 뒤 설명과 충돌한다.**  
    **원문 인용 →** S4: “①만 바뀐다. ②③④는 그대로다”; S11: “달라지는 것은 ①무엇을 자르는가와 ③누구를 볼 수 있는가뿐이다.”  
    **문제 →** 앞에서는 ③도 그대로라고 했다가 뒤에서는 달라진다고 한다. ② 역시 내용의 벡터 표현과 위치 정보가 필요하며 단순 좌표 붙이기만은 아니다. ④의 다음 토큰 선택과 연속값인 노이즈 예측은 같은 출력 작업이 아니다.  
    **구체적 수정안 →** 네 눈금을 “①조각으로 표현하기 ②내용·위치를 숫자로 나타내기 ③관련 정보를 모으기 ④목적에 맞는 값 예측하기”로 넓힌다. 핵심 문장은 “어텐션으로 정보를 모으는 원리를 공유하지만 입력 표현·참조 범위·출력은 달라진다”로 바꾼다.

15. **모형에서도 ‘마스크만 다르다’는 주장을 지키지 않는다.**  
    **원문 인용 →** S8: “다른 것은 허용 범위(마스크)뿐이다”; 모형의 같은 Q에서 SPACE는 `q = [1.40, …, −0.60, −0.60]`, TIME은 `q = [1.40, …, 0.95, 1.65]`, FULL은 `q = [1.40, …, 0.75, 1.30]`.  
    **문제 →** 모드 전환 시 허용 범위뿐 아니라 Q의 수치도 달라진다. 따라서 가중치 변화가 마스크 때문인지, 투영 방식 때문인지 분리해서 볼 수 없다. 교차 모드는 K·V의 출처까지 바뀐다.  
    **구체적 수정안 →** 공간·시간·전체의 범위 비교에서는 Q·K·V를 고정하고 마스크만 바꾼다. 현재 손설계를 유지한다면 “계산 형식은 같지만, 범위와 표현을 만드는 행렬도 달라질 수 있다”로 설명한다.

16. **계단 비유가 학습 순서와 기술 분류를 혼동시킨다.**  
    **원문 인용 →** S3·S16: “계단 1 · GAN / 계단 2 · 확산 모델 / 계단 ③ · 트랜스포머”; S9: “DiT = 확산 + 트랜스포머”.  
    **문제 →** 앞의 계단은 GAN→확산→트랜스포머라는 대체 관계처럼 보이지만, 뒤에서는 확산과 트랜스포머를 결합한다. 생성·학습 방식과 신경망 구조라는 서로 다른 축을 같은 발전 단계로 놓은 것이다. DiT는 이 구분이 필요한 대표 사례다. [DiT 원논문](https://arxiv.org/abs/2212.09748)  
    **구체적 수정안 →** 계단에는 “우리 수업에서 배우는 순서”라고 표시한다. S9에는 “만드는 방식: 확산 / 그 안에서 예측하는 신경망: 트랜스포머”라는 두 칸을 제시한다.

17. **모델이 할 수 있는 일을 보장되는 결과로 말한다.**  
    **원문 인용 →** S9: “블록을 한 덩어리로 걷어내니 프레임 사이가 튀지 않는다”; S16: “영상 생성 = 확산 + 트랜스포머(DiT), 음악 생성 = 코덱 토큰 + 다음 토큰 고르기.”  
    **문제 →** 영상 전체를 함께 처리해도 일관성 실패는 가능하다. Sora 공개 보고서도 시간적 일관성 등의 한계를 설명한다. 또한 특정 영상·음악 생성 방식의 예를 분야 전체의 등식으로 일반화한다. [Sora 기술 보고서](https://openai.com/index/video-generation-models-as-world-simulators/)  
    **구체적 수정안 →** “여러 프레임의 정보를 함께 참고해 일관성을 높이지만 실패할 수 있다”로 고친다. S16은 “오늘 살펴본 영상 생성 방식”, “MusicGen의 음악 생성 방식”으로 범위를 제한한다.

**문항의 타당성**

18. **S2는 ‘같다’의 수준을 정하지 않은 채 비유를 정답으로 만든다.**  
    **원문 인용 →** “같은 기계(트랜스포머)에 다른 조각을 넣는다”; S11: “S2 정답 공개”.  
    **문제 →** ‘같은 기계’를 동일한 모델·가중치·전체 구조로 읽으면 정답이 아니다. ‘공통 구조 원리’로 읽을 때만 의도에 맞는다. 나머지 선택지가 지나치게 극단적이라 공통점과 차이를 이해했는지도 확인하지 못한다.  
    **구체적 수정안 →** 정답을 “어텐션을 사용하는 트랜스포머 구조를 공유할 수 있지만, 입력 처리와 생성 방식은 다르다”로 바꾼다. 도입에서는 이유를 수집하고, 마지막에는 “공통점 하나와 차이점 하나”로 재응답하게 한다.

19. **S8은 교차 어텐션 답변에 정당한 반론이 성립한다.**  
    **원문 인용 →** “영상에서 ‘공이 오른쪽으로 굴러간다’를 맞추려면 어느 어텐션이 꼭 필요할까?”; 정답: “시간 어텐션”; 모형 CROSS: “오른쪽으로 굴러간다 0.41”.  
    **문제 →** ‘맞춘다’는 **프롬프트 방향을 따른다** 또는 **프레임 사이 움직임을 연결한다**로 읽힌다. 전자라면 교차 어텐션은 타당한 답이다. 모형도 그 문구에 높은 가중치를 준다. 더구나 같은 자리 시간 어텐션이 모든 영상 모델의 필수 모듈도 아니다. 해설에서 “둘은 함께 쓰이지만”이라고 인정해도 질문의 모호함은 해소되지 않는다.  
    **구체적 수정안 →** 두 문항으로 나눈다. “이 모형에서 영상 조각이 ‘오른쪽으로’라는 텍스트 표현을 참고하는 모드는?”는 교차, “같은 행·열의 여러 프레임만 참조하도록 제한한 모드는?”는 시간으로 묻는다. 기존 문항을 유지하면 근거 있는 복수 답을 허용해야 한다.

20. **S8의 오답 해설도 틀린 일반화를 강화한다.**  
    **원문 인용 →** “영상 조각은 뒤 프레임도 봐야 움직임을 압니다”; “같은 프레임 안에서는 … ‘어디로 가나’는 모릅니다.”  
    **문제 →** 미래 프레임을 반드시 봐야 움직임을 처리할 수 있는 것은 아니다. 한 프레임의 시각적 단서나 프롬프트로 방향을 추정하는 것과, 시간에 따른 실제 위치 변화를 비교하는 것도 구별해야 한다.  
    **구체적 수정안 →** “이 모형은 앞뒤 프레임을 함께 참조할 수 있다”, “실제로 위치가 어떻게 달라졌는지 비교하려면 여러 시점의 정보가 필요하다”로 한정한다.

21. **출구 티켓은 틀린 문장이 없더라도 목표 달성 증거가 약하다.**  
    **원문 인용 →** “이해도(1~5)와 한마디 … 세 방향 … 중 하나를 골라 한 문장”.  
    **문제 →** “공간은 같은 프레임을 본다”를 외워 쓰면 통과한다. 세 범위를 구별하는지, 매체가 바뀌어도 무엇이 공통인지 확인하지 못한다. 자기보고 이해도는 이해의 증거가 아니며, 공개된 채점 기준도 없다.  
    **구체적 수정안 →** 세 관계를 제시해 공간·시간·교차로 연결하게 하고, “공통 계산과 달라지는 입력을 각각 하나” 쓰게 한다. ‘낱말’은 물리적 축이 아니므로 “세 방향”보다 “참고하는 정보의 세 범위”라고 묻는다.

**3D 모형과 학생 눈높이**

22. **장난감이라는 고지는 있으나, 실제 모델과 같다는 후속 문장이 범위를 넘는다.**  
    **원문 인용 →** “임베딩과 W 행렬은 … 손으로 설계했습니다”; “실제 모델은 … ‘어떤 조각이 어떤 조각을 볼 수 있는가’의 범위는 이 모형과 같습니다.”  
    **문제 →** 손설계 고지는 충분히 명시돼 있다. 문제는 뒤에서 특정 마스크를 실제 모델 일반의 범위라고 단정하는 것이다. 학생은 미리캔버스 내부를 재현한 모형이라고 받아들일 수 있다.  
    **구체적 수정안 →** “특정 서비스 내부를 재현한 것이 아니다. 기본 어텐션 계산과 가능한 범위 제한 몇 가지를 보여 준다. 궤적이 잘 보이도록 숫자를 설계했다”를 조작 직전 화면에 표시한다.

23. **자기 자신에게 큰 가중치가 나오는 것을 해석할 장치가 없다.**  
    **원문 인용 →** SPACE: “같은 프레임에서 나와 닮은 조각은 어디 있나?”, “색과 공 포함도가 닮고 자리가 가까운 조각에 점수가 높습니다.”  
    **문제 →** 자신이 최대라면 학생은 ‘어텐션은 결국 자기 색을 복사한다’거나 ‘자기 어텐션은 자기 자신만 보는 것’으로 이해할 수 있다. 다만 제공 텍스트에는 전체 16개 가중치가 없어 실제 최대값은 확인할 수 없다. 자신이 최대인 결과 자체도 오류는 아니다.  
    **구체적 수정안 →** “자신도 참고 대상이며, 실제 모델에서 항상 최대인 것은 아니다”를 덧붙인다. 자신과 다른 조각의 가중치를 함께 읽게 하고, 자기 자신을 제외한 비교는 원래 계산과 다른 추가 실험이라고 표시한다.

24. **클릭이 Q 변경인지 K 선택인지 지시가 충돌한다.**  
    **원문 인용 →** “칸을 클릭하면 그 조각을 읽는 조각으로 바꿉니다”; “무대의 다른 조각 … 을 클릭하면 그 조각과의 계산을 보여 줍니다”; “조각 클릭 = 읽는 조각(Q)”.  
    **문제 →** 동일한 ‘조각 클릭’이 읽는 주체 변경과 비교 대상 선택으로 모두 설명된다. 두 화면 영역의 동작이 다르다면 영역을 명확히 지정해야 한다. “공 조각”도 공이 걸친 여러 칸 중 어디인지 불명확하다.  
    **구체적 수정안 →** “①‘프레임 2의 공’ 버튼으로 Q 고정 ②모드 변경 ③비교 대상 선택”으로 안내한다. Q 선택과 K 선택을 화면에서 분리하고, 잔디도 확정된 프레임·행·열을 제시한다.

25. **과제 3개가 12분에 가능한 조건을 마련하지 않았다.**  
    **원문 인용 →** S7: “공간 · 시간 · 교차를 차례로”, “잔디 조각”, “전체 어텐션에서 프레임을 바꿔 가며”; 모형: 카메라·배율·차트·재생·오버레이 조작.  
    **문제 →** 버튼을 누르는 데는 충분할 수 있지만, 접속→Q 이해→네 범위 비교→가중치 해석→궤적 설명까지는 별개다. 학생이 관찰 결과를 무엇으로 남겨야 하는지도 없다. 화면 기능 탐색으로 시간을 쓰고도 과제를 했다고 생각하기 쉽다.  
    **구체적 수정안 →** 접속·시범 2분, 고정 Q의 범위 비교 4분, 공/잔디 교차 비교 3분, 답 확인 3분으로 정한다. 궤적 과제는 심화로 돌리고, 필수 결과는 “참고 대상과 볼 수 없는 대상” 두 칸에 기록하게 한다.

26. **가중치 지도를 움직임의 원인 또는 추적 결과로 과대해석하게 한다.**  
    **원문 인용 →** FULL: “가중치 지도에 공이 지나간 궤적이 드러납니다”; S7: “공이 움직인 방향이 가중치에 어떻게 드러나는지”.  
    **문제 →** 손설계한 표현에서 공이 있는 칸들이 밝아지는 것은 학습된 모델이 움직임을 발견했다는 증거가 아니다. 비슷한 공 조각들의 밝기만으로 방향이 결정되는 것도 아니며, 프레임 순서와 위치를 함께 읽어야 한다.  
    **구체적 수정안 →** “밝은 공 조각의 위치를 프레임 1→4 순서로 읽어 방향을 설명하라”로 바꾼다. “이 지도는 설계한 예이며, 가중치만으로 모델의 판단 원인을 확정할 수 없다”를 덧붙인다.

27. **계산 화면의 소프트맥스 표기는 제시된 숫자와 맞지 않는다.**  
    **원문 인용 →** CROSS: “점수 s = 3.66”, “w = eˢ ÷ Σeˢ = 1.00 ÷ 1.86 = 0.537”; FULL: “s = 5.09”, “0.63 ÷ 2.70”.  
    **문제 →** \(e^{3.66}\)은 약 38.9이지 1.00이 아니다. 최대 점수를 뺀 안정화 계산이라면 가중치는 맞을 수 있지만, 현재 화면에는 그 과정이 없다. 계산기를 써 본 학생에게는 공식과 결과가 충돌한다.  
    **구체적 수정안 →** \(w_i=e^{s_i-m}/\sum_j e^{s_j-m}\), \(m=\max_j s_j\)로 표기하고 “모든 점수에서 같은 값을 빼도 비율은 같다”를 설명한다. 본 수업에서 다루지 않을 내용이면 세부 숫자는 심화 화면으로 숨긴다.

28. **색 가중합을 완성 영상 생성으로 오해할 수 있다.**  
    **원문 인용 →** “출력 · 섞인 색”, “값 v가 가중치만큼 모인다”; S4: “쳐다보고 고른다”.  
    **문제 →** 모형 출력은 RGB 혼합이지만, 학생은 실제 영상 생성도 주변 색을 평균 내는 일이라고 이해할 수 있다. ‘고른다’ 역시 하나를 선택한다는 뜻인데 화면은 여러 값을 가중합한다.  
    **구체적 수정안 →** “실제로는 색보다 복잡한 특징 정보를 모은다. 여기서는 보이도록 색으로 표현했다. 이것은 완성 프레임이 아니다”를 표시한다. 어텐션 단계의 동사는 “관련 정보를 비율대로 모은다”로 통일한다.

29. **음악 토큰 수의 단위가 빠져 있고, 어휘 부담이 크다.**  
    **원문 인용 →** S10: “코드북 4줄, 초당 50개”, “코덱이 초당 50개 토큰으로 줄인다”; 모형: “소프트맥스”, “내적”, “가중합”, `QKᵀ / √d`.  
    **문제 →** MusicGen 설명의 50Hz는 코드북별 시간 해상도다. 4개 코드북이면 초당 코드 인덱스는 4×50개이며, 지연 패턴을 활용한 생성 단계 수와 구별해야 한다. 학생에게 코덱·코드북·임베딩·행렬 계산을 한꺼번에 요구하면 핵심인 범위 비교가 밀린다. ‘자기회귀’라는 용어는 본문에 없어 별도 오류는 없지만, 교사가 구두로 추가할 때도 풀이가 필요하다. [MusicGen 공식 모델 카드](https://huggingface.co/facebook/musicgen-small)  
    **구체적 수정안 →** “1초를 50개 시간 칸으로 표현하고, 각 칸에는 4개 코드북의 번호가 있다”로 고친다. 코덱은 ‘소리를 압축 표현으로 바꾸고 복원하는 장치’, 코드북은 ‘소리 특징 번호 사전’, 자기회귀는 ‘앞서 만든 토큰을 참고해 다음 토큰을 만드는 방식’으로 풀고 수식은 선택 설명으로 둔다.

30. **패치·좌표·DiT를 설명하는 예시가 일반 정의처럼 제시된다.**  
    **원문 인용 →** S5: “실제 모델은 16×16 픽셀 크기로 자르고”; S6: “시공간 패치”; S9: “DiT = 확산 + 트랜스포머”.  
    **문제 →** 학생에게 16×16이 모든 모델의 고정 규칙처럼 남는다. ‘좌표’도 의미를 나타내는 벡터와 행·열 위치가 혼용된다. DiT라는 약어를 외워도 ‘어느 부분이 트랜스포머인가’를 이해하지 못할 수 있다.  
    **구체적 수정안 →** 16×16 앞에 “예를 들어”를 붙이고, “내용을 나타내는 숫자 묶음+위치 정보”를 구별한다. 시공간 패치는 ‘가로·세로·시간을 함께 묶은 조각’, DiT는 ‘확산 과정에서 예측을 맡는 트랜스포머’로 먼저 설명한다.

**두 가지로 읽히는 제작 지시**

31. **‘움직임을 쓴다’와 다섯 요소 작성 요구가 충돌한다.**  
    **원문 인용 →** S12: “프롬프트에는 움직임을 쓴다”; “① 주체와 동작 … ④ 분위기·조명 ⑤ 유지할 것”; 제목: “움직임 · 카메라 · 시간”.  
    **문제 →** 학생은 움직임만 쓰라는 뜻으로도, 다섯 요소를 모두 새로 묘사하라는 뜻으로도 읽는다. ‘시간’이 클립 길이인지, 동작 순서인지, 저녁 같은 시간대인지도 불명확하다.  
    **구체적 수정안 →** “사진의 외형 설명은 짧게 유지하고, 바꿀 동작·방향·속도·카메라와 유지 조건을 쓴다”로 정한다. 시간은 “클립 안 동작 순서”로 정의하고, 클립 길이는 서비스 설정으로 따로 안내한다.

32. **‘최소 4컷’과 ‘선택’의 범위가 불명확하다.**  
    **원문 인용 →** S15: “선택 / 최소 4컷 · 같은 주인공”; 활동지: “이어 붙일 때 한 일 선택 — 순서 조정·자막·음악·전환 효과 등”.  
    **문제 →** 추출된 문구만으로 ‘선택’이 성찰에만 붙는지, 이후 조건에도 붙는지 확정하기 어렵다. “최소 4컷”은 추가 생성까지 권장하는 표현이며, 자막·음악·전환 중 하나가 필수라고 읽힐 수도 있다.  
    **구체적 수정안 →** “필수: 정확히 4컷·같은 주인공·최종 링크”, “선택: 제출 후 자막·음악·전환 추가”로 분리한다. 성찰의 선택 여부도 해당 입력란 바로 옆에 표시한다.

**교사 개입이 없을 때의 실패 시나리오 3개**

33. **시나리오 1 — 첫 컷 대기가 뒤의 세 컷을 모두 막는다.**  
    **원문 인용 →** “앞 클립의 마지막 프레임을 캡처해 다음 컷의 이미지로”; “26분입니다.”  
    **문제 →** 학생은 이미지를 만드는 데 시간을 쓰고 첫 영상을 요청한다. 첫 결과가 늦거나 마음에 들지 않아 재생성한다. 이후 컷은 시작조차 못 하고, 마지막에는 정지 이미지나 미완성 링크를 제출한다. “이어서 제출”은 수업 내 목표 실패를 수업 밖으로 옮긴다.  
    **구체적 수정안 →** 시작 이미지 4장을 사전 확보하고, 생성 종료 시각과 예비 클립 전환 기준을 강제한다. 직접 생성한 컷 수와 편집 완성 여부는 따로 기록한다.

34. **시나리오 2 — 네 영상은 생기지만 같은 인물의 한 이야기가 아니다.**  
    **원문 인용 →** “같은 주인공 묘사를 매번 그대로”; “같은 인물 · 같은 옷 · 같은 배경”; “우산 아래로 고양이가 들어온다”.  
    **문제 →** 묘사 반복만으로 인물 외형이 고정되지는 않는다. 서로 다른 이미지에서 시작하면 얼굴·우산·고양이 위치가 바뀌고, 복합 상호작용에서 형태가 무너질 수 있다. 끝 프레임 경로에서는 앞 컷의 오류를 다음 컷 입력으로 물려줄 수도 있다.  
    **구체적 수정안 →** 일관된 이미지 세트를 제공하고 컷당 주요 동작을 하나로 제한한다. 재생성 전에 “같은 인물·소품·장소인가, 앞뒤 사건이 이어지는가”를 확인하게 하며 외형의 완벽함을 평가 기준으로 삼지 않는다.

35. **시나리오 3 — 완성했지만 교사는 볼 수도 접수할 수도 없다.**  
    **원문 인용 →** “링크 복사”, “TXT + 시트 저장”, “짝의 기기에서 링크가 열리는지”.  
    **문제 →** 학생이 편집 주소를 복사하고 로그인한 짝에게 확인받는다. 활동지에서는 TXT 파일이 내려받아진 것을 제출 성공으로 생각한다. 교사는 접근 권한 요청 화면을 보거나 제출 기록 자체를 찾지 못한다.  
    **구체적 수정안 →** 완료 조건을 “비로그인 창에서 최종 4컷 재생 확인”과 “활동지 서버 접수 완료 확인” 두 가지로 고정한다. 서버 장애 때 사용할 TXT 대체 제출 경로도 사전에 정한다.

**치명적 3가지 — 우선순위**

1. **1순위: S15의 입력물·대기·복구 경로 부재**  
   **원문 인용 →** “이미지 4장”, “끝 장면 → 다음 첫 이미지”, “생성 … 14분”.  
   **문제 →** 필수 입력 준비가 빠졌고 순차 생성의 대기 시간이 통제되지 않는다. 학생의 노력과 무관하게 4컷 제출 목표가 무너진다.  
   **구체적 수정안 →** 이미지 4장 사전 배포, 계정별 4회 생성 예행, 생성 마감 시각과 예비 클립을 수업 실시 조건으로 삼는다.

2. **2순위: 어텐션 분류 오류와 S8의 부당한 단일 정답**  
   **원문 인용 →** “자기 / 공간 / 시간 / 교차”, “‘오른쪽으로 굴러간다’를 맞추려면 … 꼭 필요”.  
   **문제 →** 서로 다른 분류 축을 병렬로 가르친 뒤, 교차 어텐션을 근거 있게 선택한 학생을 오답 처리한다. 수업의 핵심 개념과 평가가 함께 흔들린다.  
   **구체적 수정안 →** 자기/교차와 공간/시간/전체를 구분해 다시 배열하고, S8을 참조 대상이 명확한 두 문항으로 교체한다.

3. **3순위: 공통 원리를 ‘동일한 기계·동일한 처리’로 과장**  
   **원문 인용 →** “①만 바뀐다. ②③④는 그대로다”, “다른 것은 허용 범위(마스크)뿐이다”.  
   **문제 →** 실제 출력 작업뿐 아니라 제공된 모형의 Q 값도 달라진다. 학생은 공통점을 배우는 대신 차이를 지워 버린 설명을 정답으로 외우게 된다.  
   **구체적 수정안 →** 핵심 문장을 **“조각을 숫자로 표현하고 어텐션으로 관련 정보를 모으는 원리를 공유한다. 입력 표현·참조 범위·예측하는 값은 달라진다”**로 통일한다.
