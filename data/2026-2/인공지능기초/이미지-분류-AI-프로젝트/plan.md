## 정식 용어

| 화면 라벨·정의·칸 이름에 쓰는 정식 용어 | 한 문장 풀이 | 그 자리에 쓰지 않을 비유어 |
|---|---|---|
| 클래스 | 모델이 골라낼 이름표 하나 (예: 치와와, 머핀) | 바구니, 상자 |
| 학습 데이터 | 모델에게 보여 주며 가르치는 사진 | 교과서 |
| 시험 데이터 (테스트 데이터) | 학습에 쓰지 않고 남겨 두었다가 모델을 확인하는 사진 | 기출문제, 모의고사 |
| 데이터 편향 | 데이터가 한쪽 모습·한쪽 클래스로 쏠려 있는 상태 | 편식 |
| 지름길 학습 | 모델이 의도한 특징 대신 배경처럼 우연히 함께 찍힌 특징으로 구별하는 일 | 꼼수, 찍기 |
| 신뢰도 | 모델이 각 클래스에 매긴 확률 (모두 더하면 100%) | 자신감 |
| 기준값 (임계값) | 이 신뢰도보다 낮으면 답을 내지 않기로 정한 값 | 커트라인 |
| 공유 링크 (모델 URL) | 업로드한 모델을 다른 프로그램이 불러올 수 있는 주소 | 플러그 |
| 코드 생성 프롬프트 | 내 설계와 기술 명세를 합쳐 ChatGPT에 넣는 제작 의뢰문 | 주문서 |
| 클래스별 응답 | 결과 클래스마다 프로그램이 보여 줄 문장·동작 | 대사 |

「그 외」 클래스는 칸 이름과 화면 라벨 모두 「그 외」로 통일한다("기타", "배경" 혼용 금지).

## ELI5 적용 원칙 (이 수업 기준)

외부 ELI5 스킬(https://github.com/DreambigOu/ELI5)의 원칙을 고등학생 청중에 맞게 적용한다.

1. **구조**: 슬라이드마다 핵심 내용과 발표자 노트를 같은 순서로 짠다. ① 무엇인가 ② 이미 아는 것에 잇는 비유 ③ 필요한 만큼만 세부 ④ 그래서 내 프로젝트에 무슨 의미인가. 이 수업은 프로젝트 수업이라 ④는 늘 **"그러니 여러분의 데이터(또는 프로그램)는 이렇게"**로 닫는다.
2. **어휘**: 위 「정식 용어」를 처음 나오는 장에서 한 문장으로 풀이한다. 화면에는 용어 옆에 작은 풀이 칩을 둔다. 지난 시간 용어(학습·가중치·전이학습·공유 링크·코드 생성 프롬프트)는 다시 풀지 않고 한 마디로만 상기한다.
3. **비유**: 학교생활(시험·교과서·급식·교복·동아리)과 스마트폰에서 가져온다. 비유는 도입과 노트에만 쓰고 라벨은 정식 용어다.
4. **문장**: 한 문장에 생각 하나. 노트는 "여러분"을 주어로 직접 말한다. 카피(헤드라인·라벨)는 짧게 끊되 설명 문장과 노트는 완결 문장으로 쓴다.
5. **어조**: 편하게, 그러나 프로젝트를 맡은 개발자로 대한다. 규칙을 먼저 던지지 않고 "왜 그래야 하는가"를 먼저 보인 뒤 기준을 준다(S4·S5 → S6~S10).
6. **정확성**: 단순화는 하되 틀린 말은 하지 않는다. 특히 "모델이 본다·생각한다"는 표현을 쓴 자리에는 노트에 "실제로는 숫자 계산으로 특징을 비교한다"를 한 번 밝힌다(S5). 지름길 학습 사례는 일부러 만든 실험임을 밝힌다(F8).
7. **분량**: 한 장에 새 용어 셋 이하. 넘치면 장을 없애지 않고 문장을 줄인다.

## Slide 4 · 모델은 데이터가 가르친 것만 안다
- form: scene
- scene: metaphor: 같은 학생, 다른 교과서 — 똑같은 빈 모델 두 개가 서로 다른 사진 묶음으로 배운 뒤 같은 사진에 다른 답을 낸다 | emotion: 깨달음 | intent: "학습 방법은 같아도 데이터가 다르면 다른 모델이 된다"를 눈으로 보여 주어, 이후 데이터 기준 다섯 가지가 왜 필요한지의 근거를 세운다
- svg: 신규: 펼친 교과서 두 권 (표지 색만 다른 같은 모양, clean-hand-illustration)

**핵심 메시지:** 학습 방법이 같아도 학습 데이터가 다르면 다른 모델이 되므로, 무엇으로 학습시키느냐가 모델의 판단을 정한다.

**핵심 내용:**
- 같은 Teachable Machine, 같은 버튼 → 데이터만 다르게
- 모델 A: 치와와 사진이 전부 갈색 털 / 모델 B: 털색이 여러 가지
- 흰 털 치와와 시험 사진 → A는 헷갈리고 B는 맞힌다
- 새 용어: **학습 데이터** · **시험 데이터** (풀이 칩)

**형태 설계:** 가운데를 세로선으로 나누지 않는다(대칭 금지). 화면 가운데 위에 빈 모델 상자 두 개가 나란히 작게 있고, 왼쪽 아래에서 교과서 A(svg, 갈색 표지 위에 갈색 치와와 사진 썸네일 네 장), 오른쪽 아래에서 교과서 B(svg, 표지 위에 털색이 다른 치와와 썸네일 네 장)가 각 상자로 빨려 들어간다. t 타임라인: 0~1.5s 두 교과서의 사진이 상자 안으로 흘러들고 상자 안 눈금이 채워짐; 1.5~3s 화면 위 가운데에서 흰 털 치와와 시험 사진 한 장이 내려와 두 상자 사이에 멈춤(dominant 위치, 중앙 40~60% 통과); 3~4.5s 두 상자에서 판정 말풍선: A 「머핀 58%」(앰버, 물음표), B 「치와와 91%」(초록). 수치는 예시이며 화면에 "화면 수치는 예시"로 표기한다(실제 데모 모델은 흰 털 치와와 `시험_05`도 100%로 맞힌다 — 다양한 털색으로 배웠기 때문). 4.5s 이후 아래 띠에 정식 라벨 두 개: 「학습 데이터 — 모델에게 보여 주며 가르치는 사진」「시험 데이터 — 학습에 쓰지 않고 남겨 둔 확인용 사진」. 모든 모션은 t의 순수 함수. 치와와 사진은 데이터셋에서 털색으로 골라 쓴다(흰 털 사진이 시험 폴더에 있으면 그것을 우선).

**발표자 노트:** 화면 위쪽에 똑같은 빈 모델 두 개가 있습니다. 아래 교과서 두 권은 겉모양이 같고 안에 든 사진만 달라요. (0~1.5초: 사진이 흘러듭니다) "왼쪽 모델은 갈색 치와와만 보고 배웠고, 오른쪽 모델은 여러 털색의 치와와를 보고 배웠습니다. 버튼도 같고 학습 방법도 같아요." (1.5~3초: 흰 치와와가 내려옵니다) "이제 흰 털 치와와를 보여 줍니다. 여기서 모델을 확인하려고 남겨 둔 사진을 시험 데이터라고 해요. 학습에 쓴 사진은 학습 데이터고요." (3~4.5초: 말풍선) "왼쪽은 헷갈리고 오른쪽은 맞힙니다." "같은 반 친구 둘이 같은 선생님께 배워도, 교과서가 다르면 시험에서 다른 답을 쓰겠죠. 모델도 똑같아요." (실제로는 결과가 사진에 따라 달라질 수 있고, 화면 수치는 예시입니다.) "그러니 오늘 여러분이 할 가장 중요한 결정은 버튼을 누르는 일이 아니라 어떤 사진을 넣을지 고르는 일입니다."

**핵심 내용:**

**발표자 노트:** 화면 왼쪽은 눈밭 위의 허스키입니다. (0~1.5초: 돋보기가 훑습니다) "2016년에 어떤 연구자들이 허스키와 늑대를 구별하는 모델을 만들었어요." (1.5~3초) "이 허스키를 보여 줬더니 모델이 늑대라고 합니다." (3~4.5초: 눈밭만 밝아집니다) "모델이 어디를 근거로 판단했는지 비춰 봤더니, 동물이 아니라 바닥의 눈이었어요. 학습에 쓴 늑대 사진이 전부 눈 위에서 찍혀 있었거든요." "이걸 지름길 학습이라고 합니다. 문제를 끝까지 안 읽고 보기 길이만 보고 답을 찍었는데 마침 맞아 버린 거예요." ## Slide 6 · 기준 ①② 명확성과 품질: 대상이 주인공인가
- form: build

**핵심 메시지:** 사진 속에서 분류 대상이 분명히 보이고(명확성) 흐리거나 엉뚱하지 않아야(품질) 모델이 대상의 특징을 배운다.

**핵심 내용:**
- 명확성: 대상이 사진의 주인공 · 다른 대상과 섞이지 않음

Build at=1: 대상이 크게 나온 치와와 → 「통과」 도장(초록) + 칩 「명확성」. at=2: 대상이 구석에 작게 나온 사진 → 「다시 찍기」(앰버), 말풍선 "주인공이 누구?". at=3: 흐린 사진 → 「다시 찍기」 + 칩 「품질」. at=4: 아래 띠에 이렇게 고친다 두 줄("대상 위주로 다시 찍기 · 필요하면 잘라 쓰기"). 출처 줄 "사진: CC0 · Openverse".

**발표자 노트:** 가운데 심사대 위에 사진이 한 장씩 올라옵니다. (클릭 1) "이 사진은 통과입니다. 치와와가 사진의 주인공이고 다른 것과 섞이지 않았어요. 이걸 명확성이라고 합니다." (클릭 2) "이 사진은 다시 찍기예요. 치와와가 구석에 작게 있죠. 친구에게 내 강아지를 보여 주려는데 단체 사진 구석에 콩알만 하게 나온 사진을 내미는 것과 같아요. 모델은 화면 대부분을 차지하는 소파를 배울 겁니다." (클릭 3) "이건 흐려요. 사진의 질, 품질이 떨어지면 모델이 배울 특징 자체가 뭉개집니다." (실제로는 Teachable Machine이 사진을 224×224 크기로 줄여서 보기 때문에, 원래 작게 나온 대상은 더 작아집니다.) (클릭 4) "고치는 방법은 간단해요. 대상 위주로 다시 찍거나, 필요한 부분만 잘라서 씁니다." "그러니 여러분이 사진을 모을 때 한 장마다 '이 사진의 주인공이 내 클래스인가'를 물어보세요."

## Slide 7 · 기준 ③ 다양성: 한 모습만 보여 주면 그 모습만 안다
- form: scene
- scene: metaphor: 조건 다이얼 — 각도·조명·배경·종류 네 개의 다이얼이 돌아갈 때마다 같은 대상의 다른 사진이 나타나고, 다이얼이 멈춰 있던 모델은 새 모습 앞에서 막힌다 | emotion: 탐색 | intent: 같은 클래스 안에서도 여러 조건의 사진이 필요하다는 것을 "돌려 볼 수 있는 축"으로 구조화해, 학생이 사진을 모을 때 체크할 목록으로 바로 쓰게 한다

**핵심 메시지:** 같은 클래스라도 각도·조명·배경·생김새를 여러 가지로 섞어야, 모델이 처음 보는 모습에서도 그 클래스를 알아본다.

**핵심 내용:**
- 돌려 볼 네 축: 각도 · 조명 · 배경 · 종류(색·모양·크기)
- 한 모습만 학습 → 그 모습에만 맞춰짐 → 새 모습에서 틀림
- 다양성은 S5의 지름길 학습도 막는다 (배경을 섞으면 배경으로 구별할 수 없다)

**형태 설계:** 왼쪽 40%에 다이얼 네 개(코드 도형, 2×2가 아니라 반원 호를 따라 비스듬히 배치), 오른쪽 60%에 사진 한 장 자리(dominant). t 타임라인: 0~1s 모든 다이얼 정지, 사진은 정면·밝은 실내의 갈색 치와와; 1~2s 「각도」 다이얼이 돌며 옆모습 사진으로 교체; 2~3s 「조명」 → 어두운 사진; 3~4s 「배경」 → 야외 사진; 4~5s 「종류」 → 다른 털색. 5s 이후 사진 자리 아래에 다섯 장이 작은 띠로 정렬되고 위에 「같은 클래스, 다른 모습」 라벨. 클릭 1(Build): 다이얼 옆에 "다양성은 지름길 학습도 막는다" 한 줄 칩(S5 회수). 사진은 모두 데이터셋에서 털색·자세·장소로 골라 쓴다(저작 시 선택). 모든 모션은 t의 순수 함수.

**발표자 노트:** 왼쪽에 다이얼이 네 개 있습니다. 각도, 조명, 배경, 종류예요. (0~1초) "지금은 다이얼이 다 멈춰 있어서 정면에서 찍은 밝은 갈색 치와와만 있습니다." (다이얼이 하나씩 돕니다) "옆모습, 어두운 방, 바깥, 다른 털색. 전부 같은 치와와 클래스예요." "교복 입은 모습만 봐 온 친구를 주말에 사복 차림으로 만나면 순간 못 알아보잖아요. 모델은 그게 훨씬 심합니다. 본 모습에만 딱 맞춰지거든요." (클릭 1) "그리고 배경을 섞어 주면 앞 장의 지름길 학습도 막을 수 있어요. 배경이 클래스마다 골고루 섞이면 배경으로는 구별이 안 되니까요." "그러니 사진을 모을 때 이 네 다이얼을 하나씩 돌려 보세요. 각도를 바꿔서, 불을 끄고, 장소를 옮겨서, 다른 종류로 찍는 겁니다."

## Slide 8 · 기준 ④ 양과 균형: 한쪽이 많으면 그쪽으로 기운다
- form: build
- svg: (재사용 조회 후 없으면 코드 도형) 저울

**핵심 메시지:** 클래스마다 사진이 충분해야 하고 개수가 비슷해야, 모델이 사진이 많은 쪽으로 쏠리지 않는다.

**핵심 내용:**
- 양: 클래스당 학습 사진 20장 이상, 권장 30장 이상

- 사진이 모자라면: 각도·조명을 바꿔 더 찍는다 (S7의 다이얼)

**형태 설계:** 가운데 큰 저울(dominant, 중앙 통과). 저울 접시 위에 사진 썸네일이 쌓인다. **발표자 노트:** 가운데 저울에 사진이 쌓입니다. (클릭 1) "클래스마다 서른 장씩이면 저울이 평평하죠. 우리 프로젝트는 클래스당 학습 사진을 스무 장 이상, 가능하면 서른 장 이상 모읍니다." (클릭 2) "그런데 한쪽이 예순 장, 다른 쪽이 열 장이면 저울이 기웁니다. 그러면 모델은 헷갈리는 사진을 만나면 많은 쪽으로 답하기 쉬워요." "급식 메뉴 투표에 한 반만 몰려와서 투표하면 결과가 그 반 입맛으로 쏠리는 것과 같아요. 이렇게 데이터가 한쪽으로 쏠린 상태를 데이터 편향이라고 합니다." (실제로는 개수만이 아니라 앞 장의 다양성이 한쪽에만 부족해도 편향이 생깁니다.) (클릭 3) "모자란 쪽은 버리는 게 아니라 더 찍어서 채웁니다. 앞 장의 다이얼을 돌려서요." "그러니 학습시키기 전에 클래스마다 사진 개수를 한 번 세어 보세요. 활동지에도 그 칸이 있습니다."

## Slide 9 · 시험 사진은 따로 떼어 둔다
- form: build

**핵심 메시지:** 학습에 쓴 사진으로 시험하면 외운 답을 확인하는 것일 뿐이므로, 처음 보는 사진을 따로 떼어 두어야 모델의 진짜 실력을 알 수 있다.

**핵심 내용:**
- 사진을 모은 뒤 클래스마다 몇 장을 먼저 빼 둔다 → 시험 데이터 (클래스당 5장 이상)
- 학습 사진으로 시험 → 거의 다 맞음 → 잘 만든 것처럼 보이는 착각
- 시험 결과 기록: 사진 · 정답 · 모델 답 · 신뢰도 → 틀린 사진이 다음 데이터의 힌트
- 이유 분석: 틀린 사진은 S6~S8 중 어느 기준과 관계있을까

**형태 설계:** 왼쪽에 사진 더미 하나가 칼선(점선)으로 두 덩이로 갈라지는 구도: 큰 덩이 「학습 데이터」, 작은 덩이 「시험 데이터」(봉투에 넣어 봉인). 오른쪽에 시험 기록표(활동지와 같은 칸: 사진 · 정답 · 모델 답 · 신뢰도 · 맞음/틀림). Build at=1: 더미가 갈라지고 작은 덩이가 봉투로 들어감. at=2: 학습 덩이에서 사진을 꺼내 시험하는 경로에 빨간 ✕와 말풍선 "외운 문제로 시험 보기". at=3: 봉투가 열리며 기록표 행 세 개가 채워짐(맞음 2, 틀림 1 — 틀린 행이 앰버로 강조). at=4: 틀린 행에서 화살표가 S6·S7·S8 기준 칩 세 개(명확성·품질 / 다양성 / 양과 균형)로 뻗고, "틀린 사진이 다음 데이터의 힌트" 한 줄.

**발표자 노트:** 왼쪽 사진 더미가 둘로 나뉩니다. (클릭 1) "사진을 다 모으면 학습시키기 전에 클래스마다 다섯 장 이상을 먼저 빼서 봉투에 넣어 두세요. 이게 시험 데이터입니다." (클릭 2) "학습에 쓴 사진으로 시험하면 어떻게 될까요? 거의 다 맞습니다. 기출문제 답만 외운 다음 똑같은 기출문제로 시험 보면 백 점이 나오는 것과 같아요. 실력이 아니라 기억을 확인한 거죠." (클릭 3: 기록표) "봉투를 열어 처음 보는 사진을 하나씩 넣고 이 표에 적습니다. 정답, 모델의 답, 신뢰도." ## Slide 11 · 예를 들면: 바나나 언제 먹지?
- form: static
- 화면 캡처 원본: `demo/바나나-언제-먹지.html` (부속 명세 1-1) — 수업용 예시. 진짜 모델 대신 생성 그림 여섯 장과 미리 정한 신뢰도로 동작한다. 진짜 프로그램이 아니므로 **덱에서 링크·QR을 두지 않고 캡처만 보인다** (2026-10-20 수정: 치와와·머핀 「간식 지킴이」는 쓸모가 어색한 예시라 교체, 이어서 링크·QR 제거)

**핵심 내용:**
- 예시: 바나나 사진 → 덜 익음 "아직 일러요. 2~3일 실온에 두세요" / 딱 좋음 "지금이 딱 먹기 좋아요!" / 너무 익음 "오늘 꼭 드세요. 바나나 빵이나 스무디도 좋아요" + 신뢰도 막대

**발표자 노트:** 왼쪽은 이미지 분류 모델을 쓰는 프로그램의 예시, '바나나 언제 먹지?'입니다. 수업용으로 꾸민 화면이라 안에 진짜 모델이 들어 있지는 않아요. 여러분이 만들 프로그램에서는 Teachable Machine 모델이 이 자리에서 직접 계산합니다. "바나나 사진을 넣으면 덜 익음, 딱 좋음, 너무 익음 중 하나로 나누는데, 이름만 말하지 않고 '2~3일 기다리세요', '지금 드세요', '오늘 꼭 드세요'처럼 할 일을 알려 줘요." (오른쪽 위 비교) "모델은 '딱 좋음 95%'까지만 말하죠. 프로그램은 그 결과를 사람이 할 일로 바꿔 줍니다." ## Slide 13 · 프로그램 설계의 세 질문
- form: build

**핵심 메시지:** 만들기 전에 누구의 어떤 문제를 돕는지, 무엇을 입력받는지, 결과 클래스마다 무엇을 보여 줄지를 정한다.

**핵심 내용:**
- ① 누구의, 어떤 순간의 문제인가 → 프로그램 이름과 한 줄 소개
- ② 무엇을 받는가 → 입력 방식: **사진 올리기(기본)** · 웹캠(선택)
- ③ 결과마다 무엇을 주는가 → 클래스별 응답 (문장 + 색·이모지 같은 표시)
- 좋은 응답은 이름이 아니라 **할 일**을 알려 준다 ("캔" → "캔: 내용물을 비우고 찌그러뜨려 캔 수거함에")

**형태 설계:** 「나의 첫 AI 서비스」 S9와 같은 질문 셋을 반복 구도로 쓰지 않는다. 이번에는 **키오스크 화면 설계도**: 가운데 세로로 긴 키오스크 목업(dominant) 안에 세 영역(위 제목·소개 / 가운데 입력 / 아래 결과 카드)이 비어 있고, 왼쪽에서 질문 ①②③ 쪽지가 하나씩 날아와 해당 영역에 붙는다. Build at=1: ① 쪽지 → 위 영역에 「분리배출 도우미 · 쓰레기를 찍으면 버리는 법을 알려 줘요」. at=2: ② → 입력 영역에 「📷 사진 올리기」 버튼 + 점선 「웹캠 (선택)」. at=3: ③ → 결과 영역에 클래스별 응답 표 세 줄(플라스틱 / 캔 / 종이 → 각 할 일 문장). at=4: 오른쪽에 대비 메모 두 줄 "✕ 「캔입니다」 / ○ 「캔: 내용물을 비우고 찌그러뜨려 캔 수거함에」" — ○ 줄이 크다. 예시 주제는 S3의 예시와 같은 것(분리배출)을 써서 새 정보를 늘리지 않는다.

**발표자 노트:** 가운데 키오스크 화면이 아직 비어 있습니다. 질문 세 개로 채워 볼게요. 예시는 아까 본 분리배출 도우미입니다. (클릭 1) "첫째, 누구의 어떤 순간의 문제인가. 분리수거장 앞에서 이게 어디로 가는지 헷갈리는 사람이죠. 그게 프로그램 이름과 한 줄 소개가 됩니다." (클릭 2) "둘째, 무엇을 받는가. 기본은 사진 올리기예요. 웹캠은 하고 싶은 사람만 선택으로 넣습니다. ChatGPT 미리보기 같은 틀 안에서는 카메라가 막힐 수 있어서예요. 막혀도 사진 올리기는 그대로 됩니다." (클릭 3) "셋째, 결과마다 무엇을 보여 줄까. 클래스가 셋이면 응답도 셋을 정해야 합니다." (클릭 4) "여기서 차이가 납니다. ## Slide 14 · 확신이 낮을 때는 "잘 모르겠어요"
- form: scene
- scene: metaphor: 수위 눈금자 — 신뢰도 막대가 물처럼 차오르고, 눈금자에 그은 기준선을 넘은 막대만 답이 되며 넘지 못하면 "잘 모르겠어요" 팻말이 선다. 기준선을 올리면 걸러지는 것이 늘지만, 아주 확신하며 틀리는 사진은 끝까지 넘는다 | emotion: 통제감 → 한계의 자각 | intent: S2의 "모델은 모르겠다고 못 한다" 문제를 프로그램 쪽 해법(기준값)으로 일부 막고, 그 한계를 실측으로 보여 데이터 쪽 해법(「그 외」 클래스)으로 넘긴다
- svg: 신규: 눈금이 새겨진 세로 수위 눈금자 (clean-hand-illustration)

**핵심 메시지:** 기준값은 확신이 낮은 답을 걸러 주지만 아주 확신하며 틀리는 답은 막지 못하므로, 모르는 경우는 「그 외」 클래스라는 데이터로도 막아야 한다.

**핵심 내용:**
- 해법 ① 프로그램으로: 가장 높은 신뢰도가 **기준값**보다 낮으면 답 대신 "잘 모르겠어요"
- 실측(데모 모델): 치와와 100% → 통과 / 흐리게 잠든 고양이 치와와 76% → 기준값 70%면 통과(틀림), 85%로 올리면 "모르겠어요" / 또렷한 고양이 치와와 99.8% → 85%로도 통과(틀림)
- 기준값을 높이면 틀린 답은 줄지만 "모르겠어요"도 늘어난다
- 해법 ② 데이터로: 「그 외」 클래스를 만들어 빈 책상·손·다른 물건·다른 동물 사진을 학습 — 확신하며 틀리는 문제는 이쪽이 주된 해법
- 활동지 D5에서 내 프로그램의 기준값을, B4에서 「그 외」 클래스를 정한다

**형태 설계:** 가운데 큰 수위 눈금자(svg, dominant) 옆에 막대 두 개(치와와·머핀)가 물처럼 차오른다. 앰버 기준선. 왼쪽에 지금 넣은 사진. t 타임라인: 0~1.5s 치와와(`시험_07`) → 「치와와 100%」, 기준선 70% 위 → 응답 카드 「🐶 치와와예요!」(초록 ✓); 1.8~3s 잠든 고양이(`images/photo-cat-asleep.jpg`) → 「치와와 76%」, 기준선 70% 위라 「치와와예요!」(빨강 ✗ 틀림); 3.2~4s 기준선이 85%로 올라가고 같은 사진이 「잘 모르겠어요」로 바뀜(✓); 4.4~5.6s 또렷한 고양이(`images/photo-cat-awake.jpg`) → 「치와와 99.8%」, 85% 위라 다시 「치와와예요!」(✗) + 띠 "기준값만으로는 못 막는다". 6s 이후 오른쪽에 정식 라벨 「기준값 — 이 신뢰도보다 낮으면 답을 내지 않기로 정한 값」 + 한 줄 "높이면 틀린 답은 줄고 「모르겠어요」는 는다". 클릭 1(Build): 왼쪽 아래 해법 ② 카드 — 「그 외」 막대가 생긴 세 막대 도식 + "그 외 사진: 빈 책상 · 손 · 다른 물건 · 다른 동물". 수치는 데모 모델 실측값이며 "데모 모델 실측" 표기.

**발표자 노트:** 가운데 눈금자에 신뢰도 막대가 차오릅니다. 앰버색 선이 기준값이에요. (0~1.5초) "치와와를 넣으면 100%까지 올라가서 선을 넘죠. 그러면 답을 보여 줍니다." (1.8~3초) "이번엔 흐리게 잠든 고양이예요. 치와와 76%. 선이 70%라서 넘어 버립니다. 틀린 답이 나가죠." (3.2~4초: 선이 올라갑니다) "선을 85%로 올려 볼게요. 이제 76%는 못 넘으니까 프로그램이 '잘 모르겠어요'라고 말합니다. 합격선을 올리면 애매한 답은 떨어지는 것과 같아요. 이 선을 기준값이라고 합니다." (4.4~5.6초) "그런데 또렷한 고양이를 넣으면요? 치와와 99.8%. 85%든 95%든 넘어요. 2장에서 본 그 사진입니다." "기준값은 자신 없는 답만 걸러 줍니다. 자신 있게 틀리는 답은 못 막아요. 그리고 선을 높일수록 맞는 답도 '모르겠어요'로 떨어질 수 있습니다." (클릭 1) "그래서 데이터로 막는 방법이 필요합니다. 「그 외」라는 클래스를 하나 더 만들어서 빈 책상, 손, 다른 물건, 다른 동물 사진을 가르치는 거예요. 모델에게 '정답 없음' 보기를 하나 만들어 주는 셈입니다." (실제로는 「그 외」 클래스도 학습에 없던 낯선 것까지 다 잡아내지는 못합니다. 그래서 두 방법을 함께 씁니다.) "그러니 여러분 프로그램에는 기준값을 꼭 넣고, 엉뚱한 사진이 자주 들어올 주제라면 「그 외」 클래스까지 만들어 보세요. 활동지에서 둘 다 정합니다."

## Slide 16 · ChatGPT에게 맡기는 절차
- form: walkthrough
- scene: metaphor: 링크 한 줄이 프로그램이 되는 순간 — 왼쪽 ChatGPT 창의 코드 블록이 [▶]을 누르자 오른쪽 미리보기에서 사진을 받는 내 프로그램으로 살아난다 | emotion: 설렘 | intent: 지난 프로젝트에서 해 본 절차를 다시 보이되, 이번에 달라진 두 곳(공유 링크가 코드 맨 위에 들어가는지 확인 · 사진 올려 보기)을 짚어 실수를 막는다

**핵심 메시지:** 코드 생성 프롬프트를 붙여넣고 [▶]으로 실행한 뒤, 코드 맨 위의 공유 링크를 확인하고 시험 사진을 올려 보면 첫 버전이 완성된다.

**핵심 내용:**
- 지난 프로젝트와 같은 네 걸음 + 확인 한 가지
- 달라진 점: 코드 맨 위 `MODEL_URL`에 내 공유 링크가 들어 있는지 눈으로 확인
- 미리보기에서 시험 사진 한 장 올려 보기 → 신뢰도 막대와 응답 확인
- ▶에서 모델이 안 불러와지면 [다운로드] → 더블클릭 (F4 실측: 더블클릭으로 연 파일에서도 모델이 불러와진다)

**절차 대본 (창 × 행동 × 확인):** (화면 문구는 저작 시 실제 chatgpt.com에서 다시 확인. 「나의 첫 AI 서비스」 S13의 창 목업 컴포넌트를 재사용하되 배색은 이 덱 테마)
1. 활동지 창 — D 구역 [📋 전체 복사] 클릭 — 확인: "복사됨" 표시
2. 브라우저 창 `chatgpt.com` (로그인 상태) — 입력창에 붙여넣기 → 전송 — 확인: 코드 블록이 생성되기 시작
3. ChatGPT 창 — 코드 블록 맨 위로 스크롤, `const MODEL_URL = "https://teachablemachine.withgoogle.com/models/…/"` 줄에 포인터가 멈추고 강조 — 확인: 내 공유 링크와 같은가
4. ChatGPT 창 — 코드 블록 위 [▶] 클릭 — 확인: 오른쪽 미리보기에 내 프로그램 화면(제목·사진 올리기 버튼)
5. 미리보기 창 — [사진 올리기] → 시험 사진 선택 — 확인: 신뢰도 막대와 클래스별 응답이 뜬다

**발표자 노트:** 지난 프로젝트에서 해 본 절차라 빠르게 보여 드릴게요. (1~2단계) "활동지에서 전체 복사, ChatGPT에 붙여넣고 전송." (3단계: MODEL_URL 줄이 밝아집니다) "여기가 이번에 새로 확인할 곳이에요. 코드 맨 위에 MODEL_URL이라는 줄이 있고, 거기에 여러분 공유 링크가 들어가 있어야 합니다. 요리 영상을 따라 할 때 재료부터 맞는지 보는 것처럼, 이 한 줄부터 확인하세요." (4단계) "재생 버튼을 누르면 오른쪽에 프로그램이 뜹니다." (5단계) "봉투에 넣어 둔 시험 사진을 한 장 올려 보세요. 막대와 응답이 나오면 첫 버전 완성입니다." (대안 카드) "재생 버튼이 없거나 모델이 안 불러와지면, 다운로드해서 더블클릭으로 여세요. 더블클릭으로 열어도 모델은 인터넷에서 불러옵니다." (수업 전에 교사 계정으로 ▶ 미리보기 안에서 한 번 확인해 둡니다.) "그러니 여러분이 할 일은 복사, 붙여넣기, 링크 확인, 재생, 사진 한 장. 링크 확인을 건너뛰지 마세요."

## Slide 17 · 이상하면 어디를 고칠까: 데이터인가, 프로그램인가
- form: build

**핵심 메시지:** 판정이 틀리면 데이터를 고쳐 모델을 다시 학습시키고, 화면이나 문장이 이상하면 같은 ChatGPT 대화에 증상·고칠 곳·원하는 결과를 말해 프로그램을 고친다.

**핵심 내용:**

## 2. 활동지 — `활동지.html` (activity-sheet-builder)

1학기 정보 「이미지분류-인공지능-프로젝트」 활동지의 4단계(주제 선정 → 학습 설계 및 준비 → 결과와 분석 → 결론)를 뼈대로 하고, 「나의 첫 AI 서비스」 활동지의 D(코드 생성 프롬프트 자동 조립)·E(테스트·개선)·F(제출) 인프라를 이어받는다. 과목 공용 `apps-script.js`(doPost) 제출, 제출 암호 이어쓰기, `제출현황.html` 연동, 임시저장, 하단 액션 바, 서술형 칸 자동 확장(그리드 칸 `align-self: start`), 날짜 현지 시각 — 지난 활동지에서 실측으로 잡은 결함 처리를 그대로 가져온다. **칸을 바꾸면 GAS 필드 목록도 같이 고치고 URL을 유지한 채 재배포한다.**

맨 위 설계 원칙 세 줄: ① 사람 얼굴을 분류하거나 사람을 평가·비교하는 주제는 하지 않는다 ② 사진에 다른 사람 얼굴·이름·번호판이 나오면 쓰지 않는다 ③ 주제가 고민되면 B로 가기 전에 교사에게 확인받는다.

- **A 주제 선정**: A1 누가·언제·어떤 문제를 겪는가 / A2 프로젝트 주제(한 문장) / A3 분류할 클래스(쉼표로 구분 → C 시험 표와 D 클래스별 응답 칸에 자동 반영, 2개 이상 검사) / A4 사진을 직접 찍거나 구할 수 있는가(예/아니오 + 방법 한 줄). 막힌 학생용 **주제 씨앗 카드**는 `<details>` 서랍에 접어 둔다(고르면 두 요소 이상 변형 의무 + 「참고한 것 / 바꾼 것」 칸 — 지난 활동지 방식)
- **B 학습 설계 및 준비** (데이터 계획): B1 사진을 구하는 방법(직접 촬영 / Openverse CC0·PDM / 둘 다 — 선택) / B2 다양성 계획: 각도·조명·배경·종류 네 축 각각 어떻게 바꿔 찍을지(칸 네 개 — 1학기 활동지 「데이터를 선정할 때 고려한 요소」의 발전형) / B3 지름길 학습 점검: "클래스마다 배경이 섞였는가" 체크 + 한 줄 / B4 「그 외」 클래스를 만들까(예/아니오 + 이유) / B5 클래스별 사진 수 표(학습 · 시험 — 학습 20 미만이면 경고, 시험 0이면 경고, 클래스 간 학습 수 차이가 2배 넘으면 균형 경고) / B6 데이터 폴더 캡처 첨부(1학기 활동지 방식, 자동 리사이즈)
- **C 결과와 분석**: C1 공유 링크(형식 검사 `https://teachablemachine.withgoogle.com/models/…/`) / C2 시험 결과 표(클래스당 시험 수만큼 행: 사진 설명 · 정답 클래스 · 모델 답 · 신뢰도 % · 맞음/틀림 자동 + 정확도 자동 계산 — 1학기 활동지 표의 발전형) / C3 틀린 사진 분석(필수 — "어느 데이터 기준과 관계있는가" 다섯 기준 선택 + 이유) / C4 데이터 개선 계획 또는 실행 기록

## 3. 코드 생성 프롬프트 고정 기술 명세 (활동지 D6에 하드코딩)

저작 시 자연어 명세문으로 쓰고, **실제 ChatGPT에 1회 이상 넣어 생성물이 동작하는지 검증**한 뒤 확정한다(데모 1이 그 검증물). 검증 결과로 F4·F5·F7을 확정한다.

1. 결과물은 **완전한 단일 HTML 파일 하나**, `<meta charset="UTF-8">` 포함. 외부 스크립트는 F1의 두 개만(버전 고정 — `@latest` 금지)
2. **출력 규율**: 되묻지 말고 바로 완성 코드 · 코드 블록 하나 · 마지막 줄 `</html>`
3. 파일 맨 위 ★ 주석 배너 + 상수: `MODEL_URL`(공유 링크, 끝 `/` 보정) · `CLASS_RESPONSES`(클래스 이름 → {문장, 이모지, 색}) · `THRESHOLD`(0~1) · `UNKNOWN_MESSAGE`. 배너에 "이 파일의 주인이 이 값들만 고칩니다"
4. 모델 불러오기: `tmImage.load(MODEL_URL + "model.json", MODEL_URL + "metadata.json")`, 불러오는 동안 "모델을 불러오는 중…" 표시와 입력 잠금. 실패하면 "모델을 불러오지 못했어요 — 공유 링크와 인터넷 연결을 확인하세요" 안내
5. 클래스 이름 대조: `model.getClassLabels()`와 `CLASS_RESPONSES`의 키를 비교해, 응답이 없는 클래스가 있으면 화면에 경고(학생이 Teachable Machine에서 클래스 이름을 바꾼 경우를 잡는다)
6. 입력: 사진 올리기(파일 선택 + 끌어다 놓기) → 미리보기 이미지 → 이미지가 다 불러와진 뒤 `model.predict(img)`. (학생이 웹캠을 선택했으면) 웹캠 시작 버튼 + 실시간 예측, 카메라를 못 쓰면 사진 올리기로 안내
7. 결과: 모든 클래스의 신뢰도 막대(정수 %) + 가장 높은 클래스가 `THRESHOLD` 이상이면 그 클래스의 응답 카드, 아니면 `UNKNOWN_MESSAGE`
8. 표시는 **textContent로만** — 학생 문장을 innerHTML에 넣지 않는다
9. UI: 프로그램 이름 + 한 줄 소개 + 입력 영역 + 결과 영역 + 오류 안내 영역, 휴대폰 화면에서도 쓸 수 있게
