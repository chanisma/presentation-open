너는 파이썬 언어 사양을 꼼꼼히 확인하는 검증자다. <stdin>은 고등학교 「인공지능 기초」의 파이썬 두 번째 수업 「입력과 자료형」의 덱 계획서(plan.md) 전문이다. 아직 덱·활동지를 만들기 전 계획 단계이므로, 계획서에 적힌 화면 문구·발표자 노트·문항·활동지 설계·실행기 설계를 검증 대상으로 삼아라. 학생들은 지난 시간에 변수·대입·문자열·print·f-문자열·함수 호출·반환값·def·매개변수를 배웠고(웹 실행기 사용), 그 전 시간에 블록 코딩으로 알고리즘(입력·처리·출력)을 배웠다. 다음 수업은 조건문, 그다음은 리스트와 for 반복이다. 차시·시간 배분은 교사가 현장에서 정하므로 시간 계산은 하지 마라.

과제: 계획서에 들어 있는 모든 파이썬 사실 주장(실행 결과·오류 문구·연산 규칙·함수 동작·Teachable Machine 코드)을 하나씩 판정하라. 공식 문서(docs.python.org)와 원출처를 웹 검색으로 확인하고 근거 링크를 붙여라.
반드시 확인할 항목.
1. 「사실 관계 원칙」 표 F1~F10 전부.
2. 슬라이드 노트·핵심 내용 안의 주장: input()이 끝의 줄바꿈을 떼고 문자열을 돌려준다 / 문자열 * 정수는 반복 / 정수끼리 / 는 언제나 float / // 는 내림 나눗셈(음수 -7//2 = -4) / 연산 우선순위(괄호 → ** → * / // % → + -, 같은 단계는 왼쪽부터, ** 만 오른쪽부터) / int(3.9)=3 / int(" 12 ")=12 / int()는 새 값을 돌려준다 / type()의 출력 모양 <class 'str'> / np.float32는 파이썬 float와 다른 넘파이 자료형 / Teachable Machine 정규화 줄과 -1~1 범위.
3. 파이썬 3.12(Pyodide 0.26.4)의 오류 문구(F8)가 정확한가.
4. 계획서에서 사실처럼 쓰였지만 틀렸거나 오해를 부르는 다른 문장(장 번호와 함께).
5. 「실행기 확장 설계」의 기술 주장: Web Worker 안 Pyodide에서 input()이 동기적으로 기다릴 수 없다, SharedArrayBuffer 방식에는 COOP·COEP 헤더가 필요하다.
판정 어휘는 확인됨 / 부분적으로 맞음 / 틀림 / 과장 / 검증 불가 다섯 개만 쓴다. 표(항목 · 계획서 원문 · 판정 · 근거 링크 · 고칠 문장)로 정리하라. 근거 링크 없이 '틀림' 판정을 내리지 마라.
출력은 한국어 마크다운으로. 칭찬은 최소한으로 하고 결함 위주로 써라. 문제가 없으면 없다고 쓰고 억지로 만들지 마라. 파일을 절대 수정하지 마라.
