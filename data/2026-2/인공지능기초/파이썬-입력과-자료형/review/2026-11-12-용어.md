## 2. 정식 용어 대조표

공개 검색에서 출판사별 고등학교 「정보」 교과서 본문을 충분히 대조하지 못했습니다. 따라서 아래의 명칭 차이는 **통용되는 용어와의 대조**이며, 특정 표현이 국내 교과서에서 더 흔하다는 빈도까지 확정한 결과는 아닙니다. ‘프롬프트’와 예외 이름의 뜻은 [파이썬 공식 내장 함수 문서](https://docs.python.org/ko/3/library/functions.html), [공식 예외 문서](https://docs.python.org/ko/3/library/exceptions.html)를 기준으로 확인했습니다.

| 용어 | 처음 등장·풀이 위치 | 계획서의 풀이 | 명칭 대조 및 수정 필요 |
|---|---|---|---|
| 입력 | 1장 맥락, 2장 정의 | “사용자가 프로그램에 건네는 값” | 이름은 적절하다. 다만 입력을 **값만으로** 정의한다. “프로그램에 필요한 자료를 받아들이는 것”으로 정의하고, 건네는 값은 ‘입력값’으로 구분한다. |
| 출력 | 2장 사용자 화면, 3장 출력 결과. 별도 정의 없음 | 선행 학습에 의존 | 통용 명칭과 같다. 이미 배웠으므로 새 정의가 없는 것은 결함이 아니다. |
| `input()` | 3장. 지난 시간 예고됨 | “사용자에게 값을 입력받는 내장 함수” | 적절하다. 반환값이 문자열이라는 설명도 4·5장에서 이어진다. |

## 3. 「실수(float)」와 「잘못」의 동음이의 처리

**부분적으로 충분하지만, 현재 상태로 완료 판정하기는 어렵습니다.**

| 점검 대상 | 판정 | 결함·수정안 |
|---|---|---|
| 6장 첫 등장에 `float` 병기 | 충분 | 수학·자료형의 뜻을 식별할 단서가 있다. **실수형(`float`)**으로 쓰면 더 분명하다. |
| “실수(float) = 소수점이 있는 수” | 수정 필요 | 동음이의는 피하지만 개념 정의가 부정확하다. 실수에는 정수도 포함되며, `float`는 컴퓨터에서 실수를 근삿값으로 표현하는 자료형이다. 화면에는 **“실수형(float): 2.5, 3.0처럼 실수를 나타내는 자료형”**, 노트에는 근삿값 표현을 짧게 설명한다. |
| 15장에서 ‘실수’ 대신 ‘잘못’ 사용 | 어휘 구별에는 효과 있음 | 그러나 **논리 오류라는 정식 이름을 없앤 대가**가 있다. 제목을 “자주 만나는 오류와 논리 오류”로 고치고, 실행 중 예외와 구분한다. |
| 발표자 노트의 “실제로는” | 문제 없음 | ‘실수’와 다른 단어이므로 혼동 방지를 이유로 바꿀 필요 없다. |
| 계획서 내부의 “흔한 실수”, “자주 하는 실수” | 문제 없음 | 교사용 설명에서 ‘잘못’이라는 문맥이 분명하다. 학생 화면의 자료형 정의와 같은 자리에 놓이지 않는다. |

## 4. 빠진 정식 용어·풀이 및 적용 위치

| 개념·위치 | 현재 상태 | 필요한 조치 |
|---|---|---|
| **논리 오류**, 5·13·15장, 활동지 7번 | 개념은 반복해서 다루지만 이름이 없다. ‘오류가 나지 않는 잘못’이 대신한다. | 15장에서 **논리 오류**를 도입한다. 활동지 7번도 “실행 중 발생한 오류와 고친 방법 / 논리 오류와 확인 방법”처럼 구분한다. |
| **입력·형 변환·대입**, 18장 정리 | 「묻고 받는다·바꾼다·이름을 붙인다」가 동작 라벨을 대신한다. | 정식 용어를 라벨로 쓰고 카피를 보조 설명으로 둔다. 특히 **대입은 이미 배운 용어**이므로 새 개념 추가가 아니다. |
| **산술 연산자**, 12장 | 제목과 기호 목록은 있으나 풀이 문장이 없다. | 한 문장 정의를 추가한다. |
| **문자열 반복**, 5장 문항·해설 | 핵심 내용에는 명칭이 있지만 선지·해설에는 ‘이어 붙인 글자’만 나온다. | 정답 선지를 **“문자열 반복으로 `"2"`가 3000번 이어진 문자열”**로 다듬는다. 이미 있는 용어를 문항에도 연결하는 조치다. |
| **문자열 연결(이어 붙이기)**, 7장 | ‘이어 붙이기’로 일관되게 설명한다. | ‘이어 붙이기’ 자체는 통용되는 한국어 설명이므로 결함은 아니다. 처음에 **문자열 연결(이어 붙이기)**로 병기하면 용어 대조가 쉬워진다. |
| **정규화**, 17장 | ‘노트에서만 풀이’라고 했으나 핵심 내용에는 이름과 풀이가 있고 형태 설계에는 칩이 없다. | 비유만 있는 상태는 아니다. 다만 화면 포함 여부를 확정하고, 포함한다면 **정규화: 이 코드에서는 값의 범위를 -1~1로 맞춤**을 표시한다. |
| **TypeError·ValueError**, 검증 게이트 | 정식 용어 목록에는 넣고, 마지막에는 “용어가 아니라 화면 문구”라고 처리한다. | 내부 기준이 모순된다. 학생이 뜻을 알고 문항에서 구분해야 하므로 **학습할 예외 이름**으로 일관되게 취급한다. |
| 실행기의 자료형 표시 | 색·따옴표·소수점 장식과 자료형 구분은 계획되어 있으나 실제 문자 라벨은 불명확하다. | 색·모양과 함께 **문자열(str)·정수형(int)·실수형(float)**이 읽히도록 명세한다. |
| 실행기 오류 풀이, 9장·`explain.js` | “정수 모양이 아닌 글자”, “소수점이 있으면 float”로 설명한다. | 비유 대체 문제는 없지만 ‘모양’만으로 판단하게 한다. **“문자열 `"3.5"`는 `int()`로 직접 변환할 수 없습니다. 소수 부분을 포함해 입력받으려면 `float()`를 사용하세요.”**처럼 대상과 변환을 명시한다. |

`피연산자`, `리터럴`, `파싱`, `블로킹` 등을 추가하지 않은 것은 이 계획의 결함으로 보지 않았습니다. 이번 학습 목표를 설명하는 데 반드시 필요한 새 용어는 아닙니다.
