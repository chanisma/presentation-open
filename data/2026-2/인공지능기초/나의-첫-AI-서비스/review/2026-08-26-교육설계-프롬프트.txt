너는 이 수업을 심사하는 까다로운 동료 교사다. <stdin>은 고등학교 '인공지능 기초' 과목의 50분×2차시 프로젝트 수업 덱 계획서(plan.md) 전문과 연구 기록이다. 아직 슬라이드 저작 전이므로 지금 잡은 결함은 싸게 고칠 수 있다 — 그래서 더 세게 공격하라.

수업 목표는 「학생이 자신이 설계한 프롬프트가 실제 프로그램 안에서 어떻게 활용되는지 체험하며, LLM API 서비스를 설계·생성·테스트·개선하고 코드로 제출한다」이다.

수업 환경 전제: 여자고등학교, 학생 약 25명, 컴퓨터실(1인 1PC), 학생들은 직전 수업에서 토큰·온도·프롬프트 복원 활동을 마쳤다. 코딩 경험은 없다고 가정한다. 서비스 생성은 학생이 chatgpt.com 에서 주문서를 붙여 넣어 위임하고, 결과물은 단일 HTML 파일이며 학급 전체가 API 키 하나를 공유한다.

과제: 이 수업을 실패시킬 수 있는 지점을 찾아 공격하라.

반드시 다루어야 할 관점.
1. 시간 배분 — 계획서의 '시간 검산' 절이 현실적인가. 25명이 실제로 움직일 때 어디서 무너지는가. 계획서 스스로 「여유 없음」이라 적은 두 차시가 정말 들어가는가.
2. 학생이 막힐 지점 — 설계(A~C 구역), ChatGPT 생성, 파일 저장, 테스트, 프롬프트 직접 수정 각 단계에서 어느 손이 멈추는가. 코딩 무경험 학생이 메모장에서 HTML 속 프롬프트 상수를 고치는 일이 정말 되는가.
3. 기술 실패 시나리오 — 학급 공용 키 하나(분당 호출 제한), ChatGPT 게스트 메시지 제한, 생성 코드가 동작하지 않는 경우, 코드가 중간에 끊기는 경우. 계획서의 대비책이 충분한가. 빠진 대비책은 무엇인가.
4. 개념 설명의 결함 — API 두 장(S5·S6), 시스템 프롬프트(S11), 온도 3택(S10)의 분류·비유가 논리적으로 겹치거나 어긋나는 곳. 학생 눈높이에서 어려운 개념·어휘.
5. 문항의 타당성 — live 문항 3개(S3·S9·S17)의 선지가 의도한 토론을 실제로 만드는가. 반론 가능한 판정이 있는가.
6. 활동 설계의 빈틈 — 활동지 A~F 구역 설계에서 학생 결과물의 질을 떨어뜨릴 구멍. 아이디어를 못 정하는 학생, 장난 서비스(부적절 주제)로 빠지는 학생, 남의 설계를 베끼는 학생에 대한 대비.
7. 교사가 개입하지 않으면 결과물이 어떻게 망가지는가 — 실패 시나리오 3개를 구체적으로 써라.
8. 평가·제출 — 코드 전문 제출이 학습 증거로 적절한가. 무엇을 더 남겨야 하는가.
