암호는 나중에 내 제출을 다시 열어 이어 쓸 때 필요합니다. 기억할 수 있는 것으로 정하되, 학교 계정이나 다른 사이트의 비밀번호는 절대 쓰지 마세요 — 이 활동에서만 쓸 새 암호여야 합니다.

이름·학번·암호를 채운 뒤 화면 맨 아래 [이전 제출 불러오기]를 누르면 지난 제출본을 그대로 열어 이어 쓸 수 있어요.

A. 기획 — 왜 만드는가

서비스는 문제에서 시작합니다. 떠오르지 않으면 아래 아이디어 씨앗 카드를 하나 골라 두 가지 이상 바꿔 보세요.

아이디어가 막히면 — 아이디어 씨앗 카드 열기 (골라서 시작하되, 두 요소 이상 바꿔야 합니다)

B. 입출력 설계 — 무엇을 받고, 무엇을 줄 것인가

입력 칸은 1~3개면 충분합니다. 출력은 내가 정하지 않으면 기계가 확률로 정해 버립니다.

C. 프롬프트 — 서비스의 동작 규칙을 쓴다

C1은 서비스의 동작 규칙(시스템 프롬프트), C2는 사용자 입력이 앉는 문장 틀입니다. 자리표시자 {칸이름}은 C2에만 씁니다.

C1·C2 완성 예시 한 세트 보기 (주말 계획 코치) 
[C1 시스템 프롬프트]
너는 고등학생의 주말 계획을 도와주는 코치다.
항상 존댓말을 쓰고, 무리한 계획을 잡지 않는다.
하고 싶은 것을 받으면 오전·오후·저녁 세 구간으로 나눈 계획을 각 한 줄로 만든다.
마지막 줄에는 "쉬는 시간도 계획입니다"라는 문장을 넣는다.
별표, 머리기호 없이 쓴다.
주말 계획과 상관없는 입력이 오면 하고 싶은 일을 알려 달라고 정중히 안내한다.

[C2 사용자 메시지 틀]
이번 주말에 하고 싶은 것: {이번 주말에 하고 싶은 것}
(이때 B2의 입력 칸 이름도 "이번 주말에 하고 싶은 것"이어야 합니다)

D. 코드 생성 프롬프트 조립 — ChatGPT에 맡길 준비

여러분이 쓴 설계(A~C)와 선생님이 준비한 기술 명세가 한 장으로 합쳐집니다. [전체 복사] 후 chatgpt.com에 붙여넣으세요. ChatGPT에 로그인한 상태여야 합니다. 코드가 완성되면 코드 블록 위에 재생 버튼 [▶]이 생기는데, 그걸 누르면 코드가 그 자리에서 실제 화면이 됩니다 — 파일을 받지 않아도 바로 써 볼 수 있어요.

받은 코드가 이상할 때 — 자주 막히는 문제 3가지
· 코드가 중간에 끊기거나 여러 조각으로 나뉨 → "완전한 HTML 전체를 처음부터 끝까지 하나의 코드 블록으로 다시 출력해 줘" (마지막 줄이 </html>인지 확인) · 재생 버튼 [▶]이 안 보임 → 먼저 로그인 상태인지 확인. 그래도 없으면 [다운로드]로 .html 파일을 받아 더블클릭 · 받은 파일을 열었더니 글자가 깨짐 → 메모장으로 저장했다면 인코딩이 UTF-8인지 확인

E. 기능 테스트 · 개선 기록

기대와 실제의 차이가 개선의 재료입니다. 기본 두 가지 입력은 꼭 넣어 보세요.

고칠 때는 코드를 직접 손대지 않고 같은 ChatGPT 대화에 요청합니다 — 증상 · 고칠 곳 · 원하는 결과 세 가지를 말하세요. 예: "답이 너무 길고 별표가 섞여 나옵니다. 시스템 프롬프트의 「답은 짧게 써라」를 「답은 3줄 이내로, 별표 없이 써라」로 바꿔서, 수정된 전체 HTML을 하나의 코드 블록으로 다시 주세요." 바뀐 부분만 오면 전체 코드를 다시 달라고 하면 되고, 새로 받은 코드의 [▶]을 다시 눌러 확인합니다. 고칠 때마다 코드가 새로 나오니 제출은 마지막에 받은 코드로 하세요.

F. 제출 — 완성본 코드를 낸다

마지막에 받은 코드를 냅니다 — ChatGPT 코드 블록 위의 [복사]를 눌러 아래 칸에 붙여넣거나, [다운로드]로 받은 HTML 파일을 올리면 코드가 자동으로 채워집니다. 수업용 키는 자동으로 가려져 저장됩니다. 미완성이어도 수업 안에 일단 제출하세요 — 자정까지 몇 번이든 다시 제출할 수 있고, 마지막에 낸 것이 최종 제출본이 됩니다.

📚 읽을거리 — 진짜 세상의 LLM 서비스 네 가지
여러분이 오늘 만든 구조(입력 → 프롬프트 → API → 응답)는 실제 서비스들의 뼈대와 같습니다.
· 스픽 — 내 영어 문장·발음 → 교정과 피드백. 한국 시장에서 널리 쓰이는 영어회화 앱으로, OpenAI 모델을 활용하며 OpenAI 공식 고객 사례로 소개됐습니다.
· 카카오톡 '안 읽은 대화 요약하기' — 안 읽은 대화 → 한눈 요약.
· 듀오링고 'Explain My Answer' — 내 답 → 맞고 틀린 이유 설명 (GPT-4 기반 Max 기능으로 시작해, 지금은 더 널리 제공).
· 네이버 AI 브리핑 — 검색어 → 일부 검색에서 생성형 AI가 정리한 요약 답변.
스픽·듀오링고는 외부 모델을 API로 활용한 사례이고, 네이버·카카오처럼 자체 모델을 쓰는 회사도 있습니다. 어느 쪽이든 실제 제품에는 프롬프트 설계와 함께 검색·음성·데이터 기술이 결합됩니다.
