## 2. 참고 사이트 분석 — https://llmserviceproject.netlify.app/

13장짜리 프롬프트 엔지니어링 가이드 + 마지막 페이지의 실습 도구(나만의 AI
서비스 만들기). 실습 도구의 구성:

- 질문 4개: **웹사이트 제목 / 서비스 설명 / 사용자 입력 항목(동적 추가) / 프롬프트 템플릿**(`[사용자입력]` 자리 표시)
- 기술: Google Gemini API — **학생이 Google AI Studio에서 키를 직접 발급**해야 함
- 생성: 도구가 고정된 형태의 index.html을 만들어 줌 → Netlify 배포 안내

사용자 지시: 방식만 참고, 질문 구성·내용은 발전 필요, 기술은 Solar Pro 3로,
생성은 ChatGPT 위임으로 변경.

이번 설계에서 발전시킨 지점 (plan.md 헤더 "참고 사이트 대비 발전"과 동일):

1. **기획 질문 추가** — 원형에는 "왜 만드는가"가 없다. 누가·언제·어떤 문제 / 왜 LLM이어야 하나 추가
2. **출력 설계 분리** — 원형은 프롬프트 템플릿 한 칸뿐. 모양·길이·말투·포함·금지를 별도 구역으로
3. **예외 입력 설계** — 장난·무관 입력 대응 (실제 개발자의 고민)
4. **온도 선택** — 직전 수업 온도 손잡이의 응용 실물
5. **테스트·개선 루프** — 원형에는 없음. 사용자 요구("개선 과정 포함")의 구현 자리
6. **키 발급 생략** — 학생 키 발급(원형의 큰 진입 장벽)을 수업 공용 임시 키로 대체
7. **생성 위임** — 고정 폼 생성기 대신 ChatGPT 바이브코딩 → 학생마다 다른 UI
8. **소유하는 결과물** — 학생이 파일을 저장·수정·제출 (프롬프트를 코드 안에서 직접 고치는 경험 가능)

## 3. Solar Pro 3 API — 조사 + 실측 (2026-08-26)

### 스펙 (저장소 내 Edge Function `supabase/functions/solar/index.ts` 실사용 + 공개 문서)

- 엔드포인트: `https://api.upstage.ai/v1/chat/completions` (OpenAI SDK 호환 Chat Completions)
- 모델명: `solar-pro3` (이 프로젝트의 solar-proxy가 2026-08-14 `GET /v1/models` 실측: solar-pro4 / solar-pro3 두 가지)
- 지원 파라미터: `temperature` · `max_tokens` · `stream` · `reasoning_effort`(공식 예제로 확인) · `response_format: {type:"json_object"}`(공개 문서로는 미확인 — 이 저장소 Edge Function `solar`가 실사용 중이라 동작은 확인됨. 이번 수업에서는 쓰지 않는다)
- ⚠ **`reasoning_effort: 'low'`는 수업 고정값** — API의 필수 필드가 아니다(공식 예제는 이 파라미터 없이도 호출한다). 다만 같은 프로젝트의 자체 실측에서 'medium'은 응답이 126~151초까지 늘어져 함수가 504로 잘린 전력이 있어, 이번 수업의 의뢰서 기술 명세에 'low'를 고정하고 경고를 함께 넣었다

### 실측 ① CORS — 브라우저 직접 호출 가능 여부

학생 결과물이 단일 HTML(서버 없음)이므로 브라우저에서 API를 직접 불러야 한다.
preflight 실측:

```
OPTIONS https://api.upstage.ai/v1/chat/completions
Origin: http://localhost:5199
→ 204 No Content
→ Access-Control-Allow-Origin: *
→ Access-Control-Allow-Headers: authorization, content-type
→ Access-Control-Allow-Methods: POST
```

**결론: 프록시 없이 브라우저 직접 호출이 된다.** 직전 수업 활동지가 Edge
Function을 둔 이유는 CORS가 아니라 ① 키 은닉 ② 정답지(시스템 프롬프트) 은닉
두 가지였다 — 이번 수업은 임시 키 + 학생 소유 프롬프트라 둘 다 해당 없음.

### 실측 ② 활동용 키 검증

사용자 제공 키 `YOUR_UPSTAGE_API_KEY` (활동 기간에만 개방)로 실호출:

- 요청: model solar-pro3 · reasoning_effort low · temperature 0.7 · max_tokens 200
- 응답: 정상 (응답 모델 식별자 `solar-pro3-260323`) · **소요 0.5초** · reasoning_tokens 0

⚠ 유의: 이 키는 데모·주문서·학생 HTML에 평문으로 들어가고 저장소·배포에
공개된다. 수업 종료 후 비활성화가 전제. 학급 전체가 한 키를 공유하므로 분당
호출 제한 가능성 → 모든 산출물에 "로딩 중 버튼 잠금 + 실패 시 잠시 후 재시도
안내"를 필수로 넣고, 교사 확인 항목에 예비 키를 두었다.

## 4. ChatGPT 무로그인(게스트) 현황

- chatgpt.com은 계정 없이 게스트로 사용 가능 (2024-04-01 OpenAI 공식 발표, 2026 현재 유지 — 지역·배포 상태에 따라 로그인 요구가 나타날 수 있음)
- 게스트 제한: 사용량·기능 제한이 있으나 고정 수치는 비공개. 대화는 기록에 저장되지 않으며 브라우저 세션이 끝나거나 새 대화를 시작하면 다시 접근하지 못할 수 있다. 코드 블록 생성은 가능(복사 버튼이 안 보이면 전체 선택 복사로 대체)
- 무료 로그인 계정도 모델·시점에 따라 사용량 제한이 있으며 한도는 변동된다
- → 수업 운영: **로그인 권장, 게스트로도 진행 가능**을 공지. 개선 시 "같은 대화"에 수정 요청해야 하므로(의뢰서 기억) 게스트는 탭을 닫지 않게 안내
- ⚠ 학교망에서 chatgpt.com 접속 가능 여부는 수업 전 교사 확인 필요

## 5. "로그인 없이 써 볼 예시" 조사 → 데모 자작 결정

로그인 없이 체험 가능한 LLM 서비스 후보를 조사한 결과:

- ChatGPT(게스트)·Perplexity(게스트)·Microsoft Copilot 등은 가능하지만 전부 **범용 챗봇** — "채팅창이 아닌, 프롬프트가 숨은 서비스"라는 이번 수업의 관찰 대상이 아니다
- 스픽·뤼튼·듀오링고 등 "프롬프트가 숨은" 실서비스는 로그인·결제 장벽
- → **사용자가 제안한 대안대로 데모 3종을 직접 제작**하는 것이 정답: 학생 결과물과 완전히 같은 구조(단일 HTML + Solar 직접 호출)라 예시이자 모범 답안이 되고, [🔍 내부 보기] 토글로 프롬프트 조립 과정을 열어 보일 수 있다 — "내 프롬프트가 프로그램에서 어떻게 쓰이는지 간접 체험"이라는 수업 목표를 예시 단계부터 시작시킨다

데모 3종 설계 (분야 다양화 + 설계 포인트 분담):

| 데모 | 분야 | 설계 포인트 | 온도 |
|---|---|---|---|
| 면접 리허설 코치 | 진로 | 입력 2칸이 프롬프트 두 빈칸으로 조립 | 0.7 |
| 벼락치기 설계사 | 학습 | 출력 형식 강제, 낮은 온도(한결같은 계획) | 0.3 |
| 3줄 위로 | 감성 | 형식 제약·말투 규칙·예외 처리, 높은 온도(매번 다른 위로) | 1.1 |

온도를 일부러 다르게 → S2 체험 미션 ②("같은 입력 두 번")가 직전 수업 온도
개념의 실측 재현이 된다.

## 7. 핵심 설계 결정 요약 (근거 포함)

1. **예시는 체험→해부 순서** — 데모를 먼저 쓰게 하고(S2) 차이를 스스로 말하게 한 뒤(S3 live) 내부를 폭로(S4). 구체→추상.
2. **LLM API를 두 장으로 설명** (사용자 추가 요청 2026-08-26) — S5 개념(프로그램이 드나드는 뒷문, whiteboard) + S6 해부(주문서 네 줄·응답·토큰 요금). 실서비스 사례(S7)는 API를 배운 뒤에 배치해 "API로 만든 회사"가 완전히 읽히게.
3. **학생은 서비스 핵심만 쓴다** — 웹 기술 명세는 활동지 D가 고정 블록으로 제공, 학생 설계와 자동 조립. (사용자 지시: 바이브코딩용 프롬프트는 학생이 쓰지 않음)
4. **개선의 두 창구** — 답이 이상하면 프롬프트(메모장에서 ★ 배너 속 SYSTEM_PROMPT 직접 수정), 화면이 이상하면 코드(같은 ChatGPT 대화에 수정 요청). 이 판별 행동이 "프롬프트가 서비스의 심장"이라는 핵심 배움의 행동판. 이를 위해 기술 명세가 **프롬프트를 파일 상단 상수로 두도록 강제**한다.
5. **키를 코드에 넣는 것을 숨기지 않고 가르친다** — 직전 수업(키를 서버에 숨김)과의 대비 자체를 키 윤리 수업 소재로(S13). 마지막 발문(S19 "사용자 100명이면 뭘 고칠까")의 답 중 하나로 회수.
6. **제출은 기존 인프라 재사용** — 과목 공용 apps-script.js + 제출현황.html + 제출 암호 이어쓰기. 코드 전문 붙여넣기는 Sheets 셀 한도(50,000자) 경고 포함.
