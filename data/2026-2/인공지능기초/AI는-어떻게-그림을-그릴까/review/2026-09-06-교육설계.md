**판정: 현재안은 정상 접속을 전제로도 시간 여유가 없고, 교구와 정답 해설이 수업 목표에 반하는 오개념을 만들 수 있습니다.** 특히 ‘분포’의 의미, 확산의 역과정, GAN과 확산의 구별 기준은 수정이 필요합니다.

제공된 텍스트를 심사했습니다. 실제 사진·교구 코드·학생 기기에서의 실행은 검증하지 않았으므로, 이미지의 진위와 구현 동작은 단정하지 않습니다. 아래 시간은 운영 추정이며, 파일은 수정하지 않았습니다.

**시간 배분과 도구 운영**

**1. 100분에 들어가지만, 지연은 단 1분도 허용하지 않는다.**  
원문 인용 → “S1~S3 도입 8분 · S4 4분 · S5~S7 GAN 12분 · S8~S11 확산 24분 … S16 2분.”  
무엇이 문제인가 → 합계는 **휴식 제외 95분**이다. 휴식 5분이면 정확히 100분, 휴식 10분이면 105분이다. 링크 이동·재로그인·질문·문항 응답 대기를 각 구간 안에 흡수해야 한다. S12 종료도 이미 52분이어서 50분 단위 운영이라면 첫 차시 경계를 넘는다.  
구체적 수정안 → 휴식 포함 여부를 확정하고 예비시간을 편성한다. 예: 도입 7분 / S4 5분 / GAN 10분 / 확산 22분 / S12 3분 / 휴식 5분 / S13 8분 / 실습 26분 / S15~16 7분 / 지연 흡수 7분 = 100분. 이 배분은 아래의 내용 축소와 접속 사전 점검을 전제로 한다.

**2. S2의 시연은 현재 실패 이력이 있는 경로에 도입 전체를 건다.**  
원문 인용 → “교사가 한 글자씩 타이핑합니다. 낱말이 늘 때마다 그림이 흔들리며 바뀝니다.” / “대기열이 길면 예시 이미지로”  
무엇이 문제인가 → 참여 링크 접속, 낱말 수집, 상위어 선정, 영어 문장 구성, Space 호출까지 8분 안에 포함된다. 제공된 익명 접속 실측대로 60초 타임아웃이 나면 재시도 한 번만으로 도입이 무너진다. 정지 이미지 한 장은 ‘조건을 바꾸면 생성이 달라진다’는 시연을 대체하지 못한다.  
구체적 수정안 → 수업 전 실행을 확인하되, 수업 중 응답이 15초 안에 없으면 즉시 전환한다. 같은 시드에서 구절을 하나씩 추가한 **3단계 이미지와 짧은 녹화**를 준비한다. 학생 낱말과 다른 예시라면 그 사실을 밝히고, 실시간 시연 성공을 도입 성립 조건에서 뺀다.

**3. S7의 “30초”는 생성 시간이 아니라 전체 조작 시간이어야 한다.**  
원문 인용 → “StyleGAN3 Space — 시드만 바꿔 보기 … 교사 시연 30초”  
무엇이 문제인가 → 탭 전환·앱 준비·설명·시드 변경·응답 대기를 30초로 계산하면 같은 외부 서비스 위험을 다시 떠안는다. S5 투표와 GAN 학습 설명까지 들어 있는 12분 구간이다.  
구체적 수정안 → 시드가 다른 얼굴 두 장을 기본 자료로 사용한다. 실시간 변경은 이미 준비된 화면이 즉시 응답할 때만 추가하고, 30초가 지나면 종료한다.

**4. S10의 10분은 ‘열린 교구’에서 시작할 때만 가능성이 있다.**  
원문 인용 → “각자 기기에서 새 탭으로” / “조작 교구 10분”  
무엇이 문제인가 → 30명 모두 링크 열기·로딩·화면 방향 파악·버튼 찾기부터 시작한다. 접속과 안내 3분, 세 과제 각 2분, 비교 1분이면 이미 10분이다. 6명에게 30초씩만 개별 지원해도 교사 지원 시간은 3분이며, 다른 학생의 이탈까지 발생한다. 실제 성능은 미검증이므로 느리다고 단정할 수는 없지만, 복구 시간이 없는 것은 확실하다.  
구체적 수정안 → 단축 링크·QR과 첫 화면 그림을 제공하고, 접속 실패 1분 후에는 짝 화면으로 이동시킨다. 10분은 접속 2분 / 공통 조작 2분 / 분포·시드 비교 4분 / 설명 2분으로 제한하고, 픽셀 추적은 빠른 학생의 확장 과제로 내린다. 3D가 안 되면 단계별 2D 그림을 쓰게 한다.

**5. S13의 5분과 S14의 남는 6분은 로그인 복구 예산으로 부족하다.**  
원문 인용 → “krea.ai 접속 · 로그인” / “실습 · 30분” / “라운드 1 · 8분 … 라운드 3 · 8분”  
무엇이 문제인가 → 세 라운드는 24분이라 6분이 남지만, 라운드 전환·설명도 이 시간을 쓴다. 구글 로그인 가능 여부, 학교 계정의 외부 앱 접근, 학생별 잔여 한도는 기기를 가져왔다는 사실로 보장되지 않는다. S13에서 처음 확인하면 교사는 계정 지원 담당자가 된다.  
구체적 수정안 → 수업 전에 학교 네트워크와 실제 학생 계정 유형으로 로그인·Realtime 접근·첫 생성까지 확인한다. 당일에는 접속 성공 여부를 먼저 확인하고, 2분 내 해결되지 않는 학생은 작동하는 기기에서 번갈아 조작하도록 배치한다. 비밀번호 복구를 수업 전체의 대기 조건으로 삼지 않는다.

**6. 100 compute unit은 6~9분 실습을 보장하는 시간권이 아니다.**  
원문 인용 → “하루 한도(100 compute unit) — 라운드마다 2~3분 집중해서 만지고 잠시 멈춘다”  
무엇이 문제인가 → **100/day 자체는 공식 무료 플랜 안내에 있다.** 문제는 이 숫자를 실습 가능 시간으로 환산한 근거가 없다는 것이다. 공식 안내는 모델·품질 등에 따라 소모가 달라지고 사용량 표시도 보통 1~2분 늦을 수 있다고 설명한다. ‘잠시 멈춘다’도 손만 떼라는 뜻인지 생성 세션을 중단하라는 뜻인지 불분명하다. [플랜 안내](https://www.krea.ai/docs/user-guide/help-and-support/manage-subscriptions), [사용량 안내](https://www.krea.ai/docs/user-guide/help-and-support/compute-units)  
구체적 수정안 → 학생용 무료 계정과 지정 모델로 세 라운드를 그대로 수행하고, 사용량 반영을 기다린 뒤 총소모를 측정한다. 연속 타이핑 대신 **정해진 비교 상태만 생성**하게 하고, 생성 중단 방법을 실제 UI로 안내한다. 한도가 모자라면 관찰 자료로 전환하는 기준을 넣는다.

**7. Realtime-FLUX는 같은 수업을 이어 주는 예비 도구가 아니다.**  
원문 인용 → “예비 — Realtime-FLUX … 로그인이 안 될 때 · Realtime 끄고 Enter”  
무엇이 문제인가 → Realtime을 끄는 것은 요청 빈도를 줄일 수 있지만 GPU 대기열을 없애지는 않는다. 사용자 실측에는 익명 60초 타임아웃이 있고, 공개 Space도 ZeroGPU 실행으로 표시된다. 또한 자료에는 이 도구로 스케치·강도 과제를 수행하는 대체 절차가 없다. [해당 Space](https://huggingface.co/spaces/KingNish/Realtime-FLUX)  
구체적 수정안 → 대안을 세 단계로 둔다. **개별 Krea → 작동 기기에서 짝별 교대 → 사전 생성 비교 자료와 교사 시연**이다. 마지막 단계에서도 프롬프트·스케치·강도·시드 비교 자료를 각각 제공한다. 다만 전면 장애 시 ‘각자 실시간 생성’ 목표는 달성하지 못했음을 인정하고 별도 보완 기회를 잡아야 한다.

**개념 분류와 설명의 결함**

**8. 두 계단은 비교 틀로 쓸 수 있지만, 기술 전체의 교체 역사로 쓰면 틀린다.**  
원문 인용 → “그림을 만드는 기계는 두 번 바뀌었다” / “① 2014 · GAN … ② 2020 · 확산 모델 … ③ … 트랜스포머”  
무엇이 문제인가 → GAN→확산→트랜스포머를 서로 대체하는 동급 분류로 보이게 한다. 트랜스포머는 확산 모델 내부에도 쓰이는 신경망 구조다. 확산 계열의 선행 연구도 2015년에 있어 2020을 탄생 연도로 읽히게 하면 부정확하다. [DiT 논문](https://arxiv.org/abs/2212.09748), [2015년 확산 연구](https://arxiv.org/abs/1503.03585)  
구체적 수정안 → 제목을 “이미지 생성을 배우는 대표적인 두 방식”으로 바꾸고 “GAN의 대표 출발점: 2014 / DDPM: 2020”으로 표시한다. 다음 수업 예고에는 “트랜스포머는 확산 모델 안에도 사용될 수 있다” 한 문장만 넣는다. 별도 수업으로 뺀 결정 자체에는 문제가 없다.

**9. ‘속이기’와 ‘걷어내기’는 비교하는 층위가 섞여 있다.**  
원문 인용 → “GAN은 속이는 법을, 확산 모델은 걷어내는 법을 배웠다”  
무엇이 문제인가 → GAN은 학습의 경쟁 관계로, 확산은 생성 동작으로 기억하게 된다. “GAN은 생성할 때도 판별자와 대결한다”거나 “GAN은 노이즈를 한 번에 제거한다”는 오개념이 생긴다. S7의 “노이즈를 한 번에 없애지 말고”가 후자를 직접 강화한다.  
구체적 수정안 → 학습과 생성을 같은 축으로 비교한다. “GAN 학습: 판별자의 평가로 생성자를 개선 / 생성: 기본형에서는 생성자만 사용. DDPM 학습: 섞은 노이즈를 예측하도록 훈련 / 생성: 예측을 이용해 단계적으로 갱신.” GAN의 노이즈 입력은 지워야 할 오염이 아니라 다양한 출력을 만드는 출발값이라고 덧붙인다.

**10. GAN 정확도 50%를 학습 종료 조건으로 제시한 것은 오류다.**  
원문 인용 → “정확도가 50%에 닿으면 … 적대적 학습이 끝난다”  
무엇이 문제인가 → 약하거나 학습에 실패한 판별자도 50%를 낼 수 있다. 진짜·생성 표본의 비율에 따라서도 정확도 해석이 달라진다. 원 논문의 이상적 균형은 분포가 일치할 때 판별자 출력이 1/2이라는 설명이지, 정확도가 50%가 되는 순간 종료하라는 규칙이 아니다. [GAN 원 논문](https://arxiv.org/abs/1406.2661)  
구체적 수정안 → “진짜와 생성을 같은 수로 평가할 때, 잘 학습된 판별자가 구별하기 어려워지는 것이 이상적 목표다. 정확도 50%만으로 성공이나 종료를 판단하지 않는다”로 교체한다. 94→89%에도 “설명용 가상 수치, 실제 학습은 오르내림”을 표시한다.

**11. S4의 위치는 적절하지만, ‘분포’가 이후에 다른 뜻으로 회수된다.**  
원문 인용 → “오늘: 그림은 픽셀 값들의 분포” / “픽셀 값의 분포가 정규분포에서 얼마나 벗어났는지 본다”  
무엇이 문제인가 → S4는 여러 이미지에서 **위치별 픽셀 값들이 함께 구성되는 확률적 패턴**을 설명해야 한다. S10은 한 이미지 안의 값 빈도를 본다. 둘은 같은 대상이 아니다. 원본 사진의 픽셀 위치를 무작위로 섞으면 히스토그램은 그대로지만 그림은 망가진다. 현재는 분포가 회수되기는 하나 잘못 연결된다.  
구체적 수정안 → S4에 원본과 픽셀을 섞은 이미지를 나란히 넣고 “색의 개수만 같아서는 그림이 되지 않는다. 어디에 어떤 색이 함께 나타나는지도 배운다”를 추가한다. S6에서는 “생성 이미지의 분포를 실제 이미지의 분포에 가깝게”, S9에서는 “그럴듯한 이미지를 만들 수 있도록 노이즈 예측을 학습”으로 회수한다.

**12. 히스토그램만으로 ‘그림의 흔적 없음’을 판정할 수 없다.**  
원문 인용 → “막대가 점선과 겹치면 그림의 흔적이 남지 않은 완전한 노이즈”  
무엇이 문제인가 → 값의 히스토그램이 정규분포와 비슷해도 공간적 규칙이 남을 수 있다. 반대로 유한한 무작위 표본의 히스토그램은 정규곡선에 정확히 겹치지 않는다. t가 내려갈수록 벗어나는 정도가 매 단계 단조롭게 증가한다는 보장도 없다.  
구체적 수정안 → “이 교구에서는 높은 t에서 값의 히스토그램이 정규분포와 비슷해지는 경향을 볼 수 있다. 이 그래프만으로 그림 정보가 사라졌는지는 판단할 수 없다”로 교체한다. 과제도 ‘얼마나 벗어났는가’ 대신 t=50·25·0에서 이미지와 그래프를 함께 비교하도록 바꾼다.

**13. 역과정이 원본을 복구하는 기록 되감기로 설명된다.**  
원문 인용 → “매 단계 무엇이 더해졌는지를 안다면, 한 단계씩 빼며 되짚을 수 있다” / “학습 경로를 그대로 되짚습니다”  
무엇이 문제인가 → 학생은 실제 생성에서도 원본과 그 원본에 넣은 노이즈 기록이 있다고 이해할 수 있다. DDPM의 생성은 특정 학습 사진의 경로를 그대로 복원하는 일이 아니다. 노이즈 예측을 이용한 갱신에는 단계별 계수 등이 있으며, 단순히 실제로 더했던 값을 빼는 계산으로 끝나지 않는다. [DDPM 논문](https://arxiv.org/abs/2006.11239)  
구체적 수정안 → “학습에서는 정답 노이즈를 알고 예측을 연습한다. 생성에서는 새 무작위 노이즈에서 시작하고, 학습한 예측을 이용해 그림을 만들어 간다”를 구분해 제시한다. 교구에는 “원본을 아는 되감기 모형이며 실제 신경망 생성과 다르다”를 조작 전에 읽게 한다.

**14. ‘더해진 노이즈’는 직전 단계 노이즈와 누적 노이즈로 두 가지 해석이 가능하다.**  
원문 인용 → “더해진 노이즈 ε을 맞혀라” / “확산 모델은 「더해진 노이즈」를 고른다”  
무엇이 문제인가 → 앞의 ‘한 겹씩’ 때문에 직전 단계에 추가한 한 겹만 맞힌다고 읽힌다. 표준 DDPM의 대표적인 학습 설명에서는 깨끗한 그림으로부터 현재 t의 그림을 만들 때 섞은 전체 노이즈를 예측한다. ‘고른다’는 표현도 LLM처럼 후보 중 하나를 선택하는 것으로 오해될 수 있다.  
구체적 수정안 → “원래 그림에 현재 단계만큼 섞은 노이즈 값을 예측한다”로 바꾼다. LLM 연결은 “둘 다 확률적 패턴을 배우지만, 오늘 모델은 다음 낱말 대신 노이즈의 수치 배열을 예측한다”까지만 한다.

**15. 교구의 시드 과제가 교구 자신의 가정과 충돌한다.**  
원문 인용 → “목표 그림 네 가지는 수식으로 그린 도형이고 신경망은 없습니다” / “노이즈 예측이 완벽하다고 가정해 학습 경로를 그대로 되짚습니다” / “시드가 다르면 조금 다른 그림이 나옵니다”  
무엇이 문제인가 → 같은 목표 도형의 정과정을 완벽하게 되짚는다면 시드가 달라도 최종 t=0은 같은 목표로 돌아가야 한다. 최종 도형도 달라진다면 별도의 시드 의존 규칙이 있다는 뜻이다. 코드 없이 어느 쪽인지는 확정할 수 없지만, 제공된 설명끼리는 일관되지 않는다.  
구체적 수정안 → 실제 동작을 확인해 둘 중 하나로 명시한다. 목표가 고정이면 “출발 노이즈와 중간 경로는 다르지만 이 교구의 최종 도형은 같다. 실제 생성 모델은 최종 결과도 달라질 수 있다.” 도형도 바뀌면 “변형은 교구가 정한 수식이며 신경망이 생성한 것이 아니다”라고 밝힌다.

**16. t 하나가 그림 전체를 정한다는 문장은 같은 슬라이드의 시드 과제와 모순된다.**  
원문 인용 → “단계 t 하나가 노이즈와 그림 사이의 모든 것을 정한다”  
무엇이 문제인가 → 같은 t여도 프롬프트·시드에 따라 상태가 달라진다. 학생이 t를 ‘사과가 얼마나 완성됐는가’라는 만능 손잡이로 받아들이면 조건과 무작위성의 역할을 잃는다.  
구체적 수정안 → “프롬프트와 시드를 고정하면, t를 움직여 이 교구의 중간 상태를 살펴볼 수 있다”로 바꾼다.

**17. S11은 네 개의 새 개념과 한 개의 평가를 한 장에 몰아넣었다.**  
원문 인용 → “① 텍스트 조건 … ② 이미지 조건 … ③ 잠재 공간 … ④ 증류” / “그림 조각이 낱말을 쳐다본다 — 어텐션”  
무엇이 문제인가 → 벡터·이미지 조건·강도·어텐션·잠재 공간·증류를 연결한 뒤 즉시 문항까지 푼다. S8~11의 24분에서 교구 10분을 빼면 네 장 설명과 평가에 14분뿐이다. 이전에 어텐션을 배웠어도 텍스트와 이미지 사이 연결은 새 전이다.  
구체적 수정안 → 필수 화면에는 텍스트 조건과 이미지 조건만 남긴다. 잠재 공간·증류는 “압축된 표현에서 계산하기 / 적은 계산 단계로 비슷한 품질 내기” 두 보충 문장으로 내리고, 어텐션 재설명은 선택 노트로 옮긴다. “같은 답”은 “비슷한 품질의 결과”로 고친다.

**18. 강도와 t의 대응이 실제 Krea 내부 사실처럼 제시된다.**  
원문 인용 → “노이즈를 얼마나 더한 뒤 되돌리느냐 = 강도(strength)” / “AI Strength ↔ 출발 단계 t의 높이” / “대응 관계로만 읽어 주세요”  
무엇이 문제인가 → 작은 주의문은 등호와 대응표의 강한 인상을 이기기 어렵다. 교구에서 t를 옮겨 중간 상태를 보는 것과, 이미지 조건 생성에서 출발 노이즈 수준을 바꾸는 것도 다른 조작이다. Krea의 강도를 DDPM의 특정 t와 정확히 같다고 확인한 근거는 없다.  
구체적 수정안 → 본문부터 “이미지에 노이즈를 더해 다시 생성하는 방식으로 강도의 효과를 비유할 수 있다. Krea에서 직접 관찰할 것은 입력 스케치를 얼마나 따르는가다”로 바꾼다. 대응표의 등가 표현과 수치 환산은 없앤다.

**실시간 문항 4개의 타당성**

**19. 문항 1 `word-to-image`: 정답 문제는 없지만, 제약이 일관되지 않다.**  
원문 인용 → “낱말 하나만 … 사물·장소·동물” / 예시 “고양이 · 밤 · 편의점”  
무엇이 문제인가 → 워드클라우드이므로 정답 판정의 문제는 없다. 다만 ‘밤’은 안내한 범주 밖의 시간 표현이고, 자주 나온 세 낱말이 자연스러운 장면을 이룬다는 보장도 없다. 이는 개념 평가가 아니라 참여 유도 활동이다.  
구체적 수정안 → 범주에 “시간·분위기”를 추가하고, “많이 나온 말 중 함께 장면을 만들 수 있는 세 개를 고른다”로 고친다. 학습목표 달성 증거로는 계산하지 않는다.

**20. 문항 2 `real-photo`: 정답 하나는 성립하지만, 시각적 판단의 정답과 혼동한다.**  
원문 인용 → “A~D 중 실제로 촬영된 사진은?” / `"answer": 2`  
무엇이 문제인가 → 실제 출처가 C 하나라면 사실 문항으로 단일 정답은 가능하다. 그러나 이미지 없이 C의 진위를 검증할 수는 없다. 외형만으로 출처를 확정할 수 없는 상황에서 학생의 합리적 불확실성을 오답으로 처리하면 “AI 여부는 눈으로 판별할 수 있다”를 가르친다. 출처 표시는 답 공개 뒤에만 보여야 한다.  
구체적 수정안 → 점수 없는 예측 활동으로 운영하고, 선택과 함께 확신 정도를 묻는다. 공개 뒤 “C는 촬영 출처가 확인된 사진이다. 외형만으로 확정할 수 있었던 것은 아니다”라고 정리한다. 출처를 확인하는 문제와 눈으로 추측하는 문제를 구별한다.

**21. 문항 2의 해설은 관찰하지 않은 결함을 찾도록 유도한다.**  
원문 인용 → “물리적으로 맞지 않는 곳이 있는지 다시 보세요” / “글자가 없는 간판, 반사의 방향을 다시 보세요” / “여러분은 방금 판별자가 되었다”  
무엇이 문제인가 → 빈 간판은 실제 사진에도 있고, 물리적 오류가 없는 AI 이미지도 있다. 실제 이미지를 보지 않은 상태에서는 해당 결함이 존재하는지도 확인할 수 없다. 또한 네 장 중 진짜 하나를 고르는 사람의 과제는 각 표본을 평가하는 기본 GAN 판별자와 다르다. 무작위 사지선다의 25%와 S6의 50%도 연결되지 않는다.  
구체적 수정안 → 해설을 “그렇게 판단한 단서는 무엇인가? 그 단서만으로 출처를 확정할 수 있는가?”로 바꾼다. “판별자 역할을 일부 흉내 냈다”로 한정하고, GAN에서는 정답 출처가 알려진 학습 표본으로 판별자를 훈련한다는 차이를 설명한다.

**22. 문항 3 `gan-vs-diffusion`: 정답과 해설에 직접적인 반론이 가능하다.**  
원문 인용 → 정답 “노이즈를 여러 단계에 걸쳐 걷어내며 그림을 만든다” / “1~4로 줄여도 ‘여러 단계’라는 구조는 같습니다”  
무엇이 문제인가 → **1단계는 여러 단계가 아니다.** 바로 앞에서 1~4단계 증류를 배운 학생이 선지 ③을 떠올리는 것은 합리적이다. “확산 모델에는 판별자가 없고 … 시험만 있습니다”도 확산 계열 전체로 확대하면 적대적 증류 같은 사례 때문에 성립하지 않는다. [적대적 확산 증류 논문](https://arxiv.org/abs/2311.17042)  
구체적 수정안 → 문항을 “오늘 배운 **기본 DDPM의 학습 과제**는?”으로 바꾸고, 선지는 ① 생성자를 속이는 문장 만들기 ② 노이즈 낀 그림과 t로 섞인 노이즈 예측하기 ③ 학습 그림 파일 검색하기 ④ 사람이 정한 픽셀 값을 복사하기로 구성한다. 정답은 ②이며, GAN과의 차이는 판별자 평가를 학습 신호로 쓰는지로 설명한다.

**23. 문항 3의 조건 부여 해설은 GAN에 조건을 줄 수 없다는 인상을 남긴다.**  
원문 인용 → “조건 부여의 어려움” / “확산 모델은 텍스트 조건을 주기가 GAN보다 쉬워서 널리 쓰이게 되었습니다”  
무엇이 문제인가 → 복잡한 자유문장 제어의 어려움과 조건 부여 자체의 가능성을 섞는다. 조건부 GAN은 존재하며, 조건 부여 가능 여부는 두 계열을 가르는 기준이 아니다. [조건부 GAN 원 논문](https://arxiv.org/abs/1411.1784)  
구체적 수정안 → “GAN에도 조건을 줄 수 있다. 여기서는 초기의 대표적인 GAN과 텍스트 조건 확산 모델을 비교한다”로 한정한다. 선지 ④ 해설도 “오늘 배운 확산 모델은 텍스트 조건을 사용할 수 있다”면 충분하다.

**24. 문항 4 `exit`: ‘오늘 배웠다’는 주체와 시점이 모호하다.**  
원문 인용 → “오늘 실습한 Krea Realtime이 ‘배운 것’은 무엇인가요?”  
무엇이 문제인가 → 수업 중 프롬프트를 입력하면서 모델이 새로 학습했다는 답을 유도할 수 있다. “분포” 한 단어만 적어도 통과하는지, 노이즈 예측을 설명해야 하는지 기준도 없다. Krea 제품 전체를 특정 학습 방식 하나로 단정하는 문제도 있다.  
구체적 수정안 → “오늘 배운 DDPM은 **학습 때 무엇을 예측하도록 훈련되며**, 생성 때 그 예측을 어떻게 사용하는가?”로 바꾼다. 인정 기준은 ‘노이즈 예측’과 ‘새 노이즈에서 그림을 만드는 데 사용’ 두 요소로 잡는다. GAN과의 구별은 별도로 짝에게 20초씩 설명하게 한다.

**학생의 손이 멈추는 지시와 실습**

**25. 교구 과제 ①은 순서가 두 가지로 읽히며 버튼 이름도 다르다.**  
원문 인용 → “「▶ 생성」을 끝까지 재생한 뒤 t = 25에서 멈추고” / 실제 버튼 “◀ 생성 · 역과정 — 노이즈 걷어내기”  
무엇이 문제인가 → 끝까지 가서 다시 25로 옮기라는 뜻인지, 재생 도중 25에서 멈추라는 뜻인지 모호하다. 지시의 ▶와 실제 ◀도 반대다. 학생은 ‘생성’ 대신 정과정 버튼을 누르거나, 25를 지나쳤다고 처음부터 재생할 수 있다.  
구체적 수정안 → “① ‘◀ 생성 · 역과정’을 눌러 t=0까지 기다린다. ② 재생이 끝나면 t 슬라이더를 직접 25로 옮긴다. ③ t=50·25·0의 화면을 비교한다”로 분리한다. 슬라이드·교구·완료 문구에 같은 버튼 이름을 쓴다.

**26. 교구 과제 ②는 비교 시점과 비교 대상이 없다.**  
원문 인용 → “같은 프롬프트로 다시 생성한다. 무엇이 같고 무엇이 다른가?”  
무엇이 문제인가 → 출발 노이즈·중간 그림·최종 도형 중 무엇을 비교하는지 정하지 않았다. 이전 결과가 사라지면 기억으로 비교해야 한다. 프롬프트가 자유 입력인지 네 도형 선택인지도 문구만으로 알 수 없다.  
구체적 수정안 → “같은 도형 조건에서 시드 A와 B의 t=50, t=25, t=0을 각각 비교한다. 출발값 / 중간 무늬 / 최종 도형을 말한다”로 좁힌다. 비교 화면을 유지하거나 짝과 서로 다른 시드를 사용하게 하고, 예상 답은 15번의 교구 동작 확인 후 확정한다.

**27. 교구 과제 ③은 ‘클릭 성공’과 ‘변화 추적’을 혼동한다.**  
원문 인용 → “큐브 하나를 클릭해 R·G·B 값이 단계마다 어떻게 변하는지 추적한다” / 완료 상태 “행 … 열 … 추적 중”  
무엇이 문제인가 → 작은 큐브를 고르는 동안 카메라가 움직일 수 있고, 빠르게 바뀌는 세 숫자를 읽기 어렵다. 제공된 완료 문구는 선택된 좌표를 보여 줄 뿐 여러 단계의 값을 비교했는지는 확인하지 않는다. ‘값이 일정하게 증가하거나 감소해야 한다’는 예상도 생길 수 있다.  
구체적 수정안 → 기본 선택 픽셀을 지정하고 t=50·25·0의 세 상태만 비교시킨다. “같은 위치의 값이 바뀌지만 매번 한 방향으로 변하는 것은 아니다”를 관찰 기준으로 준다. 클릭은 선택 과제로 두고 완료 기준을 조작보다 설명에 둔다.

**28. Krea 라운드 1은 ‘길수록 좋지 않다’를 검증하지 못한다.**  
원문 인용 → “프롬프트는 길수록 좋다” / “‘apple’ → ‘a red apple on a wooden table’ → ‘…, soft morning light, water drops’”  
무엇이 문제인가 → 예시에서는 길이와 구체성이 함께 증가한다. 더 잘 맞는 결과가 나오면 학생은 오히려 “길수록 좋다”를 확인한다. 시드·모델 등이 고정되지 않으면 프롬프트 효과와 우연한 변화를 구별하기도 어렵다.  
구체적 수정안 → 라운드 목표를 “구체적인 조건을 추가했을 때 무엇이 반영되는가”로 바꾸거나, 정보 없는 반복과 구체적 조건을 비교하는 별도 짝을 넣는다. 모델·시드·화면비를 고정하고, 미적 선호 대신 ‘빨강 / 탁자 / 빛 / 물방울 반영 여부’를 관찰한다.

**29. 빈 캔버스는 ‘이미지 조건 없음’과 같지 않다.**  
원문 인용 → “캔버스는 비운 채”  
무엇이 문제인가 → Draw 모드의 빈 배경도 이미지 입력일 수 있다. 학생마다 모드가 다르면 같은 프롬프트 비교가 달라진다. 공식 문서는 별도의 Text Only 모드가 시각 입력을 끈다고 설명한다. [Krea Realtime 안내](https://www.krea.ai/docs/user-guide/features/realtime)  
구체적 수정안 → 라운드 1은 사전 확인한 Text Only 모드로 통일하고, 라운드 2 시작 때 Draw 모드로 전환하는 절차를 명시한다. 해당 계정에서 모드를 쓸 수 없다면 배경과 강도를 동일하게 맞추고 이미지 조건이 남아 있음을 설명한다.

**30. 라운드 2는 ‘그리기’와 ‘옮기기’ 사이에서 막힌다.**  
원문 인용 → “브러시로 빨간 원 하나 — 그 자리에 사과” / “빨간 원 하나를 그리고, 옮기고, 둘로 늘려 본다”  
무엇이 문제인가 → 브러시로 그린 획을 어떻게 선택·이동·복제하는지 안내가 없다. 원 두 개와 단수 사과 프롬프트가 충돌하면 두 사과가 안 나올 수 있다. 빨간 원이 반드시 그 자리에 사과가 된다는 보장도 없다.  
구체적 수정안 → 이동 가능한 원 도형 도구와 선택 도구를 사용하도록 안내한다. “사과를 그 자리에 만들도록 유도한다”로 표현을 낮춘다. 위치 이동 실험에서는 개수를 고정하고, 두 원 실험에서는 프롬프트의 개수 조건도 어떻게 처리할지 명시한다. 공식 문서에도 도형·선택 도구가 구별되어 있다. [도구 안내](https://www.krea.ai/docs/user-guide/features/realtime)

**31. 라운드 3의 성공 기준이 잘못됐다.**  
원문 인용 → “스케치가 언제 사라지는지 본다” / “높음 — 프롬프트가 구도를 새로 정한다”  
무엇이 문제인가 → 입력 캔버스에서 선이 사라지는 것인지 출력에서 영향이 약해지는 것인지 모호하다. 높은 강도에서도 형태가 남을 수 있어 ‘사라지는 임계값’ 찾기는 실패할 수 있다. 모델·시드가 달라지면 강도의 효과도 분리되지 않는다.  
구체적 수정안 → “입력 원의 위치·개수·색을 출력이 얼마나 유지하는지 비교한다”로 바꾼다. 같은 시드에서 강도 세 값을 비교한 뒤 강도를 하나로 고정하고 시드만 변경한다. 원이 남아도 정상적인 관찰 결과로 인정한다.

**32. 재현성을 너무 절대적으로 약속한다.**  
원문 인용 → “같은 모델 · 같은 설정 · 같은 시드면 같은 그림이 나온다”  
무엇이 문제인가 → 교육용 결정적 모형에서는 맞을 수 있지만 서비스에서는 입력 캔버스·모델 버전·실행 환경까지 같아야 한다. 학생은 숨은 설정 변경이나 서비스 변화를 자신의 조작 실패로 받아들일 수 있다.  
구체적 수정안 → “동일한 입력·모델 버전·설정과 결정적인 실행 조건에서는 시드를 고정해 결과를 재현할 수 있다. 이 실습에서는 같은 시드가 비교 조건을 맞추는 데 도움을 준다”로 한정한다.

**학생 눈높이의 어휘 부담**

**33. 정과정·역과정·노이즈 스케줄을 동시에 외워야 한다.**  
원문 인용 → “DDPM · 코사인 노이즈 스케줄 · T = 50” / “정과정” / “역과정”  
무엇이 문제인가 → ‘정’이 정답, ‘역’이 정확한 역산을 뜻하는 것처럼 읽힌다. T와 t의 차이까지 보태지만 과제를 수행하는 데 코사인 함수는 필요하지 않다.  
구체적 수정안 → 처음에는 “그림에 잡음을 섞기(정과정)”와 “학습한 예측으로 그림 만들기(역과정)”로 병기한다. 스케줄은 “단계마다 잡음을 얼마나 섞을지 정한 표”, t는 “현재 단계”, T는 “전체 단계 수”로 풀이하고 코사인은 접힌 설명으로 내린다.

**34. 가우시안 노이즈와 RGB 값의 범위가 연결되지 않는다.**  
원문 인용 → “R · G · B 값 셋 (0~255)” / “표준정규분포 N(0, 1)” / “√ᾱ”  
무엇이 문제인가 → 0~255의 색 숫자를 보다가 음수도 있는 평균 0의 분포로 넘어간다. 축이 픽셀값인지 노이즈값인지, 어떤 정규화가 적용됐는지 설명되지 않았다. 뜻을 읽을 수 없는 기호는 ‘실제 계산’이라는 권위만 더한다.  
구체적 수정안 → “가우시안 노이즈는 0 근처가 자주, 큰 양수·음수가 드물게 나오는 무작위 값”으로 설명한다. 그래프 축에는 실제 구현의 단위와 변환을 표시한다. RGB 표시값과 계산용 값을 구별하고, √ᾱ 수식은 선택 설명으로 숨긴다.

**35. 잠재 공간·증류·시드·강도는 이름만으로 역할을 추측하기 어렵다.**  
원문 인용 → “압축된 공간” / “증류” / “시드(seed)” / “AI Strength”  
무엇이 문제인가 → 잠재 공간은 파일을 압축하는 ZIP, 증류는 중요한 그림만 추리기, 시드는 그림 번호, 강도는 화질이나 AI 능력으로 오해될 수 있다. 모두 ‘숫자 손잡이’처럼 보이지만 역할이 다르다.  
구체적 수정안 → 각각 “신경망이 쓰는 압축된 특징 표현”, “많은 단계의 생성 동작을 적은 단계로 흉내 내도록 다시 학습”, “무작위 수열을 재현하는 시작 번호”, “입력 스케치를 얼마나 따르는지에 영향을 주는 조절값”으로 풀어 쓴다. 필수 확인은 시드와 강도에 집중한다.

**교사 개입이 없을 때의 실패 시나리오 3개**

**36. 실패 시나리오 ① — 일부는 생성하고 일부는 끝까지 로그인한다.**  
원문 인용 → “구글 계정으로 로그인 · 무료 플랜” / “로그인이 안 될 때 … Realtime-FLUX”  
무엇이 문제인가 → 접속 실패 학생을 HF로 보내지만 그쪽에서도 대기한다. 교사가 계정 문제를 해결하는 동안 성공한 학생은 임의 생성으로 한도를 소진한다. 마지막 라운드에는 생성할 수 있는 학생이 줄고, 결과 화면은 있어도 조건 비교는 없다.  
구체적 수정안 → 접속 복구 시간을 제한하고 실패 학생을 작동 기기에 즉시 배치한다. 성공 학생도 공통 시작 신호 전에는 추가 생성하지 않게 한다. 각 라운드의 생성 상태 수를 제한하고 교대 조작으로 실제 참여를 보장한다.

**37. 실패 시나리오 ② — 교구를 끝낸 학생이 ‘AI는 저장된 그림을 복구한다’고 설명한다.**  
원문 인용 → “어느 그림으로 수렴할지를 정한다” / “학습 경로를 그대로 되짚습니다”  
무엇이 문제인가 → 네 도형 중 하나를 고르고 노이즈를 지우자 같은 도형이 나온다. 학생에게는 “프롬프트로 목표 파일 선택→가림막 제거”라는 설명이 관찰 결과와 가장 잘 맞는다. S12의 “그림 파일이 아니다”는 선언만으로 이 경험을 이기기 어렵다.  
구체적 수정안 → 교구 시작 전과 종료 후에 “이 교구에는 목표 도형이 있지만 실제 생성은 특정 원본을 되감는 일이 아니다”를 확인한다. “이 교구와 실제 모델이 다른 점 하나”를 짝에게 말하도록 한다.

**38. 실패 시나리오 ③ — 예쁜 사과는 남지만 손잡이의 역할은 설명하지 못한다.**  
원문 인용 → “무엇이 바뀌는지 본다” / “옮기고, 둘로 늘려 본다” / “제출 없음”  
무엇이 문제인가 → 학생이 프롬프트·스케치·강도·시드를 동시에 바꿔 마음에 드는 결과만 남긴다. 어떤 변화가 무엇 때문인지 설명할 수 없고 출구 티켓에는 “픽셀 분포”를 복사한다. 제출 없음 자체는 문제가 아니지만, 관찰과 설명을 확인하는 절차도 없으면 학습 실패를 놓친다.  
구체적 수정안 → 라운드마다 “고정한 것 / 바꾼 것 / 관찰한 것”을 짝에게 한 문장으로 말하게 한다. 교사는 몇 쌍의 설명을 듣고 변인이 섞인 사례를 즉시 다시 시킨다. 이미지 제출은 추가하지 않아도 된다.

**치명적 3가지 — 우선순위**

**1순위: ‘분포’와 역과정을 잘못 가르치는 교구 설명**  
원문 인용 → “막대가 점선과 겹치면 … 완전한 노이즈” / “학습 경로를 그대로 되짚습니다”  
무엇이 문제인가 → 수업의 핵심 목표를 학생의 직접 조작 경험이 반박한다. 히스토그램과 이미지 분포를 혼동하고, 생성을 원본 복구로 이해하게 한다.  
구체적 수정안 → 히스토그램의 한계와 교구의 비신경망 가정을 전면에 표시하고, 시드별 최종 결과의 실제 동작을 확인해 과제를 다시 쓴다.

**2순위: 접속·한도 실패를 흡수하지 못하는 100분 운영**  
원문 인용 → “대기열이 길면 예시 이미지로” / “하루 한도(100 compute unit)” / “예비 — Realtime-FLUX”  
무엇이 문제인가 → 여유시간이 없고 예비 도구도 이미 실패한 경로다. 개별 실습이 중단되면 목표의 실천 부분을 잃는다.  
구체적 수정안 → 실제 학생 계정·네트워크로 사전 점검하고 소비량을 측정한다. 지연 예산, 짝별 교대, 네 손잡이별 사전 비교 자료를 준비한다.

**3순위: 개념을 이해한 학생에게 오답을 줄 수 있는 비교 문항**  
원문 인용 → “1~4로 줄여도 ‘여러 단계’라는 구조는 같습니다” / “정확도가 50%에 닿으면 … 학습이 끝난다”  
무엇이 문제인가 → 반례를 지적하는 학생이 맞고 정답 해설이 틀리는 상황이다. 두 계열을 구별하는 기준도 학습 방식과 생성 횟수 사이에서 흔들린다.  
구체적 수정안 → 기본 GAN과 기본 DDPM의 **학습 신호**를 기준으로 비교하고, 50% 종료 규칙과 ‘확산은 반드시 여러 단계’라는 해설을 삭제한다.
