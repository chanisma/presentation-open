# AI를 활용한 학습지 제작과 활용
## 한국 교사를 위한 AI 활용 수업 가이드 — AI 전문적 학습동아리 13차시

---

## 0. 발표 개요

본 발표는 교사가 AI(Claude Code 등)를 사용해 학생용 활동지(설문지·기획서·성찰일지·체크리스트)를 만들고, 학생이 제출한 데이터를 다시 AI로 분석해 수업으로 환류하는 전체 파이프라인을 다룬다. 핵심 도구는 두 가지 Claude Code 스킬, 즉 `presentation-builder`(지난 차시)와 `activity-sheet-builder`(이번 차시)이며, 두 스킬을 잇는 개념적 다리로 **바이브 코딩(Vibe Coding)** 을 안내한다.

발표 흐름(9단계):
1. 지난 시간 회고 — `presentation-builder` 스킬 사례
2. "스킬 사용 = AI로 사이트 개발"이라는 인식 전환
3. 바이브 코딩이란 무엇인가
4. `activity-sheet-builder` 스킬 소개 (Google Apps Script 핵심)
5. Google Sheets에 Apps Script 설정하는 단계별 가이드
6. 발급받은 Apps Script URL을 프레젠테이션에 연결하는 법 (AI에게 시키는 방식)
7. 활동지 라이브 테스트
8. 수집한 데이터를 Claude Code로 분석 — HTML 리포트, 엑셀 컬럼 추가
9. 응용 — 다양한 교육 업무에 확장하기

## 1. 지난 시간 회고: `presentation-builder` 스킬

### 무엇을 했는가

지난 차시(12차시)에 우리는 Claude Code의 `presentation-builder` 스킬을 사용해 수업용 발표 자료를 만들었다. 학생들이 흔히 PowerPoint로 작업하던 발표 자료를, 우리는 한 줄의 자연어 명령으로 HTML 슬라이드 묶음으로 만들어 냈다.

### 스킬(Skill)이란

스킬은 Claude Code 안에서 활성화되는 "특정 작업의 전문 지식 패키지"이다. 사용자가 특정 키워드(예: "발표자료 만들어줘")를 입력하면 자동으로 트리거되어, 해당 도메인에 최적화된 절차·디자인 가이드라인·코드 템플릿을 모두 메모리에 끌어와 작업한다.

- 스킬은 단순한 프롬프트 모음이 아니다. **참조 문서·디자인 시스템·HTML 템플릿·이미지 검색 절차** 가 함께 들어 있는 미니 라이브러리다.
- `presentation-builder`는 30가지 디자인 스타일 가이드, 코드 에디터 컴포넌트, 라이브 이미지 검색 등 **수업 현장에서 즉시 쓰기 좋은 기능**을 묶어 둔 스킬이다.
- 결과물은 단일 `index.html` 파일이며, 브라우저에서 곧바로 열어 발표할 수 있다 — PowerPoint 설치도, 폰트 호환 문제도 없다.

### 핵심 메시지

> "스킬을 호출했을 뿐인데 수십 장짜리 발표 자료가 5분 만에 완성됐다."

사용자는 코드를 한 줄도 쓰지 않았지만, 백그라운드에서는 AI가 HTML/CSS/JavaScript로 가득 찬 결과물을 자동으로 작성하고 있었다.

## 2. 인식 전환 — "스킬을 쓰는 것 = AI로 사이트를 개발하는 것"

### 우리가 못 본 사실

`presentation-builder`로 발표 자료를 만들었을 때, 우리는 단순히 **자료를 만든 것**이 아니다. 결과물을 다시 보자.

- `index.html` — HTML 마크업
- 안에 들어간 CSS — 색·여백·반응형 레이아웃
- 슬라이드 이동 JavaScript — 키보드/터치 네비게이션
- Live Code Editor 컴포넌트 — 학생이 코드를 수정하며 결과를 보는 인터랙티브 영역

이것은 **하나의 정적 웹사이트(static web app)** 이다. 즉, 우리는 자기도 모르는 사이에 "AI를 활용해 작은 웹사이트를 개발한 것"이다.

### 왜 이 시각이 중요한가

스킬이라는 추상화 뒤에는 늘 **"AI가 코드를 쓰고 있다"** 는 사실이 있다. 이 사실을 인지하면 두 가지가 가능해진다.

1. **응용 폭의 확장** — "이 발표 자료에 학생 입력창을 하나 더 넣어줘" 라고만 말해도, AI는 그것이 폼 + 데이터 저장 로직을 의미한다는 것을 안다.
2. **막힐 때의 자기 진단** — "왜 이게 안 되지?" 의 답은 결국 코드 어딘가에 있다. AI에게 "지금 만든 코드를 설명해 줘"라고 하면 학습 기회로 전환된다.

### 비유

> 우리가 워드 프로세서로 글을 쓰면, 보이지 않는 곳에서는 XML/HTML 마크업이 만들어진다. 마찬가지로 우리가 AI에게 자연어로 무엇을 시키면, 보이지 않는 곳에서는 **코드가 만들어지고 실행된다.**

## 3. 바이브 코딩 (Vibe Coding) 이란

### 정의

**바이브 코딩**(Vibe Coding) 은 Andrej Karpathy(전 OpenAI/테슬라 AI 디렉터)가 2025년 초에 소개한 용어로, 다음과 같은 개발 방식을 가리킨다.

> "코드를 직접 타이핑하지 않고, **AI와의 자연어 대화**만으로 프로그램을 만들어 내는 방식. 사람은 의도(vibe)를 전달하고, AI가 코드를 생성·수정·실행한다."

### 핵심 전제

- 사람의 역할은 **무엇을 원하는지** 명확히 표현하는 것 (요구 정의, 기획).
- AI의 역할은 **어떻게 만들지**(구현 디테일) — 라이브러리 선택, 코드 작성, 디버깅.
- 결과가 마음에 들지 않으면 **다시 말하면 된다** ("색을 더 따뜻하게", "버튼을 위로", "이 부분이 작동하지 않아요").

### 바이브 코딩의 간단한 절차 (5단계)

1. **의도 표현** — 만들고 싶은 것을 자연어로 한 문단 정도 설명한다. ("3학년 학생이 발표 주제를 제출하면 구글 시트에 저장되는 폼")
2. **AI에게 위임** — Claude Code 같은 에이전트에 그대로 맡긴다. AI가 파일을 만들고 코드를 쓴다.
3. **눈으로 확인** — 결과물을 브라우저에서 실행한다. 동작/디자인/내용 중 마음에 안 드는 부분을 메모한다.
4. **자연어 피드백** — "5번 항목 폰트가 너무 작아요", "제출 후 감사 메시지가 너무 빨리 사라져요" 처럼 **느낌을 그대로** 전달한다.
5. **반복** — 만족할 때까지 3~4번을 돈다. 보통 3~5회 안에 완성된다.

### 교사에게 의미하는 것

- 프로그래밍 지식이 **없어도** 학급 운영용 도구를 직접 만들 수 있다.
- "이런 게 있으면 좋겠다"가 즉시 **시제품**으로 변한다.
- 가장 큰 변화는 **창의적 책임**의 위치 — 아이디어가 곧 결과물이다.

### 주의: 바이브 코딩의 한계

- 보안·개인정보가 걸린 부분은 반드시 검토가 필요하다.
- AI가 만든 코드를 **모르고 그대로 배포**하는 것은 위험하다 — 적어도 무엇을 하는 코드인지 한 번은 설명을 받아야 한다.
- 본 수업에서 우리가 다룰 영역(학생 폼 → 구글 시트)은 안전한 영역이며, 좋은 출발점이다.

## 4. `activity-sheet-builder` 스킬 — 이번 차시의 주인공

### 설치 안내

`activity-sheet-builder`는 Claude Code 환경에 별도로 설치하는 스킬이다. 설치 절차는 다음과 같다.

```
/skill add activity-sheet-builder
```

또는 Claude Code의 스킬 마켓에서 검색해 추가한다. 설치 후 Claude Code를 재시작하면 자동으로 인식된다.

확인 방법:
```
/skill list
```
목록에 `activity-sheet-builder`가 보이면 설치 완료.

### 무엇을 하는 스킬인가

`activity-sheet-builder`는 다음과 같은 학생용 HTML 활동지를 자동으로 만들어 주는 스킬이다.

- **기획서 양식** — 모둠 발표 기획, 프로젝트 계획서
- **설문지** — 객관식·주관식·척도형
- **성찰일지** — 자기평가, 동료평가, 서술형 회고
- **체크리스트** — 활동 후 점검표

핵심 차별점은: 학생이 **브라우저에서 작성·제출하면 그 결과가 자동으로 Google Sheets에 누적된다**는 점이다. 추가로 TXT 파일 저장과 이미지 첨부도 지원한다.

### 어떻게 가능한가 — 핵심 기술: Google Apps Script

**Google Apps Script**는 구글이 제공하는 JavaScript 기반 자동화 플랫폼이다. 이 스킬의 진짜 가치는 **Apps Script를 어떻게 설정하고, HTML 폼과 어떻게 연결하는지**에 대한 노하우가 패키징되어 있다는 것이다.

작동 흐름:
```
학생 (브라우저 HTML 폼)
       │  fetch POST
       ▼
구글 Apps Script 웹앱 URL  (doPost 함수)
       │
       ▼
구글 시트 (행 추가)
```

스킬은 다음을 자동 생성한다:
- HTML 폼 (디자인된 학생 입력 화면)
- Apps Script `doPost(e)` 함수 본문 (붙여 넣을 코드)
- 구글 시트 헤더 행 자동 정의
- (옵션) 이미지 → Google Drive 업로드 처리 코드

### 왜 이 조합인가

- **무료** — 구글 계정만 있으면 된다. 서버 비용 0원.
- **권한 관리가 쉽다** — 시트 공유 권한이 곧 데이터 접근 권한이다.
- **즉시 가시화** — 시트는 교사에게 익숙한 인터페이스. 데이터를 보면서 차트도 바로 만든다.
- **분석으로 연결** — 시트를 CSV로 내보내면 다음 단계(Claude 분석)로 자연스럽게 이어진다.

## 5. Google Sheets에서 Apps Script 설정하는 법 — 단계별 가이드

### 사전 준비

- 구글 계정에 로그인되어 있을 것.
- 활동지 데이터를 받을 새 구글 시트(Google Sheets)를 미리 하나 만들어 둔다. 예: 시트 이름 "13차시-활동지-응답".

### 단계 1 — Apps Script 편집기 열기

1. 만들어 둔 구글 시트로 들어간다.
2. 상단 메뉴에서 **확장 프로그램(Extensions) → Apps Script** 를 클릭한다.
3. 새 탭으로 Apps Script 편집기가 열린다.
4. 프로젝트 제목을 의미 있게 바꾼다. 예: "13차시-활동지-수신기".

### 단계 2 — `activity-sheet-builder`가 알려준 코드를 붙여 넣기

1. 편집기 좌측의 `Code.gs` 파일을 클릭한다.
2. 안에 있던 기본 코드를 모두 지운다.
3. Claude Code가 만들어 준 코드를 그대로 붙여 넣는다. 보통 이런 형태:

```javascript
function doPost(e) {
  const sheet = SpreadsheetApp.getActiveSpreadsheet().getActiveSheet();
  const data = JSON.parse(e.postData.contents);
  const row = [
    new Date(),
    data.name,
    data.classNumber,
    data.topic,
    data.reflection
  ];
  sheet.appendRow(row);
  return ContentService
    .createTextOutput(JSON.stringify({ status: "ok" }))
    .setMimeType(ContentService.MimeType.JSON);
}
```

4. 상단의 디스크 아이콘 또는 `Ctrl+S`로 저장한다.

### 단계 3 — 웹앱으로 배포

1. 우측 상단의 **배포(Deploy) → 새 배포(New deployment)** 버튼을 누른다.
2. 톱니 아이콘(유형 선택) → **웹 앱(Web app)** 을 선택한다.
3. 다음과 같이 설정한다:
   - **설명**: "활동지 수신기 v1" (선택사항)
   - **다음 사용자로 실행(Execute as)**: **나** (= 구글 시트 소유자 본인)
   - **액세스 권한이 있는 사용자(Who has access)**: **모든 사용자(Anyone)**
4. **배포** 클릭.
5. 처음에는 **권한 요청** 창이 뜬다 — "권한 검토" → 본인 계정 선택 → "고급" → "안전하지 않은 페이지로 이동" → "허용".
6. 배포가 완료되면 **웹 앱 URL**이 표시된다. 이 URL이 우리가 폼에 꽂을 핵심이다.

> 형식: `https://script.google.com/macros/s/AKfycbx......./exec`

### 단계 4 — URL 복사 보관

이 URL을 잊지 말고 메모장이나 임시 문서에 복사해 둔다. 다음 단계(프레젠테이션·활동지에 삽입)에서 바로 쓴다.

### 자주 묻는 질문

- **Q. 배포 후 코드를 수정하면 URL이 바뀌나요?**
  - A. 배포 → "배포 관리" 에서 **버전을 갱신**하면 동일 URL을 유지할 수 있다. "새 배포"를 또 만들면 URL이 새로 생긴다.
- **Q. "모든 사용자" 로 열면 위험하지 않나요?**
  - A. URL을 모르는 사람은 접근할 수 없고, doPost 함수가 받는 데이터 형식 외에는 시트가 변경되지 않는다. 다만 URL을 공개 게시하지 않도록 주의한다 (학생용 폼에만 임베드).

## 6. 발급받은 Apps Script URL을 활동지/프레젠테이션에 넣는 법

### 핵심 원칙: AI에게 통째로 시킨다

이 단계는 코드를 직접 수정하지 않는다. **Claude Code에게 자연어로** 지시한다. 이것이 바로 바이브 코딩이다.

### 프롬프트 예시 (그대로 복사해서 써도 된다)

```
방금 Apps Script로 배포한 URL이 다음과 같아요:
https://script.google.com/macros/s/AKfycbx....EXAMPLE..../exec

이 URL을 이 활동지 HTML(또는 발표 슬라이드)의
제출 함수가 쓰는 엔드포인트로 바꿔 주세요.
제출 후에는 "제출이 완료되었습니다 :)" 토스트를 2초간 보여준 뒤
폼을 초기화해 주세요.
```

### AI가 내부적으로 하는 일

1. HTML 안의 `fetch(...)` 호출 위치를 찾는다.
2. 기존 placeholder URL을 새 URL로 교체한다.
3. 응답 처리 부분에 토스트 알림 코드를 추가한다.
4. 폼 reset 코드를 추가한다.

### 다양한 응용

- **여러 시트로 나누기**: "남학생/여학생 응답을 다른 시트로 보내고 싶어요" → AI는 Apps Script 쪽도 함께 수정해 준다.
- **이미지 첨부**: "사진 한 장 첨부할 수 있게 해 주세요. 사진은 구글 드라이브 폴더에 올려 주세요" → 폼에 file input + Apps Script에 DriveApp 코드가 추가된다.
- **자동 이메일 발신**: "제출되면 학생에게 확인 메일이 가도록" → MailApp.sendEmail이 doPost에 추가된다.

### 점검 포인트

- 폼 제출 후 시트에 행이 즉시 추가되는지 확인.
- 시트 권한이 본인(소유자) 외에는 보이지 않는지 확인.
- URL이 코드에 노출되어도 괜찮은지(이 URL은 데이터 추가만 가능하므로 비교적 안전).

## 7. 활동지 라이브 테스트

### 진행 절차 (수업 중 시연)

1. 완성된 활동지 HTML을 브라우저에서 연다.
2. 가짜 학생 이름과 응답을 넣고 제출한다.
3. 동시에 띄워둔 Google Sheets 탭에서 새 행이 추가되는지 보여 준다.
4. 다시 한 번 다른 데이터로 제출 → 누적되는지 확인.
5. 의도적으로 빈 칸을 두고 제출 → 클라이언트 검증이 작동하는지 확인.

### 대표적인 실패 케이스와 처방

| 증상 | 가장 흔한 원인 | 처방 |
|---|---|---|
| 시트에 아무것도 안 들어옴 | 배포가 "본인만"으로 되어 있음 | 액세스 권한을 "모든 사용자"로 재배포 |
| CORS 에러 | fetch에 mode 미설정 | AI에게 "no-cors / cors 처리 다시 해줘" 라고 시킴 |
| 한글이 깨짐 | Apps Script가 영문으로 되어 있음 | doPost에서 JSON.parse 사용 확인 |
| 두 번 눌렀더니 두 행 들어옴 | submit 비활성화 누락 | "제출 버튼 클릭 시 disabled 처리" 라고 AI에 지시 |

### 학생에게 배포하는 방법

- **클래스룸 링크 첨부**: 활동지 HTML을 학교 서버나 GitHub Pages에 올리고 그 URL을 공유.
- **로컬 시연**: 모둠별로 교사 PC 앞에 와서 차례로 입력 (소규모 학급).
- **QR 코드**: 활동지 URL을 QR로 만들어 칠판에 띄우면 모바일에서 바로 접속.

## 8. 수집한 데이터를 Claude로 분석하기

### 큰 그림

```
구글 시트
    │ (1) CSV 또는 XLSX 다운로드
    ▼
로컬 폴더의 데이터 파일
    │ (2) Claude Code에 "이 파일을 분석해줘"
    ▼
분석 결과
    ├─ HTML 리포트  (전체 경향 시각화)
    └─ 새 컬럼이 추가된 엑셀 (각 응답에 라벨/요약)
```

### 단계별 절차

1. **다운로드**: 구글 시트의 **파일 → 다운로드 → Microsoft Excel(.xlsx) 또는 CSV(.csv)** 를 선택. 같은 폴더에 `responses-13차시.xlsx` 등으로 저장한다.
2. **Claude Code 실행**: 작업 폴더를 열고 Claude Code 세션을 시작.
3. **자연어 분석 의뢰**: 다음과 같이 입력한다.

```
이 폴더의 responses-13차시.xlsx 를 읽고
'주제 선택 분포', '성찰의 정성도(문장 길이/키워드)',
'우려 사항 클러스터링' 세 가지 관점에서 분석해 주세요.

결과는
1) 시각화 포함 HTML 리포트(report.html)
2) 원본 엑셀에 'AI_라벨', 'AI_요약'
   두 컬럼이 추가된 새 파일 (analyzed.xlsx)
이렇게 두 가지로 만들어 주세요.
```

4. **결과 확인**:
   - `report.html` — 차트(원형, 막대), 키워드 빈도 클라우드, 추천 후속 활동 등.
   - `analyzed.xlsx` — 학생별 자유응답 옆에 AI가 붙인 한 줄 요약/라벨.

### 분석 결과를 수업으로 환류

- HTML 리포트를 다음 차시 도입에 띄우면 "여러분의 응답을 모아 본 결과…" 식으로 자연스러운 피드백 시작.
- analyzed.xlsx의 라벨은 모둠 재편성 자료가 된다 (예: "심층 관심 그룹", "추가 안내 필요 그룹").
- 학생이 자기 응답에 대한 AI 코멘트를 받아 보는 형태로도 확장 가능.

### 데이터 윤리 안내

- 학생 개인정보(실명, 학번)는 분석에 꼭 필요하지 않다면 **마스킹**하고 AI에 전달한다.
- 외부 LLM에 데이터를 보내는 것이 부담스러우면, **로컬 모델** 또는 학교 내부망 Claude Code 환경을 활용한다.
- 분석 결과를 학생/학부모에게 공유할 때는 라벨이 절대값이 아니라 **참고자료**임을 분명히 한다.

## 9. 응용 — 이 파이프라인으로 또 무엇을 할 수 있나

활동지 → 시트 → 분석으로 이어지는 흐름은, 이름만 바꾸면 학교 업무 곳곳에 그대로 쓰인다.

### 사례 모음

1. **학부모 상담 사전 설문**
   - "올해 우리 아이에 대해 알려 주고 싶은 점" 같은 자유응답을 모아, 상담 직전에 AI 요약본을 받아 본다.
2. **수행평가 자기평가지**
   - 평가표를 폼으로 만들어 학생 자기평가 → AI가 일관성 점검 (자기평가와 결과물의 격차).
3. **모둠 활동 회고**
   - 활동 직후 30초 회고 폼 → 다음 시간에 모둠 구성·진행 방식을 데이터로 조정.
4. **교내 행사 신청·만족도**
   - 신청 폼이 곧 명단, 만족도 폼이 곧 보고자료.
5. **동아리 운영 데이터화**
   - 출석/활동 로그를 폼으로 받아, 학기 말에 AI가 자동으로 운영보고서 초안을 작성.
6. **교사 연구회 협업**
   - 본 동아리 차시 회고를 같은 방식으로 모아, 다음 차시 기획에 반영.

### 한 단계 더 나아가기

- **챗봇 만들기**: 동일한 Apps Script 패턴 + LLM API 키 → 24시간 답하는 학급 안내 봇.
- **학습 분석 대시보드**: Google Sheets + Looker Studio 조합으로 라이브 대시보드.
- **자동 채점 보조**: 서술형 응답을 AI가 1차 채점/근거 표시 → 교사가 검수.

### 마무리 메시지

> 우리는 수업의 도구를 만들기 위해 **AI에게 무엇을 만들지 말로 설명**했다. 그것이 바로 바이브 코딩이다. 더 중요한 것은 — 만든 도구가 **데이터를 모아 다시 우리를 가르친다**는 점이다. AI는 도구를 짓고, 도구가 데이터를 모으고, AI가 그 데이터를 다시 해석한다. 이 순환이 한 번 돌기 시작하면, 교사의 시간과 시야가 동시에 넓어진다.

다음 차시에는, 모은 데이터를 바탕으로 학생 맞춤형 피드백을 자동 생성하는 워크플로를 다뤄 보자.

## 부록 A. 오늘 사용된 핵심 키워드

- **Skill (스킬)** — Claude Code의 도메인 전문 패키지
- **`presentation-builder`** — HTML 발표자료 생성 스킬
- **`activity-sheet-builder`** — HTML 활동지 + 구글 시트 연동 스킬
- **Vibe Coding (바이브 코딩)** — 자연어 대화로 프로그램을 만드는 방식
- **Apps Script** — 구글의 자바스크립트 기반 자동화 플랫폼
- **doPost(e)** — 외부에서 들어온 POST 요청을 처리하는 Apps Script 표준 진입점
- **웹 앱 배포** — Apps Script를 누구나 호출 가능한 URL로 노출하는 절차
