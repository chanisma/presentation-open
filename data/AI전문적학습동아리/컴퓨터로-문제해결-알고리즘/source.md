# 컴퓨터를 활용하여 문제를 해결하는 능력
## 알고리즘 — 컴퓨터에게 일을 시키는 가장 정직한 방법

대상: 고등학교 정보 수업 / 1차시 (50분)
디자인 톤(가이드): 연한 라이트 글래스 배경(#F8FAFC), 부드러운 카드, 둥근 모서리, 친근하지만 깔끔한 정보 디자인

---

## 0. 이 수업이 답하려는 한 문장의 질문

> "내가 머릿속으로 푸는 방법을, 컴퓨터에게도 똑같이 시키려면 어떻게 적어 줘야 할까?"

이 한 줄을 50분 동안 풀어본다. 답을 찾는 도구의 이름이 **알고리즘**이다.

---

## 1. 오늘의 목표 (3분)

학생이 수업이 끝났을 때 말로 할 수 있어야 하는 것 — 두 가지.

- ✅ "알고리즘이 무엇인지, 친구에게 라면 끓이기 비유로 설명할 수 있다."
- ✅ "순차·선택·반복 세 가지 구조를 직접 그림이나 코드 한 줄로 만들어 본다."

부가 목표:
- ✅ "라이트봇(Lightbot) 게임에서 한 스테이지를 클리어하며 알고리즘을 손으로 짜 본다."

---

## 2. 도입 — '컴퓨터로 문제를 해결한다'는 것이 정확히 무엇인가? (5분)

### 우리가 매일 하는 문제 해결

- 길을 잃었을 때 → 지도 앱이 길을 찾아 준다.
- 시험 점수가 1000명분 있을 때 → 엑셀이 평균을 계산해 준다.
- 사진 100장 중 강아지 사진만 → 휴대폰 갤러리가 자동 분류해 준다.

이 모든 일에서 **사람이 머리로 했을 일**을 컴퓨터가 대신했다. 이때 컴퓨터가 한 일은 결국 두 가지다.

1. **무엇을 해야 하는지** — 사람이 미리 적어 놓은 절차가 있다.
2. **어떻게 해야 하는지** — 빠르고 실수 없이, 반복적으로 실행한다.

> **컴퓨팅 사고력(Computational Thinking)** = 사람이 풀 수 있는 문제를, **컴퓨터가 풀 수 있는 형태로 다시 적는 능력.**

### 컴퓨터가 약한 점

컴퓨터는 빠르지만, 사람처럼 "알아서" 해 주지 않는다. 정확한 절차가 없으면 한 발짝도 못 움직인다.

- 사람: "라면 좀 끓여 줘" → 알아서 한다.
- 컴퓨터: "라면 좀 끓여 줘" → ❌ 못 한다.
  - "냄비를 꺼내라. 물을 500mL 넣어라. 가스를 켜라. 끓을 때까지 기다려라…" 처럼 **하나하나** 적어 줘야 움직인다.

이 절차서를 적는 능력 = 알고리즘을 만드는 능력 = 오늘 배울 내용.

## 3. 알고리즘이라는 단어 — 어디서 왔을까? (5분)

### 알 콰리즈미 (Al-Khwārizmī)

- 9세기 페르시아의 수학자, 천문학자.
- 본명: 무함마드 이븐 무사 알콰리즈미.
- 그가 라틴어로 번역되면서 이름이 **Algorismi → Algorithm** 으로 바뀌어 오늘날의 단어가 됐다.

### 그가 남긴 것

- **대수학(Algebra)** 의 기초 확립 — "Al-Jabr"라는 책에서 유래.
- **0과 10진법** 의 서양 도입.
- **문제 해결의 절차적 접근법** 을 글로 정리.
- 천문학·지리학·삼각법까지 절차적 사고를 확장.

### 왜 이 이야기가 중요한가

> 알고리즘은 **프로그래밍 언어가 생기기 1100년 전부터** 존재한 사고방식이다. 코드는 그 사고방식을 컴퓨터에 옮긴 것일 뿐이다.

— 즉, 알고리즘은 "코딩"이 아니라 **"생각하는 방법"** 이다. 코딩을 모르는 학생도 알고리즘을 만들 수 있다.

---

## 4. 알고리즘의 정의 (3분)

### 한 줄 정의

> **알고리즘** = 어떤 문제를 해결하기 위한, **유한한 단계**의 명확한 절차.

### 좋은 알고리즘이 가져야 하는 5가지 성질

| 성질 | 의미 | 라면으로 비유하면 |
|---|---|---|
| **입력** | 들어오는 재료 | 라면, 물, 가스 |
| **출력** | 나오는 결과 | 끓인 라면 한 그릇 |
| **명확성** | 모든 단계가 애매하지 않음 | "조금"❌ → "500mL"⭕ |
| **유한성** | 언젠가는 끝남 | 무한히 끓이지 않음 |
| **효과성** | 실제로 실행 가능 | "냄비를 마음으로 데운다"❌ |

### 학생용 점검 질문

- "노래방에서 노래 고르는 절차"는 알고리즘일까? ✅ (입력=곡명, 출력=재생, 단계가 명확, 끝남)
- "기분 좋아지는 법"은 알고리즘일까? ⚠️ (명확성·유한성이 약함)
- "원주율 100자리 계산"은 알고리즘일까? ✅ (긴 시간이 걸려도 단계가 명확하고 끝나므로)

## 5. 절차적 접근법 — 라면 끓이기 (5분)

### 가장 단순한 알고리즘

```
[시작]
  ↓
1. 재료를 준비한다 (라면, 물, 냄비)
  ↓
2. 물 500mL를 끓인다
  ↓
3. 면을 넣는다
  ↓
4. 수프를 넣는다
  ↓
5. 3분 기다린다
  ↓
6. 그릇에 옮긴다
[끝]
```

이게 바로 **순차구조** — 위에서 아래로 단 한 번씩 차례로 실행. 컴퓨터에게도 똑같이 적어 주면 된다. 이 그림(흐름도, Flowchart)이 알고리즘의 가장 보편적 표현 방식이다.

### 하지만 인생은 늘 그렇게 단순하지 않다

라면을 끓이는 도중에 이런 질문이 떠오른다.

- 🥚 "계란을 넣을까 말까?"
- 🌱 "대파는 잘게? 크게?"
- 🍳 "면이 덜 익은 것 같다 — 1분 더 끓일까?"

각 질문은 **상황에 따라 다른 길로 가야 한다**. 단순한 순차구조로는 표현할 수 없다.

여기서 새 도구가 등장한다.

## 6. 알고리즘의 3대 구조 (10분)

### ① 순차구조 (Sequence)

- 정의: 시작부터 종료까지 위에서 아래로 명령을 차례로 실행.
- 예: 위의 라면 기본 절차.
- 흐름도: 직선 + 화살표만 사용.

### ② 선택구조 (Selection / Branch)

- 정의: 주어진 조건에 따라 실행할 명령이 갈라지는 구조.
- 영어로는 if-then-else.
- 예 (라면):
  ```
  계란을 넣을까?
    ├ 예 → 계란을 깨서 넣는다
    └ 아니오 → 그냥 넘어간다
  ```
- 흐름도: 다이아몬드(◇) 모양으로 조건을 그리고, 두 갈래 화살표를 그린다.

#### 학생 직접 만들어 보기

> "버스를 탈까, 자전거를 탈까?" — 어떤 조건들이 들어갈까?
> 조건 후보: 비가 오는가? / 시간이 충분한가? / 친구가 같이 가는가?

### ③ 반복구조 (Iteration / Loop)

- 정의: 주어진 조건이 만족되는 동안 같은 명령을 여러 번 반복.
- 영어로는 for, while.
- 예 (라면):
  ```
  3분이 될 때까지 반복:
      30초 기다리기
      면이 익었는지 확인
  ```
- 흐름도: 화살표가 위로 되돌아가는 모양.

#### 학생 직접 만들어 보기

> 1부터 10까지 더하는 일을 사람이 하면 머릿속에서 9번 덧셈을 한다.
> 컴퓨터에게는 어떻게 적어 줄까? 반복으로 적으면 단 4줄이다.

```
합 = 0
i = 1부터 10까지 반복:
    합 = 합 + i
합을 출력
```

### 세 구조를 한 그림에 — 라면 + 계란 + 3분 타이머

```
[시작]
  ↓
1. 재료 준비
  ↓
2. 물 끓이기
  ↓
3. 면 + 수프 투입
  ↓
4. 계란 넣을까? ◇
   ├ 예 → 계란을 넣는다
   └ 아니오 → (그대로)
  ↓
5. 면이 익을 때까지 반복 ↻
   └ 30초 기다리기
  ↓
6. 그릇에 옮기기
[끝]
```

순차+선택+반복이 한 알고리즘 안에 모두 들어 있다.

## 7. 알고리즘이 같은 문제를 다르게 푸는 예 (5분)

### 문제: 1부터 100까지 더하기

#### 풀이 A — 무식한 방법

```
1 + 2 + 3 + ... + 99 + 100
```

99번의 덧셈. 컴퓨터에겐 빠르지만 사람에겐 지루하다.

#### 풀이 B — 가우스의 알고리즘

```
1과 100을 짝짓기 → 101
2와 99를 짝짓기 → 101
...
50과 51을 짝짓기 → 101

총 50쌍 × 101 = 5050
```

같은 답을 **50번의 곱셈 1번**으로 줄였다. 이것이 **알고리즘 효율**의 시작점이다.

> 같은 문제 → 여러 알고리즘 → 어떤 것은 빠르고 어떤 것은 느리다.

대학 가서 배울 "Big-O 표기법"이 이 차이를 측정하는 언어다.

## 8. 알고리즘은 우리 일상에 어떻게 들어와 있나 (3분)

학생이 와닿게 하는 6가지 사례.

1. **유튜브 추천** — 너의 시청 기록을 분석해 다음 영상을 고르는 알고리즘.
2. **지도 앱 길찾기** — 다익스트라(Dijkstra) 라는 1956년 알고리즘이 매일 너의 등굣길을 계산한다.
3. **카드뉴스 스팸 차단** — 단어와 패턴으로 스팸을 골라내는 알고리즘.
4. **사진 자동 분류** — 강아지/고양이/풍경을 알아보는 합성곱(CNN) 알고리즘.
5. **자판기** — 동전을 가장 적은 개수로 거슬러 주는 알고리즘 (그리디).
6. **시험 점수 정렬** — 1000명을 1초 안에 줄 세우는 정렬 알고리즘.

> 어떤 학교 점심 메뉴 배치도, 학생회 임원 추첨도, 다 알고리즘이 결정한다.

## 9. 실습 1 — 종이로 알고리즘 만들기 (5분)

### 미션

다음 문제를 **순차 / 선택 / 반복** 중 필요한 것만 골라 흐름도로 그려 보자.

> "오늘 학교 끝나고 친구와 떡볶이를 먹기로 했다. 떡볶이 가게 앞에 줄이 5명 이상이면 빙수집으로 옮긴다. 줄을 서기로 했다면, 친구가 도착할 때까지 기다린다."

### 함께 답 맞춰 보기 (예시)

```
[시작]
  ↓
1. 떡볶이 가게에 도착
  ↓
2. 줄이 5명 이상인가? ◇
   ├ 예 → 빙수집으로 이동 → [끝]
   └ 아니오 → 줄을 선다
              ↓
              친구가 왔는가? ◇
              ├ 예 → 같이 들어간다 → [끝]
              └ 아니오 → 1분 기다리기 ↻
                          (다시 친구 왔는가?로)
```

순차(도착) + 선택(줄 길이) + 반복(친구 기다림)이 모두 들어간다. 학생들이 다양한 답을 내도록 격려한다.

## 10. 실습 2 — Lightbot 도전 (10분)

### Lightbot이 뭔가요

**Lightbot**은 사용자가 화살표·점프·발광 명령을 조립해 로봇을 움직이고, 모든 파란 타일에 불을 켜는 게임이다. 코드를 한 줄도 쓰지 않지만, 학생은 **순차·반복(절차 호출)** 을 직접 손으로 조립한다.

### 진행 방법

1. 다음 링크 중 하나를 학생들에게 안내한다.
   - 무료 1편: `https://lightbot.com/hour-of-code.html`
   - 한국어 안내(예시): 학교 LMS에 사전 게시한 가이드 링크.
2. 학생은 **레벨 1-3 → 1-5 → 2-1** 순서로 푼다.
3. 한 스테이지를 클리어하면, **자기가 만든 명령 순서를 종이에 베껴 적는다.**
   - "이게 바로 너희가 처음 만든 알고리즘이야"라고 말해 준다.
4. 모둠끼리 **한 스테이지를 두 가지 다른 방법**으로 풀어 보고, 어느 쪽이 명령 수가 적은지 비교한다.

### 도전 과제 (시간 남은 학생용)

- 함수(P1, P2)를 사용해서 **명령 수를 절반으로** 줄여 본다.
- 같은 동작을 반복할 때 함수 호출이 곧 **반복 구조**의 한 형태임을 안내한다.

### 교사용 관찰 포인트

- "정답이 아니라 **줄어든 명령 수**가 곧 좋은 알고리즘이다"라는 메시지가 자연스럽게 전달되도록 둘러보며 코칭.
- 어려워하는 학생에게는 "한 발 한 발 무엇을 시킬지 종이에 먼저 쓰자"고 안내. 결국 알고리즘은 **글로 적는 것에서 시작**한다.

### 대안 실습 (인터넷이 안 될 때)

- **종이 미로 풀기** — 미로를 출력해 두고, 화살표만으로 출구까지 가는 명령 리스트를 적게 한다.
- **분식 알고리즘** — 조별로 김밥 만드는 절차를 흐름도로 그려 발표한다.

## 부록 B. 슬라이드별 시각 자료 제안

각 슬라이드에 들어가면 좋은 이미지/도형:

1. 표지 — 둥근 모서리 카드 + "알고리즘" 큰 타이포 + 작은 로봇 일러스트
2. 목표 — 체크박스 두 개 + 깃발 아이콘
3. 도입 — 길찾기, 엑셀, 사진 분류 3개 카드 (각각 아이콘)
4. 알 콰리즈미 — 책 일러스트 + 시간선(9세기 → 21세기)
5. 정의 — 큰 따옴표 카드 + 5가지 성질을 5개 작은 칩
6. 라면 흐름도 — 가로 흐름의 6단계 일러스트
7. 3대 구조 비교 — 순차(직선) / 선택(다이아몬드 분기) / 반복(원형 화살표) 3분할
8. 1~100 합 — 가우스 짝짓기 도형
9. 일상 사례 6개 — 그리드(2×3) 카드
10. 실습 1 안내 — 종이와 연필 일러스트
11. Lightbot 화면 캡처 + 명령 블록 일러스트
12. 마무리 — 큰 따옴표 인용 + 다음 시간 예고 카드
