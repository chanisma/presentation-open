3

문제를 풀기 위해 필요한 능력

이런 문제를 풀려면 다음 흐름으로 생각하는 힘이 필요합니다.

STEP 1

문제 파악

‘주어진 문제가 무엇인지’ 정확히 이해하는 능력. 무엇을 입력받아 무엇을 내놓아야 하는지 짚어 봅니다.

STEP 2

해결 방법 설계

‘문제를 해결하기 위해 어떤 방법을 사용할지’ 생각하는 능력. 어떤 순서로 풀어 나갈지 계획합니다.

STEP 3

코드로 표현

찾은 해결 방법을 ‘어떻게 프로그래밍 언어로 표현할지’ 생각하는 능력. 문법에 맞게 코드로 옮깁니다.

4

서답형 · 서술형 안내

서답형 · 4문제

코드의 빈칸을 채우는 문제

모든 코드를 직접 쓰는 것이 아니라, 코드의 한 부분을 공백으로 두고 어떤 식이 들어가야 하는지 찾습니다. 작성된 코드 각각의 의미를 해석하고, 실행되는 순서에 따라 문제가 어떻게 해결되어 가는지 파악하면 정답에 가까워집니다.

서술형 · 2문제

처음부터 끝까지 코드를 쓰는 문제

주어진 조건에 맞게 HTML·CSS·JavaScript 코드를 직접 작성합니다. 수업 시간에 했던 활동과 연계되기도 하니 프로그래밍 활동을 복습해 보세요. 단, 외우는 것이 아닙니다. 문법과 목적에 맞게 직접 작성할 수 있어야 합니다.

💡
다행인 점 서답·서술형 6문제 중 4문제(서답형)는 코드의 빈칸을 채우는 형태라, 코드를 읽고 해석하는 연습만 잘 해도 충분히 풀 수 있습니다.
5

시험에 쓰이는 HTML · CSS · JavaScript

모든 문제는 수업 시간에 배운 HTML · CSS · JavaScript 내용 안에서만 출제됩니다. 세 언어가 각각 어떤 역할을 하는지(HTML=구조, CSS=디자인, JavaScript=동작) 떠올리며 아래 내용을 다져 두세요.

HTML
기본 문서 구조 태그 · 요소 · 속성 제목 · 문단 태그 목록 태그 이미지 태그 (src 속성) 링크 태그 (href 속성)
CSS
선택자 (태그 · id · class) 스타일 적용 3가지 (인라인 · 내부 · 외부) 글자색 · 배경색 박스 모델 (margin · padding · border) 레이아웃
JavaScript
변수 (let) 자료형 (불리언 등) 비교 연산자 (== · ===) 조건문 (if · else) 반복문 (for) 함수 (function) 콘솔 출력 (console.log) 요소 선택 · 이벤트 (addEventListener)

어떻게 공부해야 할까

🚫
외워서 풀 수 있는 문제는 거의 없습니다 연습 문제나 활동지의 코드를 그대로 실행만 해 보거나 통째로 외우지 마세요. 외우는 것이 아니라, 문법에 따라·목적에 따라 코드를 직접 작성할 수 있어야 합니다.
📌
시험에 나오지 않는 차시 아래 두 차시 내용은 시험 범위에서 제외됩니다. 나머지 HTML·CSS·JavaScript 핵심 내용에 집중하세요.
✕ 9차시 · 예제를 통해 배우는 CSS3 ✕ 12차시 · JavaScript 실전: addEventListener 응용

특히 코드는 두 방향으로 이해할 수 있어야 합니다.

방향 1 · 효과 → 코드

원하는 효과를 코드로

“웹페이지에 이런 효과를 주려면 어떤 코드를 써야 할까?”를 떠올릴 수 있어야 합니다.
예) 제목 글자를 파랑으로 → h1 { color: blue; }

방향 2 · 코드 → 화면

코드를 보고 결과를

“이 코드를 실행하면 화면에 어떻게 표시될까?”를 예측할 수 있어야 합니다.
예) <img src="cat.png"> → 화면에 cat.png 이미지 표시

⌨️
이렇게 공부하세요 문법에 맞게 코드를 직접 써 보고, 결과가 내 생각대로 화면에 나오는지 확인하세요. 효과↔코드 두 방향을 오가며 연습하면 어떤 문제든 풀 수 있습니다.
7

객관식 핵심 용어 정리

웹 개발 수업에서 꼭 알아야 할 핵심 용어를 모았습니다. 설명을 토씨 하나 틀리지 않게 외우는 것이 아니라, 읽고 ‘어떤 용어와 관련된 내용인지’ 판단할 수 있으면 됩니다. 단어의 의미와 설명이 어떻게 이어지는지 연결 지으며 공부하면 관련 문제는 쉽게 풀 수 있습니다.

웹의 3대 언어

3

HTML

HyperText Markup Language

웹페이지의 뼈대와 내용을 만드는 언어다. 제목·문단·이미지·링크를 어디에 둘지 정해 페이지의 구조를 짠다. 집을 지을 때의 골조에 해당하며 디자인은 CSS가 맡는다.

CSS

Cascading Style Sheets

HTML로 만든 뼈대에 색·글꼴·크기·배치 같은 디자인을 입히는 언어다. 같은 내용이라도 CSS에 따라 전혀 다른 느낌이 된다. 웹페이지가 '어떻게 보일지'를 담당한다.

JavaScript

JavaScript

웹페이지가 움직이고 사용자에게 반응하게 만드는 프로그래밍 언어다. 버튼을 누르면 화면이 바뀌는 것처럼 동작과 상호작용을 담당한다. HTML이 뼈대이고 CSS가 디자인이라면 JavaScript는 두뇌 역할이다.

웹의 동작 원리와 인프라

9

인터넷

Internet

전 세계의 컴퓨터를 서로 연결하는 거대한 통신망이다. 정보가 오갈 수 있는 도로망과 같다. 웹을 비롯한 다양한 서비스가 이 위에서 동작한다.

웹(WWW)

World Wide Web

인터넷 위에서 문서를 서로 연결해 공유하는 서비스다. 우리가 브라우저로 보는 화면이 바로 웹이다. 인터넷이 도로라면 웹은 그 위를 달리는 서비스 하나에 비유할 수 있다.

웹페이지

Web Page

글·사진·버튼 등이 담긴 화면 한 장짜리 문서다. 서버에 저장된 HTML·CSS·JS 파일을 브라우저가 받아 보여 준다. 이런 페이지가 여러 개 모이면 웹사이트가 된다.

웹사이트

Website

하나의 주제로 모여 있는 여러 웹페이지의 묶음이다. 네이버·유튜브처럼 우리가 매일 방문하는 곳이 웹사이트다. 보통 헤더·내비·메인·푸터 같은 영역으로 구성된다.

웹브라우저

Web Browser

서버에서 받은 HTML·CSS·JS 파일을 해석해 화면에 그려 주는 프로그램이다. 크롬·엣지·사파리 등이 웹브라우저다. 우리가 웹을 볼 수 있게 해 주는 창문 역할을 한다.

웹서버

Web Server

웹사이트의 파일을 저장해 두었다가 요청이 오면 보내 주는 컴퓨터다. 손님 주문을 받아 음료를 만들어 주는 바리스타에 비유할 수 있다. 우리가 보는 화면도 서버가 보내 준 파일이다.

클라이언트

Client

서버에 정보를 요청하고 받아 보는 쪽이다. 보통 우리가 쓰는 웹브라우저가 클라이언트 역할을 한다. 카페에서 주문하는 손님에 해당한다.

프론트엔드

Frontend

사용자가 직접 보고 만지는 화면 쪽 개발을 뜻한다. 브라우저에 보이는 버튼·글자·디자인이 모두 프론트엔드다. 반대로 서버에서 데이터를 처리하는 보이지 않는 쪽은 백엔드라고 한다.

백엔드

Backend

서버에서 데이터를 저장하고 처리하는 보이지 않는 쪽의 개발을 뜻한다. 회원 정보 저장이나 로그인 확인처럼 화면 뒤에서 일어나는 일을 담당한다. 사용자 눈에 보이는 프론트엔드와 짝을 이룬다.

HTML·CSS 핵심 개념

8

태그

Tag

HTML에서 내용을 감싸 그 역할을 표시하는 기본 단위다. 보통 시작 태그와 종료 태그가 짝을 이루며 그 사이의 내용이 화면에 나타난다. 태그마다 고유한 역할이 정해져 있다.

요소

Element

태그와 그 안에 담긴 내용을 합쳐 부르는 하나의 덩어리다. 웹페이지는 이런 요소들이 모이고 겹쳐서 만들어진다. 요소 안에 또 다른 요소를 넣는 중첩도 가능하다.

속성

Attribute

태그에 추가 정보나 설정을 더해 주는 값이다. 예를 들어 이미지의 경로나 링크가 이동할 주소처럼 태그의 동작을 더 자세히 지정한다. 태그 시작 부분에 '이름=값' 형태로 쓴다.

스타일

Style

글자색·배경색·크기·배치처럼 웹페이지의 겉모습을 꾸미는 디자인 설정이다. CSS를 이용해 원하는 요소에 스타일을 적용한다. 같은 구조라도 스타일에 따라 분위기가 달라진다.

선택자

Selector

CSS에서 디자인을 적용할 대상을 골라 지목하는 부분이다. 먼저 어떤 요소를 꾸밀지 정한 다음 그 요소에 스타일을 입힌다. 요소 종류·아이디·클래스 등을 기준으로 대상을 고를 수 있다.

박스 모델

Box Model

웹페이지의 모든 요소를 하나의 상자로 보는 개념이다. 상자는 내용·안쪽 여백·테두리·바깥쪽 여백의 여러 겹으로 이루어진다. 이 겹들을 조절해 요소 사이 간격과 크기를 만든다.

레이아웃

Layout

웹페이지에서 요소들을 어디에 어떻게 배치할지 정하는 짜임새다. 요소를 가로나 세로로 나란히 정렬해 화면을 보기 좋게 구성한다. 좋은 레이아웃은 정보를 한눈에 들어오게 한다.

반응형 웹

Responsive Web

화면 크기에 따라 웹페이지의 배치와 모양이 자동으로 바뀌게 만드는 방식이다. 컴퓨터·태블릿·스마트폰 어디에서 봐도 보기 좋게 표시된다. 하나의 코드로 모든 기기에 대응하는 것이 핵심이다.

JavaScript와 동적 웹

3

DOM

Document Object Model

브라우저가 HTML 문서를 자바스크립트로 다룰 수 있도록 나무(트리) 구조의 객체로 표현한 것이다. DOM 덕분에 JavaScript가 화면의 글자나 스타일을 바꾸고 요소를 추가·삭제할 수 있다. 화면과 코드를 잇는 다리 역할을 한다.

이벤트

Event

클릭·키 입력·스크롤처럼 사용자가 하는 행동을 브라우저가 감지하는 것을 뜻한다. 이런 행동에 동작을 연결하면 사용자와 상호작용하는 웹을 만들 수 있다. 동적인 웹페이지의 출발점이 되는 개념이다.

동적·인터랙티브 웹

Dynamic / Interactive Web

사용자의 행동에 따라 화면이 실시간으로 바뀌고 반응하는 웹이다. 다크 모드 전환이나 실시간 글자 수 표시처럼 살아 움직이는 페이지를 말한다. 고정된 화면인 정적 웹과 반대되는 개념이다.

개발 도구와 방식

2

바이브 코딩

Vibe Coding

코드를 한 줄씩 직접 치는 대신 원하는 것을 일상 언어로 AI에게 설명하면 AI가 코드를 만들어 주는 새로운 개발 방식이다. 사람은 요청하고 결과를 확인하고 다듬는 역할을 맡는다. 2025년에 크게 유행한 개념이다.

프롬프트

Prompt

AI에게 무엇을 해 달라고 전달하는 요청 문장이다. 맥락을 주고 구체적으로 작게 나눠서 형식까지 정해 말할수록 더 좋은 결과가 나온다. AI를 잘 다루는 핵심 기술이다.
